## Goal
Implement the only float-to-money path of the game (00 §3.1, 02 §3.9): `roundHalfEven`, `toMoney`, `toQty`, `toPrice`, `fromMoney`, the exact bigint helpers (`divRoundHalfEven`, `mulRate`, `mulRateE12`, `accrue`, `notional`, `fxConvert`), the largest-remainder splitter `allocate` and `proRata`, plus `assertFinite` and `safeDiv`. Every module that touches money depends on these being exact.

## Imports
- T02-01: `Money`, `Qty`, `Price`, `Ccy`, `CCYS`, `EngineFault`, `SortedMap`, `cmpStr`.

## Implementation steps
1. `roundHalfEven` exactly as 02 §3.9.1; inputs with |x| ≥ 2^52 are already integers and returned unchanged (the subtraction trick is only exact below 2^52); non-finite -> EngineFault('I0.nan').
2. `toMoney` exactly as 02 §3.9.2 (assertFinite first, so `toMoney(NaN)` throws EngineFault code 'I0.nan'; step() converts it to failed invariant `I0.nan`, T02-16). `ccy` must be one of CCYS else EngineFault('I0.ccy'). Result `-0n` does not exist for bigint; for x = -0 the result is 0n. Contract (E-55): result = half-even rounding of the IEEE float product fl(x·1e6) (one multiply, as 02 §3.9.2), and, where |x·1e6| < 2^53, within 1 micro of the exact decimal value x·1e6. At or above 2^53 it returns `BigInt(x·1e6)` exactly with no rounding step (the product is already an integer double); the error is then the float input's own precision, allowed by 02 §3.9.2 note (b) (E-55 amended). it is NOT required to equal half-even of the exact product (they can differ by 1 micro, e.g. x = 2.5e-6 gives 2n, exact 3n).
3. `toQty`: v = x × Number(lotScale) (lotScale outside 1..2^31 -> EngineFault('I0.lot_scale'), E-55); HALF_EVEN -> BigInt(roundHalfEven(v)); LOT_FLOOR -> toward zero (`Math.trunc`). `toPrice(x)` = BigInt(roundHalfEven(x × 1e6)) with the same ≥ 2^53 branch as toMoney.
4. `divRoundHalfEven(n, d)`: q = n / d (truncating), r = n − q·d; compare 2|r| with d: greater -> q ± 1 away from zero (sign of n), equal -> make q even (adjust toward the sign of n only if q is odd), less -> q. Must be correct for negative n.
   **Caller rule (E-55 amended):** ledger amounts ≥ 2^53 micros never pass through float helpers (`toMoney`, `toPrice`, `fromMoney`, `roundHalfEven`, `safeDiv`); they use only the BigInt paths `divRoundHalfEven`, `mulRate`, `mulRateE12`, `accrue`, `notional`, `fxConvert`, `allocate`, `proRata`.
5. Helpers per 02 §3.9.3 table formulas verbatim (`accrue` denominator `1_000_000n * 364n`; `days` not a safe integer (`!Number.isSafeInteger(days)`) -> EngineFault('I0.accrue_days') before any BigInt conversion, never a RangeError (E-55); `notional` divides by lotScale).
6. `allocate` (largest remainder): W = Σw (all w ≥ 0, W > 0 else EngineFault('I0.allocate')); base_i = floor(total·w_i / W) for total ≥ 0 (for negative totals allocate |total| and negate parts); remainder R = total − Σbase; sort indices by (fractional remainder (total·w_i mod W) descending, id ascending by cmpStr) and give +1 to the first R. Parts always sum exactly to total. Duplicate ids -> EngineFault('I0.allocate_dup'). The result `Map` (G6 signature) is built by inserting ids in ascending `cmpStr` order, so iteration order is deterministic. G8 lint forbids `Map`; exactly one scoped `// eslint-disable-next-line no-restricted-globals -- G6 signature returns Map; built in ascending id order` at the construction site is ratified (E-55, PR #27); no other disable in the file.
7. `proRata` = allocate over the SortedMap entries (weights = holdings), result as SortedMap.
