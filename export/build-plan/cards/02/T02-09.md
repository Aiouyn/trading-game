## Goal
Implement the per-partition engine state store of G6 (`TableDef`, `StoreRead`, `Store`) with the guarantees 02 §3.6.3 and 19 Rules 3.6.3 and 3.6.6 require: tables owned by exactly one module (writes by any other module raise `OwnershipViolation`), an undo log so the open tick can be rolled back for free (whole tick or one entity, 20 Rule 3.2.5), value normalization (-0 to +0) and rejection of NaN/Infinity, per-entity hashes maintained on write, the partition-independent `logicalStateHash` (sum of per-entity terms mod 2^256), the partition `stateHash` (Merkle over (kindTag, id, entityHash)), phase stamps for INV-ENG-006, the write set handed to invariants, sorted iteration and declared secondary indexes, and a Money provenance log hook used by 03's INV-LED-012.

## Implementation steps
1. Data structure (decided here; 02 §3.6.3 allows a persistent B-tree, 19 Rule 3.6.3 an undo log; G6 binds the undo log): per table a committed `SortedMap<Id, Entity>` plus an open-tick overlay `SortedMap<Id, Entity | TOMBSTONE>`; `current` reads overlay first. Commit merges the overlay into the base. This makes `committed` (pre-tick) and `current` (post) both readable for invariants (20 Rule 3.1.1). The undo log is the ordered list of `WriteRecord`s (before/after); `rollbackEntity` removes that entity's overlay entry and its WriteRecords; `rollbackTick` clears the overlay.
2. `put(table, entity)` via a bound store: table must exist (TBL_UNKNOWN EngineFault); `def.module !== binding.module` -> record the violation and throw `OwnershipViolation` (aborts the tick via safe mode, 19 Rule 3.6.3; INV-ENG-001 also reports it). Before storing, deep-normalize: every number field `assertFinite` (EngineFault 'I0.nan' naming table and id) and -0 -> +0; `undefined` fields removed (canonical encoding has no undefined); Map/Set values forbidden (EngineFault 'I0.store_type'); bigint, string, boolean, arrays, plain objects, Uint8Array allowed. Deep-freeze the stored copy (Object.freeze recursively) so modules cannot mutate state behind the undo log; `get` returns the frozen object.
3. Phase stamps: each overlay entry remembers the phase that last wrote it. A read through a bound store of an entity written this tick by a phase with a higher `phaseIndex` than the reader's phase is recorded as a ReadStamp violation (INV-ENG-006). Reads of entities written by earlier or the same phase are normal.
4. Secondary indexes: maintained on put/del for current state; `index(table, name, key)` yields entities sorted by id.
5. Hashing (19 Rule 3.6.6, 02 §3.6.3): on every put the entity hash is recomputed and the running `logicalStateHash` is updated incrementally: subtract the old term (if any), add the new, mod 2^256; del subtracts. `stateHash` = `partitionMerkle` over all (table, id, eh). Leaf = sha256Concat(table, 0x00, id, 0x00, eh); leaves sorted by (KIND_TAG_ORDER index of kindOf(id), table name, id) using cmpStr; Merkle as T02-07's tree shape (implemented locally here: leaf prefix 0x00, node prefix 0x01, odd node promoted). Cache per-table sorted leaf arrays and recompute only tables with dirty leaves; the root is recomputed from the cached leaf lists each commit (correctness over cleverness; optimise later only with identical output).
6. Provenance hook: `notifyMoney` is a no-op when no provenance is active. T02-04's `toMoney` and helpers are NOT edited here; instead export a wrapper list that 03 can use. (03 decides how INV-LED-012 consumes it; this hook is the store-side mechanism named in 20 INV-LED-012.)
7. INV-ENG-001 (TICK, FATAL): fails if any violation fact exists, entityIds = the written ids, observed 'module=<m> table=<t>'. INV-ENG-006 (TICK, FATAL): fails if any read stamp with readerPhase < writerPhase exists.
8. `asSystem()` exists only when constructed with `{ testMode: true }` (TestWorld.asSystem, G6). In production construction it throws EngineFault('I0.test_only').

## Test plan
store.test.ts:
- ownership: module '05' writing a table owned by '03' throws OwnershipViolation and INV-ENG-001's check fails with that table in observed; negative test registered.
- NaN field put -> EngineFault I0.nan; -0 field stored as +0 (Object.is on read back); nested Map rejected.
- rollbackTick restores `current` byte-identical to `committed` and `logicalStateHash` to the pre-tick value; rollbackEntity reverts only that entity.
- property (fcParams): random sequences of put/del over 3 tables then rollbackTick -> hashes equal the pre-tick hashes; random sequences then commitTick -> `logicalStateHash` equals a full recomputation from scratch.
- INV-ENG-006: reader bound to P6 reading an entity written in P9 of the same tick (simulated by binding order) -> violation; reading an entity written in P4 -> no violation.
- index iteration sorted by id; frozen objects cannot be mutated (TypeError in strict mode).
hash.test.ts:
- logicalStateHash is independent of insertion order and of splitting the same entities across 1, 3 and 17 PartitionStores (sum of the per-store values mod 2^256 equals the single-store value) (19 Rule 3.6.6).
- worked example: entity {id:'chr_A', cash: 5n} -> entityHash equals sha256(canonEncode(...)) computed in the test; logicalTerm equals BigInt('0x' + hex(sha256('chr_A' ‖ eh))).
