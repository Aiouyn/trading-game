## Goal
Lay the first stones of `@tycoon/engine/core` exactly as GLOBAL-CONTEXT G6 names them: the primitive types, deterministic ordered collections (`SortedMap`, `SortedSet`), the canonical string order `cmpStr` and stable total `sortBy`, a pinned pure-JS SHA-256 (with HMAC-SHA-256 for the entropy scheme of 19 §3.12), `fnv1a32` for staggering, hex helpers, and the `canonEncode` re-export. It also proves that the determinism lint rule (from 19.A) rejects forbidden engine code (02 AT 13). Everything else in the engine builds on these.

## Imports
- T19A-??: `canonEncode(v: unknown): Uint8Array` and `canonDecode(b: Uint8Array): unknown` from `@tycoon/protocol` (deterministic MessagePack variant of 02 §3.16.2); ESLint flat config with rule `tycoon/deterministic` applied to `packages/engine/**`; vitest preset.

## Implementation steps
1. `cmpStr`: compare code units with `a < b` semantics on strings (JS string `<` is already UTF-16 code-unit order); return -1/0/1. Never `localeCompare`.
2. `sortBy`: decorate with index, compare `cmpKey(key(a), key(b))` then original index (stable). `cmpKey` compares part by part; mixed types in the same position are a programming error: throw `EngineFault('I0.sort_key', ...)`. Numbers compared with `<`; NaN in a key -> EngineFault. Uses `Array.prototype.sort` WITH the comparator (allowed).
3. `SortedMap`: sorted array of keys plus a parallel array of values, binary search on `cmpStr`. `set` returns `this` (chaining, G6 signature). Iterators iterate over a snapshot index range and are invalidated by mutation (document; throw if size changed during iteration via a version counter). No `Map` iteration anywhere.
4. SHA-256: standard 64-round implementation on Uint32Array with `Math.imul`-free 32-bit adds (`(a + b) >>> 0`); test vectors from FIPS: "" -> e3b0c442...b855, "abc" -> ba7816bf...15ad, the 448-bit message "abcdbcdecdefdefgefghfghighijhijkijkljklmklmnlmnomnopnopq" -> 248d6a61...06c1, one million 'a' -> cdc76e5c...d0ba3f (only in a NIGHTLY-tagged test). Write the full expected hex in the test file.
5. HMAC per RFC 2104 with block size 64; RFC 4231 test case 1 and 2 vectors in tests.
6. `fnv1a32`: offset 2166136261, prime 16777619 via `Math.imul(h, 16777619) >>> 0`, over the UTF-8 bytes of the string. Test vectors: fnv1a32('') = 2166136261, fnv1a32('a') = 0xe40c292c, fnv1a32('foobar') = 0xbf9cf968.
7. `canonHash` = sha256(canonEncode(v)).
8. Lint proof (02 AT 13): `lint.test.ts` runs ESLint programmatically (`new ESLint({ overrideConfigFile: <repo eslint.config.js>, cwd })`) on each fixture's text with `filePath` set to a virtual path inside `packages/engine/core/` (use `lintText(text, { filePath })`). Fixtures are `.ts.txt` so they are not compiled. Expect at least one error from rule `tycoon/deterministic` (or the restricted-syntax rules of the same config) for: `const t = Date.now()`, `Math.random()`, `Math.exp(1)`, `for (const k in obj) {}` and `Object.keys(o).forEach(...)`; expect zero errors for `good.ts.txt` (uses `cmpStr`, `sortBy`, `SortedMap`).
9. All files obey 02 §3.7.1 themselves (no Map/Set iteration, no Math.* outside the allowed list).
