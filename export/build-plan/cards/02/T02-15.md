## Goal
Provide the engine-side plumbing that unit 03's ledger plugs into for money that crosses partitions (02 §3.14.2–§3.14.3, §3.15.1): exchange of posting legs at barrier B3, per-partition suspense reports to the coordinator, the coordinator's global check (I13 suspense nets to zero, plus whatever global checks the provider implements), hold settle/release messages in P13, atomic multi-party settlement (both legs commit or neither), and ABORT everywhere when any partition or the global check fails. To test it before 03 exists, a test-only `FixtureLedger` implements the `LedgerProvider` port with a deliberately small double-entry book (test helper only, never imported by production code, 19 Rule 12.4.2 fixtures).

## Implementation steps
1. Leg protocol (02 §3.14.2): when the provider's `pay` (or swap) has accounts in two partitions, the source partition's LedgerPartition produces two legs with the same entryId and legId: in A `Dr A_account Cr sys:9900:A->B:<ccy>` and a leg message for B with `Dr sys:9900:B->A:<ccy> Cr B_account`. `exchangeLegs` collects `outgoingLegs()` after R3, posts them as LEG_KIND messages at B3 (sorted by (fromPartition, seq)), and calls `acceptLegs` on each receiver before R4.
2. Holds (02 §3.14.3): holds are placed in P1 (or inline in P4/P5) on the owner's partition only; in P13 the provider settles (converts into the fill/transfer postings, releasing the unused part) or releases; holds with `expiresTick < N` release automatically. Settling a hold for a consumer in another partition is announced by a HOLD_SETTLE_KIND message at B3; the consuming partition's leg and the holder's settlement commit together because both are inside the same tick's two-phase commit.
3. Two-phase commit (02 §3.15.1): R4 each partition `prepare` -> {ok, stateHash, suspense, failures}; R5 `globalDecision` = all ok AND `provider.globalCheck(reports).ok`; COMMIT -> every partition `commit` then P14; ABORT -> every partition `abort` (store, ledger, rng rollback) and the coordinator returns committed false with the failures for the safe-mode ladder (T02-16). No posting, event or delta of an aborted attempt leaves the coordinator (02 AT 31 is asserted in T02-16).
4. Atomic swap (02 §3.14.3 rule 4, §8 edge 7): both sides place holds in P1; if either side's validation fails, the handler must not produce either leg; holds of both release in P13. The plumbing guarantees that if one partition's prepare fails the other partition's leg is discarded too (ABORT is global).
5. FixtureLedger (test helper): accounts are strings `entityId:code:ccy`; `pay(from,to,amt,ccy,code)` queues an entry; `mint` queues a FAUCET-like entry from `sys`; holds placed via placeCash check `available = balance − Σ active holds` and return Reject {code: 'LED_INSUFFICIENT_FUNDS'}; prepare applies entries to a copy, settles/release holds, computes suspense; `globalCheck` = suspenseNetZero (named 'I13') plus trial balance per ccy (named 'I3'). Documented as a fixture: no reason-code catalogue, no classes, no M0/M2: 03 implements the real rules.
