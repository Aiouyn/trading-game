## Goal
Implement the effects and validation of the engine-level admin directives of 02 §4.2 (`adm.halt`, `adm.resume`, `adm.param.cutover`, `adm.version.cutover`, `adm.maintenance.schedule`, `adm.quarantine.persist`), which 21's console submits with two approvals: parameter-set and engine-version changes take effect exactly at a tick boundary and replay reproduces both sides (02 §3.18), state migrations are pure functions applied before P0 of the cutover tick, content versions change by directive at a daily boundary, planned maintenance obeys 24 R29 (at most 30 real minutes per event, at most one per real week, at least 24 real hours notice, in the quietest real hour computed by 21), and shadow verification picks a deterministic ~1% of ticks (02 §3.17.3).

## Implementation steps
1. Approvals: two distinct admin ids for every directive that changes rules (halt, resume, param, version, maintenance, quarantine.persist); exception: an automatic safe-mode halt (`automatic: true`) needs 1 (02 §4.2). Else DIR_APPROVALS.
2. `adm.param.cutover {atTick, paramsVersion}`: atTick ≥ currentTick + version_notice_ticks (17,280) unless `hotfix` (then ≥ currentTick + 1); effect (02 §3.18.4): from `atTick` the runtime loads `loadParamSet(paramsVersion)`; ticks before keep the old set; header.paramsVersion records it; emits `core.param.changed {paramsVersion, changedKeys = diffParamSets}` at atTick. Gameplay-changing patches land at chapter boundaries (02-multiplayer §2.3): enforce that a non-hotfix PARAM_CUTOVER whose diff contains any key flagged "live: no" in 23 must have atTick at a CHAPTER_OPEN tick (else DIR_NOTICE with detail 'chapter boundary required'); keys flagged live may cut over at any tick boundary.
3. `adm.version.cutover {atTick, engineVersion, migrationId?}`: requires a CiReplayReport with green = true and every divergence intended and at or after atTick (else DIR_CI_REPORT, 02 AT 37); notice as above unless hotfix. Effect: at atTick, before P0, apply the registered migration (pure) to every partition image, write a PRE_VERSION snapshot at atTick − 1 (T02-10 cadence), header carries engineVersion and migrationId; emits `core.version.cutover {engineVersion, notesKey}`.
4. `adm.halt {reason, publicMessageKey}`, `adm.resume {resumeAtUtcMs}`: validation here (resume requires status HALTED_* else DIR_NOT_HALTED; resumeAtUtcMs ≥ now + resume_notice_ms else DIR_RESUME_NOTICE); effects in T02-19's scheduler.
5. `adm.maintenance.schedule {startUtcMs, durationMin}` per 24 R29 (which amends 02 §3.20.4 and supersedes AT 36's "Saturday t = 0 ... 20 minutes" wording; precedence 24 > module): durationMin ≤ liveops_maintenance_max_minutes (30) else DIR_MAINT_DURATION; no other maintenance started within the 7 real days before or after startUtcMs (DIR_MAINT_WEEKLY); startUtcMs within the quietest real hour window supplied in the payload by 21's console (`MaintenanceSlot`, computed by 21 Rule 3.3.3) and the whole window inside that hour (DIR_MAINT_QUIET_HOUR); startUtcMs ≥ nowUtcMs + 24 real hours (DIR_MAINT_NOTICE). Effect: implemented as HALT at start + RESUME at end (T02-19).
6. `adm.quarantine.persist {entityId, untilTick}`: adds to T_WORLD.frozen (entity stays `ENGINE_REVIEW` until lifted).
7. Content versions (02 §3.18.5): `contentVersionAllowedAt` = tickOfDay 0; new content creates new streams/entities only (existing streams untouched, 02 §8 edge 9).
8. Shadow selection: deterministic per tick; the verifier process (19/20B) recomputes selected ticks and compares hashes.

## Test plan
directives.test.ts:
- `02#36 a planned maintenance can only be scheduled at Saturday t = 0 with ≥ 24 real hours notice and within 20 minutes per real week`: implemented per ruling R29 (24 > 02): accepted: 30-minute window inside the quietest hour with 25 h notice; rejected: 31 minutes (DIR_MAINT_DURATION), 23 h notice (DIR_MAINT_NOTICE), start outside the quietest hour (DIR_MAINT_QUIET_HOUR), a second event 3 real days after the first (DIR_MAINT_WEEKLY). The test name keeps the id and states "(as amended by R29)".
- `02#37 a VERSION_CUTOVER without a green CI replay report is refused by the directive validator`: missing report -> DIR_CI_REPORT; report green=false -> DIR_CI_REPORT; an unintended divergence -> DIR_CI_REPORT; green with only intended divergences after atTick -> accepted.
- `02#38 a PARAM_CUTOVER takes effect exactly at atTick; ticks before use the old paramsVersion; replay reproduces both`: fake module reads a live param each tick and writes it to state; cutover at tick 50 (hotfix path to keep the test short; also a non-hotfix case at currentTick + 17,280 accepted): ticks 0–49 header.paramsVersion = 1 and old value; 50+ = 2 and new value; replay from tick 0 reproduces every hash.
- approvals: one approval rejected; automatic halt with one approval accepted.
shadow.test.ts:
- `02#39 shadow verification at fraction 0.01 recomputes ~1% of ticks and raises a determinism incident when a deliberately non-deterministic test module is enabled`: over 100,000 ticks the selected share is within [0.009, 0.011]; with a non-deterministic fake module, re-running a selected tick via `replay` yields a DeterminismIncident.
