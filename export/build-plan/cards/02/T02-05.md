## Goal
Map every tick to its game date and calendar facts (02 §2.1–§2.3, §3.1–§3.3): the immutable clock constants, `ticksToGameDate`/`dateToTick`, `calendarOf` with the set of boundaries that occur at a tick, the per-bloc holiday table, business-day functions with modified-following adjustment, the session state of every product family at every tick (including weekends, the FX weekend window and holiday depth), the hourly stagger rule, and the canonical/display date formats. Every module schedules its work through these pure functions.

## Imports
- T02-01: `Tick`, `cmpStr`, `fnv1a32`, `SortedSet`.
- T02-04: (none at runtime; tests only).
- T23-??: `ParamsView` type (`num(key)`), used only by `formatDisplay` and `sessionState` callers that pass the values in.
- T22A-??: content holiday names (`holiday.<bloc>.<name>` keys) are validated against this table at genesis by 22.A's loader; this file owns day-of-year data (02 §3.2 DEFAULT).

## Implementation steps
1. `ticksToGameDate` exactly per 02 §3.1.1 with integer arithmetic (`Math.floor`, `%` on non-negative ticks; negative tick -> EngineFault('I0.tick')).
2. `calendarOf(t)`: `isTradingDay` (G6 field) = weekday < 5 (bloc holidays are per bloc via `isTradingDay(bloc, d)`). `gameHour = floor(tickOfDay / 30)`. Boundaries at tick t: HOUR when tickOfDay % 30 == 0; DAY_OPEN at tickOfDay 0; PHASE_CHANGE when tickOfDay ∈ {0, 60, 61, 540, 541}; DAY_CLOSE at 719; WEEK_CLOSE at 719 of weekday 6; MONTH_CLOSE at 719 of the last day of a month; QUARTER_CLOSE at 719 of dIQ 90; YEAR_CLOSE at 719 of dayOfYear 364; CHAPTER_CLOSE at 719 of dayOfChapter 1344; WEEK_OPEN at 0 of weekday 0; MONTH_OPEN at 0 of dayOfMonth 1; QUARTER_OPEN at 0 of dIQ 0; YEAR_OPEN at 0 of dayOfYear 1; CHAPTER_OPEN at 0 of dayOfChapter 1. Tick 0 has every OPEN boundary (02 §8 edge 1).
3. The extra Boundary members (`*_OPEN`, `PHASE_CHANGE`) extend G6's union (superset; every G6 value keeps its meaning). This is required by 02 §3.4 start-of-period hooks; recorded in GLOBAL-CONTEXT G6 by E-51 (PR #20).
4. `HOLIDAYS`: the 16 rows of 02 §3.2 with ids and nameKey `holiday.<bloc lower or all>.<suffix lower>` e.g. 'holiday.all.genesis', 'holiday.fdl.charter'; hol_GENESIS has all five blocs. `validateHolidayTable` runs at module load in tests and at genesis (T02-21).
5. `adjustModifiedFollowing`: n = nextTradingDay if !isTradingDay(d) else d; if month(n) !== month(d) (compare year and month of `dayIndex`), return the previous trading day before d; else n.
6. `sessionState` per the 02 §3.3 table (t = tickOfDay, wd = weekday):
   - BLOC_LISTED (equities, ETFs, listed bonds, listed options, IPO books) with `bloc`: weekend or holiday(bloc) -> CLOSED_QUEUE (orders queue, no matching); t 0–59 CLOSED_QUEUE; 60 OPEN_AUCTION; 61–539 CONTINUOUS; 540 CLOSE_AUCTION with officialClose; 541–719 CLOSED_QUEUE.
   - FX with `fxBlocs`: closed from Saturday t=0 to Sunday t=659 inclusive (CLOSED); else TRADING; depthMult = holidayFxDepthMult if either bloc of the pair has a holiday that day, else 1; dailyMark at t=719.
   - FUT_24H, CRYPTO, COMMODITY_24_7 (compute, energy): TRADING every tick; dailyMark at 719.
   - FUT_FX: follows FX. FUT_BLOC (equity index, bond futures): closed t 0–59; TRADING 60–539 (540 is TRADING with officialClose = daily settlement price); 541–719 CLOSED; weekend/holiday CLOSED.
   - COMMODITY (non-24/7): TRADING every tick Mon–Fri, CLOSED Sat and Sun, unaffected by holidays.
   - REAL_ASSET: TRADING any tick (settle at any tick).
   - OTC: state of `underlyingFamily` (required).
   `matches` = state ∈ {OPEN_AUCTION, CONTINUOUS, CLOSE_AUCTION, TRADING}.
7. Formats: `hh:mm` from minuteOfDay; display ET adds `displayClockOffsetMin` (DEFAULT 360) modulo 1440 and rolls the displayed date forward when it crosses midnight; month and weekday names are i18n keys `month.1..12`, `weekday.0..6` (L8, no raw text).
