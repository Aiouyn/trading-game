## Goal
Define the binding module contract of GLOBAL-CONTEXT G6 that every engine module programs against: `PhaseCtx`, `ValidateCtx`, `SealedIntent`, `Reject`, `IntentHandler`, `InvariantImpl` (re-export of 20.A), `ViewHandler` and `ViewerContext`, `ModuleDef` and `defineModule`, plus the module registry that validates a set of modules (unit ids, hard dependencies of 19 §12.2, table ownership, stream prefixes, event schemas, intent kinds) and the injection port through which unit 03 provides `ctx.ledger` and `ctx.holds`. Because 03 is built after 02, this task declares the G7 `LedgerApi`/`HoldApi` types (type-only, verbatim G7) and a `LedgerProvider` interface; the engine wires the provider when a module with `services.ledger` is loaded and otherwise makes `ctx.ledger`/`ctx.holds` throw `EngineFault('I0.no_ledger')`.

## Implementation steps
1. Copy G6 and G7 signatures verbatim into `ctx.ts` and `ledger-port.ts` (do not rename anything). `EngineEvent.partyIds` is optional on input; 19's `EngineEventRow.partyIds` is filled at P14 (T02-13) from `partyIds` or the subjectIds for PARTIES/PRIVATE events.
2. `defineModule`: checks that `id` starts with `module`, that every table's `module` equals `m.module` (MOD_TABLE_OWNER), every event kind has a namespace prefix allowed for the module (MOD_EVENT_NS), every intent kind namespace allowed (MOD_INTENT_NS), stream prefixes are registered in `STREAM_REGISTRY` for this module (MOD_STREAM_FOREIGN via T02-06 `matchStream` on the prefix + ':x' or the bare key), and freezes the object. Throws ModuleSetError (module load time, never in step()).
3. `buildModuleSet`: sort by (module number, unit id); every unit id must be in BUILD_UNITS (MOD_UNKNOWN_UNIT); every hard dependency of a loaded unit must be loaded (MOD_MISSING_DEP; 19 Rule 12.4.2: a missing dependency means the unit waits); duplicate tables/intents/events/views rejected; at most one module provides `services.ledger` (MOD_TWO_LEDGERS) and it must be module '03'. The core module '02' (T02-21) is always included by createTestWorld.
4. `ownsStream(module, key)`: key's registry spec module equals module and its prefix is in that module's `streams`.
5. NPC behaviour (02 §6) affects this contract: NPC intents are produced by P3/P4 (and P7/P8 institutional) phase code through the same `IntentHandler.validate` with channel 'NPC' (no private API). Decision (G6 has no NPC submit method): NPC intents are submitted with `ctx.send(<handler module entity>, 'npc.intent', {kind, payload, actorId}, 'B1')` and the pipeline (T02-12) routes 'npc.intent' messages produced in P3/P4 through the owning handler's `validate` and `apply` inline in the same tick at P4 (02 §3.5.1 "NPC ... validated with the same P1 rules inline"), assigning `orderKey = orderKeyOf(entropy, intentId)` with intentId = ctx.newId('int'). Document `NPC_INTENT_KIND = 'npc.intent'` and export it from ctx.ts.
6. The lint-level obligations of 02 §3.6.2 are enforced by T02-01's lint and the store; record them as JSDoc on PhaseCtx.
