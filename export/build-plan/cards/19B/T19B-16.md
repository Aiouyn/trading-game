## Goal
Assemble the `world` process (coordinator loop, worker pool, entropy, snapshots, recovery, standby) into one entry point with ACTIVE and STANDBY roles, create the world at genesis (19 §8 edge 29), build partition maps from 19 Rule 3.13.2's counts, and provide the headless world used by 20's harness: the production pipeline with N partitions in one process. Prove the two determinism properties every later unit relies on: replay equality (19#3) and partition independence (19#4).

## Implementation steps
1. `shapeFor`/`buildMap` per 19 Rule 3.13.2: PLAYER `max(2, ceil(agents / partition_target_agents))`; MARKET one partition per group list (a single asset is never split); CITY one per city; FINANCE one per bloc (Isla Serena's institutions on FINANCE-FDL, its city on its own CITY partition, 19 Rule 3.5.1); CCP 1; COORD 1; ACTOR `ceil(namedActors / 300)`. Group tables of the map name which partition owns each market group, city and bloc. Tests can request any PLAYER count (1, 3, 17) and MARKET partition count (1 or 4 by merging groups).
2. Genesis (edge 29): `genesisConfigHash` = hex SHA-256(canonEncode(cfg without secrets)); the world starts with map version 1, params version 1 (T23-08 launch set), content version 1; tick 0 is the first `WorldLoop` tick and its TickRecord row stores `genesis_config_hash` (migration 0003 adds the nullable column to `world.tick_record`, set only on row 0; superset of 19 §11.2, flagged).
3. `startWorldHost`: load config (T19B-07), pin check, spawn workers for the map, load latest snapshots (or genesis), start entropy, lease, loop, snapshot writer steps, metrics. STANDBY runs `StandbyFollower` and polls the lease.
4. Headless world (19 §10 definition): same engines and the reference/worker drivers of T19B-02/T19B-08, an in-memory bus, sealing via `Sealer` with injected arrival times (all intents of a tick arrive before the margin), the dev KMS entropy service (seeded), no database (records kept in memory). `HeadlessWorldDriver.step()` returns a `TickDigest` (logicalStateHash, eventDigest, postingDigest) for 20.A.
5. Replay (19 Rule 3.7.1): `replayHeadless` re-runs recorded batches from genesis with the same seed (entropy secrets come from the dev KMS seed, equivalent to revealed secrets) and returns the records.

## Test plan
`initial-map.test.ts`: agents 40,000 -> player 2; 60,000 -> 3; 450,000 -> 18; namedActors 600 -> actor 2; hash ranges cover 0..2^32 exactly once; Isla Serena city on its own CITY partition and its bank on FINANCE-FDL (home rule check through T02-14 `partitionOf`).
`headless-world.test.ts` (fixture modules plus every production module that exists; seeded synthetic intents of 50 actors):
- `19#3 re-running 3 game days of recorded batches from genesis produces identical TickRecord.worldHash and logicalStateHash at every tick`: run 2,160 ticks recording batches and records; `replayHeadless` gives identical worldHash and logicalStateHash for every tick 0..2,159.
- `19#4 the same 3 game days with 1, 3 and 17 PLAYER partitions (and 1 vs 4 MARKET partitions) produce identical logicalStateHash at every tick`: maps (PLAYER 1, MARKET 1), (3, 1), (17, 1), (3, 4) run the same intents for 2,160 ticks: `compareDigestStreams` reports no divergence of logicalStateHash or eventDigest at any tick (worldHash differs by construction: it covers partition hashes).
- Worker mode: the (3, 4) map with `workers: true` for 720 ticks equals in-thread mode digest by digest.
- Genesis row 0 carries the genesis config hash; tick 0 map version 1.
