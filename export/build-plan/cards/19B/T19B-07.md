## Goal
Build the `world` process shell of 19 Rule 3.2.1: one host runs the coordinator on the main thread and every partition as a Node `worker_threads` worker that owns one `PartitionEngine` (T19B-02). Define the control protocol (load, begin tick, phase start/done, prepare, commit, abort, serialize, query, heartbeat) as canonical bytes with fencing tokens, the runtime pinning check of 19 Rule 3.6.1, the host configuration, and the static invariant INV-STR-004: the world process's runtime configuration contains no commerce-schema or ad-network credentials.

## Implementation steps
1. Process layout (19 Rule 3.2.1): main thread = coordinator (T19B-08 onwards) + worker pool; one worker per partition; the host never runs web or gateway code (Rule 3.2.2). A host may run any number of partitions (Rule 3.5.7); `hostId` never enters any hash.
2. Worker: on `load`, `checkPin` against the coordinator's active configuration (sent in ctx); mismatch -> `error RUNTIME_MISMATCH` and the worker refuses all further messages (19 Rule 3.6.1). Then `engine.load(snapshot, ctx)`.
3. Fencing (19 Rule 3.2.3, §8 edge 8): the worker keeps the highest fencing token seen; a message with a lower token is answered `error FENCED` and ignored; an equal or higher token is processed (higher replaces). The coordinator's token is its lease epoch (T19B-11).
4. Phase messages: `phase` calls `engine.runPhase` (or returns an empty output when `!runsPhase(phase)`) and replies `phaseDone` with `outboxCount`, `outboxDigest` and timing (19 Rule 3.3.1 step 3). Before running, the worker checks every inbox message's `toEntity` is homed on it under the current map; otherwise `error WRONG_HOME` (19 Rule 3.5.2: platform fault, the whole tick is rejected).
5. Engine faults never kill the worker: thrown errors inside `runPhase` are already converted by T19B-02 into failures; anything else (out of memory, crash) ends the worker and `onFailure('EXIT')` fires.
6. Heartbeats: the pool pings every worker every `coord_heartbeat_ms`; `missedLimit` consecutive missing pongs -> failure HEARTBEAT (19 Rule 3.7.4 item 1). Hard timeout: the tick driver reports `HARD_TIMEOUT` when a phase has not returned after `phase_hard_timeout_ms` (T19B-08).
7. Config: strict zod schema (unknown keys rejected): only the listed secret references. INV-STR-004 (20 §3.1.8): the static check scans `apps/world/**` source, `infra/world/**` manifests and `apps/world` env schema for any variable name or secret reference matching `FORBIDDEN_WORLD_SECRET_PATTERNS` (`/COMMERCE/i`, `/ENTITLEMENT/i`, `/STORE_(DB|URL|KEY)/i`, `/AD_?NETWORK/i`, `/ADMOB/i`, `/APPLOVIN/i`, `/IRONSOURCE/i`, `/UNITY_ADS/i`, `/STRIPE/i`, `/PAYMENT/i`, `/IAP_/i`) and for the database role `commerce`; any hit fails with file and line.

## Test plan
`host.test.ts` (real worker threads, fake modules):
- control protocol round trip: `decodeCtl(encodeCtl(m))` deep-equals for every variant (bigint fencing preserved).
- fencing: after a message with token 5, a message with token 4 gets `FENCED` and does not change state; token 6 accepted.
- pinning: a worker loaded with a ctx whose bundleHash differs answers RUNTIME_MISMATCH and refuses `begin`.
- WRONG_HOME: an inbox message for an entity homed elsewhere yields `error WRONG_HOME`.
- heartbeat: a worker blocked in a busy loop for 4 x heartbeat is reported failed with reason HEARTBEAT (fake clock driving the pool).
- a phase run in a worker gives the same PhaseOutput digest as the same phase run in-thread (canonical bytes only).
`static-checks.test.ts`:
- INV-STR-004 negative: fixture manifest with `COMMERCE_DB_URL` and an env schema key `AD_NETWORK_KEY` -> two findings; the real repo -> zero findings; `loadConfig` rejects an unknown key `stripeKey`.
