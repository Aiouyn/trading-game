## Goal
Define the platform-side world types of 19 §2.1 and §2.2 that the world host, archiver, harness and projector share, the zod schemas of every `sys.*` and `adm.*` system input of 19 §4.3 and every platform event of 19 §5 (registered in the protocol registries), the canonical `batchHash`, and the platform signing service that signs every `SystemInput` (19 Rule 3.9.6). It also proves the commerce isolation of 19#41: no system input can carry a purchase.

## Imports
- T19A-02: `canonEncode`, `registerSystemKind`, `registerEventKind`, `systemKinds`, `eventKinds`, `MoneyStr`, `IdStr`, `TickNum`, `Ulid`, `IntentSchema`, `resetRegistriesForTest`.
- T19A-04: `PACKAGE_RULES`, `checkGraph` (the commerce-path rule).
- T02-14: `PartitionKind`, `PartitionDescriptor`, `PartitionMap` (engine types are re-exported, never redefined). T02-12: `TickHeader`.

## Implementation steps
1. Types: copy 19 §2.1/§2.2 shapes as above. `SystemInput` gets an extra `keyId` (which platform key signed it), flagged as a superset of 19 §2.2. `SealedIntentRow.receivedSeq` is the coordinator's receive sequence on INTAKE (used by T19B-07 for the seal margin test; informational, not ordering).
2. Schemas (zod 4, every object `.strict()`, strings with max length 128 unless stated, money as `MoneyStr`, ids as `IdStr`): for each row of 19 §4.3 write the payload schema exactly with the listed fields:
   - `sys.presence {characterId, present: boolean}`; `sys.load_scale {partitionId, duScale: number > 0 and <= 1}`; `sys.partition_map {map}` (PartitionMap shape: version int >= 1, effectiveTick, partitions[], playerHashRanges[] covering 0..2^32 without gap or overlap, group tables); `sys.engine_upgrade {engineVersion (semver), bundleHash (64 hex), effectiveTick}`; `sys.param_change {paramsVersion, effectiveTick, changes: [{key, old, new}] (1..200)}` (values as the 23 wire form `unknown`); `sys.content_change {contentVersion, effectiveTick, diffRef}`; `sys.entropy_commit {epoch, commitment (64 hex)}`; `sys.entropy_reveal {epoch, secret (64 hex)}`; `sys.account_status {characterId, status: ACTIVE|SUSPENDED|BANNED, enforcementId}`; `sys.account_security {characterId, holdUntilTick}`; `sys.account_deleted {characterId, newLabel (max 40)}`; `sys.profile_change {characterId, handle?, country? (ISO alpha-2), timezone? (IANA, max 64), ageBand?: '16_17'|'18_PLUS'}`; `sys.ad_grant {characterId, receiptId, amount: MoneyStr}`; `sys.guest_upgrade {characterId}`; `sys.wallclock_mark {utcIso}` (R26); `adm.halt_world {reason}` / `adm.resume_world {reason}`; `adm.halt_market` / `adm.resume_market {assetId? , venue?, reason}` (exactly one of assetId, venue); `adm.compensate {characterId, amount, ccy, reasonCode, ticketId}`; `adm.clawback {characterId, amount?, assetIds?, reasonCode, evidenceRef}` (exactly one of amount, assetIds); `adm.freeze_character {characterId, until?}`; `adm.inject_event {templateId, params (record of string), tick}` / `adm.cancel_event {templateId, params, tick}`; `adm.snapshot {partitionId?}`. That is 25 kinds (15 `sys.*`, 10 `adm.*`).
3. `SYSTEM_INPUT_SOURCE`: presence -> GATEWAY; load_scale, partition_map, entropy_commit, entropy_reveal, wallclock_mark -> COORD; engine_upgrade, param_change, content_change, account_status, adm.* -> ADMIN; account_security, guest_upgrade, ad_grant, profile_change -> WEB; account_deleted -> JOBS. `SYSTEM_INPUT_APPROVALS`: per the Validation column: 2 for engine_upgrade, param_change, content_change, halt/resume world, compensate, clawback, freeze_character, inject/cancel event; 1 for halt_market/resume_market and adm.snapshot; 0 otherwise.
4. Events of 19 §5 with the listed payloads and visibility (`sys.safe_mode_replay` PRIVATE staff, `sys.invariant_failed` SEALED, `adm.action` PRIVATE). `sys.load_scaled.partitionScope` is the literal `'world'` (E23: partition ids never shown). Presence has no event.
5. Batch hash: `computeBatchHash` = hex SHA-256 (node:crypto in platform) over `canonEncode` of the batch without `batchHash`, intents already in canonical order and system inputs sorted by `inputId`.
6. Platform signer: Ed25519 over `systemInputBytes`; rotation every `platform_key_rotation_days` real days, previous keys kept (retiredAt set) and accepted by `verifySystemInput` for 2 rotation periods. Keys never leave the KMS backend (the class never sees private keys). `localKmsForDev` derives keys from a seed with node:crypto and is refused when `NODE_ENV === 'production'`.
7. 19#41 (part 2) guarantee: no schema has a field named in `FORBIDDEN_COMMERCE_FIELDS`; because schemas are strict, a payload carrying one is rejected. `sys.ad_grant.receiptId` is an ad-network receipt (L12), not a purchase.

## Test plan
`system.test.ts`:
- `19#41 commerce isolation: no sys.* kind accepts a purchase id`: walk every schema shape recursively: no key in `FORBIDDEN_COMMERCE_FIELDS`; for every kind, a valid sample payload plus `purchaseId: 'p1'` fails parsing. Second half: run `checkGraph` (T19A-04) on a fixture repo where `apps/web/app/(store)/buy.ts` imports `@tycoon/engine` (directly, and transitively through a helper package): both produce a PACKAGE_RULE violation; the real repo produces none.
- `SYSTEM_INPUT_KINDS.length === 25` and equals the 19 §4.3 list; every kind registered with module '19' and namespace sys or adm; `SYS_EVENT_SCHEMAS` has the 14 kinds of §5 with the stated visibility.
- Edge schemas: `sys.load_scale duScale 0` and `1.01` rejected, `1` accepted; `adm.clawback` with both amount and assetIds rejected; `sys.partition_map` with a gap in playerHashRanges rejected.
`batch.test.ts`: batchHash stable under key order of input objects; changing one intent byte changes it; system inputs given unsorted produce the same hash as sorted (sorted before hashing).
`platform-signer.test.ts`: sign/verify round trip; a changed payload byte fails; after a rotation (fake clock + 91 days) the old signature still verifies and new inputs use the new keyId; a signature by a GATEWAY key on `adm.compensate` fails `verifySystemInput` (wrong service).
