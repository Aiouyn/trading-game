## Goal
Run the `jobs` service tasks that make 19 Rule 3.7.6's retention table and Rule 3.7.7's backups true: mirror every sealed batch to object storage within `batch_archive_lag_ticks`, write engine events as one Parquet file per game week, drop hot PostgreSQL partitions older than one game year only after their archive is verified, thin snapshots (last 48 DAILY, 1 per real day for 90 days, CHAPTER forever), mirror the audit log daily under object lock for `audit_retention_years`, and configure PostgreSQL PITR and ClickHouse backups.

## Implementation steps
1. Batches (19 Rule 3.4.5, 3.7.6 row 1): `archiveBatches` runs every 30 real seconds (BullMQ repeatable); bus hot retention is 2 game days, PostgreSQL `intent_batch` 1 game year, object storage forever. Object keys use game week numbers; a week object is complete when its last tick is archived (verified by re-reading and comparing batchHashes).
2. Events (row 3): PostgreSQL keeps 1 game year (partitioned by game week, T19B-04); ClickHouse warm tier (2 game years) is filled by the projector (T19C-09); `archiveEventWeek` writes one Parquet file per complete game week with rows ordered by (tick, seq) and records its sha256 in a manifest object `events/<worldId>/manifest.json`.
3. Retention plan (pure): a hot `engine_event` or `intent_batch` week partition is dropped only when (a) its last tick < currentTick − TICKS_PER_GAME_YEAR and (b) its archive exists and verifies (row count and sha256). Tick records are never dropped. Snapshots: keep every CHAPTER; keep the last 48 DAILY per partition; of older DAILY keep the first per real day for 90 real days; drop the rest (T02-10 `thin` gives the same keep set for `snapshot_daily_retention_days`; the stricter of both keeps). Phase messages are never archived (bus retention only).
4. Audit mirror (19 Rule 3.9.5, R29): daily, canonical JSON lines of that UTC day's `audit_log` rows plus the chain head, put with `objectLockUntil = now + audit_retention_years` (10 real years) under `KEYS.auditMirror(day)`; the head is also handed to the integrity report job (T19C-07).
5. Backups (19 Rule 3.7.7): `infra/postgres/backup.yaml` (continuous WAL archiving, PITR window `pg_pitr_days` = 35 days, daily base backup at the lowest-activity hour), `infra/clickhouse/backup.yaml` (daily, 30 days), object storage versioning and cross-region replication flags. The restore drill itself is T19D-07.
6. Personal data: none of these artifacts contain any (engine data only, 19 Rule 3.14.1); exports and deletion are T19C-08.
