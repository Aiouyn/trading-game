## Goal
Make a prepared tick final in the order of 19 Rule 3.7.2 so a client never sees a state the server could lose: assign the global event sequence, write `tick_record`, `intent_batch` and `engine_event` rows in one PostgreSQL transaction, and only after it commits tell partitions to commit (pointer swap and P14), publish the event bodies on `EVENTS`, the `sys.tick_committed` event and the recipient deltas on `DELTAS`. When the decision is ABORT, roll back everywhere and re-run the tick in safe mode exactly as 02 §3.15.3 specifies; when safe mode also fails, halt the world and file a reproducible case (19 Rule 3.6.5).

## Implementation steps
1. `finalizeTick` order (19 Rule 3.7.2; E10):
   a. `assignGlobalSeq`: order all partitions' events by (phase, originEntityId, provisionalSeq) with T02-12 `sequenceEvents`; seq 0..n−1; then append `sys.tick_committed {tick, worldHash, logicalStateHash, safeMode}` (PUBLIC) with seq n. The event is a pure function of the TickRecord, so replay regenerates it.
   b. `worldHash = worldHashOf(header, partitionHashes)` from the prepare reports (prepare stateHash equals the post-commit stateHash).
   c. `writeTickRecordTx`: INSERT `tick_record`, `intent_batch` (body = zstd of `batchBody`), `engine_event` rows and the tick's `system_input` rows in one transaction (role `world_coord`). On database failure (19 §8 edge 21) retry with backoff 100 ms doubling to 2 s; ticks wait (no commit without a durable record); metric `pg_tx_ms`.
   d. Only after the transaction committed: `driver.commitAll` (R6 pointer swap and P14 deltas), then publish events on `ev.<tick>` (msgId `ev:<tick>`), then all recipient and public deltas of the tick on `dl.tick.<tick>` (msgId `dl:<tick>`; the delta router of T19C-05 writes resume buffers and forwards per gateway). A gateway therefore never receives a delta of tick N before `tick_record(N)` exists (19#22).
2. ABORT path (19 Rule 3.6.5, 02 §3.15.3, which owns the procedure): `abortAll`; then up to `safe_mode_max_attempts` attempts: re-run the same sealed tick with `safeMode: true` (posting-level validation and attribution trace), take `firstFailingItem(failures, trace)` (T02-16) to add one QuarantineEntry (INTENT, ENTITY or SUBSYSTEM) to `header.quarantine`, re-run with it skipped; commit with mode SAFE when all invariants pass, emitting `sys.safe_mode_replay {tick, failedInvariants, module}` (PRIVATE, staff) and `sys.invariant_failed` (SEALED) for each original failure. A SUBSYSTEM quarantined `safe_mode_subsystem_repeat_halt` consecutive ticks halts.
3. Halt: when every attempt fails, the world status becomes `HALTED_EXCHANGE` (02 §3.15.3 and T02-16 own the halt mode; 19 Rule 3.6.5 calls it MAINTENANCE; the diegetic text "Trading halted by the Exchange" is the same), the scheduler stops sealing (T19B-10 observes `mode`), on-call is paged (log level error with `page: true` and metric `safe_mode_replays_total`), and a case file is stored with batch hash, latest snapshot ids per partition, the tick's PHASE records, failed invariants and attempts. No tick is ever committed with a failed invariant.
4. Partition failure during the tick (`PreparedTick.failure`) is not a safe-mode case: abort and hand over to recovery (T19B-11), then re-run the same sealed tick.
5. Safe mode equivalence: the quarantine decisions must equal T02-16 `runTickWithLadder` on the in-process coordinator for the same inputs (tested), so replay reproduces them.

## Test plan

- `19#20 an injected invariant failure in P13 rolls back the tick, re-runs in safe mode, and, when injected again, halts the world with a case file containing batch hash and snapshot ids`: (a) a fixture intent makes a TICK invariant fail once: tick N aborts, every partition's stateHash after abort equals N−1's, the safe-mode attempt quarantines that intent, N commits with `safeMode = true`, `sys.safe_mode_replay` emitted; (b) failure injected on every attempt: after `safe_mode_max_attempts` attempts mode HALTED, no `tick_record(N)`, the stored case file decodes with the batch hash of N and one snapshot id per partition.
