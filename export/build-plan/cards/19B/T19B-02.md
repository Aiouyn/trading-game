## Goal
19 runs the engine only through the `PartitionEngine` interface of 19 §2.6 (02 owns internals, 19 owns hosting). This task writes `packages/engine/index.ts`, the factory that builds a `PartitionEngine` for one partition from the registered modules and the 02 partition runtime, with the phase-level API the distributed tick driver (T19B-08) calls over worker threads: begin tick, run one phase with its inbox, prepare (R4), commit, P14 emit, rollback, serialize, query views. It also fixes the delivery schedule (which barrier delivers which message) and provides a synchronous local driver that runs a set of engines through a whole tick, used as the reference that every multi-process run must equal.

## Implementation steps
1. `PHASE_KINDS` from 19 Rule 3.3.2: a kind is listed for a phase when its cell is not `–` (P0 COORD and PLAYER; P1 all but ACTOR; P2 COORD, PLAYER, MARKET, FINANCE; P3 COORD, CITY, ACTOR; P4 MARKET, CITY, FINANCE, ACTOR; P5 PLAYER; P6 MARKET, CITY, FINANCE; P7 PLAYER, FINANCE, CCP; P8 PLAYER, FINANCE, CCP, ACTOR; P9 CITY; P10 PLAYER, CITY, ACTOR; P11 PLAYER, MARKET, CITY, FINANCE; P12 COORD, PLAYER, ACTOR; P13 and P14 all). `runsPhase` reads it; a phase the kind does not run returns an empty `PhaseOutput` at once (rule 3.3.1: still reports done). The module phase functions themselves are invoked by the 02 runtime exactly as T02-14 does; this table only lets the host skip work and is asserted equal to T02-14's own phase table in a test (if they differ, the test fails and names the phase: that is a reconciler issue, not something to patch here).
2. Delivery schedule (02 §3.5.3, D019; 02 owns the pipeline): messages sent with `when = 'B1'` in R1 are in the inbox of P6 and later phases; `'B2'` from P6 in P7 and later; `'B3'` (posting legs, hold settles) in `prepare`; `'NEXT'` stored and delivered at P1 of tick N+1 before any intent. Per 19 Rule 3.3.1 each phase's inbox is the cumulative set delivered at barriers before it, sorted by `canonicalKey` (`sortInbox`). The canonicalKey order is entity based, so it is identical for every partition map (19 Rule 3.6.6); the transport order (fromPartition, seq) of 02 §3.5.3 rule 1 is used only for framing on the wire. If T02-14's in-process bus delivers in (fromPartition, seq) order, the equivalence test below fails: report it (precedence: partition independence, 19 Rule 3.6.6 and 02 INV-ENG-009, needs an entity-keyed order).
3. `createPartitionEngine` wraps one `PartitionRuntime` (T02-12) configured with the descriptor's partitionId and `productionModules()` (or the given modules) and the ledger provider (T03-09 by default). Every phase call runs inside `trapPhase` (T02-16) so a thrown `OwnershipViolation` (19 Rule 3.6.3) becomes a failure `INV-ENG-001` in the output instead of crashing the worker.
3b. Ports (GLOBAL-CONTEXT G6.1): `packages/engine/index.ts` is where ports are wired. `productionModules()` builds each module through its factory (`create<Name>Module(ports)`) and passes the port implementations exported by later modules that exist (a registry `PORT_PROVIDERS: Record<portName, () => unknown>` filled from each module's `index.ts` export `providesPorts`); a missing provider leaves the port undefined so the consuming module uses its spec default. Wiring order follows 19 §12.2 unit order; a test asserts every declared provider is consumed by a module that declares that port name.
4. `serialize`: T02-10 `encodeSnapshot` chunks framed as `canonEncode({manifest, chunks: [[name, bytes]...] sorted by name})`; `load(bytes)` inverts with `decodeSnapshot` (stateHash verified).
5. `runLocalTick`: R0 split intents by home (`splitByHome` with T02-14 `partitionOf(defaultHome(onBehalfOf ?? actorId))`), `beginTick` on each engine (COORD gets the system inputs), then for each phase P1..P12 in order: for every engine (sorted by partitionId) that runs the phase, call `runPhase` with its sorted inbox; collect outboxes; at the B1/B2/B3 points route each message to `partitionOf(home(toEntity))`; then `prepare` on all with the B3 inbox, `decider.decide`, then `commit` + `emit` on all, or `rollback` on all. Global event order: `sequenceEvents` over all partitions' events (19 Rule 3.6.4). worldHash = `worldHashOf(header, partitionHashes)`; logicalStateHash = hex of `sumLogical`.
6. Determinism: this file is engine code (`packages/engine/**` lint rules apply): no async, no clocks, sorted iteration only.
