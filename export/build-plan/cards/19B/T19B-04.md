## Implementation steps
1. Write the Drizzle tables with the exact column names and types of 19 §11.2 (`bigint` money in micro-units with `mode: 'bigint'`, timestamps `timestamptz`, `jsonb`, `text[]`, `bytea`). Constraints as listed: `coord_lease` `CHECK (id = 1)`; `account_ref.character_id UNIQUE`; `account_pii.email_hmac UNIQUE`; foreign keys from `auth_session`, `signing_key`, `api_key`, `device`, `push_subscription` to `account_ref`. Add indexes: `engine_event (kind, tick)`, `engine_event USING GIN (party_ids)`, `auth_session (account_id)`, `signing_key (session_id)`, `audit_log (at)`.
2. `intent_batch` and `engine_event` are `PARTITION BY RANGE (tick)` with one partition per game week (5,040 ticks); `ensurePartitions` creates the current and next `aheadWeeks` partitions (called by the coordinator at every day close). Drizzle does not model partitioning: the DDL lives in `0001_init.sql`, the Drizzle objects map to the parent tables.
3. Roles (`roles.sql`, 19 Rule 3.9.4.5 and 3.14.2): `world_coord` is the only role with INSERT on `world.tick_record`, `intent_batch`, `engine_event`, `snapshot`, `partition_map`, `entropy_epoch`, `system_input` and UPDATE on `coord_lease`; `gateway` has SELECT on `platform.auth_session`, `signing_key`, `api_key` and UPDATE of `signing_key.last_nonce` only, and no privilege on schema `pii`; `pii` is usable only by `web`, `jobs`, `admin`; `projector` writes `readmodel`; `harness` is read-only on `world`; nobody has UPDATE or DELETE on `platform.audit_log` (append-only: `REVOKE UPDATE, DELETE`, plus a trigger raising on UPDATE/DELETE).
4. Audit chain (19 Rule 3.9.5): `appendAudit` runs in a serializable transaction: `SELECT id, hash FROM platform.audit_log ORDER BY id DESC LIMIT 1 FOR UPDATE` (or `pg_advisory_xact_lock(19005)` when empty), takes `nextval` for the id, computes `hash = auditHash(prevHash, auditRowCanonical(id, e))`, inserts with `prev_hash`. Ids are dense; `verifyChain` reports `GAP` on a missing id.
5. `verifyChain(rows, anchor)`: rows sorted by id; the first row's prevHash must equal the anchor's hash (or GENESIS when anchor null and the first id is 1); each row's hash recomputed; each prevHash equals the previous hash. The daily anchor is `integrity_report.body.auditHead` (written by the integrity job, 19 Rule 3.12.5, T19C-07).
6. `audit_retention_years` (10, owned by 21; R29) is the object-lock retention of the mirror (T19B-16); the hot table keeps every row (no deletion path).
