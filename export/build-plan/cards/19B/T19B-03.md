## Goal
Provide the durable message bus of 19 §11.1 behind one interface with two implementations: NATS JetStream for staging and production, and an in-memory bus with fault injection (quorum loss, latency, message loss) for tests and the single-process dev world. Define the five streams, their subjects, replication and retention, the per-service bus permissions (19 Rule 3.9.4 item 5), and the telemetry kit every server process uses: the minimum metric set, tick tracing with sampling, and a structured logger that cannot log personal data (19 §3.15).

- T19B-01: `IntentBatch`, `EngineEventRow`, `SystemInput` (payload types of streams).

## Implementation steps
1. Streams (19 §11.1, Rule 3.7.6): INTAKE `intake.>` (writer gateway, reader world-coord; replicas `bus_replicas`; max age 1 real day, the dedupe window of rule 3.4.3); BATCH `batch.>` (writer world-coord only; readers world-partition, jobs, harness; replicas `bus_replicas`, quorum ack required; max age 2 game days = 2 real hours, the archiver mirrors within `batch_archive_lag_ticks`); PHASE `ph.>` (writer world-partition; reader world-partition; retention at least two snapshot intervals = 1,440 ticks = 2 real hours, set 3 real hours); EVENTS `ev.>` (writer world-coord; readers projector, jobs; 2 real hours); DELTAS `dl.>` (writers world-coord for `dl.tick.*` and the delta router for `dl.<gatewayId>`; reader gateway and delta router; 10 real minutes, interest retention). Dedupe window 2 minutes (`msgId` = `batch:<tick>`, `ev:<tick>`, `ph:<tick>:<k>:<from>:<dest>`).
2. `requireQuorum` (BATCH): the publish resolves only after the server's stream ack (JetStream acks after replication to a quorum of `replicas`); `hasQuorum` checks stream cluster info (leader present and at least floor(replicas/2)+1 current replicas). The memory bus models this with `faults.quorumLost`: publish with requireQuorum rejects with `BusError('NO_QUORUM')`.
3. Permissions: `web` may publish only `intake.sysweb` (system inputs submitted by platform flows, 19 Rule 3.2.2) and never `batch.>`; `gateway` publishes `intake.>` and subscribes `dl.<own>` and `ctl.seal.<own>`; `world-coord` publishes `batch.>`, `ev.>`, `ctl.>`; `world-partition` publishes `ph.>`; `world-coord` also publishes `dl.tick.>`; the gateway role in router mode subscribes `dl.tick.>` and publishes `dl.>`; `projector` subscribes `ev.>`; `jobs` subscribes `batch.>`, `ev.>`, publishes `intake.sysjobs`; `admin` publishes `intake.sysadmin`; `harness` subscribes `batch.>` read-only. A test asserts web has no `batch` publish right.
4. Memory bus: per stream an array of messages with monotonically increasing seq; subscribe delivers existing messages from `fromSeq` then live ones in seq order; `dropSubjects` silently drops matching publishes (used by recovery tests to simulate PHASE loss); `purge` deletes messages (retention tests).
5. Metrics: exactly the names of 19 Rule 3.15.1 (`tick_commit_lateness_ms`, `tick_phase_ms{phase,partition}`, `ticks_missed_total`, `safe_mode_replays_total`, `invariant_failures_total{id}`, `intents_sealed_total{kind}`, `intent_rejects_total{code}`, `ws_sockets{gateway}`, `delta_bytes_per_tick{channel}`, `resume_hits_total`, `du_demand{partition}`, `du_scale`, `projector_lag_ticks{projection}`, `money_flow_micro{class,reason}`, `bus_ack_ms`, `snapshot_duration_ms`, `pg_tx_ms`, `client_web_vitals{name}`, `client_tick_render_ms`) plus `coord_lease_epoch`, `partition_status{partition,status}`. Exported over OpenTelemetry OTLP; Prometheus scrape is configured in infra (T19D-07).
6. Tracing (19 Rule 3.15.3): one trace per tick, a span per phase per partition; sampled when `tick % tick_trace_sample === 0`, always when late or aborted. Logs never contain personal data or private intent payloads (19 Rule 3.14.1): redaction by key at any depth.
7. `ensureStreams` writes the specs; `infra/nats/streams.json` is generated from `streamSpecs(launchParamsView())` and `natsAccountConfig()` by `pnpm --filter @tycoon/platform gen:nats` and checked in (test compares).

## Test plan
`bus.test.ts` (memory bus; the NATS implementation runs the same suite when `NATS_URL` is set, in the CI `contract` job against the docker compose NATS):
- publish/subscribe ordering by seq; `fetchRange` returns the closed range in order; durable consumer resumes after `stop`.
- duplicate `msgId` within the window returns `duplicate: true` and stores once.
- BATCH publish with requireQuorum under `quorumLost` rejects `NO_QUORUM`; `hasQuorum` false.
- request/respond round trip with timeout error after `timeoutMs`.
- permissions: web cannot publish `batch.1`; gateway cannot subscribe `ev.>`; projector cannot publish anything.
- generated `infra/nats/streams.json` equals the committed file.
`telemetry.test.ts`:
- METRICS contains every name of 19 Rule 3.15.1.
- `traceTick`: sample 60: ticks 0, 60, 120 traced; 61 not; 61 late -> traced; aborted -> traced.
- logger redacts `email` nested in `{a:{b:{email:'x@y'}}}` and a top-level `payload`; output is one JSON line with `service`.
