## Goal
Drive one tick across the partition workers of T19B-07 exactly as the reference driver of T19B-02 does, but in parallel and over canonical messages: begin tick, one bulk-synchronous barrier per phase with `PhaseStart`/`PhaseDone` (19 Rule 3.3.1), delivery of routed messages at 02's barriers (D019), recording of every partition's inbound messages on the `PHASE` stream (needed by recovery), the hard phase timeout as a partition failure, prepare (R4) and the global commit decision (R5). Money crosses partitions only by hold then settle; a P2P swap posts all legs in one tick or none (19 Rules 3.5.3, 3.5.4; E9).

## Implementation steps
1. `runToPrepared` sequence (19 Rule 3.3.1, 02 §3.5.3):
   a. `begin` to every partition in parallel: each gets its `perPartition` intents (fair order kept), COORD gets the system inputs; every partition's `nextInbox` share from tick N−1 is delivered first at P1.
   b. For P1..P12 in order: `PhaseStart` (`phase` message) to every partition with `inboxFor(d, id, phase)`; await every `phaseDone` (partitions whose kind does not run the phase answer immediately). Start the next phase only when all answered (barrier). Record `phaseTimingsMs[P] = max over partitions of the wall time including barrier wait`; compare with `phase_budget_ms_P*` (R27: operational budgets; exceeding never aborts, it only marks the tick late for T19B-09 and sets the metric).
   c. After each `phaseDone`, `routeOutbox` the partition's outbox: `B1` messages land in P6's inbox, `B2` in P7's, `B3` in PREPARE, `NEXT` in `nextInbox` for tick N+1 (19 Rule 3.3.5). A message whose `toPartition` is not in the map is a platform fault (19 Rule 3.5.2): the tick fails with `WRONG_HOME`.
   d. Before each delivery point is used, publish that partition's newly delivered set with `publishInbound` (awaited before the decision; the PHASE stream must hold every inbound message of a committed tick).
   e. `prepare` on all with `inboxFor(d, id, 'PREPARE')`; then `decider.decide(reports)` (I13 suspense net zero, global trial balance, quantity conservation via the ledger provider; T02-15 `globalDecision`).
2. Hard timeout (19 Rule 3.3.4 item 5): each awaited reply races `phase_hard_timeout_ms`; on timeout, or a pool failure event for any partition during the tick, stop the tick: `failure` set, `ok = false`, and the caller (T19B-09) issues `abortAll` and starts recovery (T19B-11). A failed partition aborts the whole tick for everyone, so partial settlement is impossible (19 Rule 3.5.4 item 3, E10).
3. Holds (19 Rule 3.5.3): placement, routing with hold ids, result messages and P13 settlement are engine behaviour (03 and the owning modules); the driver guarantees the barrier and delivery order. A hold with no result by P13 is released by the ledger and the intent result is `REJECTED` with `PLATFORM_NO_RESULT`; the driver counts such results in metric `intent_rejects_total{code="PLATFORM_NO_RESULT"}` (a bug signal for the Truth Machine).
4. Inter-partition clearing (19 Rule 3.5.3 item 5): 19's `ipc:A:B` accounts are 03's interpartition suspense accounts `sys:9900:<A>-><B>:<ccy>`; the decider aborts when any pair does not net to zero.
5. Parallelism: messages to workers are sent without awaiting each other; results are collected into a Map keyed by partitionId and always iterated in sorted partitionId order, so outputs never depend on reply timing.
6. Equivalence: for the same sealed ticks, `runToPrepared` + `commitAll` must give exactly the hashes and events of `runLocalTick` (T19B-02). Events keep `originPartition` for storage only; it is excluded from all digests.
