## Goal
Implement the two value-changing admin inputs of 19 §4.3, `adm.compensate` and `adm.clawback`: two distinct approvals checked by the engine at P1, compensating ledger postings with a FAUCET or TRANSFER (compensate) or SINK or TRANSFER (clawback) reason code from 03's catalog, never a world rollback (19 Rule 3.9.9, 02 §3.15.2), a PRIVATE `adm.action` event to the player, and an `audit_log` row per committed admin input whose hash chains to the previous row (19 Rule 3.9.5). Assemble the `sys` engine module (`defineModule`) so the world host loads it with every other module.

## Imports
- T03-05: `getCatalog` (reason class lookup), T03-09: `LedgerApi` via `ctx.ledger` (`mint`, `burn`, `pay`, `moveQty`), sys accounts. Codes from T03-02/T03-04: `ADM_COMPENSATION` (FAUCET, MINT), `ADM_CORRECTION_IN` (FAUCET), `ADM_CLAWBACK` (SINK, BURN), `ADM_CORRECTION_OUT` (SINK), `ADM_CORRECTION_TRANSFER` (TRANSFER, PAY).
- T19B-13: `SYS_HANDLERS`, tables, `SYS_VIEWS`, `SYS_EVENTS`, `PARAM_KEYS`, `systemInputToSealed`. T19B-04: `appendAudit`. T19B-09: `CommittedTick`.

## Implementation steps
1. P1 validate (COORD): approvals must be at least 2 distinct admin ids (reject `SYS_APPROVALS`; one approval is rejected even with a valid signature, 19#42); reason code must exist in 03's catalog (`SYS_UNKNOWN_REASON`) and have the allowed class (`SYS_REASON_CLASS`); amounts are decimal micro-unit strings > 0 (`SYS_AMOUNT`); clawback needs `evidenceRef` (`SYS_EVIDENCE`) and exactly one of amount or assetIds.
2. Apply: the COORD handler sends the validated instruction to the character's home with `when: 'B1'`; on the home partition the sys module's P8 hook posts: compensate FAUCET -> `ledger.mint(characterCash, amount, ccy, reasonCode)` (e.g. `ADM_COMPENSATION`); compensate TRANSFER -> `ledger.pay(COMPENSATION_ACCOUNT -> character, amount, ccy, 'ADM_CORRECTION_TRANSFER')`; clawback SINK -> `ledger.burn(character, amount, ccy, reasonCode)` (e.g. `ADM_CLAWBACK`), or for assets `moveQty` to the sys account then burn per 03's template; clawback TRANSFER -> `pay(character -> COMPENSATION_ACCOUNT)`. Clawback never drives a balance negative: the amount is capped at `available` and the remainder recorded in the event payload as `uncollected` (debts follow 03's rules, not this module). Postings land at P13 like any other (refs: [inputId, ticketId or evidenceRef]).
3. Events: `adm.action {kind, reasonKey: reasonCode, ticketId}` PRIVATE with partyIds [characterId] (no staff identity, 19 §5).
4. Audit: after each TickRecord transaction, the coordinator calls `writeAuditForTick` for the committed admin inputs (19 Rule 3.9.5: admin actions, param changes, content changes, engine upgrades). Payload = the input payload plus `{tick, inputId, result}`.
5. `sysModule` assembly: tables from T19B-13, phases (P1 NEXT-message application, P8 ledger posting, P2 effective-tick events), all handlers, `SYS_EVENTS`, views; registered in `productionModules()` (T19B-02). The engine intent namespace table of T02-11 must allow `sys.` and `adm.` for module '19' (report `MISSING EXPORT: T02-11 INTENT_NAMESPACES['19']` if the build rejects it).

## Test plan
`compensation.test.ts` (TestWorld with 03's ledger):
- `19#42 adm.compensate with one approval is rejected at P1; with two distinct approvers it posts with its reason code and an audit_log row whose hash chains to the previous row`: one approval -> REJECTED `SYS_APPROVALS`, no posting; two identical approver ids -> `SYS_APPROVALS`; two distinct -> one posting with reason `ADM_COMPENSATION` of 1,000,000,000 micro FDL on the character's cash; `auditEntriesFor` yields one entry; written with `writeAuditForTick` after a prior entry, `verifyChain` passes and the new row's prevHash equals the prior row's hash.
- reason class: `adm.compensate` with a SINK code -> SYS_REASON_CLASS; `adm.clawback` with a FAUCET code -> SYS_REASON_CLASS; clawback without evidence -> SYS_EVIDENCE.
- clawback larger than available: burns the available amount, payload `uncollected` = the rest; balance never negative.
- TRANSFER compensation from `sys:compensation` keeps the ledger trial balance (03 invariants pass).
`audit-writer.test.ts`: a tick with one accepted and one rejected `adm.*` input yields exactly one audit entry; order of entries equals input order.
