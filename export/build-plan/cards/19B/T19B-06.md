## Goal
Implement the coordinator half of 19 §3.4: read the `INTAKE` stream continuously and stamp every intent with the coordinator's own monotonic receive time, decide each intent's seal tick from the seal margin and the gateways' closed markers, enforce the EXACT and stale policies and the one-real-day dedupe window, assemble the `IntentBatch` (system inputs first, intents in canonical order), make it durable on `BATCH` with a quorum before anything executes, split it by home for P1, and reply to each gateway with the seal result of every intent it forwarded.

## Implementation steps
1. Receive stamp (19 §8 edge 1): `IntakeReader` assigns `coordReceivedMs` from the coordinator's monotonic clock when it reads each INTAKE message (single clock; gateway time is audit only, edge 30).
2. Seal decision for tick N (19 Rule 3.4.1 item 5, 02 §3.12 item 1; 23 §5.6 keeps margin and grace separate):
   a. At `sealInstant(N)` (from T19B-09's scheduler) the coordinator broadcasts SEAL(N); each gateway answers with a `ClosedMarker` for N. The coordinator waits until every known gateway's marker arrived or `markersDeadlineMs = sealInstant + seal_grace_ms` passed.
   b. Candidates = carried intents + intents read so far. An intent is sealed into N when `coordReceivedMs <= sealInstantMs − gateway_seal_margin_ms` and its gateway's marker for N arrived in time and `gatewaySeq <= marker.lastGatewaySeq`. Intents of a gateway whose marker missed the grace roll whole into N+1 (02: never split; T02-08 `assembleTickBatch` semantics) and the gateway is listed in `lateGateways` (telemetry `core.gateway.late`). All other later arrivals go to `carryToNext`.
3. Per sealed candidate, in this order: (i) dedupe (`lookup` hit -> `DUPLICATE` with the original sealTick; also a second copy inside the same tick -> DUPLICATE with N, the first copy by `coordSeq` wins: 19#7, §8 edges 3-5); (ii) `clientTick < N − intent_max_age_ticks` -> `REJECT_STALE` under both policies (19 Rule 3.4.2, R29); (iii) `tickPolicy === 'EXACT'` and `N !== clientTick` -> `LATE_EXACT`, never in a batch (19#6); (iv) else `SEALED` and `dedupe.add`.
4. System inputs read from INTAKE (`intake.sys*` subjects) are verified with `verifySystemInput` against `SYSTEM_INPUT_SOURCE` (invalid ones dropped and logged) and joined with the entropy inputs of `EntropyTickOutput` (signed by the COORD key) and the scheduler's inputs (load scale, wall-clock mark, T19B-09); sorted by inputId; they precede player intents (19 Rule 3.4.4).
5. Canonical order: map sealed intents to `RawIntent` (`nonce: BigInt(intent.nonce)`, `receivedSeq = coordSeq`, `partitionId` from `splitByHome`), run `checkEnvelopes` (Stage A: intentsRoot over accepted intents sorted by intentId) then `deriveTickEntropy(worldId, N, eN, intentsRoot, prevWorldHash)` and `sealTick` (Stage B) so `orderKey = SHA-256('TYC/order' ‖ TickEntropy(N).value ‖ intentId)` (02 owns the formula, R28; 19 Rule 3.4.4 names the same guarantee) and per-actor nonce runs (02 §3.12 item 3). Envelope rejects (`REJECT_RATE_LIMIT` keeping the lowest nonces per 02 §3.12 item 5, `REJECT_REPLAY`, `REJECT_SCHEMA`) stay in the batch: the engine's P0 re-derives them identically (they are part of the replayable batch, not acks), so a replay rejects the same intents.
6. `IntentBatch`: `intents` as `SealedIntentRow` in canonical order with orderKey, `systemInputs` sorted, `entropyCommitRef = entropy.commitRef`, versions, `batchHash = computeBatchHash`. `sealedAtMs` is informational wall time.
7. Durability (19 Rule 3.4.5): `makeDurable` publishes with quorum; on `NoQuorumError` nothing executes and nothing is replied (19 §8 edge 20: T19B-09 holds the tick and shows CATCHING_UP; gateways keep queuing). Only after durability: `replyToGateways` (19 Rule 3.4.1 item 3: the gateway acks SEALED only after this reply) and `perPartition` hand-off to the tick driver (19 Rule 3.4.6, split by home of `onBehalfOf ?? actorId`).
8. Dedupe memory: `evictBefore(N)` each tick; on startup `DedupeWindow.rebuild` from the last 17,280 batches (BATCH stream, then `intent_batch` rows). An older duplicate cannot exist because the gateway rejects ULIDs outside the clock skew window (19 Rule 3.4.3 item 2, enforced in 19C).
