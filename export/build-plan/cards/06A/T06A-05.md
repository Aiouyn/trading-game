Execute the security-level consequences of 09's dividend and split decisions and the NPC split rule: declaration checks, record-date entitlement snapshots, ex-date price adjustment hand-off to 05, payment postings, DRIP reinvestment, the manufactured-dividend amounts 07 charges shorts and borrowers (X12), and splits that scale every position and lot with zero value change. ## Implementation steps
1. Declarations come from `ports.companies.declaredActions(store, tick)` (09) each tick in P2; for CASH_DIVIDEND validate: `exTick` is the t = 60 tick of a trading day ≥ 2 game days after announce, `recordTick = exTick − 1`, `payTick ≤ exTick + 5·720`; invalid declarations are stored CANCELLED with an `mkt.corp.announced` payload `status: 'CANCELLED'` (09 must resubmit). Valid → `ast.corp_action` ANNOUNCED, emit `mkt.corp.announced` PUBLIC.
2. Record snapshot at the DAY_CLOSE boundary of the record day (P2 at t = 719): `holdersOf(asset)`; every `qty > 0` gets `Entitlement{amount = toMoney(qty·cashPerShare)}` (cashPerShare is a Price in micro-units; `amount = notional(qty, cashPerShare, lotScale)`); every `qty < 0` gets a `manufactured: true` row with the identical per-share amount (X12). Shares lent out by a lender are not in the lender's position (03), so the lender's compensation is the borrower's manufactured payment that 07 posts using `manufacturedDividendsDue`.
3. Ex-date: `exDateActions(tick)` returns `{assetId, kind: 'DIVIDEND', dividendPerShare: cashPerShare as number, effectiveTick: exTick}` so 05 drops the reference price at the opening auction (05 §3.21 applies its own order-adjustment rule); 06 also sets `markEquityDirty` and lowers the equity anchor by the same `ln(1 − d/P)` via `writeAnchor` with `changedBy = actionId` so the drop is not pulled back.
4. Pay (P2 of payTick): for each long entitlement in holder-id order, `ctx.ledger.pay(issuerId, holderId, amount, ccy, 'EQ_DIVIDEND', {refs: [actionId]})`; emit `mkt.dividend.paid` PARTIES `{assetId, holder, amount}`. If `drip`: buy `floor(amount / dripPrice)` lots from `npcCounterpartyId(bloc)` via `ctx.ledger.swapAsset(holder, npc, asset, qty, cost, ccy, 'MKT_TRADE')`, the fractional remainder stays as cash. STOCK_DIVIDEND: `ctx.ledger.moveQty(issuer, holder, asset, qty·stockPerShare floored to lot, 0n, ccy, 'EQ_STOCK_DIVIDEND')`, shares outstanding increased in the same tick. If the issuer's posting fails for insufficient cash, report via `ctx.fail` is NOT used: dividends are declared by 09 only when payable; a failed posting is 03's rejection and 06 marks the action CANCELLED and emits `mkt.corp.effective {status:'CANCELLED'}`.
5. `electDripHandler`: validate holder of the asset (qty > 0) and `tradeGate(...,'BUY')` (LIC1); apply at P1: `EquityState.drip.set(actor, on)`.
6. Splits: `splitTriggerStep` at DAY_CLOSE for NPC issuers only: official close `> eq_split_trigger` → `streakUp++` else reset; at 20 → schedule SPLIT 5:1 (or 10:1 when close > 5000) effective at t = 0 of the next trading day; close `< 1` for 20 days and status not DISTRESSED → REVERSE_SPLIT 1:10. Player companies split only via 09 declarations. `applySplitEffective` at t = 0 (P2): `splitPositions(ctx, asset, num, den, 'EQ_SPLIT')`; `sharesOutstanding`, `freeFloatShares` scaled; `EquityState.epsFwd` and anchor divided by ratio (anchor `lnF − ln(num/den)`, `changedBy = actionId`); emit `mkt.corp.effective` PUBLIC with the full action so 05 (orders), 07 (locates, loans) and 06B (option strikes ÷ ratio, multipliers × ratio) adjust. Return SPLIT rows to 05 through `splitActionsForMarket`.
