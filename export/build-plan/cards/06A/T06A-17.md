## Goal
Export the read models (ViewHandlers) the 17.B screens of 06 §7 need for the spot classes, with license and privacy filtering (L11: a viewer sees only its own holdings, receipts, shipments, bids, RFQs; public data is public). Screens themselves are 17.B's.

## Implementation steps
1. Each view is a pure function over `StoreRead` with a zod args schema. License filtering: rates desk requires LIC2 viewer license (else returns `{locked: true, required: 'LIC2'}`); credit issuer data is public; the Research-tier `fundamentalGap` is included only when 05's `WorldPort.subscriptionTier(viewer)` is RESEARCH or TERMINAL (use 05's view helper by calling `ctx`-free pure read of the tier through `AssetPorts.world.subscriptionTier`, default NONE).
2. Privacy (L11, D109): views never return another player's holdings, bids or identities; auction high bidders and results show rotating labels; `ast.collection`, `myReceipts`, `myShipments`, `ast.rfqBlotter` filter by `viewer.entityIds`.
3. Screener filters on precomputed fields refreshed hourly into a `ast.screener_cache` table (owned here) so the view does not recompute bond analytics per call; sorting with `sortBy` and a total key (value then assetId).
4. Extensions: `registerViewExtension` lets 06B (CDS rolls, CDS curves, reserved compute curve, OPTION/FUTURE/PERP/SWAP/CDS class panels) and 06C (CRYPTO/STABLE/LP class panels: peg status, hype gauge) add fields to the four base views; merged in unit order, keys must not collide (asserted at registration).
5. `ast.vDecomposition`: per game day the log change of the anchor split by cause recorded when anchors are written (`changedBy` shock ids and hourly recompute inputs: earnings, curve move, fear move, financial update), stored in `ast.anchor_log` (owned here, ring of 30 days per asset).
