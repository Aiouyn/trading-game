## Goal
Run the quarterly earnings cycle of every issuer (06 §3.4.3, R10: 06 owns schedule and consensus noise for every issuer; 09 supplies E[EPS] and actual EPS): publish the calendar, draw consensus, compute surprise when 09 reports, revise forward EPS and the re-rating state, move the anchor by the full ΔlnV, hand 05 the immediate 60% as a targeted value shock, and enforce the insider blackout for player companies.

Stream: `ast.earn:<issuerId>` (registry gap, see `_unit.md`); draw order per quarter: one `normal()` (2 draws) at quarter start, issuers in sorted id order.

## Implementation steps
1. At each QUARTER_CLOSE boundary (P2) and at genesis for the first quarter: for every listed equity, `quarterCloseDay = ports.companies.quarterCloseDay(issuer, q)`, compute `reportSchedule` with `fnv1a32(issuerId)`: `reportDay = quarterCloseDay + 5 + (h mod 20)`, slot PRE (t = 30) if `h mod 2 == 0` else POST (t = 600). Store in `EquityState` (`quarter`, `reportTick`, `slot`, `calendarPublished=false`).
2. Consensus at quarter start: `E_q[EPS]` = 09's `expectedEps4Q / 4` (quarterly expectation); `bias = 0.01·(mg − 50)/50`; `ε_c = −bias + PARAM.eq_consensus_sigma · rng.normal()` with `rng = ctx.rng('ast.earn:' + issuerId)`; `consensus = E_q · (1 + ε_c)`. No financials → no consensus, release skipped (no invented numbers).
3. `earningsCalendarStep` (P2 each tick): when `tick ≥ reportTick − 10·720` and not yet published, emit `mkt.earnings.calendar` PUBLIC `{issuer, reportTick, slot}`.
4. `earningsReleaseStep` (P2 at `reportTick`): actual = `ports.companies.actualEps(issuer, q)` (player companies: ledger profit; NPC: 09 sim); if null, defer to the next tick (up to the next quarter). `s = surprise(actual, consensus, P)` with P = last price. `newExpected = guidance ?? financials.expectedEps4Q if 09 supplied a new one this quarter else null`. `revise`: if `newExpected` is null, `epsFwd ← epsFwd·(1 + eq_earn_revision·s)`, else `epsFwd ← newExpected`; `rr ← rr_now + eq_earn_rerate·s`; `ΔlnV = ln(V_new/V_old)` computed by calling `recomputeEquityAnchor` before and after the state update (so floors are respected). Write anchor with `changedBy = shockId`. Create a `ValueShock {shockId: ctx.newId('shk'), target: assetId, logMove: immediateJump(ΔlnV, eq_earn_immediate_frac), sourceKind: 'FUNDAMENTAL', sourceRef: 'earnings:<issuer>:<q>', uncertainty: 0, publishTick: tick}` stored for `pendingEarningsShocks(tick)`. Emit `mkt.earnings.released` PUBLIC `{issuer, eps, consensus, surprise, guidance}`.
5. Blackout (§3.4.3 step 8): `inBlackout` true when the asset is a player company, the actor is in `ports.companies.insiders(cmpId)` (or its beneficial-owner group contains one), and `reportTick − 2·720 ≤ tick ≤ reportTick + 720`. The assembly task exposes it to 05's order gate through the instrument port extension; 06's own intents on that equity (`mkt.corp.tender`, `mkt.block.*`, `mkt.rfq.*`) reject with `AST_BLACKOUT`.

## Test plan
- Pure: `reportSchedule('cmp_halc', 100)` → reportDay `105 + (fnv1a32('cmp_halc') mod 20)` (compute in test), slot from parity; `surprise(1.10, 1.00, 50) = 0.1`; `surprise(0.80, 1.00, 50) = −0.2`; `surprise(5, 0.001, 10) = clamp(4.999/0.1)= 1`.
- `06#6 jump equals 0.6 ΔlnV and drift follows`: worked example 1: s = 0.1, revision 1.0, rerate 1.5, no new expectation: ΔlnV = ln(1.1) + 0.15 = 0.24531017980432493 (when the P/E branch and no floor apply), J = 0.14718610788259495. Worked example 2: s = −0.2: ΔlnV = ln(0.8) − 0.3 = −0.5231435513142096, J = −0.3138861307885258. TestWorld (05 + 06A, 09 fixture port): at the release tick `pendingEarningsShocks` returns exactly one shock with logMove J and `ast.anchor.lnF` moved by ΔlnV with `changedBy` = that shock id; then run 20 game days with 05's other shocks disabled (`setParam` factor vols 0): `ln P` approaches `lnF` with the configured equity half-life (gap after 20 days within 50% ± 5% of the post-jump gap) and the drift after the jump is positive for s > 0.
- Consensus: with mg 50, σ 0.06, a fixed seed, consensus equals `E_q·(1 + 0.06·z)` where z is the stream's first normal; bias for mg 100 is −0.01 (consensus lower, so good managers beat more often).
- Blackout: insider order 2 game days before report → blocked; 1 game day + 1 tick after → allowed; NPC company → never blocked.
