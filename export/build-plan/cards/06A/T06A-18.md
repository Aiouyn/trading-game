## Implementation steps
1. `createSpotAssetsModule(ports)`: `resolveAssetPorts(ports)`; `defineModule({ id: '06A', module: '06', dependsOn: ['05'], tables: [...ALL_06A_TABLES, ENTITLEMENT_TABLE, DISTRESSED_ORDER_TABLE, screener cache, anchor log], streams: [...STREAMS_06A], phases, boundaries, intents: SPOT_INTENTS, events: SPOT_EVENTS, invariants: [INV_BS_003], views: SPOT_VIEWS, genesis })`.
2. Genesis order: `genesisUniverse` → `genesisIndices` → initial `updateCreditStates` → first-quarter `earningsQuarterStart` → anchors for every instrument.
3. Phase P2 handler, in this order each tick: (a) intake 09/04/07 declarations (dividends, splits, mergers, tenders, spin-offs, bankruptcy, issuance announcements, call notices); (b) corporate actions effective now (splits at t = 0, mergers, spin-offs, plan confirmations) and `applyIndexCorporateEvents`; (c) `closeTender` for tenders closing now; (d) `earningsReleaseStep`, `earningsCalendarStep`; (e) hourly at `t mod 30 == 0`: `commodityHourly`, `nativeHourly`, `updateBasis`, `updateFreight`, `updateCreditStates`, `bondAnchorStep`; (f) `equityAnchorStep`; (g) `arriveShipments`; (h) `regimeEventRelay`. Boundaries (run by 02 in P2 when present): DAY_OPEN: none; DAY_CLOSE (t = 719): `snapshotRecord` for record days, `payDividends` for pay days, `serviceBonds(onMissed = recordMissedPayment)`, `defaultCheckStep`, `splitTriggerStep`, `accrueStorageFees`, `applySpoilage`, `accrueEtfExpenses`, `categoryDailyStep`, `decayConditionDaily`, `reappraiseAll`, `delistReviewStep`, expire DISTRESSED orders, SRL intensity refresh; WEEK_CLOSE: `scheduleWeeklySales`; QUARTER_CLOSE: `earningsQuarterStart`.
4. Phase P6 handler (runs after 05's P6 because 06A is registered after 05): (1) `onPhysicalFills`, accrued-interest postings for bond fills (`BOND_ACCRUED_INTEREST`, buyer → seller, `qty·face/100·accrued` from 05's `fillsOfTick`); (2) FX cross anchors; (3) `stepIndexLevels`, `stepEtfNav`; (4) at t = 300 on trading days: `npcPrimaryDealerBids` + `runPrimaryAuctions`, `runDistressedAuctions`; settle primaries due; (5) RFQ: `npcDealerResponses`, `executeAcceptedRfqs`, `expireRfqs`, `publishOtcPrints`, `frontRunSignal`; (6) at t = 540: `rebalanceAtClose`, `crossAcceptedBlocks`; `fileBlocks`; (7) collectibles: `processBids`, `closeLots`.
5. Settlement contract (06 §3.3.2, D095): no handler defers a posting beyond P13 of its tick; the integration test asserts there is no table with a pending-settlement status.
6. INV-BS-003 (20 §3.1): for every EQUITY, ETF, GOVT_BOND, CORP_BOND, CLAIM asset with status not DELISTED: `Σ_{holders} position(holder, asset)` over all entities including treasury (issuer) and CCP accounts = `sharesOutstanding` / `unitsOutstanding` / `amountOutstanding ÷ 1,000`; on mismatch return `{ok: false, entityIds: [assetId, issuerId], observed: sum, expected: outstanding}` (FATAL: the tick rolls back). Short positions count as negative holdings and the corresponding borrowed lots as positive at the buyer, so the identity holds with securities lending.
7. `params.ts` lists every key; a unit test asserts each is present in `@tycoon/params` (or in `SPEC_CONSTANTS_06` for the registry gaps of `_unit.md`).
