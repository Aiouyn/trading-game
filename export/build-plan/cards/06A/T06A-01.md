## Goal
Lay down the shared data model of module 06 that all three units (06A spot, 06B derivatives, 06C crypto) build on: the instrument types of 06 §2, the store tables, deterministic instrument ids (06 §3.1.3), the port interfaces through which later modules (07, 08, 09, 11, 12, 13B, 14B, 15, 16) feed 06 (GLOBAL-CONTEXT G6.1), the class price-parameter defaults handed to 05 (06 §3.21), the 06A event schemas (06 §5) and the genesis of the 400 authored launch instruments from 22 §4. Every later 06 task imports from here.

## Implementation steps
1. `types.ts`: transcribe every type of 06 §2.1–§2.4 and §2.7 verbatim (field names, unions, comments). Money/price fields are `bigint`; `PriceParams` stays `number`. Add the state rows listed in Exports. `CollectibleCategory['categoryId']` is widened to `CollectibleCategoryId = string` because 22 §4.14 wins on category names and counts (R39): the categories are WATCH, CAR, ART, WINE, YACHT, JET (indexed) and SNEAKER (no index).
2. `tables.ts`: one `TableDef` per row type with `module: '06'`, names `ast.<table>` as in Exports, `idOf` returning the `id`/`assetId`/`receiptId`… field. Declare the secondary indexes listed. All three units share these defs (06B and 06C add their own tables in their schema tasks).
3. `ids.ts`: implement the grammar of 06 §3.1.3 exactly; `strikeMicro` is the strike in Price micro-units as a decimal string without sign. `nextSeq` reads/increments `ast.counters` (put) and returns the pre-increment value starting at 1.
4. `constants.ts`: the spec numbers that have no 23 key (listed in `_unit.md` Registry gaps) go in `SPEC_CONSTANTS_06`; nothing else in 06 hard-codes them. `sectorParams` reads `eq_sector_<id>_pe_base`, `_ps_base`, `_duration`, `_sigma`, `_jumps` (family row `eq_sector_<id>_*` of 23) with the 06 §3.4.1 table as default if the key is absent.
5. `priceParams.ts` (06 §3.21): `priceClassOf`: equity size tier from 22's size column (L → EQ_LARGE, S → EQ_SMALL, M → EQ_MID which uses sector σ × 1.0, κ 40 days, 12 bps: the midpoint rule, see `_unit.md` decisions); corporate bond IG/HY by `FundsPort06.isInvestmentGrade` (default: IG if `ratingRef` absent). `defaultPriceParams` fills: κ half-life, σ (equity: sector σ × 0.8 / × 1.4; FX by currency EUN 0.08, NKR 0.09, PYN 0.10, SRL 0.18; commodity σ from 06 §3.10.1 table; crypto majors 0.75 and others 1.25 unless 22 authors a value within the stated range), ν, jumps/yr (equity small cap sector + 2; corporate bond 1 × PD-scaling applied later by T06A-09), jump means, base spread in bps, GARCH α 0.08 β 0.90 (stablecoins 0.02 / 0.95), factor loadings from 22 per asset (else `{}`). `toMktPriceParams`: `sigmaV = sigmaAnnual`, `nu`, `jumpsPerYear`, `jumpUpMean`, `jumpDownMean`, `jumpUpProb = jumpUp/(jumpUp+jumpDown)` counts: use 0.4 for equities, 0.5 bonds/FX/stables, 0.55 commodities (supply shocks up), 0.45 crypto (documented decision), `anchorHalfLifeDays = kappaHalfLifeGameDays` (ETF: 0 meaning "follows iNAV"; FX legs: not used by 05), `baseHalfSpread = baseSpreadBps / 2 / 10000` in log units. `toMktClass` maps: EQUITY→EQUITY, ETF→ETF, GOVT_BOND→GOV_BOND, CORP_BOND→CORP_BOND, FX_SPOT→FX, COMMODITY→COMMODITY_SPOT except COMPUTE→COMPUTE, DATA→DATA_CREDIT, POWER_*→ENERGY_MWH; CRYPTO: AUC/LTX/MRD→CRYPTO_MAJOR, MEME→MEME, STABLE_*→STABLECOIN, else CRYPTO_ALT; FUTURE→FUTURE, PERP→PERP, OPTION→OPTION. `toMarketSpecPartial` sets assetId, class, venueId, ccy, sessionProfile (EQUITY→EXCHANGE_SESSION, FX→FX_24_5, FUT24→FUT_24_5, CRYPTO→CRYPTO_24_7), lot fields, tickTable `[{minPrice: 0n, tick: tickSize}]`, minPrice = tickSize, loadings, licenseRequired = licenseLong (LIC0 never appears on an exchange instrument), floatShares for equities, indexMemberships from `tags`.
6. `ports.ts`: interfaces as exported. `defaultAssetPorts()` returns the "module not present" behaviour: every list empty, every number 0 except `activityScale = 1`, `quality/management/moat` not used when `financials` returns null (equity anchor then stays at its genesis `lnF`), `cet1 = null` (Merton only), `inResolution = false`, `onrFixing = null` (callers use 04 policy rate), `creditTier = 'BBB'`, `ownerGroupOf(e) = e`, `isDealer = false`, `tokenReviewPassed = null` (launch waits), `quarterCloseDay` = the game day of the issuer's QUARTER_CLOSE boundary from `calendarOf`.
7. `events.ts`: zod schemas for every 06A kind of §5 with the payload fields the table names (Money as decimal strings). `mkt.rfq.*` payloads never contain the requester id, only `requesterLabel` and `creditTier` (06#42). Visibility per §5 (rfq kinds PARTIES, `mkt.otc.print` PUBLIC, `mkt.surveillance.signal` SEALED).
8. `genesis.ts` (`genesisUniverse`, run in `ModuleDef.genesis`): read `ctx.content` `instruments` (22 §4.1–§4.7) and create one `Asset` row per authored instrument in sorted id order with `createdBy: 'AUTHORED'`, `status: 'LISTED'`, `listedTick: 0`, the licenses of 06 §3.2 (equities/ETFs/bills LIC1 long, LIC2 short; bonds, FX, commodity spot LIC2/LIC2; crypto launch tokens LIC1 long, `licenseShort: null`), `clearing` (spot: `NONE`), sessions (equity/ETF/bond EQUITY, FX FX, commodity spot FUT24, compute/power FUT24, crypto CRYPTO), `priceParams` via step 5, `marginClass` ('SPOT_EQ','SPOT_ETF','SPOT_BOND','SPOT_FX','SPOT_CMD','SPOT_CRY'), `collateralClass` (equities 'EQ_MAIN', govt bonds 'GOV', IG corporates 'CORP_IG', HY 'CORP_HY', gold 'GOLD', others null). Equity extras from 22 §4.1 (sharesOutstanding = cap0/FX0/px0 floored to 1,000, free float, earnings schedule placeholder filled by T06A-04 at the first QUARTER boundary). Register every issuer entity with 03 only if 22 marks it as owned by 06 (none: issuers belong to 09/04/07). Also create: hubs (22 §4.6), `CommodityDef` and `CommodityState` (inventory = normalCover × base daily demand), freight row `FRX` index 1000, category rows (22 §4.14), the `AnchorRow` of every instrument (`lnF = ln(px0)` until the owning task recomputes), and non-benchmark hub lines `ast_CM_<ID>_<HUB>` only where 22 lists non-zero regional activity (these are rule-created, not counted). Crypto token rows are created by 06C genesis, not here; this task's universe test counts them through 22 only.
9. `canSpawnNpcInstrument`: `liveInstrumentCount < PARAM.max_live_instruments`; `liveInstrumentCount` counts `ast.asset` rows with status not in DELISTED/EXPIRED/MATURED and `createdBy !== 'ENGINE_SERIES'` unless materialized (06 §3.1.2, edge 21: reaching the cap removes nothing).
