## Status
Resolved by Quant (E-21 addendum (a)): `ACCT_FRESH_START = max(0, realToNominal(5_000_000_000n, msiPpm) − liquid money)`, as restricted cash (top-up; 14 §3.13.2's $5,000 × MSI is the cap). Vectors: $1,200 liquid at MSI 1.25 → `5_050_000_000n`; liquid ≥ cap → 0 and no posting (stage NOT_NEEDED).

## Goal
The bankruptcy comeback (L13), owned by 14 (24 R12, R17). 03 (T03-26) runs the personal insolvency: liquidation, discharge, persistent claims and garnishment, then asks 14 for the top-up with `life.freshStart.topup`. 14 owns eligibility, the cooldown, the grant posting, the perk, the anti-farming blocks and Phoenix. Owner decisions: the grant tops liquid money up to `fresh_start_cash_real × MSI` ($5,000 real), at most once per 56 real days, and that cooldown is shared by every character linked to the declarer (15 §3.12.2), so alts are neutralized; surviving player debts are garnished at 30% of daily income (garnishment itself is 03/13; see open question 3).

## State model
FreshStartRow: `OPEN` (declared, case running in 03) → `GRANTED` (top-up minted, perk set) | `FLOOR_ONLY` (cooldown active: no cash, no perk) | `NOT_NEEDED` (liquid money already ≥ target: no cash, perk set, cooldown starts). Terminal after that. Forced busts create the row at case open with `trigger FORCED_NEGATIVE_EQUITY`, `perk null`, `perkChoiceDeadlineTick = tick + 51,840` (72 game days).
Cooldown: per cluster, `untilTick = grantTick + fresh_start_cooldown_real_days × 17,280` (56 × 17,280 = 967,680).

## Implementation steps
1. `acct.freshStart.declare` P1 (common validate first):
   - `nominalAtLeastReal(rankBasisNominal, fresh_start_nw_line_real, msiPpm)` true → `ACCT_FS_NOT_ELIGIBLE` (voluntary only below $1,000 real, §3.13.1).
   - `ports.isHeld` → `ACCT_FS_HELD`; `ports.inProbate` → `ACCT_FS_PROBATE`; an open 03 personal case for the chr (stage ≠ CLOSED) → `ACCT_FS_IN_CASE`.
   - Apply P12: FreshStartRow OPEN, `perkRequested = perk`, `priorPeakRankBasisNWReal = rankRow.peakRankBasisReal`; `ctx.send(chr, 'acct.insolvency.personal.open', { chrId }, 'NEXT')` (T03-26 opens a VOLUNTARY case); clawback request `ctx.send(chr, 'soc.freshStart.clawback', { chrId, fromTick: tick − fresh_start_clawback_real_days × 17,280, toTick: tick }, 'NEXT')` (15 executes the reversal, §3.13.5 #2); emit `acct.freshStart { characterId, trigger: 'VOLUNTARY' }` PRIVATE.
   - Cooldown active is NOT a validation failure: the bust proceeds and ends FLOOR_ONLY (14#39).
2. `onForcedCase`: on 03's case-open event for a chr with trigger PAYMENT_DEFAULT or BALANCE_SHEET, create the FORCED row (same fields; perk null), send the same clawback request, emit `acct.freshStart { trigger: 'FORCED_NEGATIVE_EQUITY' }`.
3. `onTopUp` (the only path that mints `ACCT_FRESH_START`):
   - Find the OPEN row for `chrId` (by caseId); none → `ctx.fail('INV-CHR-005', ...)`.
   - `ccy` must be 'FDL' (characters report in FDL, T03-08), else `ctx.fail`.
   - If `cooldownUntil(cluster) > tick` → stage FLOOR_ONLY, no mint (defense in depth: 03 only reads the declarer's fact; 14 also checks linked characters).
   - `cap = realToNominal(fresh_start_cash_real, msiPpm)`; `amount > cap` → `ctx.fail`. Else `mint(chr, amount, 'FDL', 'ACCT_FRESH_START', { refs: [caseId] })`; 03 lands it in a 72-real-hour restricted lot (T03-12).
   - Set `grantedCash = amount`, stage GRANTED, perk effects (step 5), `startCooldown`.
4. `onFreshStartOutcome`: COOLDOWN → stage FLOOR_ONLY; NOT_NEEDED → stage NOT_NEEDED, perk effects, `startCooldown` (it counts as the Fresh Start of this window: conservative, open question 8). GRANTED is handled by `onTopUp`.
5. Effects (GRANTED and NOT_NEEDED; for FLOOR_ONLY only the blocks and the Reputation event, conservative, open question 9):
   - `leverageCapUntilTick = tick + 7 × 17,280 = tick + 120,960`; `creditBlockUntilTick = tick + 14 × 17,280 = tick + 241,920`.
   - Perk (§3.13.4): voluntary uses `perkRequested`; forced waits for `acct.freshStart.choosePerk` (validate: FORCED row in GRANTED or NOT_NEEDED, `perk == null`, `tick <= perkChoiceDeadlineTick`, else `ACCT_FS_NO_PERK_PENDING`). `LESSONS_LEARNED` and `SECOND_WIND`: `perkEndsTick = start + 120,960`. `OLD_CONTACTS` (one B1 at 50% off, consumed by 09): `perkEndsTick = start + 967,680` (expires with the cooldown; open question 10).
   - Reputation −10: `ctx.send(chr, 'life.reputation.event', { chrId, kind: 'FRESH_START', delta: -10 }, 'NEXT')` (14B applies it).
6. Kept (§3.13.3, 14#42): this task never writes rank, shells, titles, licenses, profile, handle or cosmetics. Licences are kept and not suspended (24 R17 overrides 03's 28-game-day suspension). House and Legacy are 14B tables and are not touched.
7. `checkPhoenix` (§3.13.6) at DAY_CLOSE after `evaluateRanks`: for each row with stage GRANTED, NOT_NEEDED or FLOOR_ONLY, `!phoenixAwarded`, `priorPeakRankBasisNWReal >= 100,000e6`: if `rankBasisReal(chr) >= priorPeak` → `titleAwardTable` row `T_PHOENIX` (once per character ever), emit `acct.title.awarded { titleId: 'T_PHOENIX', scope: 'PERSONAL' }` PUBLIC, set `phoenixAwarded` on every row of that character.
8. `INV-CHR-005` (TICK, FATAL): (a) every `ACCT_FRESH_START` posting this tick has a matching GRANTED row with the same amount; (b) amount ≤ `realToNominal(fresh_start_cash_real)` at that tick; (c) no two GRANTED rows within any cluster (current links) have ticks less than `fresh_start_cooldown_real_days × 17,280` apart; (d) only module 14 posts `ACCT_FRESH_START`.
9. **Inert linking until 15 exists (Producer ruling, E-21).** With `DEFAULT_PORTS.linkedCharactersOf` (15 not present), `clusterOf(chr) = [chr]`, so the shared cooldown neutralizes nothing beyond the character itself. This is the intended state, not a bug. Acceptance criterion **AC-14A-09-INERT**: with the default port, (a) two characters that would be linked under 15 §3.12.2 each get their own Fresh Start grant inside 56 real days, (b) `startCooldown` writes exactly one CooldownRow and one `FRESH_START_COOLDOWN_UNTIL` fact, (c) `onLinkFormed` is never invoked (no subscriber fires without 15) and (d) INV-CHR-005 (c) passes. When 15 provides the port, the cluster rule of steps 3 and the linked test below apply with no code change in 14A. Fixture: `fixtures/linkPorts.ts` exporting `NO_LINKS: Partial<CharacterPorts> = {}` and `linkedPair(a, b): Partial<CharacterPorts>` returning `{ linkedCharactersOf: (r, c) => c === a ? [b] : c === b ? [a] : [] }`.
10. Exploit 14 §9 #7 (bust-and-restart): covered by the cooldown, the clawback request, restricted cash, Rep −10, and 15's $100k climber floor (15 owns). Alt variant (alts bust in turn and funnel the top-ups): the shared cluster cooldown plus 15's P2P refusal between linked accounts and restricted cash forbidding P2P.
