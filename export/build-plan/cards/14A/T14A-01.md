## Goal
The typed state of unit 14A: one `Account`, one `Profile` and one `Character` per player, with the rank state, license holdings and Fresh Start records that every later module gates on (05, 06, 07, 08, 13, 15, 19C read them). This task writes only types, table definitions, the id rules, the tick constants, the stable reject codes and the zod schemas of every 14A event. No behaviour. 14B fields of `Character` (prestige, reputation, notoriety, residence, legacy, chief of staff queue) are not stored here; 14B owns its own tables keyed by `characterId`.

## Imports
- T03-01: `Money`, `Ccy`, `Tick`, `Id`, `LedgerFactKind`.
- T03-08: `registerEntity` (signature only, used from T14A-03).
- T02-11: `TableDef`. T02-04: `canonEncode`, `roundHalfEven`.

## Implementation steps
1. Write `ids.ts`. `validEntityId(id)` = `id.length <= 64 && ENTITY_ID_RE.test(id)`. Every id 14A creates comes from `ctx.newId('chr')` (30 chars) and is checked; a failing id is a `ctx.fail('INV-CHR-001', ...)` in the caller, never an exception.
2. Write `constants.ts` with the literal tick values above. These are unit conversions (G3), not tunable values, so they are constants. Every tunable number is read from params in the task that uses it.
3. Write `schema.ts`. Money fields are `bigint` FDL micro-units. `Money` real-dollar fields carry the suffix `Real` and are FDL micro at MSI 1. `createdRealMs` is `bigint` (from `header.sealUtcMs`, never `Date`). `reachedTick` always has all seven keys.
4. Table ids: account `accountId`, profile `profileId` (`pro_` + 26 via `ctx.newId('pro')`, not a ledger entity, so the entity regex is not applied), character `chrId`. `licenseTable` holds both licenses (holder = chr) and charters (holder = the applying entity, e.g. a `bnk_` sponsor, chrId = its controlling chr).
5. 14B fields of 14 §2.4 that are not in `CharacterRow` (prestige, reputation, notoriety, titles except Phoenix, milestones, residence, legacy, chiefOfStaffQueue) are listed in a comment block in `schema.ts` as "owned by 14B tables keyed by characterId". `restrictedCash` is NOT a stored field: it is a read of T03-12 lots (T14A-08), so there is one source of truth.
6. `events.ts`: one zod schema per kind; money fields in payloads are decimal strings (G9). Visibility is fixed per kind as listed and exported as `EVENT_VISIBILITY_14A`.

  - `RESTRICTED_TICKS === RESTRICTED_WINDOW_TICKS` (T03-12) and `PROTECTION_TICKS === 72 * 720`.
  - `TICKS_PER_CHAPTER === 56 * 17280`; `TICKS_PER_GAME_YEAR === 364 * 720`.
  - Every `REJECT` value matches `/^ACCT_[A-Z0-9_]+$/` and values are unique.
  - Every `EVENTS_14A` schema parses a valid sample and rejects a sample with a number where a money string is required.
  - `canonEncode` round-trip of one row of each table is stable (same bytes twice).
