## Goal
Rank turns net worth into identity and is the gate every module reads (business tiers, licenses, charters, city access). It is evaluated only at day close on rank-basis net worth in real dollars, never decreases, can jump several ranks at once, and R6 needs a floor, a 24-close top-50 streak and a House. Rank changes no odds, price, fee or outcome (§3.2.5).

- T14A-04: `activeShellAfterRankUp`.

## Implementation steps
1. Thresholds are the §3.2.2 table, in real dollars. Producer ruling (E-21): PARAM keys `rank_r1_threshold_real` ($20,000), `rank_r2_threshold_real` ($250,000), `rank_r3_threshold_real` ($5,000,000), `rank_r4_threshold_real` ($100,000,000), `rank_r5_threshold_real` ($2,000,000,000), values from Quant (E-21 addendum (b)): r1 `20_000_000_000n`, r2 `250_000_000_000n`, r3 `5_000_000_000_000n`, r4 `100_000_000_000_000n`, r5 `2_000_000_000_000_000n` (r4/r5 beyond the sim horizon). R6 stays `rank_r6_floor_real` = $20B (Producer). Test: `RANK_THRESHOLD_REAL` equals these values. R6 already has `rank_r6_floor_real`, `rank_r6_top_n`, `rank_r6_streak_closes`.
2. `evaluateRanks` at DAY_CLOSE only (§8 #1, 14#8): for each character with status ACTIVE or INACTIVE, in id order:
   - `rb = rankBasisReal(read, chr, tick)`; `peakRankBasisReal = max(peak, rb)`.
   - R6 streak first (§3.2.3, §8 #3): `inTop = richestAllTimeTopN(rank_r6_top_n).includes(chr)` using the published rows at this close; streak = inTop ? streak + 1 : 0. Board corrections never revoke R6.
   - Loop: while next rank condition holds, advance (§3.2.4). R1–R5: `rb >= threshold`. R6: current rank R5 and `rb >= rank_r6_floor_real` and `streak >= rank_r6_streak_closes` and `hasHouse`.
   - For every rank reached at this close: `reachedTick[r] = tick`, append shell `r<k>`; one `acct.rank.up {from: oldRank, to: newRank}` PUBLIC per close (§8 #2: two ranks crossed → one event with the highest `to`, one ceremony). Set `pendingCeremony = newRank`; profile shell via `activeShellAfterRankUp`.
   - Never decrease (§3.2.4). A Fresh Start does not touch rank.
3. `acct.ceremony.ack`: clears `pendingCeremony` when equal. The display hold rules (pending order, 10 s idle) are client-side (17) and not engine state.
4. Exploit 14 §9 #1 (alt pumps rank with a thin asset): the counter lives in 03's rank-basis valuation; this task must use only `rankBasisReal`, never `ledger.netWorth`. A static test asserts `evaluate.ts` does not import `netWorth`.
5. `INV-PRG-001` (TICK, FATAL; 20 §3.1): for every rank row, `rankIndex(rank) >= committed previous rankIndex`, and `rankIndex(rank) == max(rankIndex(thresholdRank(peakRankBasisReal)), R6 if reachedTick.R6 != null)`, where the peak is only updated at closes.
6. `INV-CHR-009` (TICK, FATAL): `shellsEarned` equals `['r0' .. 'r<k>']` for the current rank k; `reachedTick[r]` non-null exactly for ranks ≤ current and non-decreasing along RANK_ORDER.
