## Goal
A first launch creates one guest account, one profile and one character with the 00 §5.9 start state ($5,000 FDL, LIC0, R0, an FDL-bloc home city, 72 real hours of protection). The character is a ledger entity of kind `chr`. Registration adds an auth method, applies the 16+ age gate and moves the account to REGISTERED. Guests are refused every P2P, contract and alliance action through one exported gate that 15 calls. New-player protection ends at its tick or early on the first op or non-contract lawsuit (13 §3.12).

## State model
- Account: `GUEST → REGISTERED` (acct.register); `GUEST`/`REGISTERED → SUSPENDED/BANNED` (21, not here); `→ DELETED` (14B §3.1.7). A GUEST with `ageRefusedTick` set stays GUEST, accepts no further `acct.register`, and is purged by the 14B deletion flow at `ageRefusedTick + 17,280`.
- Character status starts `ACTIVE`. Protection: `PROTECTED (tick < protectionEndsTick)` → `ENDED` (EXPIRED | FIRST_OP | LAWSUIT). Never back to PROTECTED.

## Implementation steps
1. `createCharacter` (P12, SYSTEM channel only; any other channel → `ACCT_NOT_SELF`):
   - Validate `homeCityId` is one of the three FDL-bloc cities via `ports.cityBloc` (default Port Avalon when empty).
   - `chrId = ctx.newId('chr')`; check `validEntityId(chrId)`, else `ctx.fail('INV-CHR-001', ...)` and return `ACCT_ID_INVALID`. `accountId = ctx.newId('acc')`, `profileId = ctx.newId('pro')`.
   - `registerEntity(ctx, { id: chrId, kind: 'chr', reportingCcy: 'FDL', ownerId: chrId, homeCity })`.
   - Rows: AccountRow GUEST (`guestDeviceId = deviceId`, `createdRealMs = header.sealUtcMs`, `lastActiveTick = tick`); ProfileRow with generated handle (step 2), `DEFAULT_PUBLICATION`, `shellId 'r0'`; CharacterRow `joinTick = tick`, `protectionEndsTick = tick + PROTECTION_TICKS`; RankRow R0 with `reachedTick.R0 = tick`, `shellsEarned ['r0']`, `peakRankBasisReal 0n`; LicenseRow LIC0 ACTIVE, `renewalDueTick null`, `feePaid 0n`.
   - Start cash: `ledger.mint(chrId, realToNominal(usd(5000), msiPpm), 'FDL', 'ACCT_START_CASH')` (00 §5.9). 14 §3.1.1 says "$5,000"; the catalog row says `$5,000 start cash`: charged × MSI so a year-3 joiner gets the same real start. Quant ruling (E-21 addendum (a)): start cash is MSI-scaled, `startCashNominal(read) = realToNominal(5_000_000_000n, msiPpm)`. Tests: at MSI 1.0 → `5_000_000_000n`; at msiPpm `1_769_000n` → `8_845_000_000n`.
   - Emit `acct.character.created` PRIVATE.
2. Guest handle: `guest_` + 6 base32 chars from one 30-bit draw of RNG stream `acct.handle` (registered in T14A-11). If the handle key is taken, add 1 to the 30-bit value (mod 2^30) and retry up to 2^30 times deterministically; this is a linear probe, not rejection sampling (one draw per creation).
3. `acct.register` (validate P1, apply P12): account must be GUEST (`ACCT_NOT_GUEST`), not age-refused (`ACCT_AGE_REFUSED`). `age = ageFromBirthYear(sealUtcMs, birthYear)`. If `age < 16`: set `ageBand 'U16'`, `ageRefusedTick = tick`, keep GUEST, return `ACCT_UNDER_AGE` (14#3). Else push `authMethod`, set `ageBand`, `country = countryClaim` (15 §3.2 verifies later), `state REGISTERED`, emit `acct.registered` PRIVATE. Birth year outside [1900, civilYear] → `ACCT_UNDER_AGE` too (conservative).
4. `civilYear`: days = utcMs / 86,400,000 (bigint floor), then Howard Hinnant's `civil_from_days` in integer math.
5. `guestGate`: returns `ACCT_GUEST` when the account of the character is GUEST. 15 calls it in P1 for every intent kind starting with a `GUEST_BLOCKED_PREFIXES` entry (15 §3.12.1, 14 §3.1.1). Also blocked: appearing on boards (15 reads `accountState`).
6. `guestNeedsRegistration`: `(tick − joinTick) × 5 s > guest_max_real_minutes × 60 s`. The gateway (19C) reads it; the engine does not stop a guest from playing solo.
7. Protection: `expireProtection` in P12 scans `T_CHARACTER` by `protectionEndsTick == tick` (index) and emits `acct.protection.ended {reason:'EXPIRED'}`. `endProtection` on message `acct.protection.end` from 12 (first op) or 13 (first non-contract lawsuit): if still protected, set `protectionEndsTick = tick` and the reason. Protection never extends (exploit 12 §9 #16).
8. Background (14 §3.1.4): stored once at creation; `ACCT_BACKGROUND_DISCOUNT` is posted by 09 at first purchase (not here). Export nothing more.
9. Invariants:
   - `INV-CHR-001` (TICK, FATAL): every AccountRow has exactly one CharacterRow and one ProfileRow pointing back to it and vice versa; every chrId passes `validEntityId`; no two accounts share a character.
   - `INV-CHR-002` (TICK, FATAL): `protectionEndsTick <= joinTick + PROTECTION_TICKS` and a row's `protectionEndsTick` never increases between ticks (compare with committed previous value).
   - `INV-CHR-008` (TICK, FATAL): no intent result ACCEPTED this tick has a kind under `GUEST_BLOCKED_PREFIXES` with a GUEST actor.
