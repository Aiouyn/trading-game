## Goal
Every order a manager (human, hired NPC or AI operator) places for a fund is checked before it can trade against the fund's mandate (08 §3.1.8 rules 1–4, with 05 doing self-match prevention per rule 5), related-party exposure is capped and publicly filed, post-trade drift is cured or freezes the fund, mandate and fee changes wait out a notice during which investors exit gate-free, transparency is the manager's opt-in choice, and the market-abuse patterns of 08 §3.1.12 leave sealed evidence for 13. `fund.trade` is 05's normal order intent with `onBehalfOf: fundId`; 08's part is the pre-trade check that 05 calls through `FundsPort.preTradeCheck` (port gap recorded in `_unit.md`).

## Implementation steps
1. `preTradeCheck` (P1, called by 05 for every order whose principal `onBehalfOf` is a `fnd`; reject codes returned to the actor only, nothing else happens): (0) actor is a fund operator (`FUND_NOT_MANAGER`); fund status allows trading: FROZEN allows only engine liquidation (manager orders `FUND_FROZEN`), WINDING_DOWN and CLOSED allow none (`FUND_NOT_ACTIVE`); `reduceOnly` orders skip rules 2–4. (1) asset class ∈ `allowedAssetClasses` (`FUND_MANDATE_ASSET_CLASS`), asset region (issuer bloc; FX: both currencies) ∈ `allowedRegions` (`FUND_MANDATE_REGION`), a sell that would take the position below zero requires `shortAllowed` (`FUND_MANDATE_SHORT`), derivatives (OPTION, FUTURE, PERP, SWAP, CDS) require `derivativesAllowed` (`FUND_MANDATE_DERIVATIVE`), the manager's license ≥ `requiredLicense(asset, act)` (`FUND_NO_LICENSE`); leveraged ETFs (§3.2.5) never in MONEY_MARKET or LONG_ONLY funds (`FUND_MANDATE_ASSET_CLASS`). (2) post-trade gross leverage `Σ|exposure| / NAV ≤ maxGrossLeverage` (player funds ≤ `PARAM.fund_max_leverage_player`; NPC funds `npcLeverageCap`), exposures with `deltaNotional` (`FUND_MANDATE_LEVERAGE`). (3) post-trade position value ≤ `maxPositionPctNav × NAV` (player ≤ `PARAM.fund_max_position_pct`) (`FUND_MANDATE_POSITION`). (4) related-party cap: if `relatedHolder(...)`, post-trade position ≤ `PARAM.fund_related_cap_pct × NAV` (`FUND_RELATED_CAP`). NAV is the last struck NAV adjusted by today's fills (valuation from `valueHolder` at the last marks); the check uses `o.price` (limit or last price).
2. Rule 5 (self-match) is 05's: 05 never matches a fund order against an order of the manager or a linked account; 08 supplies the membership through `MandatePort.managedFundsOf` (T08-29). This task documents it and tests it in the integration (08#10 second clause).
3. `relatedHolder`: the manager, any entity in the manager's ownership chain, or a 19-linked account (`linkScore ≥ PARAM.fund_link_score_block`) holds ≥ `PARAM.fund_related_float_pct` of the instrument's float, or is in `ports.companies.insiders(issuer)`. `fileRelatedTrades`: every fund fill (`fillsOfTick`, fund account) in such an instrument → `fund.relatedHoldingFiled` PUBLIC `{ fundId, assetId, sizeBand }` (bands: <$100k, $100k–1M, $1–10M, >$10M) emitted at the next t = 719 (within 1 game day).
4. `shadowManagerTrades` (§3.1.12, evidence only, 13 owns offences): (a) exit liquidity: within 1 game day, the manager (chain or linked) sold an asset the fund bought; (b) front-running: the manager's personal trades in the same asset and direction within 1 game day before fund trades of ≥ 2× the personal size. Each detected pair emits `fund.managerTradeShadow` SEALED `{ fundId, managerId, assetId, personalFillIds, fundFillIds, pattern }`. Detection keeps a rolling 720-tick window of manager-group and fund fills (from `fillsOfTick` each tick) in `fnd.shadow_window` (T08-01), rows pruned after 720 ticks.
5. `checkLevel3RelatedPurchase`: a fund buying a Level-3 asset from a related party must price within ±10% of the NPC valuer's appraisal, else `FUND_RELATED_VALUATION` (the 09 private-stake market calls this through `FundsPort` when the buyer is a fund; 08 also emits `fund.managerTradeShadow` with `pattern: 'RELATED_VALUATION'` on each attempt; the "+30 surveillance score" is 13's consumption of that event).
6. `driftCheck` (DAY_CLOSE after the strike): positions above `1.25 × maxPositionPctNav × NAV` start a cure timer (`positionDriftSinceTick[assetId]`); if still above after `PARAM.fund_drift_cure_days` game days → status FROZEN (`fund.frozen` PUBLIC, reason `DRIFT`) until back below (checked daily; unfreeze emits `fund.unfrozen`). Leverage above `1.1 × maxGrossLeverage` is handed to 07 margin rules (no 08 action; emit nothing). Prices moving never forces a trade otherwise.
7. `fund.updateMandate` (actor manager/sponsor; new limits within the same caps as T08-04 `validateTerms`): `pendingMandate = { mandate, effectiveTick: tick + PARAM.fund_mandate_notice_days × 720 }`, `gateFreeUntilTick = effectiveTick`, `gateFreeReasons += 'MANDATE_NOTICE'`; emit `fund.mandateChangeNotice` PARTIES `{ old, new, effectiveTick }`. `fund.updateFees`: if any rate increases → same notice and gate-free window, `lastFeeIncreaseTick = tick`, `fund.feeChangeNotice`; pure cuts apply at once. Inside the window redemptions also pay no early-exit fee (T08-07 reads `gateFreeReasons`).
8. `fund.setTransparency`: raising the level is effective next game day; lowering takes 7 game days (`pendingTransparency`). `investorDisclosure`: NAV_ONLY → daily NAV + monthly return; EXPOSURES (default, D145) → buckets rounded to 5% granularity (`round(x/0.05)×0.05`), leverage, liquidity profile; TOP_POSITIONS_DELAYED → plus top 5 positions as % of NAV as of 7 game days ago (from `fnd.position_snapshot` rows (T08-01) that `writePositionSnapshot` writes at each strike and prunes after 28 days); FULL_DELAYED → full list as of 28 game days ago. Every investor view is bound by the automatic NDA clause of 15 (recorded in the view payload as `ndaClause: true`).
9. Filings (§3.1.16, ruling R20): the holdings report is 15's `HOLDINGS_QUARTERLY`; 08 exposes `fundHoldingsForFiling(store, fundId, quarterEndTick)` in transparency.ts returning up to 20 long listed-equity positions each ≥ 0.5% of the reportable book with quantities, for 15 to file 21 game days after quarter end. Ownership-threshold aggregation (fund + manager) is 15's, using `MandatePort.managedFundsOf`. `PARAM.fund_filing_aum` is retired (R20): never read it.
