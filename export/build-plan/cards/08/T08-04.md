## Goal
Who may launch which fund (08 §3.1.1), how a fund comes into existence (08 §3.1.2: entity, custody, seed, activation, the 28-day fundraising limit) and the operator choice (self, hired NPC manager, own AI model). This task owns the intents `fund.create` and `fund.hireManager`; the validation rows of 08 §4.1 for those kinds (and the seed rules of `fund.seed`) are implemented exactly. The seed subscription itself is dealt by T08-05 (it calls `onSeedSettled` from here).

## Implementation steps
1. `KIND_REQUIREMENTS` from the 08 §3.1.1 table, with ruling R13 (CH_FUND at R3): HEDGE, FUND_OF_FUNDS, CREDIT: OPEN_ENDED, LIC3, R3, 336 days; LONG_ONLY: OPEN_ENDED, LIC2, R3, 336 days; VENTURE, PRIVATE_EQUITY: CLOSED_ENDED (or LISTED_CLOSED_END), LIC4, R4, 0; MONEY_MARKET: OPEN_ENDED, LIC4, R4, 0; ETF: ETF, LIC4, R4, 0; SOVEREIGN_WEALTH: CLOSED_ENDED, LIC4 (as Institutional sponsor), R6, 0, outsideInvestors false. LISTED_CLOSED_END for any strategy: the strategy's row plus rank ≥ R4 (`max(rank, R4)`).
2. `launchEligibility` check order (first failure wins; this order defines 08#1's codes): Held (`FUND_HELD`) → fund-management ban active (`FUND_BANNED`) → charter `CH_FUND` held by the sponsor or its root character (`FUND_NO_CHARTER`) → manager license (human manager: the manager character; NPC manager: the sponsor's root character; AI model: the model owner's character) (`FUND_NO_LICENSE`) → rank of the sponsor's root character (`FUND_RANK`) → account age ≥ `minAgeDays` (`FUND_ACCOUNT_AGE`) → clean record: `convictionsSince(root, tick − 1344, 'S4') = 0` (`FUND_RECORD`) → live funds of the sponsor `< PARAM.fund_max_per_sponsor` (`FUND_TOO_MANY_FUNDS`) → SWF: sponsor must be the R6 player's top company (largest NW `cmp` in the chain; `FUND_SWF_ONLY`).
3. `validateTerms`: `mgmtFeeRate ≤ PARAM.fund_mgmt_fee_cap` (ETF `≤ PARAM.etf_max_fee`), `perfFeeRate ≤ PARAM.fund_perf_fee_cap` (ETF must be 0), `subscriptionFeeRate ≤ 0.01`, `earlyExitFeeRate` default `PARAM.fund_early_exit_fee` when omitted and ≤ 0.03 (23 range), `custodyFeeRate` forced to `PARAM.fund_custody_fee` (`FUND_FEE_CAP` on any breach); mandate: `maxGrossLeverage ≤ PARAM.fund_max_leverage_player`, `maxPositionPctNav ≤ PARAM.fund_max_position_pct`, `maxIlliquidPctNav ≤ PARAM.fund_max_level3_pct` for OPEN_ENDED and ETF, `minLiquidityDays ≥ 1`, `derivativesAllowed` only with a LIC3+ manager, `maxDrawdownPct` in (0, 1], `allowedRegions` ⊆ the five bloc codes (`FUND_MANDATE_CAP`); gate `maxRedeemPctNavPerDay` defaults to `PARAM.fund_gate_pct_per_day`; lockup/notice days ≥ 0 (stored as ticks × 720).
4. `fund.create` validate (P1): the 08 §4.1 row: eligibility, terms, `social.nameAllowed(name)` (`FUND_NAME_MODERATION`), name unique among non-CLOSED funds ignoring case via ASCII upper-casing (`FUND_NAME_TAKEN`), managerId is the actor's own character, a staff candidate from `staffCandidate` (`npcCandidateId` path), or `ai.isOwnModel(actor, managerId)` (`FUND_BAD_MANAGER`). Apply (P8): `createFund`.
5. `createFund`: `id = ctx.newId('fnd')`; `registerEntity(ctx, { id, kind: 'fnd', reportingCcy: baseCcy, ownerId: sponsorId })`; `custodyAccount = 'ccp_TCH:ESC:' + id` (07 §3.20 ESC custody: assets live only on the fund's own balance sheet, which only 08 rules, 05 fills for the fund, and 07 PB margin can change); `status 'FUNDRAISING'`, `statusSinceTick = tick`, `createdTick = tick`, `unitsOutstanding 0n`, `navPerUnit = toPrice(PARAM.fund_initial_nav)`, `hwmSeries true`, `managerStakeUnits 0n`, `trackRecord` zeroed with `inceptionTick = tick`, `transparency` as given (default `EXPOSURES`, 08 §3.1.15 D145), `ratingIds []`, `closedEnd` per payload (`investmentPeriodEndTick`/`termEndTick` set at first close by T08-12), and a `FundState` row (`targetAum`, zero accruals, `gateFreeUntilTick = 0`). NPC manager hire: `hireStaff(ctx, sponsorId, candidateId, 'FUND_MANAGER')` then `managerId = candidateId`.
6. `fund.seed` is implemented in T08-05 (it shares the subscription path); this task supplies `minSeed` and `onSeedSettled`. Its validation: actor is the manager or the sponsor's root character (`FUND_NOT_MANAGER`), fund FUNDRAISING or ACTIVE, `amount ≥ minSeed` (`FUND_SEED_TOO_SMALL`).
7. `onSeedSettled` (called by T08-05 when the seed request fills): status → `ACTIVE`, `launchTick = tick`, `statusSinceTick = tick`, emit `fund.launched` PUBLIC with `{ fundId, name, kind, strategy, fees, gate, managerHandle }` (handle = the manager's display handle from 14A, never holdings).
8. `fundraisingTimeouts` (DAY_CLOSE, P8): a fund in FUNDRAISING for ≥ 28 game days (`SPEC_CONSTANTS_08.fundingWindowDays × 720` ticks) without a settled seed: release every pending request hold (T08-05 `cancelAllRequests`), status `CLOSED`, emit `fund.closed`.
9. `fund.hireManager` (P1 validate: actor is the sponsor's root character `FUND_NOT_SPONSOR`; candidate valid as in step 4): `fundState.nextManagerId = { managerId, effectiveTick: tick + 720 }`; `applyManagerChanges` switches it. The human principal stays responsible (13): store `Fund.flags` unchanged.
