## Goal
Implement how a fund (and, through the same functions, an SPV or an insurer) values its holdings at day close (Level 1, 2, 3 of 08 §3.1.3), the daily NAV strike of 08 §3.1.4 with series accounting and the three hurdle types, the swing-pricing factor used by dealing, and invariant INV-FND-001. Dealing itself (subscriptions, redemptions) is T08-05/T08-06; they call `strikeNav` first and use its result.

- T06A-02: `markPrice(store, params, assetId, tick)` (06 model price for Level 2: bonds, OTC derivatives, CDS; ABS tranche and cat-bond model prices come from T08-21/T08-28 through `markPrice` once 08 registers its valuers, see `_unit.md` port gap).

## Implementation steps
1. `classifyLevel` (08 §3.1.3): Level 1 if `dailyBars(store, assetId, gameDay, gameDay)[0]?.volume > 0` (a trade in today's session or closing auction). Level 2 if `markPrice` returns non-null for the asset, or the asset is a fund unit (1530 account, priced at that fund's last struck `navPerUnit`), a tranche (1560) or a cat bond. Level 3 otherwise: 1570 private stakes, side-pocket assets, 1800 properties, defaulted claims with no market, and any asset of a delisted or bankrupt issuer (edge 7: Level 3 at the recovery estimate until 09 distributes).
2. Marks: Level 1 = `officialCloseOf(assetId, gameDay)` (24h products: the 05 day-close mark at t = 719, which `officialCloseOf` returns for them). Level 2 = `markPrice(...)` or fund NAV. Level 3 = `level3Value`: the `fnd.level3_mark` row; between valuations the value rolls with the relevant sector index (06 `indexLevelOf06` of the row's `sectorIndexId`) return × β = 1.0. A manager can never set a mark: there is no write path to `fnd.level3_mark` except the valuer step (step 3), acquisitions (cost, `source 'ACQUISITION'`) and recovery estimates (edge 7, `source 'RECOVERY'`).
3. `rollLevel3Marks` at QUARTER_CLOSE (P8, t = 719): for every Level-3 holding of every fund, SPV and insurer, value it through `ports.companies.valuePrivateStake` (09B) for 1570 stakes and `appraise(propId)` (T10A-??) for properties; when the port returns null keep the rolled value and reset the anchor (`sectorIndexAtValuation = now`).
4. `valueHolder`: iterate `accountsOfEntity(store, holderId)` in key order. Cash (1001, 1010), receivables (1100–1190), longs (positive qty in 1500, 1510, 1520, 1530, 1540, 1560, 1570, 1600, 1800, 1870), shorts (negative qty, valued `|qty| × mark`), PB borrowings (2202), payables (2500, 2520, 2590), derivative liabilities (2600). For a fund, holdings named in an OPEN side pocket (`fnd.side_pocket` rows of the fund, T08-09) are excluded from the main valuation and valued separately by `valueSidePocket` (same marks). Convert every value to the fund's `baseCcy` with `fxToBase` (edge 8). `grossExposure` = Σ |position values| using delta-adjusted notional for derivatives (06B `deltaNotional`, T06B-?? import listed in T08-08) — here plain value; T08-08 overrides for leverage. Weekend days (edge 9) need no branch: `officialCloseOf` returns the unchanged equity close and moving crypto marks.
5. NAV (08 §3.1.4), all in float64, in this order: `grossAssets = cash + receivables + longValue`; `liabExFees = pbBorrowings + shortAbs + payables + derivLiab + redemptionPayable + accruedMgmt + accruedCustody` (accrued and unpaid since the last month end); `navBeforeFees = grossAssets − liabExFees`; `{mgmt, custody} = dailyAccruals(navBeforeFees, fees.mgmtFeeRate, PARAM.fund_custody_fee)` (each `navBeforeFees × rate / 364`, floored at 0 when navBeforeFees ≤ 0); `liabilities = liabExFees + mgmt + custody`; `G = (grossAssets − liabilities) / (unitsOutstanding / 1e6)`. Escrowed subscription cash is a hold on the investor, never a fund asset (§3.1.5 step 1).
6. Series (step 6 of §3.1.4): for each `fnd.series` row of the fund in id order, `hurdle = hurdleLevel(H_s, hurdleRate, day − crystallizedDay, type)` = `H_s × (1 + hurdleRate)^(days/364)` with `dmath.pow` (NONE → `H_s`); `a_s = perfAccrualPerUnit(...)`: HARD `perf × max(0, G − max(H_s, hurdle))`; SOFT `G > hurdle ? perf × max(0, G − H_s) : 0`; NONE `perf × max(0, G − H_s)`; `net_s = G − a_s`. ETFs have `perfFeeRate = 0` (§3.2.1). Lead series = oldest (lowest `openedDay`, then id) with `G ≥ H_s`; if none, the oldest. Reported NAV = `net` of the lead series.
7. `strikeNav` writes, in this order: `fundState.accruedMgmt += toMoney(mgmt)`, `accruedCustody += toMoney(custody)` (the only float→money conversions of this task), the `NavRecord` (`grossAssets`, `liabilities`, `accruedMgmt`, `accruedPerf = Σ a_s × units_s`, `nav = Σ net_s × units_s` as Money via `toMoney`, `navPerUnit = toPrice(lead net)`, `level{1,2,3}Pct = levelValue / grossAssets` (0 when grossAssets = 0), `grossLeverage = grossExposure / nav`, `netExposure = |long − short| / nav`, `liquidity1d` and `liquidity5d` = share of NAV sellable within 1 and 5 game days at ≤ 20% ADV per day (Level-1 lines: `min(value, days × 0.2 × advNotional)`), into `fnd.nav` (id `navRowId`), the `Fund.navPerUnit`/`navTick` fields, the `NavHistory` ring (append; keep ≤ 1,456 entries), and `publishModelMark(ctx, { kind: 'NAV', assetId: fundId, ccy: baseCcy, price: navPerUnit, tick })`. Then `emitFund(ctx, 'fund.navStruck', [fundId, ...investorIds], record)` (PARTIES) and, for board-eligible funds (T08-10 sets `boardEligible`), `fund.navPublic` with the return and AUM band only.
8. Swing (§3.1.4 last paragraph): `netFlow` = cash value of subscriptions minus redemptions dealing today (computed by T08-06 at `G`); if `|netFlow| > PARAM.fund_swing_threshold × nav`, `swingFactor = sign(netFlow) × min(PARAM.fund_swing_cap, estimatedLiquidationCost / nav)` else 0. `estimatedLiquidationCost(lines, |netFlow|/nav, cost)` = Σ over Level-1 and Level-2 lines sold pro rata (`qtySold = sellFraction × |qty|`) of `(halfSpread + 0.8 × σ_daily × √(qtySold / ADV)) × value × sellFraction`, with `halfSpread = makerHalfSpread`, `σ_daily = sigmaDailyOf`, `ADV = modelAdv().advUnits` (an asset with no ADV contributes `0.8 × σ × 1 × value × f`, i.e. √1, documented: no division by zero). `G_deal = G × (1 + swingFactor)`. The swing amount stays in the fund (dealing uses `G_deal`, nothing is paid out).
9. `INV_FND_001` (DAY_CLOSE, FATAL, module '08'): for every fund with a `fnd.nav` row of today: recompute `valueHolder` on the invariant's pre-commit store with the day's marks, recompute `G` from the stored `redemptionPayable`, accruals and units; fail when `|G_recomputed − G_record| × 1e6 > 1` (one micro-unit per unit) or when `record.nav` differs from `Σ net_s × units_s` by more than one micro per unit outstanding. `observed`/`expected` carry both numbers.
