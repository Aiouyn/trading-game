## Goal
Define every engine event kind of 08 §5 with its zod payload schema and visibility, the single place that maps each money flow named in 08 §3.6.2 to the 03 reason code that is actually posted (24 §8: "a builder posts only the 03 code"), the registration of the few 08 codes that 03 does not define (24 R23 extension point), the RNG stream row 08 needs beyond 02's registry, and the stable reject codes of all `fund.*` intents.

## Imports
- T08-01: all schema types (`NavRecord`, `CatEvent`, `DealReport`, `SystemicIndicators`, …), `MODULE`.
- T03-05: `registerReasonCodes(module, cls, rows)`, `aliasTargets(name)`, `getCatalog()`.
- T03-02: `CodeRow`, `FlowClass` (type only, via T03-05's re-export).
- T02-06: the registry row format of `packages/engine/core/rng/registry.ts` (`StreamSpec { module, pattern, root, use }`).

## Implementation steps
1. `events.ts`: one zod object schema per kind. Payloads follow the "Payload (main fields)" column of 08 §5; for the kinds that §5 groups with a slash, each kind gets its own schema with the same fields. Money fields are decimal strings (`zMoney`), ticks integers, rates numbers. Kinds added beyond §5 (all needed by rules in later tasks): `fund.navPublic` (PUBLIC subset for board funds: fundId, day, netReturn, aumBand), `fund.requestRejected` (PARTIES: reqId, code, refunded), `fund.unfrozen`, `fund.windingDown`, `fund.incident` (PUBLIC: fundId, kind, refEventId), `fund.capitalCall`, `fund.distribution`, `fund.lpDefault` (PARTIES), `fund.etf.noApNotice` (PUBLIC, edge 10), `fund.etf.terminated` (PUBLIC, edge 13), `fund.etf.basket` (PUBLIC daily basket of active ETFs, §3.2.8), `fund.index.blocked` (PUBLIC, §3.2.6 public note), `fund.sec.dealWithdrawn` (PUBLIC), `fund.rat.requested` (PUBLIC only when `rating_disclose_preliminary` is true: agency name and subject, no grade), `fund.ins.quote` (PARTIES: holder and quoting insurer), `fund.ins.policyEnded` (PARTIES: CANCELLED/EXPIRED/EXHAUSTED with refund), `fund.ins.fraudNotice` (PARTIES notice part of §5 "SEALED + PARTIES notice"), `fund.ins.treatyBound` (PARTIES), `fund.catbond.issued` (PUBLIC).
2. Visibility table: as §5; `fund.navStruck` PARTIES; `fund.ins.fraudReview` SEALED; `fund.managerTradeShadow` SEALED; `fund.rat.preliminary` PRIVATE. `emitFund` parses the payload with the schema (a parse failure is `ctx.fail('INV-ENG-001', subjectIds, 'bad payload <kind>', 'schema valid')`) and calls `ctx.emit(kind, sortedUnique(subjectIds), payload, FUND_EVENT_VISIBILITY[kind])`.
3. `codes.ts`: `FLOW` exactly as exported. 08 §3.6.2 names map to 03 codes per 24 §8 (`ETF_CU_FEE` → `ETF_AP_FEE`, `INS_CLAIM`/`INS_CLAIM_NPC` → `INS_CLAIM_PAYOUT` for core insurers and `INS_ELASTIC_CLAIM` for hh/frm holders, `INS_PREMIUM_NPC` → `INS_PREMIUM`, `INS_REINS_*` → `INS_REINSURANCE_*`) and per the 03 catalog (`FUND_SUB_ISSUE` → `FND_SUBSCRIPTION`, `FUND_REDEEM_PAY` → `FND_REDEMPTION`, `FUND_MGMT_FEE` → `FND_MGMT_FEE`, `SEC_SALE_PROCEEDS` → `SPV_TRANCHE_ISSUE`, `SEC_COUPON` → `SPV_WATERFALL_INTEREST`, `SEC_PRINCIPAL` → `SPV_WATERFALL_PRINCIPAL`, `SEC_SERVICER_FEE` → `SPV_SERVICING_FEE`, `RATING_FEE` → `RAT_RATING_FEE`, `CATBOND_COUPON` → `INS_CAT_BOND_COUPON`, `CATBOND_PAYOUT` → `INS_CAT_BOND_LOSS`). Classification rule (binding, recorded in `_unit.md`): named NPC entities (NPC funds, NPC insurers and reinsurers, agencies, PGS, dealer banks) are core entities (03 §3.5.2, 24 §8 note on `INS_PREMIUM_NPC`), so flows between them and players are TRANSFER; the FAUCET/SINK side of "NPC capital" is carried by the elastic codes that 03 defines for 08 (hh holders of fund units and hh/frm policyholders, row holders of tranches and cat bonds). The `_NPC` fee codes of 08 §3.1.7 therefore post `FND_MGMT_FEE`/`FND_PERF_FEE` with `sub: 'NPC_SHARE'`; the money entering the player economy from NPC capital posts at `FND_ELASTIC_SUBSCRIPTION` (FAUCET) and leaves at `FND_ELASTIC_REDEMPTION`/`FND_ELASTIC_DISTRIBUTION` (SINK). 08 §3.1.7 itself defers class to 03 ("03 owns the class registry").
   Escrow: `FUND_SUB_ESCROW`/`FUND_SUB_REFUND` are realised as a 03 cash hold (`ctx.holds.placeCash` at P1, released or settled at the strike); no posting, so no code is registered for them.
   `CODE_ROWS_08` (owner 8; legs as 03 account numbers; columns per `CodeRow`):
   | Code | Class | Tpl | Leg A | Leg B | Tax | Description |
   |---|---|---|---|---|---|---|
   | `FUND_CUSTODY_FEE` | SINK | BURN | 5080 | - | - | fund custody fee to the CCP custodian (08 §3.1.7) |
   | `FUND_ANTI_DILUTION` | TRANSFER | PAY | 5080 | 4190 | - | subscription, early-exit, swing and MMF liquidity fees paid into the fund |
   | `FUND_UNITS_CANCEL` | TRANSFER | MOVE_QTY | 1530 | 3700 | GAIN | investor units cancelled on performance-fee crystallization |
   | `FUND_IN_KIND` | TRANSFER | MOVE_QTY | @ASSET | @ASSET | GAIN | in-kind redemption slice delivered by a fund (08 §3.1.6 step 6) |
   | `FUND_CARRY` | TRANSFER | PAY | 3700 | 4040 | SERVICE | closed-end carried interest to the GP |
   | `FUND_LP_FORFEIT` | TRANSFER | MOVE_QTY | 1530 | 1530 | - | defaulting LP forfeits paid-in value to other LPs |
   | `ETF_FAIL_FEE` | TRANSFER | PAY | 5080 | 4190 | - | failed creation/redemption fee AP to fund |
   | `ETF_CASH_COMPONENT` | TRANSFER | PAY | 1001 | 1001 | - | cash component of an in-kind creation or redemption |

   `registerCodes08()` is called once at module load by `index.ts` (T08-31) before any catalog build. Every `FLOW` value must exist in `getCatalog()` after registration (test).
4. `elasticSectorFor(kind)`: returns `kind` when it is 'hh', 'frm' or 'row', else null. Callers choose the elastic code when it is non-null: fund units held by hh (FND_ELASTIC_*), tranches and cat bonds held by row (SPV_ELASTIC_*), policies held by hh or frm (INS_ELASTIC_*).
5. RNG: edit `packages/engine/core/rng/registry.ts` (T02-06) adding the row `{ module: '08', pattern: 'ins.quote:<insId>:<holderId>:<line>', root: 'P', use: 'insurer pricing error ε, 08 §3.5.2' }`. 08's other streams already exist in 02 §3.10.4: `fund.npc_flow:<fndId>` (registered; 08 rules draw nothing from it, see `_unit.md`), `ins.cat:<peril>:<regionId>` used with the city id as regionId and with peril slot `EVENTSET` and regionId `<chapter>` for the PML event set, `ins.claims:<insId>` (registered, undrawn).
