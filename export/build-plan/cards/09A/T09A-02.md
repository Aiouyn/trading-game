## Goal
Give every later task one place to read a business type and its tier constants, convert launch-price amounts to today's prices, and run the one-time genesis calibration that sets `perCapita`, `ioCoef`, capacity and fixed costs so a reference business pays back in `paybackDays(tier)` game days (option A, R18: B1 6 / B2 12 / B3 24 / B4 48 / B5 96 / B6 200). Genesis also creates every market row with its NPC field weight sized so that the field holds 50% against 12 reference player businesses.

## Implementation steps
1. `TIER_TABLE` exactly per 09 §3.1.2 (setup: B1 1 game hour = 30 ticks, B2 1 game day = 720, B3 3 days, B4 7, B5 14; B6 per type from 22 `buildDays`, 28 to 182 game days). Rank gates are 14's thresholds; this table only names the rank.
2. Indexing (09 §3.1.3): `c0`, `refPrice`, fixed costs are multiplied by `priceLevel(bloc)` and wages by `wageLevel(bloc)` every day; callers pass the level, this module never compounds inflation itself (04 rule). Each business uses its own bloc (edge 10).
3. Calibration exactly per 09 §3.2.4, in the reference city, at launch prices, for the type's default segment (apply `SEGMENT_PRICE_MULT` and `segmentCostAdj` to refPrice, κ and φ first):
   - `piStar = c0 / paybackDays`, `rStar = piStar / (1 − κ − φ)`, `unitsStar = rStar / refPrice`, `sRef = (1 − 0.5) / PARAM.biz_calib_density`, `dRef = unitsStar / sRef`.
   - HOUSEHOLD: `perCapita = dRef × nDistricts / (refPop × segShare)` for DISTRICT-scope types (the reference district has the mean footfall share 1/nDistricts) and `dRef / (refPop × segShare)` otherwise. BUSINESS_DERIVED: `ioCoef[driver] = dRef / (segShare × driverActivityRef)` with `driverActivityRef` = the driver category's own `dRef` (its reference market demand, computed first: process types in dependency order of `ioDrivers`) or the 10/11 reference quantity named by `driverQty`. TOURISM: `roomNightsPerIndex = dRef / (segShare × tourismIndex(ref))`. PLAYER_SERVICES: NPC share uses `perCapita` like HOUSEHOLD.
   - Capacity (resolution of the ambiguous "Σ_h hourProfile-weighted open hours", written down here so it is not left to the implementer): the stated purpose is "capacity binds only above 125% of reference volume", so capacity must cover the busiest hour at 125%: `capacityPerHour0 = 1.25 × unitsStar × max_h hourProfile[h]`.
   - `f0 = φ × rStar`, split by 22's `fixedSplit` (wages, rent, upkeep, energy, insurance).
   - No-demand-pool archetypes (COMMODITY_PRODUCER, FLOW_TAKE platforms, COMPUTE_PROVIDER, TRIAL_BINARY, FINANCIAL_INSTITUTION, TROPHY, FLIP_TRADING): store `outputRate0` (units per hour) or `takeRate` such that expected daily profit at launch macro equals `piStar`: `outputRate0 = rStar / (refPrice × openHours)` with refPrice = the 06 launch spot of the output; platforms keep 22's `takeRate` and solve the `platformShare` reference = 1/12 the same way as shares. FINANCIAL_INSTITUTION and TROPHY are not on the payback curve (09 §3.8.1) and store only `f0` from their upkeep rules.
   - Categories shared by several types: `perCapita` of the category comes from the lowest-tier type selling in it (ties: catalog order), every type still gets its own capacity and costs. Calibration runs once in genesis and is never re-run (later crowding and macro move profits).
4. `referenceWeight0(seg, density)`: reference player u = `a_s × ln(0.96)` (quality index 1, condition 100, fully staffed, skillAvg 3 so staffFactor = 0.96, marketing 0, price = ref, location 0, brand 0, reliability 0.9 → 0, promise PRICE gives no bonus at ref price); NPC field u = `b_s × ln(2) + r_s × 0.02` (quality 1, marketing M_ref, reliability 0.92). `weight0 = density × exp(u_p − u_npc)`, so at genesis the field share against `density` reference businesses is exactly 0.5.
5. `genesisCatalog`: for each type in content order: `calibrateType`, put `biz.calib`. For every city and every type's allowed segments create the market rows of its scope (district markets for DISTRICT-scope types per district of each city; city, bloc and WORLD markets once): `npcField = { weight: weight0, weight0, price: refPrice (indexed at read time), quality: 1 }`, `participants: []`, `shares: { NPC: 1 }`, `hourOffset = marketHourOffset(id)`, `demandDay = 0` (filled at the first t = 0), `hhi = 1`. Market creation for cities that open later (10) happens lazily: `ensureMarket(ctx, id)` (exported from genesis.ts as a helper) builds the same row on first access.
6. Content counts: `catalog_size_target` (150) is a 22 completeness target; R39 makes 22 authoritative for counts and names: genesis asserts `types.length === content count` (no hard-coded 150) and emits nothing else.
