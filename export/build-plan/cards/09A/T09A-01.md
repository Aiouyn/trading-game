## Goal
Create the data contract of the business layer (unit 09A, module 09): every entity type of 09 §2.1 to §2.4 as TypeScript types and Store tables, the id helpers, the stable reject codes, the map from 09's money names (09 §3.17) to 03's canonical reason codes (24 §8) plus the 09-only codes registered through 03's extension point, the RNG stream keys, the port interfaces through which 09 reads modules it may not import (G6.1), and the zod schemas of every 09A event kind. Every later 09A and 09B task imports from here.

## Implementation steps
1. `schema.ts`: transcribe 09 §2.1 to §2.4 exactly (names, unions, optional marks), then add the (+) fields listed in Exports. Money fields stay `Money` (bigint); rates and indices `number`. `inventory: Record<string, bigint>` is kept as declared but holds integer units scaled by 1,000 (milli-units) because inputs are fractional per unit (`qtyPerUnit` is a number); helper `toInv(x: number): bigint = BigInt(roundHalfEven(x * 1000))` and `fromInv`. `Promise` is exported as `BizPromise` to avoid shadowing the global name (determinism lint forbids Promise usage).
2. `tables.ts`: one `TableDef` per row type, `module: '09'` (09A and 09B share the module), names as `BIZ_T`, indexes as listed. 09B adds its own tables in its schema task.
3. `codes.ts`: `npcRevenueCode`: HOUSEHOLD → `BIZ_SALES_HH` sector hh; TOURISM → `BIZ_SALES_ROW` sector row; BUSINESS_DERIVED, PLAYER_SERVICES (NPC share), COMMODITY_MARKET, FLOW_TAKE, TENDER_FRM → `BIZ_SALES_FRM` sector frm (all ELASTIC_IN); TENDER_GOV → `BIZ_SALES_GOV` template PAY from the issuing `gov` entity. 24 §8 maps `BIZ_REVENUE_NPC` "by customer sector": this table is that mapping. Draw-count rule: each named use documents its exact draws in its task; no rejection sampling.
