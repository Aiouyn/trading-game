## Goal
Provide the framework every balance band, finding and release gate of 20B is built on: the `BalanceBand`/`BandResult`/`Finding`/`GateRun`/`PlaytestSession` types (20 §2.6–§2.7), a band evaluator (aggregation over seeds, bootstrap 95% interval, undefined-metric handling of 20 §8 edge case 7), the band-class response table of Rule 3.7.1, evidence grouping that never merges categories (Rule 3.4.1), and gate verdict and waiver rules (Rule 3.9.1, 3.9.2). The concrete band list, metrics and gate contents are filled in by 20B; this task must not need the engine.

## Imports
- T20A-03: `SeedRef`, `aggregateOnlyReport`.
- T20A-04: `EvidenceCategory`, `TestRecord`, `HarnessRun`.

## Implementation steps
1. `aggregate`: MEDIAN of sorted copy (even n: mean of the two middle), MEAN, SHARE (mean of values coerced to 0/1; values must be 0 or 1), MAX, MIN, COUNT (sum), P95/P99 nearest-rank (`ceil(p·n)`-th smallest). Sorting with an explicit numeric comparator.
2. `evaluateBand` (Rule 3.7.1 + 20 §8 edge cases 7 and 8):
   - `!o.isActive(b.activeWhen)` -> status 'INACTIVE', pass false (never shown as PASS for an unbuilt system).
   - defined = values with a number. If defined.length < 0.8 × values.length: call `requestMoreSeeds` repeatedly (in chunks of `b.seeds`) until ≥ 80% defined or total = 3 × b.seeds; still short -> 'INSUFFICIENT_DATA', pass = false only for ACCOUNTING bands (for other classes pass = true at G3 is NOT allowed either; per edge case 7 it "counts as fail at G3 only for ACCOUNTING bands", so set pass = (b.class !== 'ACCOUNTING')).
   - value = aggregate(defined); pass = (lower === undefined || value ≥ lower) && (upper === undefined || value ≤ upper) (inclusive).
   - ci95 by 1,000 bootstrap resamples with the injected rng (harness stream `tm:bootstrap`, never world RNG).
   - worstSeeds: up to 5 seeds farthest outside the band (ties by seed index) for regression capture; [] when passing.
3. `CLASS_RESPONSE` from the Rule 3.7.1 table verbatim.
4. `requestWaiver` (Rule 3.9.2): refuse when the check's `kind` is INVARIANT_FATAL (WAIVER_FATAL_INVARIANT), EQUIVALENCE, STATIC, or `bandClass === 'ACCOUNTING'` (WAIVER_ACCOUNTING); gate not G3/G4 -> WAIVER_WRONG_GATE; signers must include one with role TM_LEAD and one with role `OWNER:<check.module>` and be two distinct staff (WAIVER_SIGNERS); decisionRef must match /^(D\d{3}|R\d{2}|Y\d)$/ (WAIVER_NO_DECISION). Error message must name the rule: "ACCOUNTING checks can never be waived (20 Rule 3.9.2)".
5. `gateVerdict`: PASS iff every required check is PASS or is FAIL with an accepted waiver; SKIPPED required checks fail the gate.
6. `reportByEvidence`: groups records via `groupEvidence`; every acceptance-test record whose module is in its `unimplementedDependencies` is listed in `uncertified` and its result does not count as passed (Rule 3.4.1, B07).
