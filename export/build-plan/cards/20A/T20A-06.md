## Goal
Implement the three STATIC invariants owned by 20 as CI checkers that run at G0 (Rule 3.9.1: "INV-STR-001..010" in every pull request): INV-STR-006 function-input whitelists (13's verdict, fine and fee functions have no parameter of type Reputation or Prestige; 12's breach and detection functions have no parameter of type Prestige), INV-STR-008 every player-facing string key exists in both `en` and `fr` (100% French at G4), INV-STR-009 no content string in 22 or the i18n catalogues matches the real-brand block list (L6). Each checker reports `GateCheck` records with kind 'STATIC' (never waivable, T20A-05) and registers its STATIC catalogue id. Subjects that do not exist yet (unit 12/13 not built) are reported as `SKIPPED` with detail "subject not built" and never as PASS (band rule "a band for an unbuilt system is never shown as PASS" applied to checks).

## Implementation steps
1. INV-STR-006: parse each rule's file with `ts.createProgram` + type checker. For each listed function (exported function declaration or exported const arrow), inspect every parameter's declared type AND the resolved type tree (object properties, union members, array element types, type aliases, interfaces, recursively to depth 6): if any named type or property type name equals a forbidden type name, or a property is named `reputation`/`prestige` (case-insensitive), it is a violation. Missing file -> SKIPPED "subject not built"; file present but function missing -> FAIL (the whitelist must cover a renamed function). Also check the runtime half of INV-LAW-004 is NOT here (13 owns it).
2. INV-STR-008: read every JSON (or TS object) catalogue under `packages/i18n/en` and `packages/i18n/fr` (flatten nested keys with '.'). Collect used keys from source files under apps/** and packages/** (excluding tests) by AST: string literal first argument of calls named `t`, `useT`, `i18n`, JSX attribute `k`/`i18nKey`, plus `err.<code>` for each reject code literal matching /^[A-Z]{2,5}_[A-Z0-9_]+$/ used in a `{ code: '...' }` object literal. A key used but missing in en -> FAIL; missing in fr -> FAIL at G4 (100% coverage), at G0 FAIL as well when the key exists in en and fr is missing (L8 says keys from day one; the fr value may be a copy marked `"@todo-fr"` which counts as present at G0 and as missing at G4). Report `frCoverage = frPresent / enKeys`.
3. INV-STR-009: load the list from `process.env[BLOCKLIST_ENV]`; when absent in CI -> FAIL "block list not provided" (the check must not silently pass); locally absent -> SKIPPED. Scan every string value in `packages/content/**/*.{json,ts}` data files and both i18n catalogues: tokenize on /[^\p{L}\p{N}]+/u, compare lowercase tokens and also adjacent token bigrams/trigrams joined by a space against the list entries (entries may contain spaces); entries in `allow` never hit. Hit -> FAIL with file and JSON path. Never print the block-list content itself in logs beyond the matched token.
4. Each checker returns one GateCheck per subject (`checkId` = 'INV-STR-006:13-verdict', 'INV-STR-008:en', 'INV-STR-008:fr', 'INV-STR-009'), category 'E1_UNIT', kind 'STATIC', required true.
5. `runStatic` also registers the three STATIC defs (from the catalogue) in an `InvariantRegistry` so 20#1 (T20B-01) can see them registered.
