## Goal
Implement, as pure engine-independent algorithms, the decision logic of the FATAL failure ladder (20 Rule 3.2.2 as adopted by 24 D417: rollback, safe mode, bisection, quarantine, halt): the bisection of Rule 3.2.3 over an abstract trial function, the repeat-quarantine tracker of Rule 3.2.4, the ladder state machine that combines 02 §3.15.3's attributed safe-mode attempts with 20's bisection, and the fast-check presets of Rule 3.4.3 that every module's property tests use. Unit 02 wires these to the real pipeline (T02-16).

## Implementation steps
1. `bisectCulprits` follows Rule 3.2.3 literally:
   ```
   candidates = intents; trials = 0; start = now()
   while candidates.length > 1 && trials < maxTrials:
     if now() - start > budgetMs -> return {culprits: [], reason: 'BUDGET'}
     half = candidates.slice(0, ceil(len/2))
     trials++; if passes(half)            -> candidates = half; continue          // removing `half` passes: culprit inside half
     trials++; if passes(candidates minus half) -> candidates = rest; continue
     break  // interaction
   trials++; culprits = passes(candidates) ? candidates : []
   ```
   Note: `passes(x)` means "the tick passes when x is excluded". Reason: 1 culprit -> 'ISOLATED'; >1 culprits after a break that still pass when removed together -> 'PAIR_OR_GROUP' (20 §8 edge case 3: both quarantined); final check failing -> 'NO_CULPRIT'; loop exit by trial cap with >1 candidates -> 'MAX_TRIALS' (still apply the final check). Empty `intents` -> `{culprits: [], trials: 0, reason: 'NO_CULPRIT'}` (zero player intents: system defect, Rule 3.2.2 step 6).
   For 500 intents and a single culprit the loop uses ceil(log2 500) = 9 halvings; with the "first half passes" branch taken when the culprit is in the first half, the worst case is 2 trials per level. Document the trial count in the test (20 AT 4 requires ≤ 10 trials; that test lives in T02-16 and uses this function, so the cheap path must be: test `passes(half)` first, and when it fails, infer the culprit is in the rest WITHOUT a second trial unless an interaction is suspected). Implement the inference: if `passes(half)` is false, run `passes(rest)` only when `candidates.length <= 2` or the previous level ended in an inference; otherwise set `candidates = rest` directly and verify at the end with the final check. This keeps a single culprit among 500 at ≤ 9 + 1 = 10 trials. If the final check fails after inferences, restart once in strict mode (both trials per level) within the remaining budget; strict-mode failure -> 'INTERACTION'.
2. `QuarantineTracker`: keep records sorted by (actorId, kind, tick) using code-unit comparison; `record` drops records older than `tick - windowTicks` for that pair first; a remaining older record -> add `actorId|kind` to blocked and return 'BLOCK_KIND'. Default window: `tm_quarantine_repeat_window_ticks` = 17,280.
3. `decideLadder` (combined ladder, D417; 02 §3.15.3 attempts with 20 Rule 3.2.2 branches):
   1. attempt 1: `runSafe([])` (same inputs, posting-level validation on). ok -> COMMIT_SAFE with `recoveredWithoutQuarantine = true` (the caller files a HIGH determinism case, Rule 3.2.2 step 3).
   2. loop attempt = 1..maxAttempts: take `firstFailing` from the last run:
      - INTENT -> add to quarantine list;
      - NONE (failure not attributable to a single item, e.g. an aggregate invariant) -> run `bisectCulprits(intents minus already quarantined, passesWithout)`; culprits -> add each as INTENT; none -> HALT 'NO_CULPRIT' (Rule 3.2.2 step 6);
      - ENTITY -> add (entity frozen this tick);
      - SUBSYSTEM -> if `subsystemStreak(id) + 1 >= subsystemHaltAt` -> HALT 'SUBSYSTEM_REPEAT' (02 §3.15.3, PARAM `safe_mode_subsystem_repeat_halt` = 5) else add;
      - a SYSTEM input attribution (id starting with 'sys:' or 'adm:') -> HALT 'SYSTEM_INPUT' (20 §8 edge case 4, never quarantined).
      Re-run `runSafe(quarantine)`; ok -> COMMIT_SAFE. 
   3. attempts exhausted -> HALT 'ATTEMPTS_EXHAUSTED'.
   The quarantine list is in canonical order of addition (it is written into the hashed header by 02).
4. `property-presets.ts`: `fcParams` returns `{numRuns: propertyRuns(), endOnFailure: true, verbose: 1}` plus `seed` when given (regression replay). `onPropertyFailure` builds a `ShrunkCase` (no I/O). Reading `process.env` is allowed only because this file is test-only; add a header comment and an eslint-disable for the determinism rule limited to this file, and add the file to the engine bundle's exclude list in `packages/engine/core/package.json` "files" (test helpers are not shipped).
