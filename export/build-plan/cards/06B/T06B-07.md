## Goal
The 11 perpetual swaps of 06 §3.15 (AUC, LTX, MRD, SYN, FRO, TDP, QLL, ARC, KST, GRD, ORE; CCP_CRY): the index price recomputed every tick as the median of three references, the per-tick premium, funding every 240 ticks (t = 0, 240, 480) with the double-clamped rate (never beyond ±0.1% per 8 game hours), funding payments transferred between position holders through the CCP_CRY service so that they sum to exactly zero (`DRV_PERP_FUNDING`), the mark price `index·(1 + EMA60(premium))` used for liquidations and unrealized P&L (never the last print, X2), the open-interest cap and the per-owner OI share, the leverage caps by license (LIC3 10×, LIC4 20×; IM/MM are 07B's), and the stale-index rule of edge 11.

## Implementation steps
1. Index price each tick (P6, after 05 matched): CEX batch clearing price = this tick's 05 clearing price of the underlying's CEX line (no trade this tick → last clearing price); CEX 30-tick TWAP of clearing prices over the last 30 ticks; Quill oracle via the 06C extension. Median of the three. With 06C absent the oracle input is the CEX TWAP (decision: the median then equals the TWAP; documented in `_unit.md`). ORE uses the gold spot hub line (COMMODITY) as "CEX". `stale = true` when the CEX line is HALTED or has had no clearing price for > 60 ticks (05 `tradingStateOf`).
2. Premium: `(perpMid − index)/index` with `perpMid = exp(lnB)` of the perp book (05 NPC mid, which exists every tick); `premiumSum += premium`, `premiumCount += 1`; `emaPremium = emaUpdate(emaPremium, premium, 60)`; `markPrice = index·(1 + emaPremium)`. Stale (edge 11): no accumulation, mark frozen at last index × (1 + EMA) (stored).
3. Funding at each funding tick (`fundingIntervalTicks = 240`; t = 0, 240, 480 of every day — perps trade 24/7): `P̄ = premiumSum/premiumCount` (0 if count 0); `rate = clamp(P̄ + clamp(0.0001 − P̄, −0.0005, 0.0005), −0.001, 0.001)`; if any tick of the interval was stale: `rate = 0.0001` (interest only, edge 11). Payments: for each long `pay_i = toMoney(qty_i · mult · mark · rate)` (half-even), longs pay when rate > 0, shorts pay when rate < 0; the receiving side gets `allocate(Σpay, weights = |qty_j|)` so totals match exactly (largest-remainder by holderId, GLOBAL-CONTEXT `allocate`). Postings: payer → `ccp_CRY` and `ccp_CRY` → receiver, `DRV_PERP_FUNDING` (TRANSFER; the CCP nets to zero). Emit `mkt.perp.funding` PUBLIC `{scope: 'RATE', perpId, rate, mark}` and PARTIES `{scope: 'PAYMENT', perpId, amount}` per holder. Reset accumulators.
4. Gates (P1, PERP branch of the preTradeGate extension): license (LIC3, `tradeGate` act BUY/SHORT), leverage ≤ `maxLeverageFor(base = {LIC3: 10, LIC4: 20}[license])` (S3+ cases halve; rookie cap); OI cap: new opening orders that would make total OI exceed `PARAM.perp_oi_cap_frac_of_spot_mcap` (0.25) × free-float market cap of the underlying ÷ mark are rejected (`AST_OI_CAP`); per-owner share `checkPerpOwnerShare` (`perp_max_oi_share`). Restricted cash cannot fund perps (T06A-02).
5. Marks for 07B: `perpMarkPrice` is exposed via 05's `settlementPriceOf`/the mark API (T06A-02 `markPrice` reads `ast.drv_perp_state.mark` for PERP); liquidations and unrealized P&L use it (X2).
