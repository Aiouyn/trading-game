## Goal
Every change of the traded log price is decomposed into tagged causes whose sum equals the move exactly, accumulated per game hour and per day, so the trade journal, the "Why it moved" ladder, the Research Desk and 16's market-wrap stories can never contradict the tape (L13). The gap tracer attributes gap-closing moves back to the value sources that opened the gap; player flow is shown only with k-anonymity; each news item gets a priced-in band.

## Implementation steps
1. Exact decomposition (05 §3.12.1): `ΔlnP = ΔlnB + ΔΠ + ΔT + Δb + Δskew + Δε` with `ε = lnP − lnRef`. Tag every component change per the table of 05 §3.12.1: valuePrint × S per factor (GX → MARKET; EQ_bloc, FX_* → REGION; SEC_* → SECTOR; RATES_*, CREDIT, CMD_*, GOLD, CRYPTO, AI_RACE → MACRO) and idio → COMPANY_NOISE; valuePrint × A and × D → FUNDAMENTAL; newsPrint × X by `sourceKind` (NEWS with newsId, MACRO with macro ref, FUNDAMENTAL, EVENT with 04 event id); newsPrint × J → COMPANY_NOISE; gap-closing moves (VALUE pool impact, guard, opening print) split by the gap tracer; other pools → `FLOW_<pool>` (RATES_RV → FLOW_ARB; CB, TSY → FLOW_POLICY; MANDATE → FLOW_MANDATE; LIQUIDATION → FLOW_LIQUIDATION); player, AI and operator orders (net) → FLOW_PLAYERS; skew, ε and layoff side effects → MAKER; Δb → BELIEF.
2. Impact split: tick impact `ΔΠ + newly added T` is split by `share_c = q_c / q_N` over participant classes' signed net taker quantities (`makerNetFillByClass`). If `|q_N| < 0.05 Σ_c |q_c|`, tag the whole tick impact MAKER. Transient impact is tracked per class in `gapTracer["T:<class>"]`; each tick's decay `(ρ − 1) T` is credited back to the classes pro rata to their `T:<class>` balances with opposite sign (a fading whale spike leaves only its permanent part in FLOW_PLAYERS).
3. Gap tracer (05 §3.12.2): `G = lnRef − lnV` is a vector over sources. Each value move Δ from source s adds `−(1 − printShare) × Δ` to `g_s`; each non-value flow move adds its amount to its class; a gap-closing move `m` (sign opposite to G) is attributed `m_s = m × g_s⁺ / Σ g⁺` over components sharing G's sign, and `g_s += m_s`. Belief hand-off (05 §6.3, test 49): at a TRUE resolution move the claim's `BELIEF:<claimId>` gap balance into the fact's source `NEWS:<newsId>` so later closing moves are tagged NEWS, and the BELIEF release itself is tagged against the same source (no double count).
4. Floating point: compute all tagged terms with `dmath.kahanSum`, then set `OTHER = dLnP − Σ terms` (05 §3.12.1 puts any residual there). Keep a diagnostics counter of ticks whose residual exceeds 1e−12; tests assert the counter stays 0.
5. Storage (05 §3.12.3): per asset per game hour (24 per day; kept 28 game days) and per day (kept for the current chapter plus 364 days). `CauseVector.newsItems` = per newsId contributions; `macroRefs` per macro ref; `eventId` the active 04 world event; `playerOwnerGroups` = distinct player owner groups with fills in the period. `explainMove(assetId, fromDay, toDay)` sums daily vectors term by term (logs add exactly), clamped to closed days (17 "No future": toDay ≤ currentDay − 1 or the last closed day).
6. k-anonymity (05 §3.12.4): FLOW_PLAYERS appears as its own line only when `playerOwnerGroups ≥ PARAM.mkt_kanon_k`; otherwise all FLOW_* terms merge into one "Order flow" line (`SPEC_CONSTANTS.kanonMergeLabel`). A player's own signed share (`ownContribution`) is shown only to that player. No line names a player.
7. Priced-in bands (05 §3.12.5): `pricedIn = clamp(Σ terms attributed to newsId / X, 0, 1.2)`; Early < 25%, Mid 25–75%, Late 75–95%, Done ≥ 95% or 5 trading days after publish. Fill 16's `impactHint` display through the `mkt.newsBands` view (T05-20).
8. 16 hook: on `closeDay`, if |totalLogMove| > 2σ_d include `top3: [{key, value}]` (largest |terms|) in the `mkt.cause.daily` payload for 16's market-wrap stories.
