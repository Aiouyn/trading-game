## Goal
Publish only aggregate public data (L11): depth by price level including the maker's ladder (never per order, never hidden reserve, never stops), one tape print per tick at p*, tickers, daily statistics, the rounded fair-value line hourly, indicative auctions and trading states. Provide (a) the typed engine read API that 06, 07, 08, 11 and others import (`api.ts`, named after 05's entities and rules), and (b) every view the screens of 05 §7 need (`views.ts`).

## Implementation steps
1. Channels (05 §3.11, 17 §2.6) published in P14 with `ctx.delta`:
   - `book:{assetId}`: top 10 aggregated price levels per side from resting displayed quantity of all participants plus the maker ladder (`makerDepthLevels`), the last `AuctionResult`, and the indicative auction in auction windows. Never per order, never hidden reserve, never stops, never algo parents, never pool identity. Viewers need the asset's license; full 10 levels need the Terminal tier (`ports.world.subscriptionTier`), others see 3 (D085). Delta recipient `pub:book:<assetId>`; the gateway (19) applies the tier filter using the same view.
   - `tape:{assetId}`: one `TapePrint` per tick aggregating all fills at p* with the total quantity plus background volume, aggressor side, `block` and `deferred` flags (block prints from T05-18). Validate every print with `zTapePrint.parse` before emitting (strict schema: no account, owner, order or counterparty identifiers).
   - `ticker:{listId}`: last, change, volume, trading state (lists from 17/22 watchlists; 05 publishes per asset and the projector groups).
   - Daily statistics at the daily close: OHLC, volume, VWAP, model ADV, rv21 (21-day realized vol of official closes, annualized with √Dy), short interest (aggregate, daily, `mkt.shortInterest.daily`), trades count, official close → `mkt.daily.close` PUBLIC and a `DailyBar` row (kept 500 days).
   - Value layer: "Fair value (consensus)" lnV rounded to 0.1%, updated each game hour, Research tier only (exploit #9).
1b. Events emitted by `publishTick`: `mkt.auction.result` (PUBLIC, `AuctionResult`, every tick with a clearing) and `mkt.indicative` (PUBLIC, `{assetId, tick, price, imbalance}`, every tick inside an auction or reopen window).
2. No account identity, owner group, order id or counterparty is ever published; 15 publishes ownership filings from `mkt.ownership.thresholdCrossed` (05 emits; it publishes nothing per holder). L11 holds.
3. `api.ts` functions are the stable engine contract for downstream modules (06 marks and settlement, 07 margin and haircuts, 08 NAV strikes and basket costs, 11 strategy inputs through views, 03 thin-print guard). They read committed state only.
4. Views (05 §7): each `ViewHandler` has a zod args schema; private views filter by `viewer` (only the viewer's own orders, fills, algos; `ownContribution` only for the viewer's owner group). `mkt.explainMove` applies k-anonymity and clamps to closed periods. `mkt.surveillanceScore` returns `null` unless the viewer context is a system/regulator context (13, 12), never to players. Phase banner keys: `mkt.banner.queuedForOpen` ("Queued for the opening auction at 08:00"), `mkt.banner.halted` ("Trading paused · reopens at hh:mm" with the reopen indicative) as i18n keys (L8: no raw text).
5. Fees view note for screens: tier shown from `OwnerGroupStats.feeTier`; no Stabilizer fee multiplier (R04).
