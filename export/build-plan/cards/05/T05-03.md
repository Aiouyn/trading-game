## Goal
Implement the value layer `lnV` of 05 §3.3: what a well-informed consensus thinks each asset is worth, stepped every active tick from 06's anchor, orthogonal macro and sector factors, Student-t idiosyncratic noise, Kou jumps and delivered value shocks, with GARCH clustering, regime multipliers blended over 5 trading days, crisis correlation and the world hooks 04 calls on 05. The output per tick is not only the new `lnV` but the **decomposed increments** (A, D, S per factor and idio, J, X per shock) that T05-04 prints into the maker base and T05-16 tags in the cause vector.

## Implementation steps
1. Per active tick (05 §3.3.1), for each asset whose `isValueActiveTick` is true, in ascending `assetId`:
   - `σ_ann,eff = sigmaV × PARAM.mkt_lnv_vol_scale × √h × m_reg × m_event × m_hype`; `m_hype = 1 + 2H` for CRYPTO_ALT, CRYPTO_MAJOR and MEME using `ports.instruments.hype`, else 1. `m_reg` is the blended regime vol multiplier (step 5). `m_event` from `eventMultipliers` (product of active VOL_SHOCK multipliers decaying with their half-life: `1 + (mult − 1) × 2^(−elapsedDays/halfLifeDays)`).
   - `A = −k (lnV − lnF)`, `k = anchorK(anchorHalfLifeDays)`; FX legs use `PARAM.mkt_fx_anchor_hl_days` and `lnF = getFxState(store, ccy).fairValueLn`; government bonds use 06's anchor with its 2-day half-life (06 §3.21 via `priceParams`).
   - `D = −½ σ_ann,eff² / A_year` where `A_year = activeTicksPerYear`.
   - `S = σ_ann,eff √(1/A_year) (Σ_k L'_k z_k + √(1 − Σ L'²) ε)`; `z_k` drawn once per tick per factor (shared by every asset) by `drawFactorShocks` from `mkt.factor:<factorId>` in sorted factor order, done once in P3 before the asset loop; `ε = studentT(ν) × √((ν−2)/ν)` from `mkt.idio:<assetId>` (exactly one draw per active tick). Keep each factor's contribution separately in `Sfactor` and the idio part in `Sidio`.
   - `J`: one `kouJump` call per active tick from `mkt.jump:<assetId>` with occurrence probability `λ_eff/A_year`, `λ_eff = jumpsPerYear × regime jump mult × hook jumpMult`, `pUp_eff = clamp(jumpUpProb − regime skew, 0, 1)` (skew is the down-probability shift). Draw count is fixed whether or not a jump occurs (G8).
   - `X`: Σ delivered value shocks targeting this asset with `uncertainty == 0`, plus factor jumps mapped by `factorJumpToAsset` (05 §3.3.3 "Factor jumps"; `σ_ref,k` is the realized annual vol of the factor's reference index kept in `FactorState.refSigma`, initialised from content and updated by T05-19's index EWMA). Shocks with `uncertainty > 0` are returned in `beliefShocks` and never touch `lnV` (05 §3.3.4).
   - On non-active ticks (weekends for session classes) still apply `X` (05 §3.3.4, edge 5) but no A, D, S, J.
   - ETFs: no own process; `lnV = etfValueLn(...)` each tick from constituents' `lnV` (ports.instruments.etfINavLn). Options and other derivatives: no value process (skip; 06 marks them).
   - Store `lnV`, `lnF`; add X to `aux.shocksToday`, track `aux.maxShockToday = max |X|`.
2. Shock collection: `collectValueShocks` merges 04 `macroValueShocks`, `ports.instruments.valueShocks`, `ports.companies.valueShocks`, `ports.ai.valueShocks`, `ports.conflict.valueShocks`, `ports.world.valueShocks` whose `publishTick == tick`; a shock whose target is a factor id becomes a `FactorJump`. 06 moves `lnF` by the same amount on a discrete fundamental change (05 §3.3.1 last bullet), so do not add A for that move: the anchor pull uses the post-shock `lnF` and the post-shock `lnV`. Record each applied shock in `mkt.shock` (`ValueShockRecord`, band 'EARLY', attributed 0) for T05-16's priced-in bands.
3. Crisis correlation (05 §3.3.3): `c = PARAM.mkt_crisis_corr_storm` or `PARAM.mkt_crisis_corr_major` when an active 04 `WorldEvent` of tier STORM or MAJOR is in phase TRIGGER or CONTAGION and affects the asset (its bloc in `blocs`, or its sector in `sectors`, or the asset in `assetsHint`; a WORLD event with empty blocs affects all), plus the regime's `c_reg`. `L'_GX = √(L_GX² + (c + c_reg)(1 − Σ L²))`; other loadings unchanged; if Σ L'² > 1 cap at 1 by rescaling `L'_GX` so Σ = 1 and idio share 0 (05 §8 edge 19).
4. GARCH (05 §3.3.2), at t = 719 of a trading day in P8: `r_d = (lnV_close − aux.vPrevCloseLn) − aux.shocksToday`; `h_new = ω + α r_d²/σ_d,base² + β h`, `ω = 1 − α − β`, `σ_d,base = sigmaV × 1.15 × m_reg / √Dy` (1.15 = `PARAM.mkt_lnv_vol_scale`); if `aux.maxShockToday > 3 σ_d` add `0.5 (|X|/σ_d,base)² α` using the largest shock; clamp to [`mkt_garch_h_min`, `mkt_garch_h_max`]. Stablecoins α 0.02, β 0.95. Then `vPrevCloseLn = lnV`, reset `shocksToday`, `maxShockToday`. Crypto runs it at t=719 every day.
5. Regimes (05 §3.3.5): `assetRegime` = home bloc regime (bloc = asset `ccy`), global regime for crypto, gold, commodity classes. When the regime differs from `aux.regimeBlend.to`, set `from = current blended state's regime`, `to = new`, `startTick = tick`; multipliers move linearly over 5 trading days (5 × 720 trading-day ticks; weekend ticks do not advance the blend). The Fear Index never multiplies value volatility (D075).
6. Hooks (05 §6.4, 04 §3.16.6): `ingestHookCalls` in P2 turns each 04 hook call into an `ActiveHook` row (`hookId = ctx.newId('hk')`, `startTick = tick + 1` because hooks apply from the next tick, `untilTick` from ticks or days × 720). `eventMultipliers` multiplies all active matching hooks: MAKER_WITHDRAWAL → `depthEvent` (used by T05-04), NPC_SELL_PROGRAM → `sellProgramAdvPerTick` (used by T05-14), VOL_SHOCK → `mEvent`, JUMP_INTENSITY_SHOCK → `jumpMult`. Expired rows are deleted in P2. `eventIds` carry the WorldEvent ids for EVENT cause tags.
7. Edge case 15/19 and weekend shocks handled as above. All math through `dmath`; no `Math.exp/log/pow`.

## Test plan
- `garch.test.ts`:
  - Worked: hOld 1, r_d 0.03, σ_d,base 0.02, no big shock, α 0.08, β 0.90 → ω 0.02, h = 0.02 + 0.08 × 2.25 + 0.90 = 1.10. Second: hOld 2.0, r_d 0, → 0.02 + 1.80 = 1.82. Big news: hOld 1, r_d 0, maxShock 0.10 with σ_d 0.02 (> 3σ_d): h = 0.92 + 0.5 × 25 × 0.08 = 1.92.
  - **05#14 GARCH h stays within [0.25, 9] and its mean over 10,000 days is 1 ± 0.05**: simulate 10,000 days with `r_d = √h σ_base × z` (z from a seeded test Rng), assert every h in [0.25, 9] and mean(h) ∈ [0.95, 1.05]; also a fast-check property: for any finite r_d and h in range, `garchUpdate` output is in range.
- `factors.test.ts`:
  - **05#15 factor-model covariance positive definite for the 400 launch assets**: build `MarketSpec`s from the full 22 content (`content: 'full'`), `covarianceMatrix`, assert `isPositiveDefinite` and that every spec passes `validateLoadings`.
  - **05#16 crisis correlation: average pairwise equity correlation rises by ≥ 0.2 during a MAJOR's CONTAGION phase**: take the bloc's equities, compute average pairwise correlation from loadings in calm EXPANSION (c=0, c_reg 0) and with c = 0.5 (MAJOR) + c_reg of CONTRACTION 0.15; assert rise ≥ 0.2. Also simulate 2,000 ticks of `stepValue` both ways with fixed seeds and check the sample correlation of daily returns rises ≥ 0.2.
  - Worked crisis loading: L_GX 0.4, L_EQ 0.3, L_SEC 0.3 (Σ L² 0.34), c 0.3 → L'_GX = √(0.16 + 0.3 × 0.66) = √0.358 = 0.598331; idio share = 1 − 0.538 = 0.462. Cap case: Σ L² 0.9, c 0.5 + c_reg 0.15 → L'_GX² = L_GX² + 0.065, sum 0.965 (< 1, no cap); with c+c_reg 1.5 → capped, idio 0.
  - Factor jump: L_GX 1.0 relative, σ_ann,asset 0.30, σ_ref 0.20, J −0.03 → X = −0.045 (the 1.5-beta example of 05 §3.3.3).
- `value.test.ts`:
  - `anchorK(20)` = 4.81341e−5; `anchorK(2)` = 4.81236e−4.
  - Convexity: sigmaV 0.25, h 1, m_reg 1, session → σ_ann,eff 0.2875, D = −2.20770e−7 per tick.
  - Draw discipline: two assets, one with 5 shocks and one with none: the second asset's lnV path is identical to a run without the first asset (streams per asset).
  - Uncertain shock (uncertainty 0.4) leaves lnV unchanged and appears in `beliefShocks`.
  - Weekend: EXCHANGE_SESSION Saturday tick with a 0.05 shock: lnV += 0.05 exactly, no diffusion draws consumed (stream state unchanged).
  - Regime blend: switch EXPANSION→CONTRACTION, vol mult after 2.5 trading days = 0.90 + 0.5 × 0.55 = 1.175.
  - Hooks: VOL_SHOCK mult 2, half-life 1 day, after 1 day mEvent = 1.5; MAKER_WITHDRAWAL 0.2 for 30 ticks applies from tick+1 and expires at tick+31.
  - Martingale property (fast-check, 200 seeds × 2,000 ticks with lnF = lnV0 and k tiny): mean of exp(lnV − lnV0) within 1 ± 3 standard errors.
