## Goal
Price every fill's exchange fee (taker, maker, auction, per-contract, minimums, volume tiers on the owner group's 30-day FDL notional), charge the message fee above an order-to-trade ratio of 100, post the Stabilizer's L3 transaction levy once per day, report securities-tax notional to 03, and turn fills into the exact 03 postings at P7 (queued, committed at P13), including the NPC side for maker, pool, CB and treasury fills and the hold release.

## Implementation steps
1. Fee table (05 §3.15.1) via `PARAM.mkt_fee_<class>_<taker|maker|auction|min|per_contract>`; read each with `ctx.params.num/money`. If a key is missing from 23, use the 05 §3.15.1 table value and list the key under Registry gaps (T05-23's `_unit` note); the expected keys are `mkt_fee_eq_taker` 0.0003, `mkt_fee_eq_maker` 0.0001, `mkt_fee_eq_auction` 0.0001, `mkt_fee_eq_min` $0.10, `mkt_fee_bond_*` 0.00005 / min $0.10, `mkt_fee_fx_*` 0.00003 / $0.10, `mkt_fee_crypto_taker` 0.0010, `mkt_fee_crypto_maker` 0.0005, min $0.01, `mkt_fee_fut_taker` $0.50 per contract, maker/auction $0.30, `mkt_fee_opt_taker` $0.40, maker/auction $0.25, `mkt_fee_commodity_*` 0.0002/0.0001/0.0001, min $0.10.
2. Liquidity: an order that rested through at least one prior tick's auction is MAKER; entered this tick TAKER; OPEN, CLOSE (fix, settlement), REOPEN and VOL_INTERRUPTION reopen fills are AUCTION. `postOnly` orders are always billed the maker rate (05 §3.6.3).
3. Tiers on the owner group's 30-day exchange notional in FDL (rolling 30 game days, real fills only; wash-flagged linked-group fills (F3 episodes of T05-17) are excluded, exploit #2). The tier multiplier applies to percentage and per-contract fees; the ≥ $1B tier sets `highVolume = true`. Per ruling R04 (24 > 05 text, and the 05 §10 test 39 wording "L4 applies only to the ≥ $1B tier" is superseded): no Stabilizer multiplier ever touches the fee schedule; high-volume trading is affected only by 03's L3 levy (step 6).
4. Fee money: `fee = max(minFee, rate × notional × tierMult)` with `toMoney`; for FUT/OPT `perContract × contracts × tierMult` (no minimum). Registered MM quote fills: `PARAM.mkt_mm_rebate` (−0.5 bp, a rebate) posted `MKT_MAKER_REBATE` from `exc_<bloc>` to the MM (T05-18 sets `isRegisteredMmQuote`).
5. Message fee (05 §3.15.1): messages = order entries, modifications, cancels of an actor in a game day; trades = fills. When messages/max(1, trades) > `PARAM.mkt_otr_threshold`, each further message that day costs `PARAM.mkt_message_fee`, posted `MKT_EXCHANGE_FEE` with `sub: 'MESSAGES'`. `mkt.mm.quote` counts one message per quote update and is exempt up to `SPEC_CONSTANTS.mmMessageExempt` (2,000) per day. The fee is charged at P7 of the tick of the message (the message is not rejected).
6. Levy (05 §3.15.3, 03 §3.7.4, R04): at t = 0 read `tradingLevers(store)` (levy 0 if absent); at P8 t=719 post per consolidated group: `levy = levyBp × 1e−4 × max(0, todayNotionalFdl − levyFreeDailyNotional)` as `MKT_TRANSACTION_LEVY` (SINK, `ctx.ledger.burn`) from the group's root entity in FDL.
7. Settlement (05 §3.13), at P7 for every fill, T+0 (commit at P13):
   - Player-economy vs player-economy: `ctx.ledger.swapAsset(buyer, seller, assetId, qty, notional, ccy, 'MKT_TRADE', {refs:[fillId], holdId})`.
   - Against maker, pool, CB or treasury: same `swapAsset` with the NPC side `npc_MKT_<bloc>` (bloc = asset ccy; crypto venues: `npc_MKT_<venue ccy>`), 03 classifies the boundary crossing (F3).
   - Fee: `ctx.ledger.pay(payer, exc_<bloc> (or the crypto venueId), fee, ccy, 'MKT_EXCHANGE_FEE')` for each player-economy side; never routed to a concession holder (D086, exploit #14).
   - Securities transaction tax: call `reportTaxableNotional` per fill for equities and ETFs (03 posts `TAX_SECURITIES_TX`).
   - Block crosses: `MKT_BLOCK_TRADE` (T05-18 calls `settleFills` with a block flag; add `block?: boolean` to SettleInput).
   - Derivatives (FUTURE, PERP, OPTION): no `swapAsset`; record the fill for 07's novation (`derivativeHandoffs`), fees still posted.
   - NPC-vs-NPC fills (pool vs maker) and background prints create no postings.
   - Release or reduce the order's hold: `ctx.holds.reduce(holdId, used)` on partial fills, `release` when filled, cancelled or expired.
8. `mkt.fill` PRIVATE event to each player-economy side with the `Fill` payload (`counterpartyKind` 'PLAYER' or 'NPC' only).
