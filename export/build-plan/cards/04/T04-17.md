## Goal
Step 11 of the macro day step: decide when the world gets ripples (small one-target news moves), storms (multi-asset pushes) and majors (the crisis catalog of T04-18), under hard constraints that keep crises fair: one major at a time, three real weeks between major triggers, none in a chapter's last 48 game days or first 24, suppression after a player-caused major, triggers rotating across three UTC bands so no timezone always sleeps through them, crisis weeks announced 48 game days ahead. It also runs each event's phases (PRECURSOR hidden, TRIGGER, CONTAGION, POLICY, RECOVERY, ENDED) so the public sees only real state changes, identical in shape whatever the planned length (exploit 3). 04 is authoritative for tiers, rates and constraints (R08); 16 §3.7 draws non-financial shock content within these limits.

## Implementation steps
1. **Fixed draw order (§3.19, G8).** At day close step 11, on `S.crisis()` (04's `macro:events` and `macro:events:kind` mapped to one stream, fixed order): (1) `u_r` → ripple count `poissonInverse(u_r, macro_ripple_rate)` (1/7 per game day); (2) 3 ripple slots × 5 draws (kind, target, sign, size, length) always drawn, a slot used only if `slot < count` and fewer than 3 ripples are active; (3) storm: start u, kind, precursor length; (4) major: start u, kind, severity, precursor length, contagion length. 24 draws every day, used or not. Chapter start adds 2 draws (crisis-week yes/no, week). Bloc choice for kinds that need it uses `chooseBlocs(store, kind, u_kind)` with the same kind draw (T04-18 documents the split of the uniform).
2. **Crisis week (§3.16.1).** At chapter start: with probability 0.6 a crisis week in real week `w = 2 + floor(u × 6)` of the chapter (168 game days each), `startTick = chapterStart + (w − 1) × 168 × 720`; announced 48 game days ahead: at `startTick − 48 × 720` write a `HookCall { owner: '16', hook: 'WIRE_ITEM', args: { key: 'crisis_week_announced', startTick, endTick } }` and set `crisisWeek.announcedTick` (the window then appears in T04-20's public calendar view). Inside it: storm rate × 2, a forced storm on its day 3 if none started yet in it, major rate × 1.5. At most one per chapter (`crisisWeekUsedThisChapter`).
3. **Ripples.** Kind uniform over RippleKind; target via `rippleEffect` (T04-18: sector weighted by sector size, commodity uniform, city weighted by activity), sign 50/50, size `U(0.03, 0.08)`, length `1 + floor(3u)` game days; no precursor; at most 3 active. They start at the next tick (TRIGGER phase immediately; public through 16 news).
4. **Storms.** If none active and ≥ 7 game days since the last ended and not in the first 24 game days of the chapter: start with probability `1 − e^(−rate)`, rate `macro_storm_rate` = 1/91 (× 2 in a crisis week); kind uniform over StormKind; precursor `1 + floor(2u)` game days; active until the precursor plus the kind's effect length (`STORM_EFFECT_DAYS`) has passed, then ENDED.
5. **Majors (§3.16.2, §3.16.3).** `λ_m = macro_major_base_rate × V(t)` (× 1.5 in a crisis week), `V = Σ_k elig_k × base_k × e^{vuln_k} / 3.0` from T04-18. Kind: cumulative weights in catalog order, pick with the kind draw. Severity `0.6 + 0.8u`; precursor `8 + 8u` game days (≥ 8); contagion `5 + 25u` game days; planned trigger tick = `plannedTrigger(header, precursorEnd, timezoneBandNext)` using 02's tick→UTC map (bands 00–08, 08–16, 16–24 UTC). Constraints checked against the planned trigger: no active major (PRECURSOR to ENDED), ≥ `macro_major_min_gap_days` (504) game days since the last major trigger, trigger not in the final 48 game days of the chapter, start not in the first 24 game days, `playerCausedSuppressUntil` passed. If allowed and `u < 1 − e^(−λ_m)`: `startEvent`, then rotate `timezoneBandNext` (0 → 1 → 2 → 0). Edge 9: a crisis that spans a chapter boundary continues; only new triggers obey the final-48 rule; chapter counters reset.
6. **WorldEvent record.** `startEvent` writes `mac.event` with hidden `precursorStartTick`, `triggerTick`, `plannedEndTick`, `severity`, the shock vectors (T04-18), `causeChain` (first entry: the scheduler key and the vulnerability terms that dominated). It emits `macro.event.internal` SEALED with the full plan. Nothing public before the trigger (exploit 3, 04#37).
7. **Phases (`stepPhases`).** PRECURSOR: precursor shocks active (real state changes players can observe: spreads, valuations, guidance, data), no announcement, `publicEventView.phase = 'UNANNOUNCED'` and the event is not listed by `activeWorldEvents`. At `triggerTick`: TRIGGER (1 game day), trigger shocks and hooks applied (T04-18 `applyEventShocks`), `publicTitleKey` set, `macro.event.trigger` PUBLIC (id, tier, kind, blocs, publicTitleKey; no planned length, no planned moves). Then CONTAGION for the planned contagion days; POLICY starts (overlapping CONTAGION) at the first tick a CB emergency meeting or a crisis-specific response for the event fires (`crisisResponseFired`); RECOVERY after CONTAGION ends, until `F < 40` and `FSI < 0.3` for 10 consecutive trading days or 180 game days; then ENDED with `macro.event.ended` PUBLIC (measured outcomes from `measureOutcomes`, for the archive). Each change emits `macro.event.phase` PUBLIC. Shocks decay on their own schedules regardless of phase labels, and the CONTAGION end is the only place the planned length shows, after it happens.
8. **Player-caused majors.** An emergent event with origin PLAYER_CAUSED (T04-18) sets `playerCausedSuppressUntil = tick + 336 × 720`. Emergent majors are never blocked and count for later constraints (they set the last trigger tick). Edge 8: an emergent label during an active major attaches as a sub-phase (a `causeChain` entry and a `macro.event.phase` with the sub-label) rather than a second major.
9. Ownership note (R08): 16 §3.7 lists its own shock rates for non-financial world shocks; those are 16's content drawn on 16's streams and never start a 04 tier event. Only this scheduler starts RIPPLE, STORM and MAJOR events.

## Test plan
- `scheduler.test.ts`:
  - **04#33 over 1,000 simulated chapters with default rates: share with ≥ 1 major 35% ± 5%; storms 12–18 per chapter; ripples 150–230 per chapter**: scheduler-only harness (synthetic store with `V(t) = 1`, F and FSI calm so recoveries end quickly, majors occupying the scheduler until ENDED): measured on the reference implementation of these rules: ripples ≈ 191 per chapter, storms ≈ 12.9, share with a major ≈ 0.36. Assert the three bands.
  - **04#34 no two majors active; no scheduled major within 504 game days of the previous trigger or in the last 48 game days; precursors ≥ 8 game days**: over the same 1,000 chapters plus 200 chapters with `V × 20` (stress the constraints): pairwise checks on every major.
  - **04#35 trigger ticks rotate across the three UTC bands (33% ± 10% over 300 majors)**: forced-rate harness producing ≥ 300 majors with a realistic `sealUtcMs` drift (5 s per tick): each band's share ∈ [0.233, 0.433], and consecutive majors use bands 0, 1, 2 in rotation.
  - `poissonInverse(0.5, 1/7)` = 0; `poissonInverse(0.95, 1/7)` = 1 (P(0) = 0.866878, P(≤1) = 0.990717); draw count per day exactly 24 whether or not anything starts (stream position test).
  - Crisis week: announced exactly 48 × 720 ticks before start; forced storm on day 3 when none; never two per chapter; no scheduled MAJOR or STORM start in the first 24 game days; PLAYER_CAUSED suppression of 336 game days.
- `phases.test.ts`:
  - **04#37 a world event's public view on day 3 is identical whether its planned length is 10 or 30 game days**: two worlds, same seed, `forceEvent('EQUITY_BUBBLE_BURST', { contagionDays: 10 })` vs `30`: the sequence of PUBLIC events, `activeWorldEvents` and every client payload up to trigger + 3 game days are byte-identical (canonical encoding); SEALED `macro.event.internal` differs.
  - Phase chain: TRIGGER lasts 720 ticks; POLICY starts at the first emergency meeting and overlaps CONTAGION; RECOVERY ends after 10 calm trading days or at 180 days; ENDED emits measured outcomes.
  - PRECURSOR: no PUBLIC `macro.event.*` exists, and `activeWorldEvents` does not list the event.
  - Edge 8: an emergent BANKING_PANIC during an active major is attached to it (no second major row).
