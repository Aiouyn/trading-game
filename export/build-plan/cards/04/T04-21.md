## Goal
Assemble module 04 into one `ModuleDef`. The pieces exist: tables and events (T04-01), intent handlers (T04-08, T04-11, T04-12, T04-13), phases, boundaries, views and state genesis (T04-20). This card adds the parts no other card owns:
- the 17 reason codes 04 registers on top of 03's catalog (E-104 (1) adds `MAC_FX_CAPITAL_FLOW`);
- the 16 world entities 04 owns (5 treasuries, 5 central banks, 5 dealer pools, the Concord fund);
- the Concord fund's genesis cash of Σ quotas × 3;
- the module's parameter accessor list.

Its genesis runs these steps before `macroGenesis` (T04-20). It also owns 04#40 and reruns 04#20, 04#29 and 04#30 with the real 05 order books in place of the market stub.

## Implementation steps
1. **ModuleDef (`index.ts`).**
   ```ts
   defineModule({
     id: '04', module: '04', dependsOn: ['03'],
     tables: ALL_MACRO_TABLES, streams: MACRO_STREAMS,
     phases: macroPhases(ports, stab), boundaries: macroBoundaries,
     intents: MACRO_INTENTS, events: MACRO_EVENTS,
     invariants: MACRO_INVARIANTS, views: MACRO_VIEWS,
     genesis: (ctx) => macroModuleGenesis(ctx, ports),
   })
   ```
   `ports = { ...defaultMacroPorts(), ...opts.ports }`; `stab = opts.stab ?? NULL_STAB`. Event visibility comes from `MACRO_EVENT_VISIBILITY` through the event schemas, as T04-01 declares it. No other logic in `index.ts`.

   3 SINK, 14 TRANSFER, no FAUCET. The remaining row fields (cash-flow category, `legA`, `legB`) follow 03's row of the same template and class (Open point 3). `registerMacroReasonCodes(catalog)` calls `catalog.registerReasonCodes(MACRO_REASON_ROWS)`: an equal row already present is skipped, a different row with the same code throws `LEDGER_EXTENSION_CONFLICT` (E-88 (7)). `MAC_GENESIS_ENDOWMENT` is already a seed row (FAUCET, owner 4) and is not re-registered.
5. **Entities (`registerMacroEntities`).** For each `b` in `BLOC_ORDER` (FDL, EUN, PYN, NKR, SRL), in this order:
   - `govId(b)`: kind gov, `reportingCcy = BLOC_DEFAULTS[b].ccy`, `ownerId null`, `homeBloc b`;
   - `cbkId(b)`: kind cbk, same ccy, `ownerId govId(b)` (chain ends at gov, INV-BS-004), `homeBloc b`;
   - `DEALER_POOL_ID(b)`: kind npc, same ccy, `ownerId null`, `homeBloc b`.

   Then `CSF_ID` (`npc_CSF`): kind npc, `reportingCcy 'FDL'`, `ownerId null`, no home bloc. That makes 16 calls, all idempotent (T03-28). The dealer pools hold no cash: T04-11 settles NPC ladder awards through `elasticIn('row', ...)`, and pool bids carry no hold. The exchanges `exc_<bloc>` are 05's (T05-23); `reg_*`, `crt_*` and `sys_STAB` are not registered here (Open point 4).
6. **Concord fund endowment.** `S0 = scaleTarget(ports.players.activityWeighted(store), p)`, the same value T04-20 genesis uses. For each bloc:

   `quota_b = toMoney(((CSF_QUOTA_SHARE × macro_world_gdp_ref) × S0) × gdpShare0_b, 'FDL')`

   Use that multiplication order, with no FX round trip. Then `endowment = CSF_CAPACITY_MULT × Σ_b quota_b`, summed in bigint. Post it with `ctx.ledger.mint(CSF_ID, endowment, 'FDL', 'MAC_GENESIS_ENDOWMENT')`, once at genesis. Afterwards, capacity drifts with S and GDP through T04-14's `lendingCapacity(store)`; the cash is not topped up (Open point 5).
   - Worked example 1, no players (`S0 = macro_scale_min = 0.2`, `macro_world_gdp_ref = 100e12`):
     - quotas in micro FDL: FDL 128,000,000,000,000,000; EUN 88,000,000,000,000,000; PYN 96,000,000,000,000,000; NKR 28,000,000,000,000,004 (float 0.02 × 100e12 × 0.2 × 0.07 = 28,000,000,000.000004); SRL 60,000,000,000,000,000.
     - Σ = 400,000,000,000,000,004 micro, endowment 1,200,000,000,000,000,012 micro (1.2e12 FDL).
   - Worked example 2, `S0 = 1` (`macro_scale_min = 1` by setParam): FDL 640,000,000,000,000,000; EUN 440,000,000,000,000,000; PYN 480,000,000,000,000,000; NKR 140,000,000,000,000,000; SRL 300,000,000,000,000,000. Σ = 2,000,000,000,000,000,000 micro, endowment 6,000,000,000,000,000,000 micro (6e12 FDL), which matches T04-14's `lendingCapacity` test at world GDP 100e12.
7. **Genesis order (`macroModuleGenesis`).**
   1. (E-92 (4)) no reason-code step: `MACRO_MODULE.services.reasonCodes = MACRO_REASON_ROWS`, registered by 03 on every world build before genesis;
   2. `registerMacroEntities(ctx)`;
   3. `registerMacroInstitutions(ctx)` then `postOpeningBalanceSheets(ctx)` (T04-22, E-92 (5));
   4. Concord endowment (step 6);
   5. `macroGenesis(ctx, ports)` (T04-20, state rows only).

   03's genesis has already run (`dependsOn ['03']`, so `sys_SYSTEM` exists). No draw in this card. The catalog is not world state: on snapshot restore or replay, the same rows must be registered again before the first 04 posting (Open point 2).
8. **Parameters (`params.ts`).** `MACRO_PARAM_KEYS` is the union of the `params` lists of T04-01 to T04-20: 44 exact keys plus the families `macro_xreg_*`, `macro_x_*`, `macro_rr_*`, `macro_cb_haircut_*`, `macro_rev_base_*`, `macro_issue_mix_*` (50 entries). This includes `npc_to_player_wealth_band` (T04-04). A static test reads every `p.num/p.int/p.str/p.bool('<key>')` literal under `packages/engine/macro/**`. Each one must match an entry here, and each entry must exist in the 23 registry (T23-02).
9. **Market ports with 05 (`harness/integration/macro05Ports.ts`).** This is test-only code in `harness/`, because `packages/engine/macro` may not import 05 (INV-STR-001). It maps the 05 read api onto `MacroPorts.markets` (closing yields, FX clearing, pool fills) and places the CB pool orders T04-09 writes. This adapter is the only new code the reruns need.

## Open points
1. **Invariants.** 20 lists no `INV-MAC-*`, so `MACRO_INVARIANTS` is empty. 04's ledger safety rests on 03 INV-LED-* and INV-BS-*. If 20 adds macro invariants (for example corridor ordering or `reservesFdl ≥ 0`), they go here.
2. **Reason-code registration point.** Resolved by E-92 (4): the 02/03 build hook (T02-11, T03-28) registers `services.reasonCodes` on genesis, restore and replay. Original note: The cards say "at module init", but `ModuleDef` has no init hook, and `ReasonCatalog` is per world and not in the snapshot (E-79, E-88 (7)). This card registers the codes in genesis, which does not run on snapshot restore or replay. 02 or 03 needs a hook that runs on every world build (for example a `reasonCodes` field on `ModuleDef` that `LedgerWorld` reads). Until then, restore must call `registerMacroReasonCodes` itself.
3. **Row fields.** The owning cards give class, template and owner, but not the cash-flow category or the legs. They are taken from 03's row with the same template and class; 03 should confirm them. The spec and the cards also disagree: §3.18 lists `GOV_SUBSIDY_P` and `GOV_SYNDICATION_FEE_P` as FAUCET, while T04-10 and T04-12 register them as TRANSFER (R23, 03 boundary rule). The table follows the cards. §3.18 also says 03 registers the codes; the cards moved that to 04.
4. **Other authored entities.** Resolved by E-92 (5) and T04-22 (registration of reg/crt/sys_EXA/sys_STAB and gov/cbk opening postings); the `cbk_*` owner defect noted there is open. Original note: 03 §3.1 lists `reg_*`, `crt_*` and `exc_*` as authored at genesis, and T04-01 defines their ids. `exc_*` belongs to 05 (T05-23). Who registers `reg_*`, `crt_*` and `sys_STAB` (T04-19 mirror) is not stated. Genesis balance sheets of `cbk_*` and `gov_*` (reserves, treasury cash, bonds outstanding) are not posted by any card I found. This card posts only the Concord endowment.
5. **Concord capacity and cash.** The endowment is fixed cash at genesis. `lendingCapacity` (T04-14) moves with S and bloc GDP, so later capacity can exceed the fund's cash. Should the fund be topped up (more `MAC_GENESIS_ENDOWMENT` mints), or should disbursement be capped by cash as well as capacity?
6. **Rounding.** The NKR quota is 28,000,000,000,000,004 micro only under the stated multiplication order and T03-05 `toMoney` rounding half away from zero. T04-14's `quotas(store)` goes through FX and differs by up to 10,000 micro, which is why the cross-check has a tolerance and is not an equality.
7. **Cyclic schedule.** T05-23 depends on "T04-??", which is this card, so T04-21 cannot list T05-23 in `depends_on`. The reruns ship here but run only after T05-23 merges. Alternatives: move them to T05-23's Done list, or add a T04-21b after T05-23.
8. **Stabilizer port.** `MACRO_MODULE` uses `NULL_STAB`, so `pew` is absent in weekly reports. A store-readable `MoneySupplyReport` source (T04-19 Open point 4; T03-24 `buildDailyReport` needs samples) is needed before the real port can be wired.
9. **Harness skip.** The harness needs a module-presence skip (`requires: ['05']`). If 19 forbids skipped tests in CI, apply Open point 7 instead.
10. **E-90 dependency.** E-90 item 3 adds a T04-05 rule: credit is held at the day-0 close, so `row(0).credit === credit0`. That rule needs to be in T04-05 before the 5-year run here can pass E-90's ACs.
11. **dependsOn.** `['03']` follows T03-28's pattern of naming only unit ids. 05 lists `['03', '04', '14A', '13A']`, so `'04'` is the id this module must use.
