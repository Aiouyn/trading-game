## Implementation steps
1. `acct.report.exploit` (P1): account FULL; description 20-4,000 chars (else TM_REPORT_TOO_SHORT); ≤ `tm_reports_per_day` (5) per real day (TM_REPORT_RATE_LIMITED, day key from the header's sealUtcMs); `entityIds` ≤ 20 and each own or public (TM_ENTITY_NOT_VISIBLE). Effect: records `T_REPORT_FILED`, emits PRIVATE `tm.report.filed {ticketId, tick}` to the reporter; the support ticket is created by 21 outside engine state from the event (ticket id derived deterministically from the intent id). No money is posted.
2. `acct.integrity.optin_credit`: ticket belongs to the actor and is VERIFIED (TM_TICKET_NOT_VERIFIED); toggles credit.
3. Integrity report (weekly per league week, chapter summary after each boundary): money from 03's report (M0, M2 by currency, faucets and sinks by reason, stabilizer), systemic indicators from 07, integrity counts (ticks run and missed, invariant evaluations and failures, safe-mode ticks, quarantined intents, shadow verified-through tick and mismatches), fixes with public titles only, enforcement counts, ad grant and fresh-start totals, commitments published; every count < `tm_report_min_count` is shown as "fewer than 5"; no character, company, fund or alliance named; a fix credit line names a player only with their opt-in; the job asserts ΔM0 for the week = Σ faucets − Σ sinks to the micro-unit before publishing; publishing emits PUBLIC `tm.integrity.published {reportId, coversTicks}` (16 news). A week with a halt reports `ticksMissed` and the halt duration and category (20 §8 edge 12).
4. `tm.verify.outcome {eventId}`: the viewer must be in the event's `partyIds` (TM_NOT_PARTY otherwise); fetch the epoch commitment, and when revealed the epoch secret and e(N); recompute the draw with `partyRollU(eN, domain, subjectIds, rollIndex)` from the event's roll record and compare with the recorded draw; "Does not match" opens a support ticket (client action through 21).
5. Safe harbour (Rule 3.16.2): harbour iff the report tick − first use ≤ `tm_disclosure_window_ticks` (17,280), not used on other players' accounts, not used after the report, uses ≤ `tm_disclosure_max_uses` (3) and gain ≤ max(`tm_disclosure_max_gain` $100,000, 5% of NW). Gains are always reversed by compensating entries through 21 §3.6. With harbour, no enforcement action. Rewards (Rule 3.16.3): "Auditor" title for the first verified original report per Finding (20 §8 edge 11 links later reports), opt-in credit line, "Integrity Seal" frame for CRITICAL findings; never cash or Prestige.
6. Screen view models: Integrity report sections Money, System risk, Integrity, Fixes, Enforcement, Ads and fresh starts, Commitments with weekly M0/M2 and faucet/sink class series; verify sheet VM; report form field schema (21 renders the form); halt overlay uses `tm.world.halted` category 'SYSTEM_CHECK'; profile title and frame come from 14.
