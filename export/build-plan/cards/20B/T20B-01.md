## Goal
Prove at whole-game level that the invariant catalogue of 20 §3.1 is complete and enforced: every id of the launch catalogue (INV-LED-001..014, INV-BS-001..012, INV-MKT-001..006, INV-CCP-001..003, INV-BNK-001..002, INV-FND-001..003, INV-INS-001, INV-CON-001..007, INV-LAW-001..004, INV-SOC-001..004, INV-PRG-001..002, INV-ENG-001..010, INV-STR-001..010) is registered by exactly its owning module when every unit is loaded, and each has a passing negative test (20 Rule 3.9.4); then run the three ledger fault-injection acceptance tests of 20 §10 (#2, #3) against the full module set, checking that safe mode, violation records and repro bundles behave as 20 Rule 3.2.2 (24 D417) requires.

## Implementation steps
1. `catalogueReport`: build an InvariantRegistry from `ALL_MODULES` (every ModuleDef of every unit) and add the static ids registered by the static checkers (INV-STR-001..010: 006/008/009 from T20A-06, the others from 19A's checkers); compare with `LAUNCH_CATALOGUE`: any missing id, any id registered by a module other than its catalogue owner, any extra id not in the catalogue is a failure (an extra id requires a 24 decision and a catalogue update first).
2. Negative tests (20 Rule 3.9.4): every unit writes, next to each invariant, a fault-injection test whose title contains the invariant id and the word "negative" (for example `INV-LED-001 negative: unbalanced entry aborts the tick`). The reporter collects them across the monorepo run (`pnpm -r test --reporter=./apps/harness/src/catalogue/negative-reporter.ts`); `negativeCoverage` marks an id covered only when at least one such test passed. For FATAL invariants the test must assert that the tick did not commit and the ladder ran; the coverage check reads the `ladder` tag the TestRecord carries (systemExercised contains 'safe_mode').
3. `truth:catalogue` script: runs steps 1 and 2 and exits non-zero with the list of gaps (used by G1 of every unit and by T20B-21's gates).
4. Ledger fault tests use the full module set with 4 partitions; the crafted input is injected through a test-only fake module 'zz_fault' whose P5 phase calls `ctx.ledger` raw posting hooks exposed only under the testing entry of 03 (`ledgerTestHooks.injectRaw`), or crafts a FAUCET or TRANSFER through `asSystem`.
