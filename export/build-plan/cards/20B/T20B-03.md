## Goal
Turn every failure source of 20 Rule 3.10.3 (invariant failures, equivalence mismatches, a failing band's worst seed, a finding, the shadow verifier, a player exploit report, a reproducible support ticket, a playtest defect) into a permanent `RegressionCase` with a `ReproBundle`, minimize each case by delta debugging over ticks, intents and agents (Rule 3.10.4), sort cases into the FAST tier (minimized and replaying in ≤ 30 s, run in G0) and the NIGHTLY tier (run in G2), convert sandbox run files into cases (Rule 3.10.5), and re-express cases whose engine version can no longer be loaded before deletion.

## Implementation steps
1. `captureCase`: every source produces a FailureSignal (shadow verifier T20B-17, findings T20B-10, bands T20B-11..16 for the worst seed of a failing band, gates T20B-21, safe-mode records from T02-16 written by 19.B, support and player reports through 21's ticket export, playtests T20B-20). Cases are permanent and keyed by SHA-256 of the canonical bundle.
2. Minimization order (Rule 3.10.4): (a) ticks: try snapshots from latest to earliest at or before the failure tick and keep the latest that still reproduces; (b) intents: ddmin over the intents of the tick range (system inputs, quarantine lists and admin directives are never removed); (c) agents: ddmin over agent ids for harness-origin bundles. Every oracle call is a headless replay; total work is capped by `budgetMs` and the steps taken are recorded in the case.
3. Tiers: measure the minimized case's replay on the CI reference runner; ≤ 30 s and minimized -> FAST; else NIGHTLY. FAST runs in G0, all cases run in G2 (T20B-21).
4. Re-expression: a case is only removed when its engine version cannot load; first it is re-recorded by replaying its scenario on the current engine (`rerecord`), and the new case records the old case id in `expectedDetail` ("re-expressed from rc_...") and the old one is kept until the new one passes.
5. Run files: decode, verify the final hash with a headless replay; a mismatch marks the file tampered (no case is created; the support ticket is still triaged on its description). A valid file becomes a case with source SUPPORT.

- system inputs survive minimization.

- `20#28 every RegressionCase in the FAST tier replays in <= 30 s and reproduces its expected outcome on the current main branch`: run `runTier('FAST')` over the committed case store fixture (and over the live store in CI): every case passes and each `ms <= 30,000`; a case artificially slowed to 31 s is re-tiered NIGHTLY by `assignTier`.
- a tampered run file -> tampered true, no case; a valid one -> case with source SUPPORT.
- reexpress keeps the case when its version is loadable and re-records it otherwise.
