## Goal
Run the equivalence statement of 20 Rule 3.3.2 over the whole game: for the same seed, params, content, engine version and sealed intent log, `(logicalStateHash, eventDigest, postingDigest)` is identical at every tick for 1, 4 and 16 partitions (Rule 3.3.3 shapes, with the 16-partition run receiving one partition move at a snapshot boundary) and one random 2-24 partition map; also when resumed from a mid-run snapshot; on x64 and arm64 with the pinned Node minor, plus the 7-game-day old-versus-new toolchain comparison (Rule 3.3.5); in the browser Web Worker build versus Node (Rule 3.3.7); and the version replay of the last production game day against a candidate (Rule 3.3.6). On any mismatch the first-divergence search of Rule 3.3.4 fills `EquivalenceRun.firstDivergence` and files a CRITICAL RegressionCase. Also supplies the cross-architecture golden checks of 02 AT 11 and 02 AT 14 in the CI matrix.

## Implementation steps
1. Record once, replay many: `recordLog` runs the world at k = 1 with its agents and stores every sealed batch; equivalence runs replay the same batches without agents so agent scheduling cannot differ. Hunt-farm logs (T20B-10) are recorded the same way.
2. Maps: `partitionMapsFor([1, 4, 16], seed)` uses `standardMap` and adds the random map drawn from `tm:partitionmap`; the 16-partition run calls `applyRebalance` at the first DAILY boundary after mid-run (19 §3.5.6 exercised). `tm_equivalence_partition_counts` supplies the counts.
3. Resume: run k = 4 from genesis to tick M, snapshot, build a new world from that snapshot and continue; digests from M+1 on must equal the genesis run's.
4. On mismatch: `firstDivergence` compares `logicalEntityHashes` at the tick, sorts differing ids, replays the tick phase by phase in both configurations and reports the first differing phase output for the first entity down to the field path; an EquivalenceRun with result FAIL and a CRITICAL RegressionCase (source EQUIVALENCE) are produced.
5. Host matrix (`.github/workflows/equivalence-matrix.yml`): jobs on x64 and arm64 runners compute `digestFile` for the 20#6 and 20#8 worlds and for 02's goldens (`packages/engine/core/world/golden/ticks-10000.sha256` of 02 AT 11 and the dmath golden of 02 AT 14) and a final job compares them. Toolchain upgrades add a 7-game-day STANDARD comparison old vs new.
6. Browser: Playwright launches headless Chromium, loads the worker build, feeds batches and collects digests per tick.
7. Version replay: candidate run over the last production game day; divergences before the declared effective tick, or in undeclared fields, mark `green = false` (T02-18 refuses the cutover).
