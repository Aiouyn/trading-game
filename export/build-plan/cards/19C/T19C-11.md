## Goal
Write the main-thread half of 19 Rule 3.17.1: one Zustand store per channel family (T19C-01's 27 families), fed exclusively by the `changes` messages of the socket worker (T19C-10), and the view models behind the platform surfaces that 19 §7 requires (tick pulse and clock, connection indicator, pending intent chips, diegetic halt overlay, update required screen, maintenance notice, Settings Security, Settings Data and privacy, API screen, Verify, Stabilizer and Exchange report, replay viewer entry, PWA offline screen). Layouts and components belong to 17; this card provides data hooks and pure selectors only. Then enforce two guarantees: Rule 3.17.2 (the client never predicts money) with an ESLint rule (19#56, threat E1 of §9) and the content split of Rule 3.9.8 with a build check on the client bundle (19#58, threat E2 of §9).

## Implementation steps
1. Stores (Rule 3.17.1): `createFamilyStore` builds a Zustand store whose only mutator is `__applyChange`; a snap replaces the slice, a patch is applied with `applyOps` to a structural copy; `seq` must be `current + 1` (the worker already guarantees gaps are refetched, the store asserts and marks `stale` otherwise). `connectStores` subscribes to the worker bridge and applies all sets of one `changes` message inside one `unstable_batchedUpdates` call so a tick renders once (Rule 3.17.3 tick render budget is measured in T19D-06).
2. Pending chips (Rule 3.17.2): `submitIntent` creates the chip `SENDING`, posts `submit` to the worker, moves to `PENDING_TICK` with `sealTick` on `ack` (ACCEPTED or DUPLICATE), and to `DONE` or `REJECTED` on `result`. The chip never computes a balance or a fill; money values appear only when the owner channel's delta arrives. Only cosmetic stores (layout, local widget names) may update optimistically, and they live under `apps/web/lib/stores/cosmetic/`.
3. Lint rule (19#56): `tycoon/no-money-prediction` reports (a) any call to `setState`, `set`, `__applyChange` or `produce` on a family store, and (b) any assignment or object literal property whose key matches `MONEY_FIELD_PATTERN` inside a Zustand `create(...)`/`setState` callback, in every file of `apps/web/**` except `apps/web/lib/stores/registry.ts` and `apps/web/lib/stores/channel-store.ts` (the delta application path); files under `apps/web/**/sandbox/**` are exempt (sandbox engine output, Rule 3.17.4). Registered as `error` in the web eslint config; CI `lint` fails on any report.
4. Content split (19#58, Rule 3.9.8): (a) the import boundary of T19A-04 already denies `@tycoon/content/server` in `apps/web`; (b) `checkContentSplit` runs after `next build` over `.next/static/**/*.js` and the Capacitor static export, searching every key returned by `serverKeys()` as a whole quoted token (`"key"` or `'key'`); any hit fails the `build` job with the file and key. Keys shorter than 6 characters are matched only as quoted object keys to avoid false hits.
5. Surfaces (19 §7): pure functions over channel bodies and HTTP responses, unit-tested, consumed by 17's components. `tickPulse.msToSeal = nextSealAtMs − serverNowMs` from the `clock` body and `ClockSync.serverNow` (Rule 3.8.1); `ringFraction = 1 − msToSeal / tickMs` clamped to [0,1]; `catchingUp` from `status.mode === 'CATCHING_UP'`; halt from `status.worldStatus` in {`HALTED_EXCHANGE`, `MAINTENANCE`} (driven by `sys.world_status`). `updateRequired` is visible on `bye UPGRADE_REQUIRED` or `notice PROTO_DEPRECATED`; native shows the store link, web reloads. All labels are i18n keys (Rule 3.17.7); numbers and money formatted by locale with `Intl.NumberFormat`.
6. Offline (Rule 3.17.5): the service worker (T19D-06) stores only the last `me` snapshot and its tick; `offlineView` renders it read-only; market data is never cached.

## Test plan

- `19#56 Client code review check: no store mutation of balances, positions or fills occurs outside the delta application path (enforced by a lint rule on Zustand stores)`: invalid cases: a component calling `FAMILY_STORES.me.setState({ balance: 10 })`; a custom store `create((set) => ({ cash: 0, buy: () => set({ cash: 5 }) }))` in `apps/web/app/(game)/trade/x.tsx`; `useMe.getState().__applyChange(...)` from a component. - `19#58 The client bundle contains no key from content/server; the build fails if client code references one`: a fixture bundle dir with 3 js files, server keys `['hidden_weight_table', 'npc_secret_curve']`; a file containing `"npc_secret_curve"` gives one hit and `ok: false`; the clean bundle gives `ok: true`; a fixture web file importing `@tycoon/content/server` fails the T19A-04 boundary check.
