## Goal
Give every authenticated session a registered signing key and every intent a verifiable signature (19 Rule 3.9.1), with replay protection by a per-key 64-nonce sliding window (19 Rule 3.4.3 item 1) and the ULID time window (item 2), plus the platform HTTP actions of 19 §4.2 that manage them: register and revoke session keys, issue single-use socket tickets, list and revoke sessions and devices. Revocation is broadcast so gateways close sockets within one tick.

## Imports
- T19A-02: `Intent`, `signingBytes`, `ulidTimeMs`. T19B-04: `authSession`, `signingKey`, `device` tables, `appendAudit`. T19C-02: Better Auth session lookup (`auth.api.getSession`), `ipHash`.
- GLOBAL-CONTEXT: Valkey 8 client (`iovalkey` or `ioredis`-compatible), Node `crypto.webcrypto`.

## Implementation steps
1. Key registration (19 §4.2 row 1): authenticated session; at most `max_keys_per_session` (2) active keys (else `KEY_LIMIT`); public key must parse for its alg (else `KEY_MALFORMED`); id `sk_` + ULID; row in `signing_key` with `last_nonce = 0`.
2. Signature (19 Rule 3.9.1): `signingBytes` is RFC 8785 canonical JSON of the signed fields (T19A-02); verification with WebCrypto (`Ed25519`, or `ECDSA P-256 SHA-256` for ES256). Any changed byte in any signed field fails; a revoked key always fails. The batch keeps the signature (non-repudiation).
3. Nonce window (rule 3.4.3 item 1, `nonce_window` = 64): accept iff `nonce > lastNonce − 64` and not already seen; `nonce > lastNonce` shifts the bitmap left by the difference (bits beyond 63 drop) and sets bit 0, `lastNonce = nonce`; `lastNonce − 63 <= nonce <= lastNonce` sets bit `lastNonce − nonce` if clear (else REUSED); `nonce <= lastNonce − 64` is TOO_OLD. The Valkey Lua script stores `{lastNonce, bitmap}` as two fields of hash `nw:<sessionKeyId>` and is the gateway's authority; `persistLastNonce` writes the high-water mark to PostgreSQL every tick (batched).
4. ULID window (rule 3.4.3 item 2, §8 edge 2): `|ulidTimeMs(intentId) − now| <= intent_clock_skew_ms` (600,000) else the gateway answers `BAD_SCHEMA` and the client re-syncs.
5. Tickets (rule 3.8.1 item 1): issued only to an authenticated web session (cookie) or native bearer token; bound to session and device; TTL `ws_ticket_ttl_s` (60); `GETDEL` makes it single use.
6. Sessions routes (19 §4.2 row 2): list own sessions with device info; revoke one (`revokeSession`): session revoked, its signing keys revoked, revocation published (gateways close sockets with `bye SESSION_REVOKED` within one tick, T19C-04). Responses for an unknown or foreign session id are identical (404 with the same body).
7. Keys are also revoked on logout, session expiry and security changes (T19C-02 calls `revokeSessionKey` for each).

## Test plan
`keys.test.ts`:
- `19#9 an intent with any changed byte in a signed field fails BAD_SIGNATURE; a revoked key's intent fails`: sign a sample intent with an Ed25519 and an ES256 key: verifies; for each of the 11 signed fields, change one character/digit: verification false; changing the unsigned `signature` field to another valid-looking value: false; after `revokeSessionKey` the original intent: false.
- registration: third key -> KEY_LIMIT; 31-byte Ed25519 key -> KEY_MALFORMED.
- tickets: redeem twice -> second TICKET_INVALID; different device -> TICKET_DEVICE; after TTL -> TICKET_INVALID (fake clock).
- ULID skew: id from now − 600,001 ms rejected, now − 599,999 ms accepted.
`nonce-window.test.ts`:
- `19#8 a nonce at or below lastNonce − 64, or one already used in the window, is rejected; out-of-order nonces inside the window are accepted once`: sequence 100 (OK), 105 (OK), 103 (OK), 103 (REUSED), 41 (TOO_OLD: 41 <= 105 − 64), 42 (OK), 42 (REUSED), 200 (OK), 137 (OK: 137 > 200 − 64 = 136), 136 (TOO_OLD).
- property (fast-check, `fcRuns()`): for random nonce sequences the pure function and the Lua script (when `VALKEY_URL` is set; skipped with a printed reason otherwise) agree on every result.
