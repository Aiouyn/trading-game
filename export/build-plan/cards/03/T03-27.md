## Goal
This card provides one `ViewHandler` (G6 shape: `{ id, schema, run(store, args, viewer) }`) per screen of 03 §7. Layouts are 17's job. Every view is pure: it reads `StoreRead` only, never writes and never draws RNG. Every view that returns entity financials passes the access check, which T03-19's static scan test enforces.

The data each screen shows is produced by earlier cards; this card only selects, filters, paginates and shapes it:
- statements: T03-19;
- postings: `led.entry`;
- group structure: T03-16;
- net worth: T03-17;
- tax: T03-20 to T03-23;
- Stabilizer: T03-24;
- insolvency: T03-25 and T03-26;
- restricted lots: T03-12;
- holds: T03-08.

## Implementation steps
1. **Access** (`accessOf`). Statement visibility follows T03-19:
   - OWNER: the viewer is admin, or `actorControls(viewerId, entityId)`;
   - REGULATOR: `viewer.partyOf` includes `reg_<bloc>` of a chartered entity of that bloc;
   - PUBLIC: what the entity publishes (listed companies, public funds, the Stabilizer Board);
   - NONE: everything else.
   Each view returns `{ error: 'ACCT_VIEW_FORBIDDEN' }` when the viewer's access is below what it needs. Counterparties of postings are shown through `counterpartyLabel` and never as raw ids of private entities the viewer does not control.
2. **Books** (needs OWNER, or the PUBLIC/REGULATOR statement rows that `canSeeStatement` allows):
   - the default scope is CONSOLIDATED for a chr and SOLO otherwise;
   - FLASH is built live with `buildStatement`; other periods read the stored `led.stmt` row and build on a miss (owner only);
   - `BooksPayload = { statement (income, balance, cash flow, equity changes, KPIs), periods available (from statementTable byEntity), drill: { lineId → { accountCodes, explorerArgs } } }`. The drill-down gives each line the explorer filter (account codes plus the period's tick range).
3. **Ledger explorer** (OWNER, or REGULATOR for chartered entities):
   - reads `led.entry` byTick within the retention window (20,160 ticks, T03-09); an older `fromTick` returns `archivedBefore` (the 19 archive serves it);
   - filters on account code, reason, counterparty label and period;
   - sorted by (tick desc, entryId, seq); cursor = the last `(tick, entryId, seq)`; limit ≤ 500, default 100;
   - `cause` comes from `requestedBy.intentId`, the entry's refs (eventId, contractId, caseId) and `holdId`; `citation` is `T<tick>`.
4. **Group structure** (OWNER of the root, else only PUBLIC nodes):
   - `GroupPayload = { nodes: { entityId, label, kind, perimeter, controlled, effectiveOwnership, nci, lookThroughNav }[], edges: OwnershipEdge[], cycles: { path: Id[]; product: number }[] }`;
   - nodes come from `groupOf` and `solveLookThrough`;
   - the cycles warning lists every cycle with product > 0 (`maxCycleProduct`).
5. **Net worth panel** (OWNER; a PUBLIC viewer sees only NWI and the rank tier through 15's boards):
   - `NetWorthPayload = { nw: nwConsolidated, nwSolo, flash: flashNw, nwRank, haircuts: { concentration, controlCap, stale }, nwi, msi, rankProgress: { current, nextThresholdKey } }`;
   - the haircut breakdown comes from `getNwRank(...).breakdown`. The rank thresholds are 14's: the view returns the NWrank and 14 resolves progress, so `nextThresholdKey` is passed through from the 14 fact `RANK_THRESHOLD_NEXT` when present.
6. **Tax Center** (OWNER):
   - residency (`taxStatus`, `residencySegments`);
   - the YTD estimate per tax type (`personalIncomeYear` or `corporateYear` with `ytdToDay`, and capital gains);
   - installments due (`led.taxdue` rows open);
   - withholding and foreign tax credits (`foreignTaxCredit`);
   - CFC attributions (`led.cfc`) and transfer-pricing adjustments;
   - loss carry-forwards (`led.taxacct`);
   - elections (`led.taxpref.elections`, `led.taxgroup`);
   - audit status (`led.audit`, `led.assess`);
   - with `simulateBloc`, the residency planner `residencySimulation` (exit tax and the rates afterwards). It is pure, and no state changes.
7. **Money Supply Report** (PUBLIC; the diegetic "Stabilizer Board", 03 §3.7.7):
   - the daily report row of `dayIndex` (default latest);
   - with `chapter`, `buildChapterReport`;
   - lever history (`led.stab.history`, 364 days) for charts;
   - faucet/sink families of the day and year, ρ, M0/M0_sys/M2 per currency, and MSI.
   It contains aggregates only and never an entity id.
8. **Insolvency**:
   - case view (`caseId`): the case is PUBLIC for companies and institutions and OWNER-only for characters (T03-25 visibility). It shows claims grouped by rank (outstanding, recovered), estate realizations, distributions (INSOLV_DISTRIBUTION entries of the case), and claim trading (INSOLV_CLAIM_TRADE entries plus the current claim holders as labels);
   - for a chr (OWNER) it adds the PersonalCaseRow stage, the protected set, the fresh-start result and explanation key `acct.freshstart.explain.<reason>`, and the persistent claims with garnishment progress: `persistentTable` rows with the 2990 balance, `collected` and the pending garnish.
9. **Restricted cash badge** (OWNER):
   - lots from T03-12 `lotsOf` per ccy, with amount and release tick;
   - `canPay` = the catalog codes with `restrictedOk`;
   - `cannotPayKeys` = the i18n keys of the forbidden categories (ops, insider actions, margin, derivatives, P2P transfers).
10. **Holds** (OWNER only, never REGULATOR or PUBLIC): the ACTIVE holds of the entity (`holdTable` byOwner), with amount or qty, purpose, expiry and ref.
11. Register `LEDGER_VIEWS` in the 03 ModuleDef (T03-28).

## Test plan
- `views.test.ts` (TestWorld with two characters A and B, A's cmp, a listed cmp L, a regulator party):
  - access: B gets `ACCT_VIEW_FORBIDDEN` on A's books, explorer, tax and holds; the regulator gets the explorer of a chartered bank but not its holds; anyone sees L's published QUARTER statement and the Money Supply Report;
  - the explorer pages deterministically (two pages of 100 = one page of 200); labels hide B's id from A; `cause.intentId` and the `T…` citation are present;
  - books drill-down: summing the explorer rows of a line equals the line amount;
  - the group view of A shows the cmp with effective ownership and a cycles warning when a test cycle exists;
  - net worth: the payload `nwRank` equals `getNwRank`;
  - Tax Center simulation leaves the store unchanged (snapshot equal);
  - insolvency: a chr case is OWNER-only; persistent rows show garnishment progress after a garnish;
  - restricted badge: a $250 AD_GRANT lot shows its release tick and canPay includes `BIZ_PURCHASE_NEW`.
  - static: no Store write API is imported by any file under views/.
