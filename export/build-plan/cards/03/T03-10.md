## Goal
Implement the ledger invariants of 03 §3.16 that guard the books themselves and register them under their 20 §3.1 ids: double entry per entity and currency, posting well-formedness, REVALUE never touching money, no negative money (overdrafts are loans, reserves bounded by the intraday credit limit), the day-close trial balance with the mirror checks (central-bank holder accounts, bank deposits, bilateral instruments, escrow, suspense accounts, per-entity book identity), quantity conservation, interpartition suspense netting and the bigint/no-NaN rule. Includes the integration proof that a corrupted posting aborts the tick (03#38).

## Implementation steps
1. Definitions: each `def` copies the id, scope, severity and description of its 20 §3.1 row (scope TICK for 001, 005, 006, 007, 008, 012; DAY_CLOSE for 010), `costClass` O_TOUCHED (010: O_ENTITIES), `...LEDGER_INV_BASE`. Every failure goes through `fail(iNumber, ...)` so `observed` starts with the 03 check number.
2. `INV_LED_001` sub-checks in order:
   - I2: for every valid staged entry, `netByEntityCcy(entry.postings)` is 0n for every (entity, ccy), MEMO excluded, 3800 included. Observed `I2: entry=<id> entity=<e> ccy=<c> net=<n>`.
   - I8 (incremental): for every valid entry, `qtyNetByAsset` over all its postings (memo included) is 0n for every asset (QTY_ONLY codes balance through 9200).
   - I5/I6/I7 incremental: for touched money accounts recompute the mirror only for the touched keys (`cbkHolderMirror(post, ccy, touchedKeys)`: for each touched holder account `X:1001|1002|1003`, Σ holder balances of X in that code equals −(cbk `2001|2002|2003:X` balance)); `depositMirror` for touched banks; `bilateralMirror` for touched subs.
3. `INV_LED_005` (I13 local, 02 §3.14.2): for every valid entry whose primary class is TRANSFER, every posting touching a `sys_SYSTEM` account uses code 9900; the sum of this tick's 9900 deltas on this partition equals the Σ of outgoing legs minus incoming legs recorded by T03-09 (each leg once). The cross-partition total (`balance(A->B) + balance(B->A) == 0`) is the COORD check `suspenseNetsToZero`, fed by fact `ledger.suspense` (array of partition suspense balances, supplied by the coordinator, 19B); export it and test it.
4. `INV_LED_006`: no posting of a REVALUE entry touches a money account (1001, 1002, 1003, 1009, 1010), except a move between two sub-accounts of the same money code of the same entity (`LED_RECLASS` releasing restricted cash, 03 §3.5.6, where value is unchanged).
5. `INV_LED_007` (I1 except code/template, which is INV-LED-002): every posting `amount` is a bigint `> 0n` (0n allowed only for `QTY_ONLY_CODES`); both account keys parse and their codes exist in the chart and `kindMayUse(code, kind)`; account ccy equals posting ccy; `qty` present ⇒ `assetId` present and both accounts' asset equals it; every entry marked `invalid` fails here with its own recorded invariant id in `observed`.
6. `INV_LED_008` (I9, I10; 20 INV-LED-008 is satisfied because the 03 rule is stricter: overdrafts are loans):
   - I10: every touched money account except 1002 and elastic 1009 has staged balance ≥ 0n (every 1001 sub, 1003 subs, 1010); every touched bank 1002 ≥ −limit, `limit` = fact `INTRADAY_CREDIT_LIMIT` (Money) if present, else fact `ELIGIBLE_COLLATERAL` (D050: 100% of pledged eligible collateral), else 0n; at t = 719 (after the facility conversion of T03-15) every 1002 of a bank whose central bank is on the same partition is ≥ 0n; a bank whose cbk is on another partition must be ≥ 0n at the first tick of the next game day (after T03-15's DAY_OPEN catch-up), because no leg can cross partitions after B3. 1009 has no bound (03 §8 edge 9).
   - I9: a touched quantity account of an asset code (15xx, 1210, 1220, 1870) with negative qty requires fact `SEC_BORROW` for `${entity}:${asset}` ≥ |qty|; issuance accounts (3100, 3150, 2300, 2310, 2320, 2330) and derivative position accounts (1600, 2600) are exempt.
7. `INV_LED_012` (I0, I16): every staged `led.account` row has bigint `balance` (and bigint `qty` when present); every posting amount bigint; additionally, if `ctx.facts.get('core.money_provenance_violations')` (supplied by 02's store provenance tagging, 20 INV-LED-012) is a non-empty array, fail with its first entry.
8. `LED_010_SUBCHECKS` (full scans at day close, DAY_CLOSE scope):
   - I3: for each ccy, Σ balance of every `led.account` row of the partition (incl. 9900, excl. other MEMO) = 0n.
   - I5, I6, I7: full `cbkHolderMirror`, `depositMirror`, `bilateralMirror` (`BILATERAL_PAIRS`, matched by `sub`: lender's account `<A>:<code1>:<sub>` and borrower's `<B>:<code2>:<sub>` sum to 0n; deposits by holder/bank subs; intercompany by entity subs).
   - I8 full: for every asset, Σ qty over all accounts (memo 9200 included) = 0n; if fact `MARKET_STATS.outstanding` exists for the asset, −(issuer issuance-account qty) equals it.
   - I14: Σ ccp 2160 = −Σ 1070 deposits (per ccy); if fact `ESCROW_OPEN_TOTAL` exists for the ccy, also equal to it.
   - I15: every 1999 and 2999 balance is 0n; for every entity and ccy, Σ non-MEMO balances = 0n.
   `makeInvLed010(extra)` = `composeInvariant(def010, [...LED_010_SUBCHECKS, ...extra])`; T03-28 passes T03-23's I22 sub-check.
9. Edge case 9 (03 §8): no invariant on 1009 balances.
