## Goal
Lay the type foundation of the ledger (unit 03): the entity, account, posting, entry, hold and fact types, the five core store tables, the complete chart of accounts of 03 §3.2 as data (every code with its class, sub-key meaning, money flag and allowed entity kinds), the account-key codec, the authored system entity ids, and the zod schemas of every 03 engine event (03 §5). Every later 03 task builds on these names.

## Imports
- T02-01: `Tick, Money, Qty, Price, Ccy, Id, PhaseId, SortedMap, cmpStr, sortBy`. T02-09: `TableDef` (with optional `indexes: IndexDef[]`, used for the secondary indexes below); T02-01: `Visibility` from `@tycoon/engine/core` (GLOBAL-CONTEXT G6).

## Implementation steps
1. `schema.ts`: transcribe the types above. `ENTITY_KIND_ORDER` = the order in 03 §2.1 (`sys, cbk, gov, reg, crt, exc, ccp, rat, bnk, ins, fnd, spv, cmp, biz, prop, ali, npc, hh, frm, row, chr`). Table defs: `module: '03'`, `idOf` returns `id` / `key` / `entryId` / `holdId` / `id`. Declare the secondary indexes named in Exports in the TableDef `schema` field in the shape 02's TableDef expects (if 02's TableDef carries an `indexes` array, use it; this is a reconciler item).
2. `chart.ts`: one `ChartEntry` per code of 03 §3.2, every row of the 1xxx, 2xxx, 3xxx tables, every 4xxx/5xxx/6xxx code of the income, expense and income-tax lists and the 9xxx memo list (9100, 9110, 9200, 9300, 9900, 9910). Use the exact names of the spec. Rules:
   - `cls`: by first digit (step in Exports). 9xxx are MEMO. 1309 and 1839 are contra assets (`contra: true`, class ASSET, normally credit balance). 3150 contra equity.
   - `kinds`: from the notes column and 03 §2.1: 1003 gov; 1009 hh/frm/row; 1307, 1910 cbk; 1909, 2900, 2909, 3990, 4900, 5900, 9900 sys; 2001, 2002, 2003 cbk; 2100 bnk; 2140 ccp and bnk (prime brokers); 2150, 2160 ccp and crt (2160 courts for case escrow); 2310 gov; 2320 spv; 2700, 2710 ins; 2950 biz, prop; 3700 fnd; 3900 chr, ali; 3500, 3600 'ALL' but `consolidatedOnly: true`; everything else 'ALL'.
   - `qtyBearing`: 1200, 1210, 1220, 1221, 1500, 1510, 1520, 1530, 1540, 1541, 1542, 1560, 1570, 1580, 1800, 1850, 1860, 1870, 1880, 2300, 2310, 2320, 2330, 3100, 3150, 9100, 9110 (issuer-side 3100/2300/2310/2320/2330 hold negative qty of their own instrument, so Σ qty of every asset over all accounts is 0 and I8's outstanding supply = −issuer account qty; this is how issuance and cancellation stay quantity-conserving).
   - `mustBeZeroAtP13`: 1999, 2999.
   - `isMoney` true for 1001, 1002, 1003, 1010; 1009 is money only for elastic kinds and never counts in M0 (03 §3.5.2).
3. `accountKey.ts`: format `'<entityId>:<code>[:<sub>]:<ccy>'`; code printed as 4 digits. Entity ids never contain ':'; `sub` may contain ':' (e.g. `RESTRICTED:51840:AD_GRANT`, `bnk_x:term_y`, `P1->P2`). Parse = first segment entity, second code, last segment ccy (must be a Ccy), the middle joined by ':' is sub (absent if empty). `parseAccountKey(accountKey(...))` round-trips for every input.
4. `ids.ts`: constants and helpers as exported. `kindOfId('chr_01H...')` = 'chr'; unknown prefix → undefined.
5. Sign convention (03 §3.3.1) documented in `schema.ts` as a comment and as two helpers exported from chart.ts? No: keep them in T03-06 (posting rules). Here only document.
6. `events.ts`: zod 4 payload schemas for every kind of 03 §5, money as decimal strings (`z.string().regex(/^-?\d+$/)`), ids as strings:
   - `ledger.entry.committed` `{ entryId, reason, amount, ccy, counterpartyLabel }` (PARTIES)
   - `ledger.statement.ready` `{ entityId, period: { kind, index }, scope }`
   - `ledger.tax.estimate` `{ entityId, ytdByType: Record<TaxType, string> }`
   - `ledger.tax.due`, `ledger.tax.paid`, `ledger.tax.late` `{ taxAccountId, amount, dueTick }`
   - `ledger.tax.audit.selected` `{ entityId, scope: 'PERSONAL'|'CORPORATE' }`; `ledger.tax.audit.finding` `{ entityId, findingKind: 'UNEXPLAINED_WEALTH'|'FALSE_SUBSTANCE', amount, codes: string[], evidencePoints: number }` (SEALED; the "findings until 13 discloses" half of 03 §5 row 5)
   - `ledger.default` `{ debtorId, obligationRef, amount }`
   - `ledger.insolvency.review` `{ entityId, equity }`
   - `ledger.insolvency.opened`, `ledger.insolvency.distribution`, `ledger.insolvency.closed` `{ caseId, debtorId, procedure, recoveriesByRank: Record<ClaimRank, string> }`
   - `ledger.freshStart` `{ chrId, amount }`
   - `ledger.related_party.flag` `{ entryId, deviationPct }`
   - `stab.daily.report` (object with the §3.7.7 fields: per-ccy M0, M0_sys, M2; PEM, PEW, N_a, e, u, levers, leverChanges, familiesDay, familiesYear, rho)
   - `stab.lever.changed` `{ lever: 'L1'|'L2'|'L3'|'L4', from: number, to: number }`
   - `stab.alert` `{ alert: 'STRUCTURAL_IMBALANCE'|'INFLATION'|'RHO_BAND', value: number }`
   - `msi.updated` `{ msi: number, raw: number }`
   - `ledger.invariant.failed` `{ invariantId, entryId?, entityId?, module }`
   Export `LEDGER_EVENT_VISIBILITY: Record<kind, Visibility>` alongside (PARTIES, PRIVATE, PUBLIC or SEALED as in 03 §5; insolvency events: emitter chooses PUBLIC for non-chr debtors and PRIVATE for chr; `stab.alert` uses PRIVATE addressed to `sys_SYSTEM` as the ops channel).
7. Entity lifecycle constants (03 §3.1): export nothing new; document in `schema.ts` that accounts open lazily on first posting (T03-08 creates them), and that dissolution requires zero balances (T03-25 enforces).
