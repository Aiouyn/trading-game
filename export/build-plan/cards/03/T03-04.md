## Goal
Transcribe the last 126 rows of the TRANSFER table of 03 §3.4.3 (from `INSOLV_DEBT_DISCHARGE` to `WLD_NPC_ACTOR_DEAL`, in spec order, including the four TRANSFER codes 24 R06 added for 07: `CCP_LIQUIDATION_PENALTY`, `BNK_FX_MARGIN`, `BNK_ENFORCEMENT_FEE`, `CLR_DEBT_REPAY`) into catalog entries with their ledger metadata. TRANSFER codes move value between core entities and never change base money (00 §5.4).

## Imports

## Implementation steps
1. One `CodeRow` per table row below, same order. Owner, CF and description come from the row of the same code in the spec excerpt 03 §3.4.3 (verbatim).
2. Templates: `PAY` for money payments with value legs; `SWAP_ASSET` for an asset exchanged against money (`@ASSET` legs = the asset account the caller passes; issuer-side legs 3100, 2300, 2310, 2330, 3150 mean the issuer books the instrument against its own issuance account, which carries the negative quantity outstanding, T03-01 step 2); `MOVE_QTY` for assets moving without consideration; `FX` for currency exchange (legs `-`: the template uses 3800 per currency).
3. Special handling recorded in the entry metadata (no extra fields; documented in comments for T03-07):
   - `INSOLV_DEBT_DISCHARGE` (MOVE_QTY with `@ASSET` legs, no quantity): one entry per discharged claim: debtor `Dr 22xx/25xx liability / Cr 4130`, creditor `Dr 1309 allowance or 5190 / Cr 13xx/11xx receivable` (03 §3.14.3), built by T03-25 through `moveQty` with qty 0n and explicit legs; the qty-zero form is allowed only for this code and `LED_ESTATE_TRANSFER`-style zero-quantity moves where the account has no qty.
   - `INSOLV_DISTRIBUTION`: legs `@` (debtor's liability account of the claim / creditor's receivable account), passed by T03-25.
   - `MAC_TREASURY_SWEEP`: payer and payee are the same `gov`; the cash leg moves between its 1003 sub-accounts (`GENERAL`, `DEPOSIT_INSURANCE_FUND`) given in `PostOpts.sub` as `'<fromSub>><toSub>'`; no value legs. It is the only code where `from === to` is allowed.
   - `LAW_ASSET_SEIZURE`: MOVE_QTY of the seized asset into court escrow (`crt` 1070-side asset account given by caller); value legs Dr owner:5210 / Cr court:2560.
   - `CBK_INTEREST_ON_RESERVES` stays registered for the flows 04 does not split; 24 §8 registers `CBK_IOR_P`/`CBK_IOR_W`/`CBK_DEPOSIT_INTEREST_P`/`_W` in T03-05.
4. Value legs per row are defaults; callers override with `PostOpts.valueLegA/valueLegB`.

Column legend (identical in every catalog task T03-02..T03-05):
- **Code**: the reason code exactly as in the spec table (owner, description and CF come from the spec excerpt row of the same code; transcribe them verbatim: `owner` as a number, `descriptionEn` = the Description cell, `cf` = the CF cell).
- **Tpl**: `allowedTemplates` (space separated when several). It must belong to the class's template set (`CLASS_TEMPLATES`).
- **Sectors**: `elasticSectors` for ELASTIC_IN / ELASTIC_OUT codes (comma separated `hh`, `frm`, `row`), `-` = none.
- **Leg A / Leg B**: default value-leg accounts (03 §3.3.3 "value leg"). Meaning per template: PAY: A = payer's debit account, B = payee's credit account; MINT / BURN: A = the entity's value leg (MINT credits it, BURN debits it), B unused; ELASTIC_IN: A = sector's debit account, B = core payee's credit account; ELASTIC_OUT: A = core payer's debit account, B = sector's credit account; SWAP_ASSET: A = buyer's (receiver's) asset or issuance account, B = seller's (giver's) asset or issuance account; MOVE_QTY: A = giver's value-leg debit, B = receiver's value-leg credit, while the moved asset accounts come from `PostOptsExt.assetAcct` (receiver) and `assetAcctFrom` (giver, default the same code); LEND / REPAY / CB_CREDIT / CB_CREDIT_UNWIND: A = the account debited in step (2), B = the account credited in step (2); ACCRUE / RECLASS: A = dr, B = cr. `@ASSET` = the caller must pass the asset account code (`valueLegA` / `valueLegB` in PostOpts) because it depends on the asset (1500, 1580, 1870, ...); `@` = caller must pass it (any account); `-` = not used. A caller may always override a default through `PostOpts.valueLegA` / `valueLegB`.
- **Tax**: `taxTag` (`-` = none).
- **Fam**: `stabilizerFamily` of 03 §3.6 (`-` = none).
- **R**: `restrictedOk` (Y = restricted cash may fund it, 03 §3.5.6; every other code is a forbidden purpose for restricted cash).
- **Also by**: `requestableBy` beyond the owner: module numbers, `ALL`, or `-` (owner only). These are service codes other modules post through 03 (taxes at source, accruals, depreciation, intragroup sweeps).
- `illicit` = true exactly for `OPS_LOOT_CASH`, `OPS_RANSOM`, `OPS_FENCE_SALE_NPC`, `OPS_BRIBE_NPC`, `OPS_BRIBE_CORE`, `SOC_EMBEZZLEMENT` (03 §3.12.14 finding (a)).
- `descriptionKey` = `reason.<CODE>` (i18n key).
