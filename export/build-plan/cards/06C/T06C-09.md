## Implementation steps
1. Views: pure, zod args; privacy (L11, D109): wallets, vaults, health factors, queued ops only for `viewer.entityIds`; liquidation events and DeFi aggregates without identities; class panels via `registerViewExtension('ast.asset', '06C', …)` (peg status, hype gauge, chain, supply, staking APR).
2. `createCryptoModule`: `resolveAssetPorts` + `defaultStablePorts`; register op executors, the LP_TOKEN valuer and the port extension (`hype`, `otherVenueLnP`, `oraclePrice`, preTradeGate CRYPTO branch: LIC1 long, no short) at module load; `defineModule({ id: '06C', module: '06', dependsOn: ['05', '06A'], tables: ALL_06C_TABLES, streams: [...STREAMS_06C], phases, boundaries, intents: CRYPTO_INTENTS, events: CRYPTO_EVENTS, views: CRYPTO_VIEWS, genesis: [genesisCrypto, genesisPools, genesisLendingMarkets] })`.
3. Phase order: P2 each tick: `memeSpawnStep`; hourly (t mod 30 == 0): `hypeHourly`, `cryptoAnchorStep`, `hypeCampaignSignal`, `memeLauncherStep`, `npcLpStep`, `custodyStep`, `bridgeStatusStep`. P4: `minerSellOrders`. P6 (after 05 and after 06A/06B): `oracleStep` → `npcKeeperOps` → `venueArbOps` → `runBlocks` (all chains; executors of T06C-01…08) → `bridgeArrivals` → `stableStatusStep` → `cdpLiquidationStep` → `closeAuctions`. P13: `assertBridgeInvariant` and pool-reserve mirror checks (tick fails on violation). DAY_CLOSE: `dailyIssuance`, `npcStakerStep`, `processFiatQueue`, `cdpDailyStep`, `mirageSavingsStep`, `vestingStep`, `memeDeathStep`, `playerTokenDelistStep`; CHAPTER: AUC halving flag.
4. `assets/index.ts`: build order 06A, 06B, 06C; after the three module factories have run (they register port extensions at module load), create the instrument port and pass it to `createMarketsModule({ instruments })` from `packages/engine/index.ts`.
5. Posting audit (06#45): a test helper replays a full-content world and checks every 03 posting produced by a 06 handler (`ctx.moduleId` in {06A, 06B, 06C}) uses a code from 03's catalog with the right template (TRANSFER, FAUCET, SINK, MOVE_QTY/mint/burn), and that per tick per currency Σ postings = declared faucet − sink totals (20's invariant hook). The gaps of `_unit.md` (no SINK+burn template for `DEFI_NETWORK_FEE`, no quantity template for `CRY_TOKEN_MINT`/`CMDTY_SPOILAGE`, missing `CRY_TOKEN_LAUNCH_FEE`) are asserted as known-gap allowances that fail once 03 adds them (so the allowance is removed).
6. Benchmark (06#46): `apps/harness/bench/assets06.bench.ts` builds a world with the full 400-instrument universe, 2,000 materialized option series (spread over GX100 and the top-40 names), 50 live DeFi pools (24 launch + 26 synthetic), 20k agents generating the harness's standard order and op mix; measures 06A+06B+06C P2/P4/P6/P13 work per partition per tick over 2,000 ticks; target ≤ 60 ms p95 per partition per tick (19's budget); reports the per-handler breakdown.
