## Goal
The value layer inputs 06 owns for crypto: each token's fundamental `V` (06 §3.11.2) written as the 05 anchor with pull half-life 120 game days (stables and ORE 1 game day), the per-token hourly hype process `H ∈ [0, 1]` with its drift bonus and volatility multiplier passed to 05 through the instrument port (`hype`), the NPC-spawned meme coins of §3.11.4 (Poisson spawns capped at 2 per game week and by the instrument cap, a seeded Tidepool pool, launcher behaviour, death after 7 days of thin liquidity), and the surveillance signal for hype campaigns while holding (X14).

## Implementation steps
1. Fundamentals (§3.11.2), hourly in P2: AUC `S2F = supply/annualIssuance` (T06C-01 issuance × 364), `adoption` = active-wallets index normalized so genesis = 0: `activeWallets_t/activeWallets_0 − 1` (decision; 16 + players' wallets with ≥ 1 op in the last 7 game days), `v0 = PARAM.auc_v0` (22: 34,000). LTX/MRD `A` = 7-game-day EWMA of executed ops on that chain (players + NPC) from block results. SYN from 11's AI-race index; GRD from compute utilization × power utilization (average of bloc reserve-margin-based utilizations), `norm` = genesis value of `(cu·pu)^0.7` so V = v0 at genesis. GOV tokens (FRO, TDP, ARC, QLL, VSG, MSH) = annualized protocol fee revenue × 12 / circulating supply (verbatim; MSH also gets T06C-06's Mirage term); VXT = Vault Exchange 91-day fee revenue (16 via `WorldPort06`; default from 05 fees on `ven_VAULTX`) × 4 × 0.3 × 15 / supply; ORE = gold spot; stables = T06C-06's `V` (peg × solvency). MEME: V from hype only (no fundamental: `lnF = ln lastPrice` with half-life 365). Write `lnF` to `ast.anchor` with the class half-lives (05 κ uses `anchorHalfLifeDays` from PriceParams; crypto majors and others 120, stables and ORE 1).
2. Hype (§3.11.3), per token per game hour (`dt_h = 1`): `m` = normalized Wire mentions (16 via `WorldPort06.mentions`, 0–1, default 0); `f = clamp(net player buy volume over 24 game hours / circulating market cap · 20, 0, 1)` from 05 fills where the buyer/seller is a player; `shock` = 16 news template and 09 Media-campaign shocks (`WorldPort06.hypeShock`, default 0); `H ← clamp(H + 0.15·(m + f − H) − b·H + shock, 0, 1)`, `b = 0.03` (MEME 0.06). Genesis H from 22 (default 0.3; meme 0.6 at spawn). Port member `hype(store, assetId)` → H; 05 applies `drift_bonus = c·H` (c 0.5/yr, MEME 3.0) and `vol_multiplier = 1 + 2H`.
3. X14 surveillance: when a 09 Media campaign (`hypeShock` with a campaigner id) raises H while the campaigner's beneficial-owner group holds the token (or sells within 2 game days after), emit `mkt.surveillance.signal` SEALED `{pattern: 'HYPE_CAMPAIGN_HOLDING', actors, evidence}`.
4. Meme spawns (§3.11.4): each tick in P2, `u < rate/(7·720)` with `rate = PARAM.meme_spawn_per_game_week` (2), `u` from `rng('ast.crypto_hype', 'MEME_SPAWN', tick)` (02 registry has no `meme` stream; registry gap `ast.meme` reported, this key is the fallback), hard cap 2 spawns per game week and `canSpawnNpcInstrument` (`max_live_instruments`, edge 21). Spawn: name and ticker from 22's meme generator (stream `content/meme`, 22-owned); supply log-uniform 10⁹–10¹² (draw from the same stream key); NPC launcher entity `npc_MEME_<seq>`; Tidepool CP pool seeded with `U($20k, $200k)` of LTX and 50% of supply; `H0 = 0.6`; asset `memeId(seq)` cls CRYPTO kind MEME, LIC1 long; `mkt.meme.spawned` PUBLIC.
5. Launcher (hourly): while H > 0.4 sell the remaining allocation into the pool at 20% of that hour's pool volume (block ops by the NPC; same ordering rules); the first game hour H < 0.15 (and each later re-crossing) abandon with probability 0.5 (draw `ast.crypto_hype`, key memeId+tick) → stops all activity. NPCs are not prosecuted (16).
6. Death: pool liquidity < $1,000 FDL-equivalent for 7 consecutive game days → status DELISTED (removed from discovery and 05 listings), tokens stay in wallets, mark 0; `mkt.meme.dead` PUBLIC. The "90% to ~0 within a chapter" target is a 20 balance band, not a rule.

## Test plan

  - hype: H 0.5, m 0.6, f 0.2, non-meme, no shock → 0.5 + 0.15·0.3 − 0.03·0.5 = 0.53; meme with the same inputs → 0.515; clamp at 0 and 1; `flowTerm(1e6, 1e8)` = 0.2.

  - X14: a campaign while holding emits one SEALED signal; no holding → none.
  - port: `createInstrumentPort().hype(store, memeId)` returns H.
