## Goal
Implement 19 Rule 3.7.8 and the replay action of 19 §4.2: any tick range (at most `replay_max_ticks` = 8,640, 12 game days) can be replayed in an isolated harness world from the nearest earlier snapshot and the archived batches (cold object storage for old ticks), the recomputed TickRecord hashes must match the recorded ones, and the result is exposed only through views filtered by the requester's visibility (SEALED evidence hidden unless 13's discovery revealed it, §8 edge 27; threat E22). Then the client sandbox of Rule 3.17.4: the engine runs in a Web Worker from a local seed for the Academy, tutorials and the replay viewer; results are unranked and non-transferable, and the server writes only Academy completion flags and sandbox badges (19#57, threat E24).

## Implementation steps
1. Request (19 §4.2): authenticated; the requester must be a party (`party_ids` contains the character) to at least one event in the range, or staff with a ticket (21); `toTick − fromTick + 1 <= replay_max_ticks`; `toTick` must be committed; audit row for staff requests. The job is queued on BullMQ (jobs service).
2. Source: the nearest earlier snapshot per partition (DAILY within 48 days, else the 1-per-real-day warm set, else CHAPTER forever, Rule 3.7.6), batches from `intent_batch` for the last game year, else the cold archive in object storage; the partition map active at the snapshot tick from `world.partition_map`.
3. Isolated run (Rule 3.7.8): a harness-role process (read-only on `world`, no live bus subjects, no write path to any player table) restores the snapshots, replays batches with the recorded engine version per TickRecord and compares each tick's `worldHash` with the recorded TickRecord; any mismatch stops with `HASH_MISMATCH`, an alert and a case file (it never shows a divergent replay).
4. Views: frames are built from the replay's events and deltas through 02's visibility filter for the requester; SEALED events appear only when `discoveryAllows` (13) says the requester may see them (§8 edge 27); staff with a ticket see what the ticket's scope allows. The "Why it moved" ladder data for 17 and 18 is attached when `focus` is given.
5. Sandbox (Rule 3.17.4): `apps/web/lib/sandbox/sandbox.worker.ts` (the only web path allowed to import `@tycoon/engine`, T19A-04) runs `createTestWorld`-style local worlds from a local seed with 02's sandbox entropy; it has no socket and no HTTP client except the two sandbox write endpoints. Server side, `acceptSandboxWrite` is the only gate through which sandbox output reaches the platform: Academy lesson completion flags (18) and sandbox-only cosmetic badges; any other write tagged as sandbox is refused `SANDBOX_NOT_TRANSFERABLE`. No sandbox output is ever a `sys.*` input or an intent. In sandbox mode Held is off and replaced by the fine, op ban and record (13's rule, Rule 3.17.4 default).
