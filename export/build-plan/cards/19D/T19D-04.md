## Goal
Run player AIs on servers as 19 Rule 3.11 requires: strategy graphs only (no user code, Rule 3.11.1, threat E7), compiled at `lab.graph_save` into compact bytecode and rejected at save when over the limits (Rule 3.11.2, 19#16), executed by a pure interpreter that charges each block's DU before running it and stops at the block boundary when the per-tick allowance runs out (Rule 3.11.3, 19#15, threat E8), in P5 across a worker pool whose size never changes results (Rule 3.11.4, 19#14), with the uniform scale factor of `sys.load_scale` when partition demand exceeds `du_partition_cap` (Rule 3.11.5). Also the NPC execution plumbing of 19 §6: NPC internal intent ids, the per-partition NPC work budget and per-class caps.

## Implementation steps
1. No user code (Rule 3.11.1): a `GraphDoc` is data only (nodes referencing catalog block ids, edges, constants of primitive types); the compiler refuses unknown block ids; iteration exists only through `ForEachSymbol` over at most 50 symbols; nothing is evaluated with `eval`, `Function` or dynamic import (the T19A-03 determinism lint already forbids them in `packages/engine`).
2. Compile (Rule 3.11.2): build the DAG, reject cycles, compute depth (longest path in edges) and max fan-out; violations return 11's codes and the save is rejected at P1 of `lab.graph_save` (never at run). Topological order breaks ties by node id; constant folding evaluates pure blocks whose inputs are all constants; `hash = sha256(canonEncode(bytecode))`.
3. Interpret (Rule 3.11.3): for each node in order, if `duUsed + node.du > allowance` stop with `stoppedAt` = that index; else charge and evaluate. Outputs never produced are "no signal"; unused allowance does not carry over. The view is a frozen per-tick snapshot of committed state the agent may read (prices, own positions, signals its model has access to); writes are only proposed intents with `localSeq` counted per agent per tick.
4. Pool (Rule 3.11.4): `W = ai_workers_per_partition` resolved from the text `cores − 2` as `max(1, os.availableParallelism() − 2)` on the host; jobs are sharded by `workerFor`; each worker runs its agents in agentId order; results are merged and sorted by `(agentId, localSeq)` before the P6 inbox; worker count and scheduling never affect content or order. Workers receive bytecode and a structured-clone view; a worker crash fails the tick (safe-mode ladder of T19B-09), never drops agents silently.
5. Scale-down (Rule 3.11.5): the effective allowance is `floor(allowanceDu × duScale)` where `duScale` comes from the `sys.load_scale` input committed for this tick (default 1); COORD computes it from the previous tick's measured `du_demand{partition}` against `du_partition_cap` (3,000,000; the 11-owned value), so behaviour is deterministic. Diegetic effects belong to 11 and 06.
6. NPCs (19 §6): NPC internal intents use `npcIntentId`, pass the same validators and matching as player intents, are not stored in the batch and are recorded in the PHASE stream and as events (T19B-08); `NpcBudget` with `npc_du_per_tick_per_partition` (500,000) is created per partition per tick and offered to owner modules through PhaseCtx; when it binds, owners aggregate background NPCs (16); per-class caps registered by owners are checked on every internal intent and never exempt NPCs from per-asset order caps. Harness bots are external SDK clients, not NPCs (§6 item 5).

## Test plan
`sg.test.ts` (fixture block catalog of 12 blocks standing in for 11's, each with a DU cost):
- `19#16 Saving a graph with 401 nodes or depth 33 is rejected at save with the module's error code`: a 400-node graph compiles; 401 nodes -> one violation `NODES` with 11's code; a chain of depth 32 compiles, depth 33 -> `DEPTH`; fan-out 17 -> `FANOUT`; `ForEachSymbol` over 51 symbols -> `FOREACH`; a cycle is rejected; the same graph doc always compiles to the same `hash`.
- `19#15 An agent with allowance 2,000 DU running a graph whose full evaluation costs 3,000 DU stops at the block boundary at or below 2,000 DU every tick`: a 30-block graph of 100 DU each, allowance 2,000: over 50 ticks `duUsed === 2000` and `stoppedAt === 20` each tick, nothing carries to the next tick; with block costs 300 DU, `duUsed === 1800` (stops before exceeding); with `duScale = 0.5`, `duUsed === 1000`.
- `npcIntentId` stable for fixed inputs; `NpcBudget(500000)` refuses the charge that would exceed it.
`pool.test.ts` (worker threads, 3,000 agents with random graphs from a seeded generator, 20 ticks):
- `19#14 P5 with 1, 4 and 16 workers produces identical proposed intents and identical state hashes`: proposed intent lists (canonical bytes) identical for W = 1, 4, 16 at every tick, and the headless world's `worldHash` identical for the three runs; a worker crash at tick 7 aborts that tick and the retry produces the same result.
