## Goal
Prove the capacity and deploy rules of 19 against staging with production-shaped hosts: the launch target (5,000 CCU and 40,000 agents on one world host for 72 real hours, zero missed ticks, p99 tick work < 2.5 s; 19#52), the architecture target (synthetic 100,000 CCU and 750,000 agents on the partitioned deployment for 24 real hours, p99 tick work < 2.5 s, delta p95 < 500 ms; 19#53), a full rolling deploy during 5,000-CCU bot load with zero missed ticks and p99 lateness < 500 ms (19#26, Rule 3.16.1), per-client bandwidth <= 4 KB per tick for a typical active client (19#34, Rule 3.8 delta design) and the "whole world buys one stock" hot asset clearing inside the P6 budget on one MARKET partition (19#54, Rule 3.13.2). The swarm uses `packages/sdk` with player-level permissions only (19 Rule 3.10.3 item 4, 19 §6 item 5).

## Implementation steps
1. Swarm: each bot is a full SDK client with its own account (staging accounts minted by a jobs fixture), session key and nonce store; personas drive intents per tick and subscriptions; AI_OWNER bots save strategy graphs so player-AI agents run in P5 (the "agents" count = players + player AIs, Rule 3.13.1); bots run only on staging worlds with player-level permissions. Bots respect the shared rate bucket; rejects are counted by code.
2. Measurement: server-side from the metrics of Rule 3.15.1 (`ticks_missed_total`, `tick_commit_lateness_ms`, `tick_phase_ms`, `delta_bytes_per_tick`) and client-side delta latency (tick commit time from `tick` message vs arrival, using `ClockSync`). Tick work = sum of phase wall times of the critical path (P0..P14) per tick.
3. Launch (19#52): one world host (>= 32 cores) plus warm standby, 5,000 CCU, 40,000 agents, 72 real hours (51,840 ticks); pass: `missed === 0`, `tickWorkP99Ms < 2500`.
4. Architecture target (19#53): partitioned deployment sized by `shapeFor` (30 PLAYER partitions for 750,000 agents) over about 40 hosts; 100,000 synthetic sockets (`syntheticLoad`) with 5% full SDK sessions, 750,000 agents (mostly player-AI agents driven by graphs plus scripted intents at the persona rate); 24 real hours; pass: `tickWorkP99Ms < 2500`, `deltaP95Ms < 500`.
5. Deploy under load (19#26, Rule 3.16.1): 5,000-CCU swarm running; `rollService` for gateways, web, projector, jobs in `ROLL_ORDER`, then an engine upgrade at the next boundary (T19D-02); pass: `missed === 0`, `latenessP99Ms < 500` over the drill, and every bot reconnects with resume (no delta gap, `disconnects` only from planned gateway drains).
6. Bandwidth (19#34): one ACTIVE_TRADER client for 1 game day (720 ticks) at the normal load mix; total bytes received over the socket divided by ticks.
7. Hot asset (19#54, Rule 3.13.2): in one tick 100,000 limit orders from 100,000 distinct bot characters on one asset; the asset's MARKET partition alone runs P6; P6 wall time must be within `phase_budget_ms_P6`. In staging through the gateway; in CI as an in-process test with the 05 auction on a headless world.
