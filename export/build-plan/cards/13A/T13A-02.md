## Goal
One pure function computes every fine, so spending down before trial (13 §15 #1) never helps, money cannot buy a verdict, and no verdict or chapter takes more than its cap. No reads, no RNG, bigint only.

## Imports
- T13A-01: `TIERS`, modifier and cap constants. T02-04: `roundHalfEven`, `divHalfEven`, bigint helpers. T14A-02: `realToNominal`.

## Exports
```ts
export interface FineInput { severity: Severity; nwOffense: Money; nwVerdict: Money; priorConvictionsThisChapter: number;
  plea: boolean; msiPpm: bigint; finesThisChapter: Money; peakNwThisChapter: Money; otherFinesThisVerdict: Money }
export interface FineResult { base: Money; afterModifiers: Money; amount: Money; cappedBy: 'NONE'|'TIER_CAP'|'VERDICT_35'|'CHAPTER_60'; nwBasis: Money }
export function computeFine(i: FineInput): FineResult;           // no Reputation parameter, by type
export function statutoryMinimumRestitution(severity: Severity, msiPpm: bigint): Money;   // tier floor × 2
```

## Implementation steps
1. `nwBasis = max(nwOffense, nwVerdict)`; negative NW counts as 0.
2. `base = clamp(nwBasis × pct, floor, cap)` in bigint ppm with half-even rounding (cap null for S6).
3. Modifiers: repeat ×1.5 per prior conviction this chapter, product capped at ×2.5; then plea −30%. The punching-down multiplier applies to damages, not fines (13 §3.2), so it is out of scope here.
4. Caps in order: tier cap, then this verdict's total fines ≤ 35% of nwBasis, then chapter total ≤ 60% of peak NW. Report which bound bit. The floor never lifts a fine above a cap. Where floor > cap room, the cap wins (conservative; open question).
5. Amount is never negative; the result is the fine owed. Collection against the `protected_floor_cash_real` floor ($7,300 × MSI, E-45) is T13A-04. % caps win over tier $ floors (E-31a): AC-13A-02-CAPWIN: tier floor $50,000, NW $100,000, 35% cap → fine 35,000, not 50,000.
