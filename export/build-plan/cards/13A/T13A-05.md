## Goal
Held freezes a character; it never wipes them. The timing is exact and bounded, and Held never exists outside the online world. It tells other modules what changes during Held (businesses at 70%, AIs and standing orders keep running) without owning their logic.

## Exports
```ts
export function scheduleHeld(ctx: PhaseCtx, chrId: Id, caseId: Id, sanctionId: Id, reason: 'S5'|'S6'|'THIRD_S4', verdictTick: Tick): HeldRow | null;
export function heldStep(ctx: PhaseCtx): { started: Id[]; ended: Id[] };   // P11 each tick: emit start/end
export function isHeldAt(read: StoreRead, chrId: Id, tick: Tick): boolean;  // startTick <= tick < endTick
export function businessOutputFactorPpm(read: StoreRead, chrId: Id, tick: Tick): number; // 700_000 when Held, else 1_000_000
export function heldScreen(read: StoreRead, chrId: Id, tick: Tick): { until: Tick; remainingTicks: number } | null; // 14 Held screen data
```

## Implementation steps
1. If `ports.worldKind() !== 'ONLINE'` → return null and write nothing (13#12).
2. `startTick = verdictTick + held_grace_ticks` (720).
3. Duration = HELD_TICKS[S5|S6] (THIRD_S4 uses S5's 6 h, open question) + 6 h × prior Held this chapter; cap 24 h per verdict, then the chapter's remaining room from 48 h. Room 0 → no Held, record `truncatedBy`.
4. Overlap: a second Held while one is pending or active is appended after the current `endTick` (one row per chr, extended); caps still apply.
5. Held never crosses a chapter boundary: truncate at the chapter end tick (open question 6).
6. `heldStep` emits `law.held_started` at startTick and `law.held_ended` at endTick, both PUBLIC.
7. During Held, 09 reads `businessOutputFactorPpm`; AI mandates (11) and standing orders (05) are not blocked by the gate (T13A-06). Margin liquidations during Held use 05's fair-value band (05 owns this; 13A only exposes `isHeldAt`).
