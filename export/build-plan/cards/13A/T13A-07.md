## Goal
Ship 13A as a module of its own: register tables, phases, directives, events, views and invariants, wire the 14A ports, and give 13B and other modules a TestWorld helper to sanction a character.

## Exports
```ts
export const lawSanctionsModule: ModuleDef;        // id '13A'
export function sanction(world: TestWorld, chrId: Id, severity: Severity, kinds: SanctionKind[]): Id[];
export function holdChr(world: TestWorld, chrId: Id, ticks: number): void;
export const INVARIANTS_13A: InvariantDef[];       // INV-LAW-001..003
```

## Implementation steps
1. `defineModule('13A')`: tables from T13A-01; phase P11 runs `heldStep`, then pending collections; DAY_CLOSE runs `runGarnishment` after 03's income totals; `sanctionGate` exported as a service (`services.law.gate`).
2. `adm.law.apply_sanction { order }` and `adm.law.lift { sanctionId }` (19 Rule 3.11 admin input, approvals per 21). These are the only non-13B paths, and they are logged.
3. `invariants.ts`: INV-LAW-001 (Held bounds and sandbox off), INV-LAW-002 (no 13A posting below the floor), INV-LAW-003 (fine basis is the max NW), each with a negative test (20 Rule 3.9.4). The verdict-function part of INV-LAW-004 is left to 13B and stays registered by 13B.
4. View `me.sanctions` (PRIVATE): active sanctions, Held countdown (`heldScreen`), garnishment plans (owed, collected, rate), freezes. Public view `law.held_list` lists only `{chrId, until}` for currently Held characters.
5. `testing.ts`: `sanction(world, chrId, severity, kinds)`, `holdChr(world, chrId, ticks)`.
6. 14A wiring: `resolvePorts({...LAW_PORTS_FOR_14A})` in the world composition.
