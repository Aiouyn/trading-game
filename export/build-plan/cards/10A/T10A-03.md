## Goal
The authoritative physical city: same seed and package → same bytes. It runs in a worker, never in the tick, and the client never runs topology.

## Imports
- T02-06 xoshiro128** streams `(cityId, regionId, stage, featureId)`. Personality files (T10A-02). The prototype algorithms in `prototypes/cities/src/gen.js` (`generateCity`, line 29), `avalon-roads.js`, `roadgraph.js` and `junction-mesh.js` are the reference implementation to port (JS, float, client-side).

## Exports
```ts
export function generateMacroPlan(city: CitySeed, seed: bigint): MacroPlan;
export function generateRegion(plan: MacroPlan, regionId: Id, contracts: BoundaryContract[]): RegionOutput;   // parcels, buildings, streets in integer cm
export const GENERATOR_PACKAGE: string;   // pinned version id
```

## Implementation steps
1. Port the prototype pipeline to TypeScript with integer-cm topology and robust integer predicates; floats only in noise and land-value fields, quantised before decisions. No DOM, no `Math.random`, no clock.
2. Stages 1–9 of 10 §3.19.3 (stage 10 'life' stays client-side cosmetic, as in the prototype).
3. Regions of 512–2,048 m with boundary contracts; chunks of 128 m cut after generation for streaming.
4. Output is persisted per region (19 tables) and never regenerated by replay.
5. Parcel ids `pcl_<city>_<persistentFeatureSeq>`; the renderer's coordinate key (`<rendererKey>:<seed>:p:<qx>:<qy>:<qrot>`, `parcel-id.js`) is stored alongside as `rendererParcelKey` for the seam (T10A-09).
