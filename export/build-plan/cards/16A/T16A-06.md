## Goal
Make every follow-on effect an explicit, recorded link from a cause to an effect, fired by the owner module, so news and 'Why it moved' can trace any chain to its root.

## Imports
- T16A-02 queue, T02-13 next-tick boundary hooks.
- Owner hooks via `ports.owners` (09, 10, 07, 04, 05, 06, 08, 11, 13, 14).

## Exports
```ts
export const LAUNCH_RULES: readonly ConsequenceRule[];      // C01..C20, magnitudes 'Quant'
export function onCommittedEvent(ctx, e: EngineEvent): void;  // spawn PendingConsequence (≤ 12 per event)
export function fireDue(ctx): void;                            // P3, (dueTick, pcId) order
export function chainTo(read, eventId: Id): CausalLink[];      // back to root (05 explainMove, archive)
```

## Implementation steps
1. `dueTick = eventTick + U(lag)` from `rng('world.news', eventId)`.
2. Firing: evaluate magnitude, call the owner hook, record `CausalLink`, emit `world.consequence.fired`; an owner veto records `world.consequence.vetoed` with its reason. `recordOnly` effects write only the link (no double count).
3. Stop at depth `consequence_max_depth` or when magnitude < 2% of root; at most 12 pending per event.
4. Rules C01-C20 are data; trigger kinds owned by 16B/16C (succession, election, bill, breakthrough) are present but never match until those units emit them. Magnitudes are E-28 §5 (PROVISIONAL): C01/C02 employment ±jobs/LF, housing **recordOnly** (the employment channel already moves it), supplier orders ±site B2B share, rent index ±0.3× employment change; C03 +0.2; C04 +50 bp; C05 layoffs U(0, 8%); C06 wage +x, prices +0.5x; C07 mortgage 1.0× surprise, turnover −10% per +1 pp; C08 input = spike × sector weight, CPI 0.1× spike × CPI weight; C09 reconstruction 0.5× insured loss, population U(0, 2%); C11 ±distance × 50 bp; C12 +5% starts per 0.1 density; C13 0.5% of exposed jobs per level; C15 as C02; C16 +25 bp per notch, bank mark 1.0×; C17 +outage share × 2; C18 +1–3 GD, 2% premium; C19 −10% ENT/TRANSPORT, +5% HEALTH/TECH, labour −2%; C10/C14/C20 probabilities as written.
