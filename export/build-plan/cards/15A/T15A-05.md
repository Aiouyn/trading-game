## Goal
Price contracts and cap value flows so that new accounts and suspected alts cannot be used to funnel wealth.

## Imports
- T15A-02 `suspectPair`. T03-09 postings. T03-17 rank-basis NW. T14A-08 account age.

## Exports
```ts
export function notionalReal(ctr: ContractRow, read): Money;
export function registrationFee(notional: Money, msiPpm: bigint): Money;
export function p2pTax(amount: Money, sameBeneficialOwner: boolean, kind: FlowKind): Money;
export function p2pCapRemaining(read, payerChrId: Id, tick: Tick, payeeId?: Id): Money;
export function chargeP2P(ctx, payer, payee, amount, kind): Reject|null;   // used by every P2P flow incl. 14 gifts
```

## Implementation steps
1. Registration fee = clamp(0.5% × notionalReal, $100, $5M) × MSI, paid by the offering party at activation. Waived for a LIVE hosted-event pair (14B port).
2. P2P tax is 2% on one-directional value between different beneficial owners. Exempt: loan principal, escrow returns, and flows within the same beneficial owner. Collateral seizure is taxed as the debt it settles.
3. Daily cap per payer, by account age:
   - under 7 real days: $10,000
   - 7–20 days: $1M
   - 21 days or more: max(10% of rank-basis NW, $1M)
   - all real × MSI; loan principal counts 50%; inflows are uncapped
   - the window is a rolling 17,280 ticks per payer (E-25): a ring of 24 hourly buckets (720 ticks each) with a running sum, O(1) amortised per charge. The current bucket is rotated lazily, and expired buckets are subtracted from the sum. Precision: a charge is held to the cap over the last 24 full hourly buckets plus the current one (conservative: at most 720 extra ticks of memory, never less).
4. A suspect pair is limited to $10,000 per real day between them.
5. `chargeP2P` is the single entry point for every P2P money flow. INV-SOC-003 checks that each P2P posting has a cap-ledger row.

## Test plan
  - **15#24** fee on notionals $10k / $1M / $2B gives $100 / $5,000 / $5M; P2P tax is 2% on rent and 0 on principal.
  - **15#25** an account aged 3 days is refused at $10,000.01; at day 25 the cap is max(10% NW, $1M).
  - **15#43** a suspect pair is capped at $10,000 per real day.
  - **AC-15A-05-INV** (INV-SOC-003) a forged P2P posting that bypasses `chargeP2P` fails the invariant (negative test).
  - **AC-15A-05-ROLL** (E-25): the window is rolling, not the calendar day. Boundary-burst test for an account aged 3 real days (cap $10,000):
    - $9,000 at calendar-day end − 10 ticks, then $2,000 at day start + 10 ticks → the second payment is refused (and $1,000 is allowed).
    - A payment of $10,000 is allowed again once the first burst has left the window (+17,280 ticks, plus at most one bucket).
    - The running sum equals a brute-force recomputation over 100k random charges.
    - Each charge costs O(1) amortised (benchmark: a constant number of bucket operations).
