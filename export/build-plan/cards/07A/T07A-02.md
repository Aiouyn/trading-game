## Goal
One collateral table serves margin, repo, central-bank eligibility, PB and loans (07 §3.15.6, D129): classify every asset into a collateral class, give its base haircut and eligibility per venue, apply the fear stress multiplier, the issuer concentration add-on, the Lombard ×1.5 rule and active 04 haircut shocks. Then build the **single pledge registry** every 07 product uses (loans, Lombard, repo, PB, securities lending collateral, 07B margin, 15 contracts through 07), which encumbers units so they cannot be sold or pledged twice, and the **re-use link** records for title-transfer products. Both FATAL invariants INV-BS-006 (no double pledge) and INV-BS-007 (re-use only where allowed, chain ≤ `PARAM.inv_rehypo_max_chain`) are implemented here.

## Implementation steps
1. `collateralClassOf` (07 §3.15.6): CASH in account currency → `CASH_SAME`, other currency → `CASH_OTHER`; government bonds/bills: bills with issuer rating AA− or better (`AA` or `AAA` grade) → `GOVT_BILL`; rating below A (BBB and lower, incl. SRL in stress when 08 rates it so) → `GOVT_BELOW_A`; linkers → `GOVT_LINKER`; tenor ≤ 10y → `GOVT_2_10` (tenors under 2y that are not bills also map here); > 10y → `GOVT_10_30`; corporate bonds rated ≥ BBB → `CORP_IG_LE5`/`CORP_IG_GT5` by tenor 5y, else `CORP_HY`; equities GX100 → `EQ_LARGE`, other equities `EQ_OTHER`; ETFs by underlying `ETF_EQUITY`/`ETF_BOND`; GOLD and ORE → `GOLD`; AUC, LTX → `CRYPTO_MAJOR`; GUSD, EUNX → `STABLE_FIAT`; tranches AAA → `TRANCHE_AAA`, AA..A → `TRANCHE_AA_A`, BBB → `TRANCHE_BBB`; collectibles LIMITED/UNIQUE → `COLLECTIBLE`; everything else `INELIGIBLE`. Rating = `FundsPort07.rating`, fallback `pdBand(issuerPd)` (06A) when 08 is absent.
2. Base haircuts and eligibility exactly as the table: base `CASH_SAME 0, CASH_OTHER 0.08 (0.20 if either currency is SRL), GOVT_BILL 0.005, GOVT_2_10 0.02, GOVT_10_30 0.04, GOVT_LINKER 0.03, GOVT_BELOW_A` = the tenor row + 0.10, `CORP_IG_LE5 0.05, CORP_IG_GT5 0.08, CORP_HY 0.15, EQ_LARGE 0.15, EQ_OTHER 0.25, ETF_EQUITY 0.15, ETF_BOND 0.08, GOLD 0.15, CRYPTO_MAJOR 0.40, STABLE_FIAT 0.10, TRANCHE_AAA 0.10, TRANCHE_AA_A 0.20, TRANCHE_BBB 0.35, COLLECTIBLE 0.50`. CCP eligibility per service: CASH and GOVT rows all services (GOVT_BELOW_A eligible unless a CCP suspension fact is set by 07B); CORP_IG only OTC and REPO; EQ_LARGE, ETF rows LD only; EQ_OTHER not CCP; GOLD LD and CRY; CRYPTO_MAJOR and STABLE_FIAT CRY only; tranches, HY, collectibles not CCP. Tri-party/PB/bilateral: all rows yes except CRYPTO_MAJOR and STABLE_FIAT (PB only) and COLLECTIBLE (no). Lombard: all rows except STABLE_FIAT, tranches (no) and COLLECTIBLE ("loans only": eligible for venue LOAN, not LOMBARD). CB venue uses the CCP column for GOVT and CORP_IG (07 §3.7.5 default) and 04 may widen it: when `up.macro` exposes a crisis widening, accept its list (absent → CCP column).
3. Stress: `h = min(0.95, (h_base + shockPts) · (1 + κ_venue · fear))`, fear = `up.macro.fear`. Lombard: `h_base' = lombardBase(cls, h_base)` before the stress step. Concentration: an issuer whose posted value is > 25% of the account's posted collateral takes `+0.10` added after the stress step (then min 0.95). Shock points from active `repoHaircutShock` hooks (`deltaPts / 100` per hook, summed) for the class.
4. Rating cliff: `refreshCollateralClasses` runs in the DAY_CLOSE boundary (P2 of t = 719's next boundary run, before T07A-08's daily loop) and writes `bnk.coll_class`; `haircutFor` reads the cached class when present (so a downgrade during the day changes the class only at the next day close) and computes it on the fly for never-cached assets.
5. Pledge registry: one `CollateralPledge` row per pledge. `canPledge` sums active pledges of the same unit: SECURITY by `(pledgorId, assetId)`: Σ pledged qty + new qty ≤ holder qty (`up.ledger.qty` of the holder's position account) + received re-use capacity (only when the pledgor received the units with re-use allowed); PROPERTY/BUSINESS: multiple liens allowed, each with increasing `lienRank` (first lien ranks first, 07 §8 edge 12) but a second pledge to the **same** secured party for the same unit is a double pledge (`BNK_ENCUMBERED`); COLLECTIBLE and CASH: at most one active pledge (cash by amount ≤ balance); RECEIVABLES: Σ frac ≤ 1. `createPledge` also pushes the encumbrance so 06's sale path blocks: `BankPort06.pledgedQty` (implemented in T07A-20) returns `pledgedQty` here, which 06/05 subtract from sellable quantity (07 §9 Y11).
6. Re-use (07 §3.12.5): `openReuse` checks `REUSE_ALLOWED[product]` (else `BNK_COLLATERAL`), depth = parent depth + 1 (root = 1), rejects when depth > `PARAM.inv_rehypo_max_chain` (default 1; 07's "finite, acyclic, ends at the legal holder" is satisfied by this bound) and when the edge would form a cycle (toId equal to any ancestor's fromId) or when Σ open links from `fromId` for the unit exceed what it received. PB re-use is additionally capped by T07A-18 at `pb_rehypo_cap × debitBalance` by value. The legal holder keeps the security on its balance sheet as encumbered (03 position account unchanged); the receiver books only an obligation to return (no 03 position movement in this task: repo and PB tasks post `REPO_COLLATERAL` qty moves where 03 requires them).
7. INV-BS-006 (TICK FATAL): over `post` state, for every unit key, the active pledges satisfy step 5 (SECURITY: Σ pledged + repo out + lent ≤ holder qty + received re-use capacity; COLLECTIBLE/CASH ≤ 1 active pledge; RECEIVABLES Σ frac ≤ 1; no two active pledges of one unit to one secured party). Report `entityIds` = pledgor ids, observed = the over-pledged unit and totals.
8. INV-BS-007 (TICK FATAL): every open `ReuseLink` has `REUSE_ALLOWED[product]`, depth ≤ `ctx.num('inv_rehypo_max_chain')`, its chain of parents is acyclic and ends at a link whose `fromId` is the `legalHolderId`, and per (fromId, unit) Σ open child qty ≤ qty received. Check only units written this tick (`writeSet` of `bnk.pledge`, `bnk.reuse`, `bnk.repo`, `bnk.pb`) plus a full sweep at DAY_CLOSE scope (cost class bounded).
9. Edge 19 (07 §8): when an original borrower defaults, each link closes out against its own counterparty: `closeReuse` closes descendants depth-first so each holder's obligation resolves in order; T07A-15 uses it.
