## Goal
Deliver `@tycoon/protocol`: the one package shared by client, gateway, world and SDK. It holds the deterministic canonical encoder (MessagePack variant of 02 §3.16.2, used for hashing, snapshots, batches, messages and the event store), the RFC 8785 canonical JSON used for intent signatures (19 Rule 3.9.1), zod schemas for the intent envelope, intent results, client and server messages and delta ops (19 §2.3, §2.4), decimal-string codecs for money/price/quantity, and the registries in which every module later registers its intent kinds and event kinds. The package imports nothing but zod (19 Rule 3.1.2).

## Imports
- T19A-01: workspace, `@tycoon/config` presets.

## Implementation steps
1. **Canonical MessagePack (`canon/msgpack.ts`)**, rules of 02 §3.16.2 made exact:
   - `null` -> 0xc0; `false/true` -> 0xc2/0xc3.
   - JS `number`: if `!Number.isFinite` throw `CanonError('NON_FINITE')`. If `Object.is(x, -0)` encode as integer 0. If `Number.isSafeInteger(x)`: smallest MessagePack int form (positive fixint 0..127; negative fixint -32..-1; then uint8/16/32/64 for positives, int8/16/32/64 for negatives, choosing the first that fits). Otherwise float64 (0xcb + 8 bytes big-endian). Never float32.
   - `bigint`: ext type 1 (0xd4..0xd8 fixext when length is 1,2,4,8,16 else ext8/16/32), data = sign byte (0x00 for ≥ 0, 0x01 for < 0) followed by the big-endian magnitude with no leading zero bytes (zero magnitude = no bytes, so `0n` = sign byte only, length 1 -> fixext1 `d4 01 00`).
   - `string`: UTF-8 via TextEncoder; fixstr/str8/str16/str32 smallest form.
   - `Uint8Array`: bin8/16/32.
   - Arrays: fixarray/array16/array32; elements in order. `undefined` inside an array throws `UNDEFINED`.
   - Plain objects (prototype `Object.prototype` or null): drop keys whose value is `undefined`; sort remaining keys by the UTF-8 bytes of the key (lexicographic, shorter prefix first); fixmap/map16/map32. Keys must be strings.
   - `Map`/`Set`/class instances/functions/symbols: throw `UNSUPPORTED_TYPE` (engine code passes `SortedMap` contents as arrays of `[k, v]`, 02 owns that conversion).
   - Encoder writes into a growable `Uint8Array` buffer (start 256 bytes, double on demand); no `Buffer`, no Node imports.
2. `canonDecode` accepts only canonical input: rejects non-minimal ints, float32, unsorted or duplicate map keys, and ext types other than 1 with `CanonError('BAD_INPUT')`. ints outside the safe range decode only as ext-1 bigints, so a uint64 > 2^53-1 is `BAD_INPUT`.
3. **Canonical JSON (`canon/json.ts`)**, RFC 8785: objects with keys sorted by UTF-16 code units (use `cmp` on `charCodeAt`, never `localeCompare`); no whitespace; strings escaped as JSON.stringify does for a single string (RFC 8785 uses the same escaping); numbers serialized with the ECMAScript Number-to-String algorithm (`String(x)` equals JSON number output for finite numbers; `-0` -> `0`; non-finite throws `NON_FINITE`); `bigint` throws `UNSUPPORTED_TYPE` (money travels as decimal strings, 00 §3.1); `undefined` properties omitted.
4. Scalars as in Exports. `fromWireBig('-0')` is rejected (grammar forbids it). `ulidTimeMs` decodes the 10 leading Crockford characters (alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`).
5. `envelope.ts`: IntentSchema fields and types exactly as 19 §2.3: `intentId` Ulid, `actorId` IdStr, `onBehalfOf?` IdStr, `mandateId?` IdStr, `kind` string ≤ 64 chars matching `^[a-z]+(\.[a-z0-9_]+)+$`, `payload` unknown, `clientTick` TickNum, `tickPolicy`, `nonce` non-negative safe integer, `sessionKeyId` string ≤ 64, `channel`, `signature` base64url ≤ 128 chars. `.strict()` (unknown fields rejected, 19 Rule 3.9.2). IntentResultSchema as 19 §2.3 with `rejectParams` record of strings each ≤ 256 chars.
6. `messages.ts`: one zod object per variant of `ClientMsg`, `ServerMsg`, `DeltaOp` in 19 §2.4, each `.strict()`, combined with `z.discriminatedUnion('t' | 'op', …)`. `tickMs` is the literal 5000. `intentAck.status` uses `INTENT_ACK_STATUS` (19 §2.4 list plus `REJECT_STALE` from 19 Rule 3.4.2). `path` strings are JSON-pointer-like: `^(/[A-Za-z0-9_.:~-]+)*$`, ≤ 256 chars. `req.op` ≤ 64 chars. String fields get a max length (locale ≤ 35, sessionToken ≤ 128, appVersion ≤ 32, tz ≤ 64).
7. `registry.ts`: module-level sorted arrays (keep sorted on insert with `cmp` on code units). `registerIntentKind` requires `kind`'s first segment in `INTENT_NAMESPACES`; `registerSystemKind` requires `sys` or `adm`; event kinds may use any lowercase namespace (`core`, `sys`, `adm`, and module namespaces). Duplicate kind -> throw `Error('DUPLICATE_KIND <kind>')` (this is build-time registration, not engine control flow). `parseIntentPayload` returns zod issue paths joined as strings, never the payload values.
8. `codes.ts` and `index.ts` re-export everything in Exports.
9. No `Date`, no `JSON.stringify` in canon code paths, no Node imports; `package.json` dependencies: `zod` only.

## Test plan
`canon/msgpack.test.ts` (exact bytes, hex):
- `canon 1 small ints`: `0` -> `00`; `127` -> `7f`; `128` -> `cc80`; `-1` -> `ff`; `-33` -> `d0df`; `65536` -> `ce00010000`; `-0` -> `00`.
- `canon 2 float`: `0.5` -> `cb3fe0000000000000`; `1.5` -> `cb3ff8000000000000`.
- `canon 3 bigint ext1`: `0n` -> `d40100`; `255n` -> `d50100ff` (fixext2: sign 00, magnitude ff); `-256n` -> `c703010101 00` written out as bytes `c7 03 01 01 01 00` (length 3 = sign + 2 magnitude bytes, so ext8).
- `canon 4 map key order`: `{b:[true,-1], a:1}` -> `82 a161 01 a162 92 c3 ff`; insertion order of keys does not change bytes; `{a:undefined, b:1}` equals `{b:1}`.
- `canon 5 strings`: `'é'` -> `a2c3a9`; a 32-byte ASCII string uses `d9 20 …`.
- `canon 6 rejects`: NaN, Infinity -> NON_FINITE; `new Map()` -> UNSUPPORTED_TYPE; `[undefined]` -> UNDEFINED.
- `canon 7 decode strictness`: `cc05` (non-minimal 5) -> BAD_INPUT; map `82 a162 01 a161 01` (unsorted) -> BAD_INPUT.
- Property (fast-check, `fcRuns()`): for random JSON-like values with bigints, `canonEncode(canonDecode(canonEncode(v)))` equals `canonEncode(v)`; encoding is independent of object key insertion order (shuffle keys).
`canon/json.test.ts`:
- RFC 8785 example: `{"numbers":[333333333.33333329,1E30,4.50,2e-3,0.000000000000000000000000001],"string":"€$\u000f\nA'B\"\\\\\"/","literals":[null,true,false]}` canonicalizes to `{"literals":[null,true,false],"numbers":[333333333.3333333,1e+30,4.5,0.002,1e-27],"string":"€$\u000f\nA'B\"\\\\\"/"}`.
- key order by UTF-16 units: an object with keys '€' (U+20AC), CR (U+000D), '1' (U+0031) and '😀' (first UTF-16 unit 0xD83D) serializes its keys in the order CR, '1', '€', '😀'. Assert that order.
- bigint throws.
`scalars.test.ts`: `toWireBig(-1234567n) === '-1234567'`; `fromWireBig('007')` throws; `ulidTimeMs('01ARZ3NDEKTSV4RRFFQ69G5FAV') === 1469922850259`.
`messages.test.ts`: every ClientMsg/ServerMsg variant round-trips through its schema; an `intent` message with an extra field fails; `hello` with `protoVersion: '1'` fails; `signingBytes` of an intent without `onBehalfOf` contains no `onBehalfOf` key and its JSON starts with `{"actorId":`.
`registry.test.ts`: duplicate kind throws; `mkt.order.place` accepted, `foo.bar` rejected for intents; `intentKinds()` returned sorted; `parseIntentPayload` on an unknown kind returns BAD_SCHEMA.
