## Goal
Make the determinism coding standard of the engine machine-enforced. A custom ESLint plugin `tycoon` with the rule set `tycoon/deterministic` runs on `packages/engine/**` (and on `packages/params/src/**`, `packages/content/src/**`, which the engine loads) and fails CI on every forbidden construct of 19 Rule 3.6.2 / 02 §3.7.1 / GLOBAL-CONTEXT G8. This closes acceptance test 19#2.

Spec reconciliation (decided here): 19 Rule 3.6.2 lists `Math.sqrt` as forbidden and `Math.round` as allowed, 02 §3.7.1 and GLOBAL-CONTEXT G8 say the opposite. 02 owns the engine coding standard and G8 is binding for code shape, so: `Math.sqrt`, `abs`, `floor`, `ceil`, `trunc`, `min`, `max`, `sign`, `fround`, `imul`, `clz32` are allowed; `Math.round` is forbidden (use `roundHalfEven`). Every other forbidden item of 19 Rule 3.6.2 is enforced.

## Implementation steps
1. `no-nondeterministic-globals`: report any reference (identifier read, member root, `new`, call) to `Date`, `performance`, `setTimeout`, `setInterval`, `setImmediate`, `queueMicrotask`, `process`, `globalThis`, `window`, `self`, `global`, `Intl`, `crypto` (except imports from the relative path or module `@tycoon/engine/core/crypto`, which is the vendored pure SHA-256/Ed25519 of 19 Rule 3.6.2), `WeakMap`, `WeakRef`, `FinalizationRegistry`, `Atomics`, `SharedArrayBuffer`, `Symbol` (call), `require`; any member call `.localeCompare(` or `.toLocaleString(` / `.toLocaleDateString(` / `.toLocaleTimeString(`; any `import` from a Node built-in (`node:*`, `fs`, `path`, `os`, `net`, `http`, `https`, `child_process`, `worker_threads`, `crypto`, `timers`, `perf_hooks`, `process`, `url`, `util`, `events`, `stream`, `zlib`, `dns`, `tls`, `dgram`, `cluster`, `module`, `vm`, `buffer`) and dynamic `import()`. Use scope analysis so a local variable named `process` is not reported.
2. `no-raw-math`: allow exactly `Math.sqrt|abs|floor|ceil|trunc|min|max|sign|fround|imul|clz32` and constants `Math.PI|E|LN2|LN10|LOG2E|LOG10E|SQRT2|SQRT1_2`; report every other `Math.*` member (including `random`, `round`, `exp`, `log`, `pow`, `sin`, `cos`, `tan`, `atan`, `atan2`, `cbrt`, `hypot`, `expm1`, `log1p`, `sinh`, `cosh`, `tanh`, `asin`, `acos`, `log2`, `log10`) and the `**` operator when either side is not an integer literal (`2 ** 53` allowed; `x ** 2` reported: use `x * x` or `dmath.pow`). Message names the dmath replacement (`round` -> `roundHalfEven`, `random` -> RNG streams).
3. `no-unordered-iteration`: report `for…in`; calls `Object.keys(…)`, `Object.values(…)`, `Object.entries(…)` and `Reflect.ownKeys(…)` when the result is iterated (used in `for…of`, spread, `.forEach/.map/.reduce/.filter/.some/.every/.flatMap`, `Array.from`) unless directly wrapped in `sortBy(…)` or followed by `.sort(cmp…)` with a comparator; `for…of`, spread, `Array.from` and `.forEach` over an expression whose TypeScript type is `Map`, `Set`, `ReadonlyMap` or `ReadonlySet` (requires type information: enable `parserOptions.projectService`). `SortedMap`/`SortedSet` (02) are classes not named Map/Set and are allowed.
4. `sort-needs-comparator`: `.sort()` and `.toSorted()` with no argument are errors; a comparator that is an arrow function whose body is `a - b` / `b - a` on operands typed `number` is reported with "subtraction comparator may be inconsistent with NaN; use sortBy" (19 Rule 3.6.2 bullet 3); a comparator calling `localeCompare` is already reported by rule 1.
5. `no-async`: report `async` functions and arrows, `await`, `Promise` references, generator functions (`function*`, `yield`), `.then(` calls.
6. `no-json-stringify`: report `JSON.stringify` and `JSON.parse` (engine reads and hashes only through `canonEncode`/`canonDecode`).
7. `no-number-money`: report `Number(x)`, `parseFloat`, `parseInt`, unary `+x` where `x` has TypeScript type `bigint` or a type alias named `Money`, `Qty` or `Price` (type-aware); report `BigInt(x)` where `x` is typed `number` unless the call is inside a file under `packages/engine/core/fixed/` or the enclosing function is named `toMoney`, `toQty` or `toPrice` (02 §3.9.2: those are the only float -> integer conversions).
8. `index.mjs`: export `base`, `deterministic`, `plugin`. Root `eslint.config.mjs`: `[...base, ...deterministic]` plus ignores `**/dist/**`, `**/.next/**`, `docs/**`.
9. All rule files are plain ESM JavaScript with JSDoc types (no build step), each with `meta.type = 'problem'`, `meta.docs.description`, `meta.schema = []`.

## Test plan
`packages/config/eslint/plugin/rules.test.ts` uses ESLint's `RuleTester` (flat config, `@typescript-eslint/parser` with a tiny tsconfig fixture so type-aware rules work). For each rule at least 3 valid and 3 invalid snippets, including:
- invalid: `const t = Date.now();`, `new Date()`, `performance.now()`, `Math.random()`, `Math.round(x)`, `Math.exp(1)`, `x ** 0.5`, `for (const k in o) {}`, `Object.keys(o).forEach(f)`, `for (const [k] of new Map()) {}`, `arr.sort()`, `arr.sort((a, b) => a - b)` with `number[]`, `async function f() {}`, `JSON.stringify(x)`, `a.localeCompare(b)`, `import fs from 'node:fs'`, `Number(m)` with `m: Money`, `BigInt(0.5 * 3)` outside fixed/.
- valid: `Math.sqrt(x)`, `Math.floor(x)`, `2 ** 53`, `sortBy(Object.keys(o), k => [k])`, `arr.sort(cmpStr)`, `for (const [k, v] of sortedMap.entries())` with a class `SortedMap`, `import { sha256 } from '@tycoon/engine/core/crypto'`, a local `const process = 1; process + 1`.

A final case writes a clean file and asserts `errorCount === 0`.
  - **AC-19A-03-STR010** (E-22 addendum): an AST rule `tycoon/no-random-reward` forbids any RNG call (`Math.random`, `crypto.getRandomValues`, `randomInt`, the engine `rng.*` streams) in files under `**/rewards/**` in `packages/engine` and `apps/web`; reward functions are constants or table lookups.
