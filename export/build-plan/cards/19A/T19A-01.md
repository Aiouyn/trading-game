## Goal
Create the empty-but-working monorepo that every later task writes into: pnpm workspaces, Turborepo pipeline, pinned Node 24 toolchain, shared TypeScript, Vitest (with fast-check) and Prettier presets in `packages/config`, one `package.json` per package and app of 19 Rule 3.1.1, and the docker compose file of the `local` environment (19 Rule 3.18.1). After this task `pnpm -w lint`, `pnpm -w typecheck` and `pnpm -w test` exist and run green on the empty tree. Later tasks of 19A add the lint rules, protocol skeleton and CI.

## Imports
None (first task of the build).

## Implementation steps
1. Root `package.json`: `"private": true`, `"packageManager": "pnpm@10.x.y"` (pin the exact version you install), `"engines": { "node": ">=24 <25" }`, scripts as in Exports, devDependencies pinned exactly (no `^`): `turbo`, `typescript` (5.x latest stable), `vitest`, `fast-check`, `eslint` (9.x, flat config), `typescript-eslint`, `prettier`, `tsx`. `.nvmrc` = `24`. `.npmrc`: `save-exact=true`, `engine-strict=true`.
2. `pnpm-workspace.yaml`: `packages: ["apps/*", "packages/*"]`.
3. `turbo.json`: tasks `build` (dependsOn `^build`, outputs `dist/**`, `.next/**`), `lint` (dependsOn `^build`), `typecheck` (dependsOn `^build`), `test` (dependsOn `^build`), `verify:static`, `test:contract`, `test:replay`, `test:partition`, `e2e:smoke` (no cache for the last four), `dev` (persistent, no cache).
4. Create every package and app folder listed in Exports with a `package.json` (name, `"type": "module"`, scripts `lint`, `typecheck`, `test` with `vitest run --passWithNoTests`), a `tsconfig.json` extending the right preset (engine.json for `packages/engine`, `packages/protocol`, `packages/params`, `packages/content`; next.json for `apps/web` and `apps/admin`; node.json for the rest), and `src/index.ts` exporting nothing but a `export {};` line. Do not write any game logic. For `packages/engine` add an `exports` map with every subpath in Exports pointing at `./<folder>/index.ts`, and create each module folder with an `index.ts` containing `export {};`.
5. `packages/protocol/package.json` dependencies: only `zod` (4.x, exact). `packages/engine` dependencies: `@tycoon/params`, `@tycoon/content`, `@tycoon/protocol` (workspace:*), nothing else. Record these as the starting dependency sets; T19A-04 enforces them.
6. `packages/config/vitest/preset.ts`: returns `{ test: { environment, include: include ?? ['**/*.test.ts'], pool: 'threads', testTimeout: 30000, reporters: ['default'] } }`. Every package's `vitest.config.ts` calls `definePreset()`.
7. `packages/config/vitest/fast-check.ts` as in Exports (20's 200 cases per property on PRs, 10,000 nightly).
8. `packages/config/scripts/check-workspace.ts` (run by `verify:static` of `@tycoon/config`): reads `pnpm-workspace.yaml` and every `package.json`, fails (non-zero exit with a message per problem) when: a folder of 19 Rule 3.1.1 is missing; a package name is not `@tycoon/<folder>`; a dependency version contains `^` or `~`; a package has no `lint`/`typecheck`/`test` script; two packages pin different versions of the same external dependency.
9. `infra/local/docker-compose.yml` (19 Rule 3.18.1 `local`): services `postgres` (image postgres:18, port 5432, db `tycoon`, schemas created by later migrations), `nats` (nats:2 with `-js`, port 4222), `valkey` (valkey/valkey:8, port 6379), `minio` (port 9000, bucket `tycoon-local` created by an init container), `clickhouse` (port 8123). `.env.example` lists `DATABASE_URL`, `NATS_URL`, `VALKEY_URL`, `S3_ENDPOINT`, `S3_BUCKET`, `CLICKHOUSE_URL`, `TYCOON_DEV_TICK_MS=5000` (the dev-only fast clock `PARAM.dev_tick_ms`; real value read through `@tycoon/params` by the world host, this env var only overrides it in `local`).
10. `docs/README.md`: one page that states the layout of 19 Rule 3.1.1 and the commands. `docs/spec/README.md`: says the specification files are placed in this folder verbatim and are read by verification scripts; copy the 25 spec files into `docs/spec/` if they are available to you, otherwise leave the README and report it.
11. Root `tsconfig.json` uses project references to every package (so `tsc -b` works for editors); package `typecheck` scripts stay per package.

## Test plan

  - the real repository passes.
