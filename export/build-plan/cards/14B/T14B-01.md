## Goal
Types, tables, reject codes, event schemas and reason-code bindings for everything in module 14 that 14A did not build. 14B adds its own tables keyed by `characterId` (14A design: no 14B field lives on the 14A `CharacterRow`). It extends 14A's `acct.title` table (`titleAwardTable`, which so far holds only `T_PHOENIX`) with the full `TitleAward` fields instead of creating a second title store.

## Imports
- T14A-01: `CharacterRow`, `Rank`, `titleAwardTable`, `TitleAwardRow`, `REJECT`, constants, `validEntityId`.
- T14A-02: `CODES_14A`, `realToNominal`, `msiPpm`, `CharacterPorts`.
- T03-02 / T03-05: `getCatalog()`, the 24 §8 alias table (`LIFE_BOUTIQUE_PURCHASE → LIFE_PURCHASE`, `LIFE_DONATION → LIFE_CHARITY`, `LIFE_NPC_BUYBACK → LIFE_RESALE_TO_NPC`).

## Implementation steps
1. Numbers that are fractions in the spec (condition, Reputation, Notoriety, upkeep rates) are stored as integers scaled by 1e6 (G3 rule "rates persisted as integer rateE6"); math happens in float64 inside pure rules and converts once.
2. Extend `titleAwardTable` rows with `chapter`, `scope`, `personaGeneration`, `houseTitle` (default for the existing 14A `T_PHOENIX` row: chapter of its tick, scope 'PERSONAL', generation 1, false). Migration is a pure read-time default; no rewrite of 14A rows.
3. `CODES_14B` maps every 14 §3.17 code to the catalog: `LIFE_BOUTIQUE_PURCHASE→LIFE_PURCHASE` (ELASTIC_OUT with `valueLegA` asset recognition, which also covers `LIFE_ITEM_RECOGNIZE`), `LIFE_ITEM_MARK→LED_LIFESTYLE_DEPRECIATION` (REVALUE ACCRUE), `LIFE_NPC_BUYBACK→LIFE_RESALE_TO_NPC`, `LIFE_DONATION→LIFE_CHARITY`; identity for `LIFE_UPKEEP`, `LIFE_STAFF`, `LIFE_CLUB_DUES`, `LIFE_HOSTING`. Ledger errata E-22 added catalog rows (owner 14, amounts 'Quant sign-off') for the 14 names that had none, so `CATALOG_GAPS_14B` is `[]`: `LIFE_EDITION_SALE`, `LIFE_STORAGE`, `LIFE_RESTORATION`, `LIFE_SECURITY`, `LIFE_RENT`, `LIFE_EXPERIENCE`, `LIFE_BERTH_RENT`, `LIFE_HANGAR_RENT`, `LIFE_SLOT_RENT_P2P`, `LIFE_HOSTING_REFUND`, `ACCT_HOUSE_FEE`, `ACCT_STARTER_GIFT`, `ACCT_INHERITANCE_TAX`, `ACCT_DELETION_ESCHEAT`.
4. Ids: items `ctx.newId('itm')`, houses `ctx.newId('hse')`; item and house ids are not ledger entities, but they still must pass `validEntityId` (cheap and keeps one id grammar).
