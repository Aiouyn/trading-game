## Invariants (20 §3.1, added by ledger errata E-22)
INV-CHR-012 Reputation stays in [0, 100] and every change has a `life.repevent` row and a `life.reputation.changed` event. INV-CHR-013 Notoriety stays in [0, 100] and never feeds breach, detection, verdict, fine or price. INV-CHR-019 philanthropy Reputation gained per chapter ≤ `rep_philanthropy_chapter_cap`.

## Goal
Trust (Reputation, public) and crime fame (Notoriety, private unless opted in) as two separate axes (§1 goal 4). Every module emits typed events; 14 owns the numbers and the scaling `Δ_eff = Δ × (100 − R)/50` for gains and `Δ × (0.5 + R/100)` for losses. This task consumes the 14A handoff message `life.reputation.event { kind: 'FRESH_START', delta: -10 }`.

## Imports
- T14A-09: message `life.reputation.event`. 14A ports `linkedCharactersOf`, `chapterOf`. Event schemas from 13, 15, 16, 11, 08, 12 (fixtures).

## Implementation steps
1. `onRepEvent`: look up the kind; ignore events whose counterparty is linked (15 §3.12.2 effect; inert until 15); apply weekly caps per kind (reset at the real-week boundary) and the chapter philanthropy cap (cap applies to the effective delta); write `RepEventRow`, emit `life.reputation.changed` PUBLIC with the public line key. `FRESH_START` (−10) from 14A uses this path unchanged.
2. Drift: R < 50 and no negative event in the last real week → +0.5 (DIPLOMAT heir trait +1), never above 50.
3. Notoriety: `CONVICTION_CONVERT` halves N and sends a Reputation event of `−0.2 × removed` (14#27); `DECAY` −2 per real week without an op; `SUCCESSION` × 0.25 (T14B-09).
4. 14#28 static check: a test parses 13's verdict, fine and fee function modules (import graph) and asserts no import of `repOf` (INV-LAW-004 is 13's; this test protects 14's export).
5. Exploits §9 #3, #4 (hosting and contract farming): weekly caps, unlinked and value floors are enforced here on the incoming events.

Inert linking. **AC-14B-07-INERT** (Producer ruling, E-22): with `DEFAULT_PORTS.linkedCharactersOf` (15 not present) no pair is linked, so ignoring Reputation events between linked accounts (CONTRACT_HONORED, HOSTED_EVENT_ATTENDED and others) is inert; this is the intended state until 15 provides the port, and no 14B code changes when it does. Fixture `fixtures/linkPorts.ts` re-exports 14A's `NO_LINKS` and `linkedPair(a, b)`.
