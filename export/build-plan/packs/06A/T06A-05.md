## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. Declarations come from `ports.companies.declaredActions(store, tick)` (09) each tick in P2; for CASH_DIVIDEND validate: `exTick` is the t = 60 tick of a trading day ≥ 2 game days after announce, `recordTick = exTick − 1`, `payTick ≤ exTick + 5·720`; invalid declarations are stored CANCELLED with an `mkt.corp.announced` payload `status: 'CANCELLED'` (09 must resubmit). Valid → `ast.corp_action` ANNOUNCED, emit `mkt.corp.announced` PUBLIC.
2. Record snapshot at the DAY_CLOSE boundary of the record day (P2 at t = 719): `holdersOf(asset)`; every `qty > 0` gets `Entitlement{amount = toMoney(qty·cashPerShare)}` (cashPerShare is a Price in micro-units; `amount = notional(qty, cashPerShare, lotScale)`); every `qty < 0` gets a `manufactured: true` row with the identical per-share amount (X12). Shares lent out by a lender are not in the lender's position (03), so the lender's compensation is the borrower's manufactured payment that 07 posts using `manufacturedDividendsDue`.
3. Ex-date: `exDateActions(tick)` returns `{assetId, kind: 'DIVIDEND', dividendPerShare: cashPerShare as number, effectiveTick: exTick}` so 05 drops the reference price at the opening auction (05 §3.21 applies its own order-adjustment rule); 06 also sets `markEquityDirty` and lowers the equity anchor by the same `ln(1 − d/P)` via `writeAnchor` with `changedBy = actionId` so the drop is not pulled back.
4. Pay (P2 of payTick): for each long entitlement in holder-id order, `ctx.ledger.pay(issuerId, holderId, amount, ccy, 'EQ_DIVIDEND', {refs: [actionId]})`; emit `mkt.dividend.paid` PARTIES `{assetId, holder, amount}`. If `drip`: buy `floor(amount / dripPrice)` lots from `npcCounterpartyId(bloc)` via `ctx.ledger.swapAsset(holder, npc, asset, qty, cost, ccy, 'MKT_TRADE')`, the fractional remainder stays as cash. STOCK_DIVIDEND: `ctx.ledger.moveQty(issuer, holder, asset, qty·stockPerShare floored to lot, 0n, ccy, 'EQ_STOCK_DIVIDEND')`, shares outstanding increased in the same tick. If the issuer's posting fails for insufficient cash, report via `ctx.fail` is NOT used: dividends are declared by 09 only when payable; a failed posting is 03's rejection and 06 marks the action CANCELLED and emits `mkt.corp.effective {status:'CANCELLED'}`.
5. `electDripHandler`: validate holder of the asset (qty > 0) and `tradeGate(...,'BUY')` (LIC1); apply at P1: `EquityState.drip.set(actor, on)`.
6. Splits: `splitTriggerStep` at DAY_CLOSE for NPC issuers only: official close `> eq_split_trigger` → `streakUp++` else reset; at 20 → schedule SPLIT 5:1 (or 10:1 when close > 5000) effective at t = 0 of the next trading day; close `< 1` for 20 days and status not DISTRESSED → REVERSE_SPLIT 1:10. Player companies split only via 09 declarations. `applySplitEffective` at t = 0 (P2): `splitPositions(ctx, asset, num, den, 'EQ_SPLIT')`; `sharesOutstanding`, `freeFloatShares` scaled; `EquityState.epsFwd` and anchor divided by ratio (anchor `lnF − ln(num/den)`, `changedBy = actionId`); emit `mkt.corp.effective` PUBLIC with the full action so 05 (orders), 07 (locates, loans) and 06B (option strikes ÷ ratio, multipliers × ratio) adjust. Return SPLIT rows to 05 through `splitActionsForMarket`.

# SPEC EXCERPTS (verbatim; binding game rules)

**[06 §1 Purpose]** (context)

## §1 Purpose

This module defines **every tradeable thing in the world** and the rules that are specific to its asset class: what an instrument is (fields), what it is worth (its fundamental value, which 05's price model pulls toward), how it pays (dividends, coupons, funding, settlement), how it is created and destroyed (listing, series generation, issuance, expiry, default, delisting), who may trade it (licenses), how it is marked for net worth, and every class-specific event (earnings, splits, credit events, depegs, auctions).

Division of labour, binding:
- **05** owns *how* prices move tick to tick (the return equation, GARCH, jumps, factor model, batch auction, NPC market makers, square-root impact, halts). 06 owns *what* each asset's fundamental value `V_i` is, its class parameters (`PriceParams`, §3.21), and everything that is not the generic order book: OTC and RFQ fills (P6), DeFi venues, primary auctions, collectible auctions, option exercise, futures settlement, perp funding, coupons and corporate actions.
- **07** owns margin, collateral haircuts, securities lending, repo and the Clearing House. 06 tags each instrument with its `marginClass`, `collateralClass` and `clearing` service.
- **08** owns ETF creation and redemption, rating agencies, securitization tranches and fund units. 06 defines ETF and index instruments and their NAV.
- **09** owns company decisions (dividend amount, buybacks, issuance, M&A, bankruptcy, IPOs). 06 executes the security-level consequences.

Design laws (from 01 §0 and V3 T1–T3, kept):
1. Every price has a cause a player could have seen or inferred. Each class's `V_i` is a function of world state, never a random walk.
2. Parities hold by construction where they hold in reality (forward = CIP, put-call parity via NPC arbitrage, ETF ≈ NAV, cross FX from legs). Residual arbitrage after fees is ≤ fees.
3. Each class differs where the difference creates a decision (MASTER-BIBLE T02): fundamentals, sentiment, liquidity, financing, sessions and liquidation rules.
4. Defaults, depegs and failures are **mechanical outcomes of balance sheets**, never dice rolls with a fixed probability.

**Status of numbers:** every `PARAM.*` value in this module, and every choice tagged `DEFAULT`, is `DEFAULT (Mathis may override)`. Locked decisions L1–L15 (00) and the 00 time model are not defaults. The full list is in `_notes/06-notes.md`.

#### §3.4.4 Dividends (decision by 09, execution here)
- Declaration publishes `cashPerShare`, `exTick` (≥ 2 game days after announce, at t = 60 of that day), `recordTick = exTick − 1`, `payTick` (≤ 5 game days after ex).
- At the ex-date opening auction, 05 subtracts `cashPerShare` from the reference price and from resting limit prices of orders on that asset (resting stops and limits are adjusted, not cancelled).
- Entitlement: holders with `qty > 0` at the close of `recordTick`. Lent shares: the borrower's account pays a manufactured dividend equal to the dividend to the lender (07 §3.13.6). Shorts pay the same amount.
- Pay: P13 of `payTick` posts `EQ_DIVIDEND` from the issuer to each holder (03 classifies the flow).

**[06 §3.4.5]** (from spec file 06-ASSET-CLASSES.md)

#### §3.4.5 Splits, offerings, buybacks
- NPC issuers split 5:1 when `P > PARAM.eq_split_trigger = 1000` currency units for 20 consecutive trading days, 10:1 above 5,000. Reverse split 1:10 when `P < 1` for 20 days and the company is not DISTRESSED. Player companies split only by 09 decision.
- On a split effective at t = 0: all positions, lots, resting orders, locates and loans scale by the ratio; option strikes divide by the ratio and multipliers multiply by it.
- Secondary offerings and rights: 09 decides size; 06 runs them through `PrimaryAuction` with `UNIFORM_PRICE` (§3.7.6) and a 1-game-week Wire notice for player companies (ROADMAP 2.1).
- Buybacks are company orders submitted by 09 into 05, capped at 1% of float per game day for player companies.

**[05 §3.21]** (from spec file 05-MARKETS-PRICE-ENGINE.md)

### §3.21 Instrument lifecycle and corporate actions
- **Listing** (06/09 IPO): an asset becomes tradeable with an opening (IPO) auction whose reference is the offer price; the band for the IPO auction is ±50%.
- **Splits and consolidations** (06): at P2 of the effective tick, all resting order prices and quantities, stop prices, trailing peaks, pool positions, ADV and price history are adjusted by the ratio; fractional lots are rounded down and the remainder cancelled.
- **Dividends**: on the ex-date open, `lnV`, `lnF` and `lnB` drop by `ln(1 − d/P)`; resting buy limits are not adjusted (`DEFAULT`, as most real venues), GTC sell stops are not adjusted.
- **Delisting, suspension, bankruptcy** (09): state SUSPENDED; all orders cancelled with `ASSET_SUSPENDED`; positions remain and are marked by 03's rules.
- **Index changes** (§3.22): announced 5 trading days before the effective day; MANDATE pool trades in the effective day's closing auction.
