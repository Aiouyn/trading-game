## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. `requiredLicense` encodes the 06 §3.2 table row by row (R15: 06 §3.2 is authoritative): collectibles LIC0; equities/ETFs/government bills LIC1 long, LIC2 short; spot launch crypto on the CEX LIC1, meme coins and every AMM/LP/lending/CDP/bridge act LIC2 (D115); bonds, FX spot, commodity spot and receipts LIC2 both sides; primary non-competitive LIC2, competitive LIC4; option buy LIC3, covered/cash-secured write LIC3, naked write LIC4; futures and perps LIC3 (leverage ≤ 10), perps 20× at LIC4; OIS/FX forwards and swaps/ZCIS/commodity swaps LIC3; CDS buy LIC3, CDS sell/TRS/XCCY/bilateral OTC/block desk LIC4; token launch LIC4 (+ R4 checked by 06C). `licenseShort === null` + act SHORT → `AST_NOT_SHORTABLE`.
2. `tradeGate` order of checks (first failure wins, all at P1): (a) Held (`isHeld`) → `AST_HELD` unless `opts.intentKind ∈ HELD_ALLOWED_INTENTS`; (b) license → `AST_NO_LICENSE` with params `{required}`; (c) restricted cash: if `isRestrictedBlocked(a.cls)` or act ∈ {BUY_PROTECTION, SELL_PROTECTION} or the action posts margin, and the actor's spendable cash net of restricted buckets (`ctx.ledger.available − restrictedCashOf`) is below the required amount, or `fundedFromRestrictedOnly` → `AST_RESTRICTED_CASH` (D113, 03 §3.5.6); (d) leverage: `maxLeverageFor` = base (10 LIC3, 20 LIC4 for perps) halved when `activeCaseSeverity ≥ 3`, then `min(·, PARAM.rookie_max_leverage)` during new-player protection; requested leverage above → `AST_LEVERAGE_CAP`. Return `maxLeverage` for 07.
3. `sessions.ts`: EQUITY open Mon–Fri with opening auction t=60, continuous 61–539, closing t=540; FX open from Monday t=0 to Saturday t=0 and Sunday from t=660 (06 §3.3.1; note 05 closes FX books all weekend per its own ruling, so 06 uses this only for 06-run FX forward/RFQ acceptance windows); CRYPTO every tick; FUT24 every tick Mon–Fri plus Sunday from t=660; OTC any tick Mon–Fri; AUCTION per-lot (always "open" for the auction engine); DISTRESSED one call at t=300 on trading days; NONE never. Coupon/maturity dates on weekends move to Monday t=719 via `nextBusinessDayTick`.
4. Settlement (§3.3.2, D095): document in `gates.ts` header and enforce by construction: every 06 trade is posted through `ctx.ledger.swapAsset`/`pay`/`moveQty` in the tick it executes (postings commit in P13); cross-partition legs use `ctx.holds` placed at P1 and released at P13 (edge 23). No settlement-fail state exists in any 06 table. X23: shorts require a locate, which is 07's (`BankPort06` is not consulted here; 05's order path calls 07's locate), and `tradeGate` refuses SHORT on `licenseShort === null`.
5. `marks.ts` implements the pseudocode of §3.3.3 exactly: model-valued classes call the registered `ModelValuer` (06B registers OPTION, SWAP, CDS; 06C LP_TOKEN); otherwise if `getPriceState(...).tick ≥ tick − PARAM.mark_stale_ticks` and a last batch price exists, clamp `lastPrice` into `[vOrMid·(1−b), vOrMid·(1+b)]` with `σ_tick = sigmaDailyOf(asset)/sqrt(720)`; else NPC mid (05 `lnB` via `getPriceState`); COLLECTIBLE → `collectibleMark`; `forLadder` on a player-company equity → `min(m, 3-game-day VWAP from dailyBars)`; DEFAULTED/DISTRESSED → last DISTRESSED auction price (T06A-09 stores it in `ast.bond`/`ast.asset.tags`), else 09 recovery estimate × face. Edge 22: on weekends equity marks are the Friday close (no batch price within the stale window and NPC mid frozen by 05). X1/X2: marks never use an unclamped last print.
6. `limits.ts`: `beneficialOwnerGroup` = `ultimateOwnerOf` → all `controlledEntities` of that owner ∪ members of `SocialPort06.linkedGroups(ownerGroupOf(owner))`, sorted. Long cap 25% of `freeFloatShares` of NPC companies; 49% of a player company for any group other than its controller unless `viaTender`; short-interest cap 50% of free float; perp per-owner ≤ `perp_max_oi_share` of open interest; CDS net protection sold ≤ 25% of the reference entity's debt outstanding. Reject codes `AST_POSITION_CAP` / `AST_SHORT_CAP`. Futures limits are T06B-06's.
7. Edge 25: every conversion to Money in 06 uses `toMoney` (half-even); every pro-rata uses `allocate`/`proRata` with remainders in hash order. Add a lint-style unit test that greps nothing; instead `limits.test.ts` checks `allocate` sums.

# SPEC EXCERPTS (verbatim; binding game rules)

**[06 §1 Purpose]** (context)

## §1 Purpose

This module defines **every tradeable thing in the world** and the rules that are specific to its asset class: what an instrument is (fields), what it is worth (its fundamental value, which 05's price model pulls toward), how it pays (dividends, coupons, funding, settlement), how it is created and destroyed (listing, series generation, issuance, expiry, default, delisting), who may trade it (licenses), how it is marked for net worth, and every class-specific event (earnings, splits, credit events, depegs, auctions).

Division of labour, binding:
- **05** owns *how* prices move tick to tick (the return equation, GARCH, jumps, factor model, batch auction, NPC market makers, square-root impact, halts). 06 owns *what* each asset's fundamental value `V_i` is, its class parameters (`PriceParams`, §3.21), and everything that is not the generic order book: OTC and RFQ fills (P6), DeFi venues, primary auctions, collectible auctions, option exercise, futures settlement, perp funding, coupons and corporate actions.
- **07** owns margin, collateral haircuts, securities lending, repo and the Clearing House. 06 tags each instrument with its `marginClass`, `collateralClass` and `clearing` service.
- **08** owns ETF creation and redemption, rating agencies, securitization tranches and fund units. 06 defines ETF and index instruments and their NAV.
- **09** owns company decisions (dividend amount, buybacks, issuance, M&A, bankruptcy, IPOs). 06 executes the security-level consequences.

Design laws (from 01 §0 and V3 T1–T3, kept):
1. Every price has a cause a player could have seen or inferred. Each class's `V_i` is a function of world state, never a random walk.
2. Parities hold by construction where they hold in reality (forward = CIP, put-call parity via NPC arbitrage, ETF ≈ NAV, cross FX from legs). Residual arbitrage after fees is ≤ fees.
3. Each class differs where the difference creates a decision (MASTER-BIBLE T02): fundamentals, sentiment, liquidity, financing, sessions and liquidation rules.
4. Defaults, depegs and failures are **mechanical outcomes of balance sheets**, never dice rolls with a fixed probability.

**Status of numbers:** every `PARAM.*` value in this module, and every choice tagged `DEFAULT`, is `DEFAULT (Mathis may override)`. Locked decisions L1–L15 (00) and the 00 time model are not defaults. The full list is in `_notes/06-notes.md`.

### §3.3 Sessions, settlement, marks, limits

#### §3.3.1 Session profiles (clock per 00 §5.1)
| Profile | Trading | Notes |

| OTC | RFQ any tick Mon–Fri; CDS and swaps; valuation hourly | |
| AUCTION | Per-lot close ticks (§3.18) | Collectibles |
| DISTRESSED | One call auction per trading day at t = 300 | Defaulted bonds, suspended equities, claims |

#### §3.3.2 Settlement
`DEFAULT (Mathis may override)`: **every trade settles delivery-versus-payment in P13 of the tick it matched** (T+0). There are no settlement fails, no failed-delivery state, no T+2 queue. Consequences: naked shorting is impossible (locate is required at P1), and a buyer can re-sell on the next tick. Cross-partition trades use hold → settle (02, 19); the hold is placed in P1 and released in P13.

#### §3.3.3 Mark price (used for net worth, margin, NWI and ladders)
```
markPrice(i, t):
  if cls ∈ {OPTION, SWAP, CDS, LP_TOKEN}: model value (§3.13.3, §3.16.4, §3.17.2, §3.12.2)
  elif last batch-clearing price exists within PARAM.mark_stale_ticks = 30:
       m = clamp(lastPrice, V_or_mid · (1 − b), V_or_mid · (1 + b)),  b = max(0.02, 4·σ_tick·√30)
  else m = NPC mid quote (05)
  COLLECTIBLE: appraisal (§3.18.2) × (1 − PARAM.collectible_mark_haircut = 0.10)
  player-company equity on ladders: min(m, 3-day VWAP) (ROADMAP 2.1; 15 owns ladders)
  DEFAULTED bond / DISTRESSED: last DISTRESSED auction price, else 09 recovery estimate
```
`V_or_mid` is the fundamental value from this module if the class has one, else the NPC mid. The clamp is what stops a thin-market print from moving everyone's marks or triggering liquidations (01 §9 "liquidation uses fair value with a band").

#### §3.3.4 Position and order limits (enforced in P1)
- Long position ≤ 25% of free float of an NPC company; ≤ 49% of a player company for anyone other than its controller, except through a tender (09).
- Aggregate short interest ≤ 50% of free float; orders that would breach it are rejected.
- Order size per tick ≤ 3 × ADV is 05's rule (auto-split).
- Futures spot-month and all-months limits (§3.14.5); perp position ≤ `PARAM.perp_max_oi_share = 0.10` of open interest per beneficial owner; CDS net protection sold by one owner ≤ 25% of the reference entity's debt outstanding.
- All limits apply to the **beneficial-owner group** (03 ownership chain: the character, its companies, funds it controls, and linked accounts flagged by 15's collusion graph).

## §8 Edge cases

1. **Zero or negative prices.** Spot and futures prices floor at one tick (01 §2.2): commodities cannot go negative (storage-full hubs reject purchases instead). Interest rates and bond yields may be negative if 04 sets negative policy rates; all formulas accept negative `z`.
2. **Index constituent halted** at rebalance: it stays in at its mark; units recalculated at the next quarter.
3. **Option expiry on a market holiday**: there are no holidays; weekends cannot be expiries by construction (Friday expiries).
4. **Underlying delisted before expiry** (merger): options adjusted (§3.13.5); futures cash-settled at the consideration value on the effective tick.
5. **Underlying bankrupt** with open options: settle in cash at the first DISTRESSED auction price (§3.4.6); puts pay, calls expire worthless unless ITM at that price.
6. **Bond coupon due while issuer short of cash** but within grace: no default yet; `mkt.credit.state` PD jumps to `max(PD, 0.5)`; if paid within grace, PD recomputes normally.
7. **Sovereign restructuring** (04): old bonds exchange into new bonds per 04's terms at P13 of the effective tick; CDS RESTRUCTURING event; linkers keep their indexation in the new bonds.
8. **FX controls during a pending forward settlement**: settlement occurs (contractual) but the controlled-currency proceeds cannot be converted until controls end; forward is not cancelled.
9. **Hub storage full** when a physical-delivery long elects delivery: election rejected; position cash-settles.
10. **Shipment lost**: receipt destroyed; insured value paid by 08 if insured; CDS-like contracts unaffected.
11. **Perp funding when index is stale** (CEX halted): funding for that interval = interest component only; mark = last index × (1 + EMA premium) frozen.
12. **Oracle stale** for > 60 ticks: lending pauses new borrows; liquidations use last price; if the true market has moved > 20%, the next fresh price can create bad debt, which is socialized (§3.12.4).
13. **Stablecoin issuer reserve bank fails**: ρ drops by the uninsured haircut (07); GUSD may depeg; PSM transmits to VSD; every protocol uses the oracle price of GUSD (not 1.00) from the next block.
14. **Chain congestion**: queued ops keep their order; an op whose `minOut` fails when executed later is rejected without moving funds (gas still charged).
15. **Bridge impaired while a transfer is in flight**: the in-flight amount is treated as locked (pro rata recovery) and the mint on arrival is scaled by `recoveryRatio`.
16. **Auction bidder becomes unable to pay** (cash moved after the hold): impossible, the bid hold reserves cash; if a court order (13) seizes held cash, the bid is voided and the next-highest valid bid wins at its own amount.
17. **Collectible destroyed or stolen** (12, 14): item flagged; owner's mark becomes 0 (or insured value receivable from 08).
18. **Consigned item becomes subject to a seizure order**: lot withdrawn without fee.
19. **Player company with CDS outstanding is taken private**: CDS continue on the private entity (its bonds remain); PD uses the unlisted method.
20. **Split crossing an exercise request**: exercise processed post-split with adjusted terms.
21. **Instrument cap reached** (§3.1.2): NPC spawns pause; no existing instrument is removed.
22. **Weekend gap**: equity marks freeze from Friday close to Monday open; Monday's opening auction may gap through stops; 07 margin uses the opening auction price with price protection (07 §3.16).
23. **Partition boundary**: an instrument's book lives in one partition (19); cross-partition orders are held and settled per 02.
24. **Lazy option series with no quotes requested** at expiry: nothing happens (no state existed).
25. **Rounding**: every conversion to Money uses `toMoney` with round-half-to-even (00 §3.1); pro-rata allocations distribute remainders in hash order so the sum equals the total exactly.

### §3.8 Pre-trade validation (P1)

In this order; the first failure rejects the intent with its code (§4.2):
1. Schema, ids, lot and price-grid conformity, price inside `[minPrice, 10 × prevClose]`.
2. **Rate limits**: ≤ 20 intents per tick per character (00); ≤ `PARAM.mkt_max_open_orders (200)` open orders per actor and ≤ `PARAM.mkt_max_open_orders_asset (20)` per asset.
3. **License** (13): `MarketSpec.licenseRequired` and LIC2 for algos, LIC4 plus the `CH_EXCHANGE_MEMBER` charter for registered market making. **Held** state (13): a Held character may only cancel and reduce. Defendant restrictions from 13 (for example half leverage) are applied by 07's buying-power check; 05 only passes the check's result.
4. **Session**: order type allowed in the current trading state (§3.10); halted assets accept orders and cancels but do not match (11 §edge 13 is satisfied: AI orders for halted assets are refused only for IOC and FOK types).
5. **Capital controls** (04 §3.13.6): level 1 adds the 1% levy (`CAPCON_LEVY`) to conversions out of the controlled currency; level 2 and 3 reject sales of the currency except reduce-only closes of FX derivatives.
6. **Onboarding cap** (18): if `onb.firstTradeCap(chrId)` returns a value, buy notional is capped at it.
7. **Limits** (§3.15.2): position caps, short-interest cap, compute OI cap.
8. **Buying power and holds**: cash accounts hold `qty × limit (or band hi for market buys) × (1 + taker fee)`; sells hold the asset; short sells require a locate from 07 (`borrow.locate(accountId, assetId, qty) → locateId | reject`); margin accounts call 07 `bp.check(accountId, orderDelta) → { ok, initialMarginHold }`. Holds are 03 holds released at fill, cancel or expiry.
