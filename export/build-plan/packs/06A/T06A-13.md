## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. Hubs (§3.10.4): 5 hubs (one per bloc, 22 assigns the city); benchmark per commodity as in Exports; `P_hub = P_bench + basis_hub`; `basis_hub = shipCost(bench → hub)·(importer ? +1 : −1) + 0.5·shipCost·clamp(localImbalance, −1, 1)` with `localImbalance` from `ports.companies.regionalImbalance` (09/16); importer = hub demand > hub supply. Hub lines exist only where 22 lists activity (T06A-01). Native commodities (COMPUTE, DATA, POWER_*) have no hubs or receipts.
2. Receipts: in P6 after 05 has matched, scan `fillsOfTick` for physical commodity lines: buyer → `createReceipt` at the line's hub in the NPC public warehouse (`facilityId: null`) unless the buyer already holds a receipt at the hub in its own facility (then that one grows); seller → reduce receipts FIFO by `createdTick` then `receiptId`. P1 capacity check: the instrument-port extension (T06A-17) calls `physicalCapacityCheck` for buy orders; at 100% hub utilization → `AST_HUB_FULL` (06#21).
3. Storage fees (DAY_CLOSE): `fee = storageCostPerYearFrac·value/364` with value = qty × hub mark; NPC public warehouse charges `× cmd_public_storage_markup` and posts `CMDTY_STORAGE_FEE_NPC` (SINK, `ctx.ledger.elasticOut(owner, frm_<bloc>, …)`); a player facility (09 storage business) charges its posted `ratePerYearFrac·value/364` and posts `CMDTY_STORAGE_FEE_B2B` (`pay`). Above 95% hub utilization every fee ×2. Spoilage: `lossQty = qty·perishDecayPerYear/364` per day, receipt qty reduced and the asset qty removed via `ctx.ledger.moveQty(owner, 'sys_SPOILAGE', asset, lossQty, book, ccy, 'CMDTY_SPOILAGE')` (see `_unit.md` registry note on qty-destroying templates).
4. Withdraw (`mkt.commodity.withdraw`): owner, facility at the same hub with free capacity for the commodity; moves the receipt (or splits it) to `toFacilityId`.
5. Shipping: `mkt.commodity.ship` validates LIC2, owner, route exists (22 §4.6), freight capacity available (fleetUtil < 1), cash for freight available, capital controls (`controlsBlock(ccy,'WITHDRAW_FROM_BLOC')` when leaving a controlled bloc). Effect: freight `cost = qty·unitWeight·FRX·distanceFactor` posted `CMDTY_FREIGHT_NPC` (SINK, `elasticOut` to `frm_<from bloc>`) or `CMDTY_FREIGHT_B2B` to a player shipping line chosen by 09's capacity order; receipt qty removed; `Shipment {departTick: tick, arriveTick: tick + routeDays·720, status: IN_TRANSIT}`; emit `mkt.ship.departed` PARTIES. FRX: `FRX_base·(fleetUtil/0.80)²` clamped to [0.4, 6] × base, updated hourly.
6. Arrival (P2 at `arriveTick`), shipments in ascending `shipmentId`: one draw `ctx.rng('ast.commodity:' + commodityId).bernoulli(PARAM.ship_loss_prob_per_trip)` (the 02 registry stream; 06's text `rng('ship', …)` is not in the registry): loss → status LOST, qty written off (`CMDTY_SPOILAGE` to `sys_SPOILAGE`), emit `mkt.ship.lost` PARTIES; 08 pays the insured value if `cargoInsured` (edge 10; CDS-like contracts unaffected). Otherwise receipt at the destination hub (rejected? if the hub is full the cargo waits in transit one more game day and retries) and `mkt.ship.arrived`.
7. Marks: in-transit cargo = destination spot − remaining freight (`shipmentMark`).

# SPEC EXCERPTS (verbatim; binding game rules)

**[06 §1 Purpose]** (context)

## §1 Purpose

This module defines **every tradeable thing in the world** and the rules that are specific to its asset class: what an instrument is (fields), what it is worth (its fundamental value, which 05's price model pulls toward), how it pays (dividends, coupons, funding, settlement), how it is created and destroyed (listing, series generation, issuance, expiry, default, delisting), who may trade it (licenses), how it is marked for net worth, and every class-specific event (earnings, splits, credit events, depegs, auctions).

Division of labour, binding:
- **05** owns *how* prices move tick to tick (the return equation, GARCH, jumps, factor model, batch auction, NPC market makers, square-root impact, halts). 06 owns *what* each asset's fundamental value `V_i` is, its class parameters (`PriceParams`, §3.21), and everything that is not the generic order book: OTC and RFQ fills (P6), DeFi venues, primary auctions, collectible auctions, option exercise, futures settlement, perp funding, coupons and corporate actions.
- **07** owns margin, collateral haircuts, securities lending, repo and the Clearing House. 06 tags each instrument with its `marginClass`, `collateralClass` and `clearing` service.
- **08** owns ETF creation and redemption, rating agencies, securitization tranches and fund units. 06 defines ETF and index instruments and their NAV.
- **09** owns company decisions (dividend amount, buybacks, issuance, M&A, bankruptcy, IPOs). 06 executes the security-level consequences.

Design laws (from 01 §0 and V3 T1–T3, kept):
1. Every price has a cause a player could have seen or inferred. Each class's `V_i` is a function of world state, never a random walk.
2. Parities hold by construction where they hold in reality (forward = CIP, put-call parity via NPC arbitrage, ETF ≈ NAV, cross FX from legs). Residual arbitrage after fees is ≤ fees.
3. Each class differs where the difference creates a decision (MASTER-BIBLE T02): fundamentals, sentiment, liquidity, financing, sessions and liquidation rules.
4. Defaults, depegs and failures are **mechanical outcomes of balance sheets**, never dice rolls with a fixed probability.

**Status of numbers:** every `PARAM.*` value in this module, and every choice tagged `DEFAULT`, is `DEFAULT (Mathis may override)`. Locked decisions L1–L15 (00) and the 00 time model are not defaults. The full list is in `_notes/06-notes.md`.

**[06 §3.10.4]** (from spec file 06-ASSET-CLASSES.md)

#### §3.10.4 Hubs, basis and warehouse receipts
- 5 hubs (one per bloc; 22 assigns the city). Benchmark hubs: CRUDE NKR, NATGAS FDL, metals FDL, LITHIUM SRL, RARE_EARTH PYN, AGRI FDL, URANIUM NKR.
- Spot at a non-benchmark hub: `P_hub = P_bench + basis_hub`, `basis_hub = shipCost(bench → hub) · (importer ? +1 : −1) + 0.5 · shipCost · clamp(localImbalance, −1, 1)`. `localImbalance` = (hub demand − hub supply) / hub demand from 09/16 regional data. Each non-benchmark hub line is a separate `CommodityAsset` (`ast_CM_<ID>_<HUB>`), created at genesis for hubs with non-zero regional activity.
- Physical spot purchases create a **warehouse receipt** at the hub. Storage fee accrues daily at `storageCostPerYearFrac · value / 364`, paid to the facility owner (an NPC public warehouse at `PARAM.cmd_public_storage_markup = 1.5 ×` base cost, or a player's own storage business from 09 at cost, or another player's at their posted rate). Perishable commodities lose `perishDecayPerYear / 364` of quantity per game day (spoilage), so hoarding coffee is costly.
- Hub storage capacity is finite (`Hub.storageCapacity`); when a hub is 100% full, new physical purchases there are rejected and contango steepens (convenience yield cannot fall further, storage fee rises ×2 at > 95% utilization).


<!-- excerpt 06§3.10.5 -->
**[06 §3.10.5]** (from spec file 06-ASSET-CLASSES.md)

#### §3.10.5 Shipping and delivery
- `mkt.commodity.ship` moves a receipt between hubs: transit time = `routeDays` (2–12 game days, 22 table), cost = `qty · unitWeight · FRX · distanceFactor`. During transit the cargo is a `Shipment` (marked at destination spot minus remaining freight). Loss risk: `PARAM.ship_loss_prob_per_trip = 0.002` per trip, insurable (08); the draw uses `rng('ship', shipmentId)`.
- Freight Index: `FRX = FRX_base · (fleetUtil / 0.80)²`, clamped [0.4, 6] × base, where `fleetUtil` = booked tonnage ÷ fleet capacity (NPC fleet + player shipping-line businesses from 09). Shocks (16: canal closure, war) cut capacity.
- Futures are **cash-settled** against the benchmark hub's closing spot by default. A long holder with storage capacity at the delivery hub may elect physical delivery (`mkt.future.electDelivery`) during the last 3 trading days; the matched short is selected from shorts that hold receipts at the hub, else shorts are assigned by size pro rata and must deliver (buy spot at the hub) or pay a delivery-failure penalty of 5% of value plus the cost of the hub spot purchase executed by the engine for them.
