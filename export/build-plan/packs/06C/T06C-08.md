## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. `mkt.token.launch` (P1): if `PARAM.player_tokens_enabled` is false → reject `AST_FEATURE_DISABLED` (06#44) before any other check. Otherwise `launchEligibility` evaluates all conditions and lists every failure: LIC4 (`licenseOf`), rank ≥ R4, no S4+ conviction within the last 8 real weeks, account ≥ 30 real days (real time from 14A, not game time), FINTECH sector tech level ≥ 3 and era ≥ 2 (16, via port members; defaults keep the feature closed), fee affordable from unrestricted cash, `liquidityFdl ≥ $2M`, creator allocation ≤ 20%, total allocation = 100%, symbol unique among live tokens and not reserved (22 ticker rule). Reject `AST_TOKEN_INELIGIBLE` with the list.
2. Accepted: pay `PARAM.token_launch_fee` ($5M) as a SINK with reason code `CRY_TOKEN_LAUNCH_FEE` (not yet in 03's catalog: registry gap reported in `_unit.md`; the code must be added before the flag can be turned on); mint the supply to the launch escrow (`CRY_TOKEN_MINT`); create a Tidepool CP pool pairing the liquidity allocation with `liquidityFdl` of GUSD (or LTX at the oracle, creator's choice in the request) whose LP tokens are held by the protocol lock account with `lockedUntil = launchTick + 28 × 720`; record the disclosure (supply, allocation, vesting, use of funds) PUBLIC; status PENDING; request the 13 review.
3. After 1 game day, `finalizeLaunch`: `LawPort06.tokenReviewPassed(launchId)` true → LIVE (trades on its Tidepool pool; a CEX listing on `ven_VAULTX` is 16's decision, default none), `mkt.token.launched` PUBLIC; false → REJECTED: pool unwound to the creator after the lock period ends (the lock still binds), fee not refunded (SINK); null (13 absent) → stays PENDING (fail closed).
4. Lock (X15): `lockGuard` is called by `removeLiquidityHandler` and by any LP-token transfer; while `tick < lockedUntil` every reduction of the locked LP position is rejected `AST_LIQUIDITY_LOCKED`, whoever submits it (creator, linked accounts, system intents). After the lock the protocol returns the LP tokens to the creator.
5. Vesting: creator allocation (≤ 20%) released linearly over 91 game days at DAY_CLOSE into the creator's wallet; unvested tokens cannot move.
6. Surveillance: creator or linked accounts (`SocialPort06.linkedGroups`) selling vested tokens within 2 game days of a promotion they paid for (09 Media campaign with campaigner in the group) → `mkt.surveillance.signal` SEALED `{pattern: 'TOKEN_PROMO_DUMP'}`; selling after false claims is S5 (13 decides). Delisting: < $1,000 pool liquidity for 7 game days → loses LISTED status (tokens stay in wallets).

# SPEC EXCERPTS (verbatim; binding game rules)

**[06 §1 Purpose]** (context)

## §1 Purpose

This module defines **every tradeable thing in the world** and the rules that are specific to its asset class: what an instrument is (fields), what it is worth (its fundamental value, which 05's price model pulls toward), how it pays (dividends, coupons, funding, settlement), how it is created and destroyed (listing, series generation, issuance, expiry, default, delisting), who may trade it (licenses), how it is marked for net worth, and every class-specific event (earnings, splits, credit events, depegs, auctions).

Division of labour, binding:
- **05** owns *how* prices move tick to tick (the return equation, GARCH, jumps, factor model, batch auction, NPC market makers, square-root impact, halts). 06 owns *what* each asset's fundamental value `V_i` is, its class parameters (`PriceParams`, §3.21), and everything that is not the generic order book: OTC and RFQ fills (P6), DeFi venues, primary auctions, collectible auctions, option exercise, futures settlement, perp funding, coupons and corporate actions.
- **07** owns margin, collateral haircuts, securities lending, repo and the Clearing House. 06 tags each instrument with its `marginClass`, `collateralClass` and `clearing` service.
- **08** owns ETF creation and redemption, rating agencies, securitization tranches and fund units. 06 defines ETF and index instruments and their NAV.
- **09** owns company decisions (dividend amount, buybacks, issuance, M&A, bankruptcy, IPOs). 06 executes the security-level consequences.

Design laws (from 01 §0 and V3 T1–T3, kept):
1. Every price has a cause a player could have seen or inferred. Each class's `V_i` is a function of world state, never a random walk.
2. Parities hold by construction where they hold in reality (forward = CIP, put-call parity via NPC arbitrage, ETF ≈ NAV, cross FX from legs). Residual arbitrage after fees is ≤ fees.
3. Each class differs where the difference creates a decision (MASTER-BIBLE T02): fundamentals, sentiment, liquidity, financing, sessions and liquidation rules.
4. Defaults, depegs and failures are **mechanical outcomes of balance sheets**, never dice rolls with a fixed probability.

**Status of numbers:** every `PARAM.*` value in this module, and every choice tagged `DEFAULT`, is `DEFAULT (Mathis may override)`. Locked decisions L1–L15 (00) and the 00 time model are not defaults. The full list is in `_notes/06-notes.md`.

### §3.20 Player-launched tokens (specified in full, disabled at launch)
`PARAM.player_tokens_enabled = false` at launch, honouring L10 ("player-launched tokens later"); turning it on is a 21 live-ops switch, no code change.
- Eligibility: LIC4, rank ≥ R4, no S4+ conviction in 8 real weeks, account ≥ 30 real days.
- Launch fee `PARAM.token_launch_fee = $5M` (SINK); mandatory locked liquidity ≥ `$2M` FDL equivalent paired in a Tidepool pool, locked by the protocol for 28 game days (cannot be withdrawn: a classic "rug" of pool liquidity is impossible by construction); creator allocation ≤ 20% of supply, linear vesting over 91 game days; disclosure page (supply, allocation, vesting, use of funds) PUBLIC.
- Surveillance (05, 13): creator or linked accounts selling vested tokens within 2 game days of a promotion they paid for is a manipulation signal; selling after false claims is S5. Tokens lose LISTED status after 7 game days with < $1,000 liquidity.
