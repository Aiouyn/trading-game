## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. **Number token grammar** (used by every parser): optional sign `+`, `-` or `−` (U+2212), digits with optional `,` thousands separators, optional fraction, optional exponent `e[+-−]?\d+`; optional magnitude suffix `k`=1e3, `M`=1e6, `B`=1e9, `T`=1e12 (only directly after the digits). Remove `,` before converting. Convert to `number` with `Number(...)` on the normalized ASCII string (parsing, not money conversion). Money tokens are prefixed by `$` or `€` (sign before or after the symbol: `−$5` and `$−5` both mean −5) and are converted by `decimalToMicros` with exact string arithmetic (scale the decimal string by 10^6 and by the suffix power; reject if more than 6 decimals remain after scaling).
2. **parseDefault** in this order (first match wins; the cell is trimmed; a trailing ` †` is not part of the cell because † belongs to the key cell):
   a. `override` present -> use it.
   b. `true`/`false`, optionally followed by ` (…)` -> bool.
   c. `[n, n, …]` -> list.
   d. `U(a, b)` -> uniform.
   e. A quoted string `"…"` -> string without quotes.
   f. A single money token, optionally followed by ` real` and/or a parenthetical `(…)` -> money (`$` GAME, `€` EUR).
   g. A single number token followed by `%` -> number /100.
   h. A single number token, optionally followed by ` (…)`, ` bp`, `×`, or by a space and exactly the text of the row's unit cell (case-insensitive, e.g. `7 real days` when unit is `real days`) -> number (bp values stay in bp; the unit column says so).
   i. Anything else -> throw `ParamParseError(key,'default')`; the transcription task must supply an override for that key.
3. **parseRange**: strip a trailing ` ‡` (sets `rangeAssigned`) and a trailing parenthetical; then:
   - `fixed…`, `locked …`, `<n> (fixed …)` -> fixed. `bool…` -> bool. `any…`, `int`, `list`, `monitored`, `per class`, `as listed per lever`, `0–all` -> any. `per owner table` -> perOwnerTable.
   - `0.5× – 2× default` or `0.5×–2×` or `×0.5–×2` -> interval [0.5·d, 2·d] where d is the numeric default (money: dollars).
   - `±p%` or `±p% each` -> [d·(1−p/100), d·(1+p/100)] (for families: applied per member).
   - `±x` (no %) -> [d−x, d+x].
   - `≥ x` -> [x, null]. `a–∞` -> [a, null]. `[a,b]` -> [a,b].
   - `a–b` (separator `–` en dash or a hyphen between two tokens; tokens may carry `$`, `%`, `×`, k/M/B, fractions `1/60`) -> interval; if the second token ends with `%` and the first has no unit, both are percent; money tokens give dollars; fractions `p/q` evaluate to p/q; if min > max swap them (`1/60–1/182`).
   - Trailing words after the second token (`real days`, `chapters`, `base`) are ignored.
   - Composite range text not matching any rule (`120–720; ±0.05–0.5%`, `Cover-1 to Cover-3`) -> `any` and the row is flagged `rangeAssigned=false`; T23-08 lists such rows in its report.
   - For a default of kind money, interval bounds are in display dollars; for percent defaults bounds are fractions (both converted by step 1's rules).
4. **parseLive**: `yes` -> live; `no (X)` -> not live with code X ∈ {L,E,V,C,G}; anything else throws.
5. **parseRow**: key cell may end with ` †` (assigned); a key containing `<…>` or `*` is a family; `affects` text containing `Replaces \`a\`` (one or more) fills `replaces`.
6. **buildParamSet**: rows from all tables; a family member without its own range inherits the family row's range applied to the member value (relative and ± ranges are computed per member); when the family range is `perOwnerTable` the member range is the ‡ rule of 23 §2.1: [0.5·v, 2·v] for v > 0, [2·v, 0.5·v] for v < 0, fixed for v = 0, any for non-numeric; duplicate key -> throw `PARAM_DUPLICATE <key>`; a family row must have ≥ 1 member in `members`, member keys must match the family pattern (`<x>` = `[A-Za-z0-9_]+`, `*` = `[a-z0-9_]+`) and be unique across the set; `hash` = hex SHA-256 of `canonEncode(toJsonFile(set))`. `@tycoon/params` must not import the engine, so `set.ts` contains its own small pure SHA-256 (FIPS 180-4, about 60 lines, no globals), tested with the vector `sha256('abc') = ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`.
7. **ParamsView**: lookup order override -> member -> row. Accessor rules:
   - `num`: kinds number (any unit) ; money not allowed (use `money`).
   - `int`: number whose value is an integer else `ParamKindError`.
   - `money(key, ccy)`: kind money with currency GAME -> `BigInt(micros)` (same micro value in any game currency: the row is in display units of that currency; the caller supplies ccy for documentation and future per-currency rows).
   - `ticks`: number with unit (case-insensitive, text before any `(`) `ticks` ×1; `game days`, `GD`, `days` ×720; `game hours`, `GH` ×30; `game minutes` ×0.5; `real days` ×17,280; `real hours` ×720; `real minutes` ×12; `real seconds`, `s` ×0.2; `chapters` ×967,680; `game weeks` ×5,040; `game quarters` ×65,520; `game years` ×262,080. Result must be an integer (else `ParamKindError`).
   - `ms`: unit `ms` ×1; `s`, `real seconds` ×1000; `min`, `real minutes` ×60,000; `real hours` ×3,600,000; `real days` ×86,400,000.
   - Other accessors require the matching kind.
   - Every accessor throws `ParamKindError` for an unknown key (engine tests catch this; production keys are verified by T23-08 and INV-STR-007).
8. **validateParamChange** (23 §2.3 rule 4; 21 Rule 3.4.1, 3.4.3), checks in this order:
   1. key unknown -> `PARAM_UNKNOWN_KEY`.
   2. `next.kind !== registry kind` -> `PARAM_KIND_MISMATCH`.
   3. `old` differs from the set's current value -> `PARAM_STALE_OLD`.
   4. Numeric or money value outside the row's interval (fixed: must equal the registry default) -> `PARAM_OUT_OF_RANGE` with params `{min, max}`.
   5. `live === false` and `patchClass` not in {RULES, ENGINE_CUTOVER} -> `PARAM_NOT_LIVE`.
   6. `patchClass === 'BALANCE'`: `|next − old| > PARAM.liveops_param_step_max_share × (max − min)` -> `PARAM_STEP_TOO_LARGE` (read the share from the set itself, key `liveops_param_step_max_share`, default 0.25; unbounded intervals skip this check); last BALANCE change of the key within 7 × 86,400,000 ms of `nowRealMs` -> `PARAM_TOO_FREQUENT`. `HOTFIX` with `criticalFinding` skips both (21 Rule 3.4.3 exception).
9. **paramChangedPayload**: `changedKeys` sorted byte order; values printed in display units: number -> shortest round-trip string (`String(v)`), percent rows as `v*100` + `%` when the raw default ended with `%`, money as `$` + decimal dollars without trailing zeros (micros /1e6 by string arithmetic), bool `true/false`, others `canonJson`.

## §1 Purpose

1. Give the builder one place to load every tunable number: a single, versioned parameter set (02 §3.18.4) whose keys, defaults and ranges are exactly the rows of §4.

4. Remove ambiguity: every key has one owner, one default, one unit; duplicates and synonyms are resolved in §5 with the file that must be corrected.

## §2 How to read the registry

### §2.1 Columns

| Column | Meaning |
|---|---|
| key | The parameter name, used in code and in specs as `PARAM.<key>`. A key with `<id>`, `<city>`, `<use>`, `<product>`, `<class>`, `<service>` or `*` is a **family**: one value per member, listed in the owner section's table. `†` marks a key this registry assigned because the source row (a writer-notes summary line) had no key; the owner module adopts it as written |
| default | The value the builder uses. Units as written by the owner (money in display dollars, rates as fractions or %, durations in the unit column). Engine conversion per 00 §3.1: Money → micro-units with `toMoney`; `%` → fraction; game days × 720 = ticks; real days × 17,280 = ticks |
| range | The interval LiveOps may move the value within (inclusive). `fixed` = never changes in live play. `‡` marks a range this registry set because the owner gave none: **0.5× – 2× the default** for a positive scalar, owner judgement for zero defaults, and "per owner table" for composite values. `DEFAULT (Mathis may override)` |
| unit | Unit of the default and the range. `real $ (× MSI)` means the dollar figure is scaled by the Money Supply Index (03 §3.8) when applied |
| owner § | The module that owns the system the number belongs to, and the section that defines or uses it. The owner's value wins (00 §3.5) |
| what it affects | One line from the owner (notes table) or, if the owner wrote none, the sentence of the spec that uses it |
| live | `yes` = LiveOps may change it without a code release, as a BALANCE param change (21 Rule 3.4.1: at a day close, ≥ 48 real hours notice, two approvals, within range, step ≤ 25% of range, ≤ 1 change per key per real week). `no` = it changes only with a release or never; the letter gives the reason (§2.2) |

### §2.2 Live-tunable rule (applied mechanically)

A key is **live-tunable = yes** unless one of these applies (`DEFAULT (Mathis may override)`):

| Code | Rule | Why |
|---|---|---|
| L | Range written as `fixed`, or the value is pinned by a locked decision (L1–L15, e.g. breach floor 1% L2, hidden-session ceiling 0.85 L3, ad grant $250 / 10 per day / $1,000 line L12) or a 00 §5 contract | locked decisions never change |
| E | Owner is 02 (time engine) or 19 (tech architecture) | determinism, protocol and infrastructure numbers change only with an engine-version cutover (02 §3.18.1) or a deploy; changing them live would break replay or security |
| V | Owner is 20 (verification) | harness thresholds change with the release that changes the gate (20 §3.9) |
| C | Owner is 17 (UX) | presentation numbers ship in a CLIENT patch (21 Rule 3.4.1), not a sealed param change |
| G | Owner is 21 and the key is a governance, compliance or anti-abuse guardrail (`adm_*`, `liveops_*`, `enf_*`, `age_*`, `dr_*`, `export_*`, `audit_*`, `tz_*`, `mod_*`, `support_*`, ad verification keys) | the rules that constrain staff cannot be loosened by the same staff; they change only in a RULES patch at a chapter boundary |

Every `yes` key is still bounded by its range; a value outside the range is a RULES change (chapter boundary, 21 Rule 3.4.1). Module kill switches (21 §3.3) are `sys.param_change` of a module flag and are always live.

### §2.3 Builder rules

1. **One file.** All keys load from one parameter set `params/v<paramsVersion>.json` (19) with the shape `{ key: { value, min, max, unit, owner, live } }`. Unknown keys fail the build; missing keys fail the build.
2. **Aliases.** The keys listed as replaced in §5.2 must not appear in code. A builder who meets one in a spec reads the canonical key instead. CI (20, G0) greps the code for alias keys and fails on any hit.
3. **Families.** A family key expands to one key per member at load: `natural_vacancy_<use>` → `natural_vacancy_RES`, … with the member list from 22 and the values from the owner table cited.
4. **Range checks.** `sys.param_change` (19 Rule 3.16.2) rejects any value outside `[min, max]` with `PARAM_OUT_OF_RANGE`, and any `live = no` key with `PARAM_NOT_LIVE` unless the change is part of a RULES patch or an engine cutover.
5. **Units.** The engine stores every value in the engine unit of 00 §3.1; the conversion happens once at load. The registry shows display units for readability.
6. **Public.** Every value is public (19 `sys.param_changed`); the Exchange notice of a BALANCE patch prints old and new values (21 Rule 3.4.4).

### §3.4 Parameters, content and patches

**Rule 3.4.1 (patch classes and timing).**

| Class | When it may take effect | Notice | Gate (20) |
|---|---|---|---|
| HOTFIX | any tick (between ticks) | patch note within 24 real hours; "Fix" line in the next integrity report | hotfix path |
| BALANCE | a day close (t = 719) | ≥ `PARAM.liveops_balance_notice_hours = 48` real hours, as an Exchange notice on the Wire and in patch notes | G4 + diff run of the changed params on the touched bands |
| RULES | a chapter boundary only (15 §3.3.2) | ≥ `PARAM.liveops_rules_notice_days = 14` real days | G4 + G5 |
| CONTENT | a day close | ≥ 24 real hours (new cities: ≥ 7 real days) | G4 |
| CLIENT | any time | release notes in Settings › About | G0–G2 client suites |

**Rule 3.4.2 (no retroactivity).** No change applies to ticks before its `effectiveTick`. A change never rewrites history, never re-prices past fills and never re-runs past rolls. Where a defect produced wrong outcomes in the past, the remedy is compensation or clawback (§3.6), never a rewrite.

**Rule 3.4.3 (rate of change).** A BALANCE patch may move each parameter by at most `PARAM.liveops_param_step_max_share = 0.25` of its 23 range per patch and at most one BALANCE patch per parameter per real week, except to stop an active CRITICAL Finding (then any value within range, as a HOTFIX-class param change with two approvals including TM_LEAD).

**Rule 3.4.4 (honest patch notes).** Patch notes state what changed, why, and the effective tick, in EN and FR. Balance notes give the old and new value of any player-visible number. Patch notes never name a player. A nerf of a strategy that some players use says so plainly ("Returns from X were higher than intended at large sizes; the capacity limit now ...").

**Rule 3.4.5 (staged rollouts).** World-affecting features roll out through `FeatureRollout` stages (19 Rule 3.16.3, 02 §11): `CHALLENGE_ONLY` (ring-fenced challenge portfolios), then `ONE_CITY` or `ONE_COUNTRY`, then `WORLD`. Each stage lasts ≥ `PARAM.liveops_rollout_stage_min_days = 7` real days with its bands monitored live (20 Rule 3.11.2). A stage advance is a BALANCE-class param change.

**Rule 3.4.6 (new cities).** When 15/10 report that `N_a` has grown by `PARAM.new_city_na_step = 4000` since the last opening (01 §14.1), LIVE_OPS schedules a CITY_OPENING LiveEvent within the next chapter, announced ≥ 7 real days ahead, content from 22's generator, opening at a day close.
