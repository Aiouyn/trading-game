## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

# TASK T22A-01: ContentView - typed, pure, hashed read API over the content catalogs (blocs and aliases, releases, cities, indices with peNorm0, primary dealers, sectors, SWF ids, FX pair ids) plus ParamsView pass-through

## Goal
One read-only, typed and deterministic view over the shipped content catalogs (22 §0.1), handed to every module as `ctx.content`. The first consumers are units 04 (T04-01, T04-10, T04-14 and T04-03's `peNorm0`), 02 (runtime and genesis), 03 (T03-08 entity registration), 05 (sector factor ids), 09A (business types, typed here only as a pass-through) and 20B (presets, through T22B). Presets, including MICRO, are owned by T22B `contentForPreset('MICRO'|'SMALL'|'STANDARD')`; T22A-01 loads only the full content. Rules:
- **Pure.** No I/O after load and no `Date`. Every call returns the same frozen value for the same content hash.
- **Canonical blocs.** Bloc ids are the canonical currency codes FDL, EUN, PYN, NKR and SRL (24 R39, 22 §0.3). 04's aliases FU, EC, PL, NA and SC resolve through one alias table.
- **Replays.** Content is versioned (`catalogVersion` per file) and hashed into `contentHash` (22 §0.1.5), so a replay can refuse a content mismatch.
- **Money.** Content money columns are nominal genesis amounts in whole FDL units (22 §0.1 rule 2), loaded with `toMoney()`. They are not real. `realFields` lists only columns that 22 explicitly labels real (for example 22 l.2418). Converting real to nominal belongs only to T14A-02 `realToNominal`, which 13A, 14B, 15A and 16A also use.

## Implementation steps
1. **Load.** Read every `packages/content/data/*.json` once and validate it with the 22 §18 loader checks. Deep-freeze the result. Each file must carry an integer `catalogVersion`.
2. **Hash.** `contentHash = sha256(canon({ [fileName]: fileJson }))`, with keys sorted by `cmpStr`. Overrides are part of the hashed object, so a preset world never shares a hash with full content. The engine stores the hash at genesis, and a replay with a different hash fails with `CONTENT_HASH_MISMATCH` (02 replay rule).
3. **Bloc aliases.** There is one table, `BLOC_ALIAS_04`. `canonicalBloc` accepts both canonical ids and 04 aliases. `canonicalEntityId` rewrites only the 22 §0.3 institution prefixes (`cbk_`, `exc_`, `reg_`, `gov_`, `crt_`) when they are followed by a 04 alias. ContentView getters always return canonical ids.
4. **Derived lists:**
   - `primaryDealers(b)` (22 §5.2 l.1240): 8 per bloc, 40 seats in total. The list is b's SIB, b's commercial bank A (`commercialBankA`: FDL bnk_lksb, EUN bnk_bvlc, PYN bnk_tscb, NKR bnk_sksb, SRL bnk_bavd, per 22 §5.1), the four other blocs' SIBs, `npc_dlr_GRAY` and `npc_dlr_OSTP`, sorted. `npc_dlr_*` ids are valid under the `npc` kind with holder class npcFirm.
   - `tchMembers()`: the 5 SIBs, the 5 commercial banks A, `npc_dlr_GRAY`, `npc_dlr_OSTP`, `npc_VAULTCLR` and `bnk_serena`. That is 14 at launch.
   - `npcBanks()`: the 26 rows of 22 §5.1. "Assets (% bloc GDP)" is kept as a ratio (`assetsPctGdp`); the loader converts it to money at genesis with 04's GDP. The one fixed row (bnk_serena "$40B fixed") goes to `fixedAssets` via `toMoney()`. Roles are split on `,` and `;`. "—" and "no" become null or empty lists.
   - `swfEntityId(b)` = `fnd_SWF_${b}`: holder class npcFirm, `ownerId` = `gov_${b}`. Its flows (SWF_TRANSFER) are TRANSFERs, never MINT or BURN.
   - `fxAssetId`: the 22 §4.5 legs `ast_FX_EUNFDL`, `ast_FX_FDLNKR`, `ast_FX_FDLPYN` and `ast_FX_FDLSRL`. Quote order follows the base priority EUN > FDL > NKR > PYN > SRL, so only EUN is the base against FDL. CB pools never trade crosses.
   - `releases(b).statisticsOfficeId` = `npc_STATS_${b}` (E-58): kind `npc` (03 §2.1, 22 §1.4), holder class npcFirm, `ownerId` = `gov_${b}`. It publishes data and declares cycles only; it never holds money and no reason code posts to it.
   - Cities: 3 per bloc with ids `cty_<slug>`, 15 in total. `cty_isla_serena` belongs to no bloc: `serena()` returns homeBloc `SERENA` and reportingCcy `FDL`, and the city is excluded from `cities()`.
   - `canonicalEntityId` stores canonical ids only. T03-08 `registerEntityRt` passes ids through it, so 04-alias ids never reach storage.
   - `sectors()`: the 12 06 §3.4.1 rows. 22 §4.1 has no standalone sector table, so names come from the `idx_GXS_*` names in 22 §4.8.
5. **peNorm0 (source for T04-03 `peNorm` genesis; the T04-01 card's UNSOURCED flag).**
   - `peNorm0_b` is the genesis aggregate P/E of the bloc's 30-stock index at neutral valuation:
     `peNorm0_b = Σ_{i∈top30_b} cap_i / Σ_{i∈top30_b} (cap_i / PE_base_{sector(i)})`.
   - `top30_b` is the 30 largest b-listed equities by `cap0 × freeFloat`, with ties broken by assetId. Free float (22 §4.1 l.521; dynasty set from 22 §10.4 l.2570–2581): `freeFloat = 0.90` for a listed REIT; else `0.60` if the ticker appears in any §10.4 "Listed stakes" cell (dynasty-linked); else `0.75`.
   - Free float only selects the 30 constituents. Index weights are full `cap0`, not float-adjusted.
   - `PE_base` comes from params the sector `PE_base` params (e.g. `PARAM.eq_sector_tech_pe_base`) (06 §3.4.1). Defaults: TECH 32, SEMI 26, ENERGY 11, MATERIALS 12, INDUSTRIALS 16, FINANCIALS 10, HEALTH 20, STAPLES 18, DISCRETIONARY 20, REAL_ESTATE 16, MEDIA 18, SECURITY 24.
   - Aggregate P/E is total cap over total earnings, so the weighting is harmonic, which is how an index P/E is defined.
   - "Neutral" means the 06 §3.4.2 rate term `exp(−d·(y10 − r*))` = 1 and risk appetite RA = 0 (F = 50). That makes peNorm0 the long-run normal valuation, which `peNorm` (the 5-year trailing mean of peAgg) converges to. It is not a snapshot of genesis rates.
   - Values with the default content and params:

     | Bloc | peNorm0 |
     |---|---|
     | FDL | 16.79 |
     | EUN | 16.94 |
     | PYN | 17.77 |
     | NKR | 14.63 |
     | SRL | 15.45 |

   - The ordering follows the sector tilts: PYN and FDL are tech- and semis-heavy, NKR and SRL are energy- and materials-heavy (04 §2.2).
   - Money units do not affect it. P/E is cap divided by earnings, and both are in the same units (nominal genesis FDL via `toMoney`), so the money correction leaves every peNorm0 value unchanged.
   - Storage: the value is written into `content/indices.json` as field `peNorm0` on the five regional index rows. It is recomputed by the loader and must match to 0.01, or the loader fails with `CONTENT_PENORM0_STALE`. Range is [8, 40], the 06 sector P/E span [10, 32] widened by about 20%.
   - Retuning the sector `PE_base` params (e.g. `PARAM.eq_sector_tech_pe_base`) within the registry's ±50% re-derives the value through `peNorm0Of`. It is not a separate tuning knob.
   - Consumer: T04-03, which seeds `peNorm` at genesis and serves as the fallback while `peAgg` history is shorter than 5 game years. T20B presets read the same field.
   - Expected genesis offset (consistent with the spec, not a bug): if genesis has y10 > r*, the starting peAgg is below peNorm0 and the T04-03 valuation imbalance starts negative ("rates high, valuations below normal"). Engine Dev reports the genesis valuation z per bloc in the T04-03 test log.
6. **Money.** Every money column is nominal genesis whole-unit FDL (22 §0.1 rule 2) and is loaded with `toMoney()`. `realFields` lists only columns that 22 explicitly labels real. Nothing in ContentView multiplies or divides by MSI; T14A-02 `realToNominal` is the single converter.

## §0 Conventions for all catalogs

### §0.1 Data files

1. Every catalog below is shipped as one JSON file under `packages/content/data/` (19 owns the package; 19 §3 module graph loads it before genesis). The file name is given in each section header as `→ content/<name>.json`.
2. One table row = one JSON object. Column names map to camelCase field names. Money columns are written in whole FDL dollars unless the column says otherwise; the loader converts with `toMoney()` (00 §3.1).
3. IDs are stable forever. A renamed item keeps its ID; only its string key text changes. Removing a row after launch is forbidden (mark it `retired: true`).
4. Display names are string keys `<namespace>.<id>.name` (L8). The English text is the name given here. **French rule (resolves every "FR translations" request in the notes files, DEFAULT, Mathis may override):** proper names (cities, districts, companies, brands, people, tokens, ships, artworks, institutions whose name is a proper noun) are identical in French; descriptive labels (sector names, board names, item types such as "Penthouse", rule texts) are translated by the localization pass using the glossary of §17.3. A row whose name mixes both (e.g. "Federal Treasury") is translated by the localization pass ("Trésor fédéral").
5. Every catalog file carries `catalogVersion` (integer). The engine hashes all content files into the world's `contentHash` at genesis (02 replay determinism): a replay must load the same content hash.

### §0.2 Generators

1. A **generator** produces rows deterministically from the world seed. Every generator uses its own RNG stream `rng('content/<generator-id>', worldSeed)` from 02 (stream names listed in each section).
2. Generators run **once**: at world genesis for launch content, and at the creation event for later content (a new city, a new actor). Their output is written into world state and never regenerated, so a later code change cannot rename an existing thing.
3. **Sampling rule** (all generators): to pick from a list of length `n`, draw `u` from the stream and take index `floor(u × n)`. "Without replacement" removes the picked item. Weighted picks use the cumulative-weight method in list order.
4. **Uniqueness rule**: a generated name must be unique within its scope (stated per generator). On collision, redraw up to 10 times; after 10 collisions append a roman numeral ` II`, ` III`, … to the first candidate.
5. **Moderation rule**: every generated name is checked against the reserved-word list and the banned-word list (§16.4) before acceptance; a hit counts as a collision.

### §0.3 Bloc codes

00 §5.7 and modules 06, 10 identify blocs by their currency code; module 04 uses two-letter bloc ids. Both are valid; this file defines the mapping, and **institution entity IDs use the currency code** (`cbk_FDL`, `exc_FDL`, `reg_FDL`, `gov_FDL`, `crt_FDL`). 04's ids `cbk_FU` etc. are aliases resolved by the content loader (one alias table, §1.1). DEFAULT (Mathis may override); listed in 22-notes as a cross-module fix for 04.

### §4.1 Equities: the 240 NPC listed companies

**Columns.** `assetId = ast_EQ_<TICKER>`, issuer `cmp_<ticker lowercase>`. Sector = 06 `SectorId`. HQ = headquarters city (10 premises and city employment). `cap0` = genesis market capitalisation in billions of FDL (converted at genesis FX), from the authored rule below. Size = 06 size class by free-float cap within the bloc: L (top 12, large cap), M (next 24), S (bottom 12, small cap). `px0` = genesis share price in the listing currency; shares outstanding = `cap0 / FX0 / px0` rounded down to 1,000. `09 type` = the catalog business type used when 09 absorbs the company into the catalog economy (09 §3.13.10 mapping) and the type whose `ArchetypeRef` drives its fundamentals. Notes name special roles.

**Authoring rule for cap0 (DEFAULT, Mathis may override).** World listed cap at genesis = $40T FDL. Bloc total = $40T × `gdpShare0` (04). Within a bloc, sector weight = 1.8 for the bloc's three tilt sectors (04 §2.2 sector tilt), 1.0 otherwise, normalised. Within a sector the four companies take 45%, 27%, 17%, 11% in table order. `px0 = 20 + (h mod 380)` listing-currency units, where `h` = first 32 bits of SHA-256 of the ticker (deterministic). Free float 75% by default; dynasty-linked companies 60% (§10.4 sets which); REITs 90%. Earnings report slot: tickers sorted alphabetically within a bloc alternate PRE and POST; report day within the quarter = trading day `6 + (h mod 15)` (09 earnings calendar).

**Default factor loadings (05 §3.3.3).** By size class: L `L_GX 0.55, L_EQ 0.30, L_SECTOR 0.45`; M `0.50, 0.28, 0.42`; S `0.42, 0.25, 0.38` (each satisfies `L_GX² + L_EQ² + L_SECTOR² ∈ [0.35, 0.65]`). #### §3.4.2 Fundamental value
Inputs per issuer come from 09 (`CompanyFinancials`, assumed interface in §8 of the notes): `revenueTTM R`, `netMarginTTM m`, `debt D`, `interestRate on debt`, `taxRate`, `sharesOutstanding N`, `bookEquity B`, `expectedEps4Q` (09's model expectation of the next four quarters, computed from its business simulation), `growthFwd g_f` (expected revenue growth), hidden `quality q`, `management mg`, `moat mo` (0–100).

```
EPS_fwd   = expectedEps4Q                                       (09)
RA        = 1 − F / 50                                          risk appetite (04 §3.14.1), F = 04's Fear Index (0–100)
PE_s      = PE_base_s · exp(−d_s · (y10_bloc − r_neutral_bloc)) · (1 + 0.3 · RA)
gp        = clamp(PARAM.eq_growth_beta(1.5) · (g_f − g_sector_median), −0.30, +0.60)
qm        = 1 + 0.004 · (q − 50) + 0.002 · (mo − 50)            quality/moat multiplier, ±30% max
rr        = earnings re-rating state (§3.4.3), starts at 0, decays with half-life 91 game days
sent      = sentiment multiplier from 05, in [0.75, 1.25]

if EPS_fwd > 0:  V = EPS_fwd · PE_s · (1 + gp) · qm · exp(rr) · sent
else:            V = (R / N) · PS_base_s · (1 + gp) · qm · exp(rr) · sent · PARAM.eq_loss_maker_ps_haircut(0.7)
V = max(V, 0.3 · B / N)  if B > 0                                asset-value floor
V = max(V, tickSize)                                              hard floor 0.01 (01 §2.2); bankruptcy is an event, not a drift
```
**Player-listed companies** (09 §3.10.4; ruling in 24): `V = 09.fundamentalValue(cmpId) · sent` replaces the formula above (the sum-of-the-parts value of its businesses, properties and financial assets, because player businesses run on game-pace economics); the floors still apply. The P/E formula is used for NPC issuers only.

`y10_bloc` and `r_neutral_bloc` come from 04. The P/E guard of 01 §2.2 (P/E cannot sustainably exceed 3× the sector band) is implemented by 05's pull term: if `P / EPS_fwd > 3 · PE_s`, 05 multiplies κ by 4 for that asset.

### §3.8 Money Supply Index (MSI) and Net Worth Index (NWI)

The NWI is the ranking metric (00 §4): net worth in **real** terms, so that "a dollar in year 3 is worth the same as on launch day" (01 §0.6).

```
design_money(t) = κ · Σ_i w_i · W_target(age_i)          over all characters (not only engaged), κ = PARAM.msi_money_share = 0.20
raw(t)          = PEM_FDL(t) / design_money(t)            (actual player money relative to designed money for this population)
ema(t)          = ema(t-1) + α · (raw(t) − ema(t-1)),     α = 1 − 2^(−1/28)  (half-life 28 game days), daily at day close
MSI(t)          = clamp( ema(t) / ema_base, MSI(t-1)·(1 − 0.005), MSI(t-1)·(1 + 0.005) )
ema_base        = mean of ema over the world's first 168 game days; MSI = 1.000 during that period
NWI_i(t)        = NWrank_i(t) / MSI(t)
```

- Reading: MSI = 1.10 means players hold 10% more money than the design path for a population of this age profile; every nominal dollar of net worth then counts as 0.909 "real" dollars on the boards.
- MSI is published daily with 4 decimals. Boards show NWI in "real $" with the label `real`; personal screens show nominal NW first and NWI second (17).
- Seasonal ladders (15) use NWI deltas exactly as 01 §14.4 defines.
