## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. `stepWorld`: compute eN (live: from the supplied secret; harness/sandbox: `localSeedEntropy`), assemble the full header (intentsRoot, intentCount, prevTickHash = lastRecord.worldHash or the genesis value), run `runTickWithLadder`, and on commit build the TickRecord: postingsRoot/eventsRoot = Merkle over canonEncode of committed postings (sorted as postingDigest) and events (seq order); worldHash = worldHashOf(header incl. quarantine, partitionHashes). On HALT, status changes and no record is produced. Pure: no clock (durations come from an injected telemetry clock passed in `world.cfg`-free options).
2. Genesis (02 §8 edge 1): `createWorld` builds stores, registers entities via each module's `genesis(ctx)` in module order with phase 'P2' binding and tick 0 context; computes `genesisStateHash`; prevTickHash(0) = hex SHA-256('TYC/genesis' ‖ genesisStateHash). Tick 0 then runs the full pipeline with start-of-period hooks for chapter 1, year 1, quarter 1, month 1, week 1, day 1 (T02-13 hookPlan already includes them).
3. Event-sourcing records (02 §3.17.1): stepWorld outputs exactly the inputs needed to rebuild everything (header, sealed intents per partition, entropy secret) plus derived records (events with visibility, postings, snapshots when due via `snapshotKindsDueAfterCommit`). Persisting is 19.B's job.
4. `replay`: load the snapshot (stateHash verified by T02-10), then for each stored tick run stepWorld with the recorded header (including its quarantine list) and compare per-partition stateHash, worldHash, logicalStateHash, eventDigest, postingDigest; the first mismatch stops and returns a DeterminismIncident with the first divergent partition and the RNG draw counts of that tick (emit `core.determinism.incident` internal + SEALED when hosted). Engine version switching at a VERSION_CUTOVER tick is delegated to `engines(version)` (T02-18 provides migration application; 02 §8 edge 11).
5. `restorePartition`: `selectRestorable` newest DAILY ≤ target, then replay up to `targetTick` (at most 719 ticks for DAILY cadence, 02 §3.16.1).
6. Failover (02 §3.15.4): `recomputeNonDurable` discards any prepared state (abort) and re-runs the tick from N−1 with the same sealed inputs (the sealed batch is durable at P0). The timeout `coord_failover_timeout_ms` is used by 19.B; document it.
7. INV-ENG-008 (OFFLINE, FATAL): evaluated by the shadow verifier and nightly jobs over replay results.
8. Golden file: `golden/ticks-10000.sha256` = SHA-256 over the concatenated worldHash hex strings of a fixed 10,000-tick test world (seeded synthetic intents, fake modules from the test). CI on other architectures (20B G2 matrix) recomputes it.

# SPEC EXCERPTS (verbatim; binding game rules)

**[02 §1 Purpose]** (context)

## §1 Purpose

The world of TYCOON is one persistent, deterministic simulation that advances in discrete **ticks** of 5 real seconds. This module defines:

1. **The clock and calendar**: how a tick maps to a game date, time of day, trading phase, week, month, quarter, year and chapter, plus the holiday calendar of each bloc and what happens at every boundary.
2. **The tick pipeline**: the 15 phases P0 to P14 of 00 §5.2, how they run across invisible partitions, their time budgets, and what happens when a tick fails (rollback, safe mode).
3. **The pure `step()` contract**: the world advances only through a pure function of (state, sealed intents, entropy). No module may read the wall clock, a random source, the network or the disk inside `step()`.
4. **Determinism**: the coding rules, the deterministic math library, the fixed-point conversions (`toMoney` and friends), and the RNG streams (xoshiro128**, one stream per purpose and subject).
5. **Provable fairness**: commit-reveal entropy and fair intra-tick ordering, so the operator can prove it never rigged an outcome and no player can predict one.
6. **Persistence of time**: snapshots, event sourcing, replay, audit, versioning, catch-up when the server lags, clock drift, and maintenance in a world that never resets.

Design goals, in priority order: (a) the same inputs always give bit-identical outputs on any machine running the same engine version; (b) no player can gain anything from latency, device, timing or knowledge of the server; (c) a tick never commits partially; (d) the 5-second rhythm holds at 100k concurrent players and 750k AI agents (00 §5.7, 02-multiplayer §1).

#### §3.15.4 Coordinator failover

The hot-standby coordinator follows the primary's event store and entropy buffer synchronously. On primary loss: the standby waits until `PARAM.coord_failover_timeout_ms` (DEFAULT 3,000) without heartbeat, fences the primary (19), and resumes from the last durable `TickRecord`. Any tick that was prepared but not durable is recomputed from scratch with the same sealed inputs (the sealed intent batch is written durably at P0, before R1). Partitions that already prepared a different state for that tick discard it.

**[02 §3.17.2]** (from spec file 02-TIME-ENGINE-CORE.md)

#### §3.17.2 Replay

`replay(worldId, fromSnapshot, toTick, engineVersions)`:
1. Load the snapshot; verify its `stateHash`.
2. For each tick T in order: load header, intents, entropy secret; run `stepWorld` with the engine version recorded in the header (all historical engine bundles are retained, content-addressed); compare `stateHash` per partition and `worldHash` with the stored `TickRecord`. Any mismatch stops the replay and opens a **determinism incident** (20) with the first divergent partition, module trace and RNG draw counts.
3. Replays run in a sandbox (19) and never write to the live event store.

Uses: court evidence (13 cites ticks and requests replays of a tick range through the replay subpoena), support investigations, the Truth Machine (20), "Why it moved" explanations (17/18 read stored events, not replays), spectator replays of famous days (15), version-upgrade checks (§3.18).

**[19 §3.6]** (from spec file 19-TECH-ARCHITECTURE.md)

### §3.6 Determinism

**Rule 3.6.1 (runtime pinning).** Every world host and every harness runner uses the same Node.js minor version and the same `@tycoon/engine` bundle hash for a given `engineVersion`. The world host refuses to load a partition when the bundle hash or Node version differs from the value recorded in the coordinator's active configuration. The client sandbox (§3.17.4) is not authoritative and may differ.

**Rule 3.6.2 (forbidden in engine code).** Enforced by the `@tycoon/eslint-config/determinism` rule set on `packages/engine/**`, failing CI:
- `Math.random`, `Date`, `performance`, `setTimeout`, `setInterval`, `queueMicrotask`, `process`, `globalThis` access, `crypto` (except the vendored pure SHA-256 and Ed25519 verify in `engine/core/crypto`), `Intl`, `toLocaleString`, `localeCompare`.
- `Math.sin/cos/tan/exp/log/pow/sqrt/cbrt/hypot/atan2` and friends directly: use `detmath` (02), which is implemented with correctly rounded or fixed-algorithm versions identical on every platform. Only `+ − × ÷`, `Math.abs/min/max/floor/ceil/round/trunc/sign/fround` and `Math.imul` are allowed raw.
- `Array.prototype.sort` without an explicit comparator; comparators that can return inconsistent results (lint checks for `localeCompare` and subtraction of possibly NaN values).
- `for…in`, iteration over `Object.keys` of objects used as maps (use the engine `SortedMap`), `WeakMap`, `WeakRef`, `FinalizationRegistry`, `Symbol()` as keys in state.
- `async`/`await`, Promises, generators that yield across phases.
- `JSON.stringify` for anything hashed or serialized: use the canonical encoder of `packages/protocol`.
- Summation of floats over collections must iterate in canonical order (sorted by entity id); the store API only exposes collections in that order.

**Rule 3.6.3 (store API).** Engine state lives in a typed in-memory store per partition. `store.get(kind, id)`, `store.iter(kind)` (sorted by id), `store.put(entity)`, `store.del(id)`. Each write records an undo entry for the open tick. `put` and `del` check the ownership table: the calling module (bound when the phase handler is invoked) must own the entity kind; otherwise it throws `OwnershipViolation`, which aborts the tick (safe mode, §3.6.5). The ownership table is generated at build time from each module's `schema.ts`.

**Rule 3.6.4 (event sequence numbers).** Each partition assigns provisional `seq` within its outputs. At P14, COORD orders all events of the tick by `(phase, originEntityId, provisionalSeq)` and assigns the global `seq` 0…n−1. Consumers rely only on `(tick, seq)`.

**Rule 3.6.5 (rollback and safe mode).** If any invariant fails in P13 on any partition, or any partition throws, COORD broadcasts `TickAbort(N)`. Every partition calls `rollback(N)` (undo log), and the tick is re-executed in **safe mode** (02): the same batch, with the failing module's optional behaviours disabled as 02 specifies, and with extra invariant checks. If the safe-mode run also fails, COORD halts the world (`WorldStatus = MAINTENANCE`, diegetic "Trading halted by the Exchange", 17), pages on-call, and files a reproducible case (batch hash, snapshot ids, partition messages) for 20. No tick is ever committed with a failed invariant.

**Rule 3.6.6 (partition-independent hash).** Every entity has `entityHash = SHA-256(canonicalEncode(entity))`, updated when written. `logicalStateHash = Σ_entities u256(SHA-256(entityId ‖ entityHash)) mod 2^256`, maintained incrementally (subtract old term, add new). Because addition is commutative, the value does not depend on which partition holds which entity. `TickRecord.logicalStateHash` is the sum over partitions. Tests (§10) run the same batches with 1, 3 and 17 partitions and require identical logical hashes at every tick.

**Rule 3.6.7 (golden replay in CI).** Every engine change runs the regression seeds of 20 (headless) and, before deployment, replays the last `PARAM.deploy_replay_game_days = 1` game day of production batches from the latest snapshot on both the old and new engine. Divergence is allowed only for event kinds and entities listed in the change's `intendedDivergence` manifest; anything else blocks the deploy.
