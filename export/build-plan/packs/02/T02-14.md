## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. Home rule table (02 §3.14.1, 19 §2.1): COORD = clock, headers, entropy, global calendar hooks, macro state (04), courts/regulators dockets (13), boards aggregation (15), Stabilizer (03), cross-partition invariant checks; ACTOR = named NPC actors (16), news, politics, dynasties; MARKET = order books, NPC liquidity providers and inventories, auction and per-asset price state; FINANCE = exchanges' books, central banks, treasuries, NPC banks, NPC funds and insurers, SPVs, rating agencies, regulators' and courts' accounts, the `sys` entity; CCP = the clearing house; CITY = `hh` of the city, businesses and properties located in it (incl. player-owned), districts, demand pools; PLAYER = characters, their cmp, funds, banks, insurers and alliances whose root owner is there, AI agents, hidden sessions on their models, holds, positions, margin accounts. Modules declare `home(e)` on tables where the id alone is not enough (biz/prop by cityId, market rows by assetGroup, player-owned cmp/fnd/bnk by rootChrId).
2. Rounds (02 §3.5.3) per tick, coordinator side:
   - R0 (COORD): P0 seal for all intents; broadcast header + entropy; split sealed intents to each actor's home PLAYER partition (institutional intents to FIN/CITY by the handler's target home) preserving the global fair order.
   - R1 (all): deliver NEXT inbox; P1 (PLAYER, and FINANCE/CITY for their own institutional intents); P2 local hooks on every partition and global hooks on COORD; P3 on ACTOR; P4 on MARKET/ACTOR/FINANCE; P5 on PLAYER. Each partition's runtime runs only the phases its kind runs (02 §3.5.1 "Runs in" column) but every module's phase function is invoked on each partition of the right kind (modules see only local state).
   - B1: deliver 'route.*' messages (orders to MARKET, business/property intents to CITY, institutional to FINANCE, conflict to the target's PLAYER).
   - R2: MARKET P6. B2: 'fill', 'mark'.
   - R3: FINANCE+PLAYER P7, P8; CITY P9; PLAYER P10; COORD+PLAYER P11; PLAYER+COORD P12. B3: 'posting.leg', 'hold.settle'; buffer NEXT.
   - R4: each partition prepares (ledger prepare, local invariants, stateHash). R5 (COORD): ledger.globalCheck + global invariants; decide COMMIT/ABORT. R6: commit (pointer swap) and P14, or abort everywhere.
   A partition with nothing to do still reports done (rule 3).
3. Message identity: a module's `ctx.send(toEntity, ...)` is routed to `partitionOf(home(toEntity))`; sequence numbers are per (fromPartition, tick) in send order; delivery sorted by (fromPartition, seq) (rule 1). With `isolate: true` every message and every input/output crossing the coordinator boundary is canonEncoded and decoded (no shared objects), so the in-process run is a faithful model of multi-process execution.
4. Institution-aware routing (02 §3.14.4): a decision of an institution in tick N is sent with `when = 'NEXT'` to each counterparty's home; the bus buffers and delivers at R1 of N+1 in sorted order. Assert in tests that no partition applies another partition's decision in the same tick.
5. Hashes: each partition reports stateHash (T02-09) and its logical sum; worldHash = worldHashOf(header, partitionHashes); logicalStateHash = sumLogical (19 Rule 3.6.6). Events from all partitions are sequenced together by COORD at P14 (T02-12 sequenceEvents) so the canonical event stream is partition independent (origin partition excluded).
6. Rebalancing (02 §3.14.5): moves only between commit of t = 719 and t = 0, entities with zero active holds and zero suspense; the new map takes effect via a directive in the next header (T02-18 validates). Moving never changes results (asserted by equivalence with a mid-run move).
7. INV-ENG-009 (OFFLINE, FATAL): `runEquivalence` produces digests for each map; the invariant compares (logicalStateHash, eventDigest, postingDigest) per tick (postingDigest empty string until 03 supplies postings).

# SPEC EXCERPTS (verbatim; binding game rules)

**[02 §1 Purpose]** (context)

## §1 Purpose

The world of TYCOON is one persistent, deterministic simulation that advances in discrete **ticks** of 5 real seconds. This module defines:

1. **The clock and calendar**: how a tick maps to a game date, time of day, trading phase, week, month, quarter, year and chapter, plus the holiday calendar of each bloc and what happens at every boundary.
2. **The tick pipeline**: the 15 phases P0 to P14 of 00 §5.2, how they run across invisible partitions, their time budgets, and what happens when a tick fails (rollback, safe mode).
3. **The pure `step()` contract**: the world advances only through a pure function of (state, sealed intents, entropy). No module may read the wall clock, a random source, the network or the disk inside `step()`.
4. **Determinism**: the coding rules, the deterministic math library, the fixed-point conversions (`toMoney` and friends), and the RNG streams (xoshiro128**, one stream per purpose and subject).
5. **Provable fairness**: commit-reveal entropy and fair intra-tick ordering, so the operator can prove it never rigged an outcome and no player can predict one.
6. **Persistence of time**: snapshots, event sourcing, replay, audit, versioning, catch-up when the server lags, clock drift, and maintenance in a world that never resets.

Design goals, in priority order: (a) the same inputs always give bit-identical outputs on any machine running the same engine version; (b) no player can gain anything from latency, device, timing or knowledge of the server; (c) a tick never commits partially; (d) the 5-second rhythm holds at 100k concurrent players and 750k AI agents (00 §5.7, 02-multiplayer §1).

#### §3.5.3 How phases run across partitions (rounds and barriers)

Partitions are single-writer and run their own slice of each phase. The coordinator drives the tick in **rounds** separated by **barriers**; inside a round, partitions run in parallel and never talk to each other.

```
Round R0 (COORD):           P0 seal -> broadcast TickHeader + TickEntropy
Round R1 (all partitions):  P1 validate+hold (PLAYER), P2 local hooks,
                            COORD P2 global hooks, WORLD P3, MARKET/WORLD/FIN P4, PLAYER P5
Barrier B1:                 deliver 'route.*' messages produced in R1
Round R2 (MARKET, CITY*):   P6 match ; (*CITY runs nothing yet)
Barrier B2:                 deliver 'fill', 'mark' messages
Round R3 (all):             FIN+PLAYER P7, FIN+PLAYER P8, CITY P9, PLAYER P10, COORD+PLAYER P11, PLAYER+COORD P12
Barrier B3:                 deliver 'posting.leg', 'hold.settle', and buffer 'NEXT' messages for tick N+1
Round R4 (all):             P13 prepare: apply postings, settle/release holds, local invariants, stateHash
Round R5 (COORD):           P13 decide: global invariants, write TickRecord, broadcast COMMIT or ABORT
Round R6 (all):             P13 commit (pointer swap) ; P14 emit
```

Rules:

1. Messages are delivered at a barrier **sorted by (fromPartition, seq)** using byte order of the partition id string; the receiving partition processes them in that order. Network timing can never change the order.
2. Messages produced in R3 with `round = 'NEXT'` are consequences: they are stored in the receiving partition's inbox and processed at the start of R1 of tick N+1, before any intent of N+1 (in sorted order). Examples: liquidation orders found in P7, a hidden session opened by a breach resolved in P10, a court-ordered freeze from P11, a contract payment due from P12.
3. A partition that has nothing to do in a round still reports `done` at the barrier.
4. In single-process deployments (launch), all partitions share one process and barriers are function returns; behaviour and hashes are identical to multi-machine deployments.

#### §3.14.4 Institution-aware routing (V3 Part 10)

A bank run, a CCP default or a fund gate is an event of an institution in one partition (FIN or the owner's PLAYER) that affects counterparties in many partitions. It is ordered by the same rules: the institution's partition decides the event in tick N (P7/P8), emits `NEXT` messages to every counterparty partition, and counterparties apply it in tick N+1 in sorted order. No partition ever applies another partition's decision in the same tick.

#### §3.14.5 Rebalancing

Moving entities between partitions happens only at a **daily snapshot boundary** (after the commit of t = 719, before t = 0 of the next day): the planner (19) writes a `REBALANCE` snapshot, the entities' state is moved, partition descriptors are updated in the header of the next tick (`directives` with kind `PARAM_CUTOVER` carrying the new assignment table), and holds and suspense balances must be zero for moved entities (the planner selects only entities with no active holds; others move next day). Rebalancing never changes any result, because partitioning does not enter any model formula.

### §3.6 Determinism

**Rule 3.6.1 (runtime pinning).** Every world host and every harness runner uses the same Node.js minor version and the same `@tycoon/engine` bundle hash for a given `engineVersion`. The world host refuses to load a partition when the bundle hash or Node version differs from the value recorded in the coordinator's active configuration. The client sandbox (§3.17.4) is not authoritative and may differ.

**Rule 3.6.2 (forbidden in engine code).** Enforced by the `@tycoon/eslint-config/determinism` rule set on `packages/engine/**`, failing CI:
- `Math.random`, `Date`, `performance`, `setTimeout`, `setInterval`, `queueMicrotask`, `process`, `globalThis` access, `crypto` (except the vendored pure SHA-256 and Ed25519 verify in `engine/core/crypto`), `Intl`, `toLocaleString`, `localeCompare`.
- `Math.sin/cos/tan/exp/log/pow/sqrt/cbrt/hypot/atan2` and friends directly: use `detmath` (02), which is implemented with correctly rounded or fixed-algorithm versions identical on every platform. Only `+ − × ÷`, `Math.abs/min/max/floor/ceil/round/trunc/sign/fround` and `Math.imul` are allowed raw.
- `Array.prototype.sort` without an explicit comparator; comparators that can return inconsistent results (lint checks for `localeCompare` and subtraction of possibly NaN values).
- `for…in`, iteration over `Object.keys` of objects used as maps (use the engine `SortedMap`), `WeakMap`, `WeakRef`, `FinalizationRegistry`, `Symbol()` as keys in state.
- `async`/`await`, Promises, generators that yield across phases.
- `JSON.stringify` for anything hashed or serialized: use the canonical encoder of `packages/protocol`.
- Summation of floats over collections must iterate in canonical order (sorted by entity id); the store API only exposes collections in that order.

**Rule 3.6.3 (store API).** Engine state lives in a typed in-memory store per partition. `store.get(kind, id)`, `store.iter(kind)` (sorted by id), `store.put(entity)`, `store.del(id)`. Each write records an undo entry for the open tick. `put` and `del` check the ownership table: the calling module (bound when the phase handler is invoked) must own the entity kind; otherwise it throws `OwnershipViolation`, which aborts the tick (safe mode, §3.6.5). The ownership table is generated at build time from each module's `schema.ts`.

**Rule 3.6.4 (event sequence numbers).** Each partition assigns provisional `seq` within its outputs. At P14, COORD orders all events of the tick by `(phase, originEntityId, provisionalSeq)` and assigns the global `seq` 0…n−1. Consumers rely only on `(tick, seq)`.

**Rule 3.6.5 (rollback and safe mode).** If any invariant fails in P13 on any partition, or any partition throws, COORD broadcasts `TickAbort(N)`. Every partition calls `rollback(N)` (undo log), and the tick is re-executed in **safe mode** (02): the same batch, with the failing module's optional behaviours disabled as 02 specifies, and with extra invariant checks. If the safe-mode run also fails, COORD halts the world (`WorldStatus = MAINTENANCE`, diegetic "Trading halted by the Exchange", 17), pages on-call, and files a reproducible case (batch hash, snapshot ids, partition messages) for 20. No tick is ever committed with a failed invariant.

**Rule 3.6.6 (partition-independent hash).** Every entity has `entityHash = SHA-256(canonicalEncode(entity))`, updated when written. `logicalStateHash = Σ_entities u256(SHA-256(entityId ‖ entityHash)) mod 2^256`, maintained incrementally (subtract old term, add new). Because addition is commutative, the value does not depend on which partition holds which entity. `TickRecord.logicalStateHash` is the sum over partitions. Tests (§10) run the same batches with 1, 3 and 17 partitions and require identical logical hashes at every tick.

**Rule 3.6.7 (golden replay in CI).** Every engine change runs the regression seeds of 20 (headless) and, before deployment, replays the last `PARAM.deploy_replay_game_days = 1` game day of production batches from the latest snapshot on both the old and new engine. Divergence is allowed only for event kinds and entities listed in the change's `intendedDivergence` manifest; anything else blocks the deploy.

### §3.3 Determinism and partition equivalence

**Rule 3.3.1 (hashes).** 19 defines two hashes per tick: `worldHash` (Merkle root over partition hashes, depends on the partition map) and `logicalStateHash` (partition independent, 19 §3.6.6). The Truth Machine's equivalence claims are always about `logicalStateHash` plus the **canonical event stream digest** `eventDigest(T) = SHA-256(canonical encoding of all EngineEventRow of tick T in seq order, excluding originPartition)` and the **posting digest** `postingDigest(T)` defined the same way over committed postings sorted by `(entryId, debitAccount, creditAccount)`.

**Rule 3.3.2 (the equivalence statement).** For any seed, params version, content version, engine version and sealed intent log, the triple `(logicalStateHash(T), eventDigest(T), postingDigest(T))` is identical for every tick `T` when the world runs as **1, 4 or 16 partitions** (`PARAM.tm_equivalence_partition_counts = [1, 4, 16]`, `DEFAULT (Mathis may override)`), on every supported host profile, and when resumed from any snapshot instead of genesis. This is INV-ENG-009.

**Rule 3.3.3 (how partition maps are chosen for the test).** For a partition count `k`:
- `k = 1`: everything in one partition (one process, one worker).
- `k = 4`: COORD; one PLAYER partition; one MARKET partition holding all asset groups; one partition holding CITY, FINANCE, CCP and ACTOR shards.
- `k = 16`: COORD; 4 PLAYER hash ranges; 4 MARKET asset groups (equities, rates and FX, commodities and crypto, derivatives); 3 CITY groups; FINANCE; CCP; ACTOR; plus one spare that receives a partition move at a snapshot boundary mid-run (exercises 19 §3.5.6 rebalancing).
A nightly run also draws one **random partition map** with 2–24 partitions from stream `tm:partitionmap` (harness RNG, not world RNG) so the property is tested beyond the three fixed shapes.

**Rule 3.3.4 (first-divergence search).** On a mismatch at tick `T`, the runner compares per-entity hashes (19 `Snapshot.logicalEntityHashes`, computed on demand at `T`) between the runs, sorts differing entity ids canonically, then replays tick `T` phase by phase on both configurations and reports the first phase whose outputs (phase messages, events, postings) differ for the first differing entity, down to the first differing field path. The result fills `EquivalenceRun.firstDivergence` and a CRITICAL RegressionCase.

**Rule 3.3.5 (host profiles).** Supported host profiles are the cross product of CPU architecture {x64, arm64} and the pinned Node.js minor (19 Rule 3.1.4). Every nightly G2 runs equivalence on both architectures. A toolchain upgrade (Node minor, V8 flags, dependency of `engine/core`) runs a 7-game-day STANDARD world on old and new toolchains and compares all three digests every tick (part of G2).

**Rule 3.3.6 (version replay).** Every deploy of a new engine version runs the last full game day of production on the candidate version against the production intent batches (02 §3.3 of the old vision, 19). Ticks must be identical except where the release notes declare an intended behaviour change; for intended changes, the candidate's divergence must start at or after the change's effective tick (changes take effect only at the declared tick, never retroactively, 21 §3.4).

**Rule 3.3.7 (sandbox and Academy worlds).** The browser sandbox (19 §3.17) and Academy practice worlds (18) run the same `packages/engine` bundle. A G2 check runs a 30-game-day MICRO world in the browser build (headless Chromium, Web Worker) and in Node and compares `logicalStateHash` every tick.
