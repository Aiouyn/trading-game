## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. Per active tick (05 §3.3.1), for each asset whose `isValueActiveTick` is true, in ascending `assetId`:
   - `σ_ann,eff = sigmaV × PARAM.mkt_lnv_vol_scale × √h × m_reg × m_event × m_hype`; `m_hype = 1 + 2H` for CRYPTO_ALT, CRYPTO_MAJOR and MEME using `ports.instruments.hype`, else 1. `m_reg` is the blended regime vol multiplier (step 5). `m_event` from `eventMultipliers` (product of active VOL_SHOCK multipliers decaying with their half-life: `1 + (mult − 1) × 2^(−elapsedDays/halfLifeDays)`).
   - `A = −k (lnV − lnF)`, `k = anchorK(anchorHalfLifeDays)`; FX legs use `PARAM.mkt_fx_anchor_hl_days` and `lnF = getFxState(store, ccy).fairValueLn`; government bonds use 06's anchor with its 2-day half-life (06 §3.21 via `priceParams`).
   - `D = −½ σ_ann,eff² / A_year` where `A_year = activeTicksPerYear`.
   - `S = σ_ann,eff √(1/A_year) (Σ_k L'_k z_k + √(1 − Σ L'²) ε)`; `z_k` drawn once per tick per factor (shared by every asset) by `drawFactorShocks` from `mkt.factor:<factorId>` in sorted factor order, done once in P3 before the asset loop; `ε = studentT(ν) × √((ν−2)/ν)` from `mkt.idio:<assetId>` (exactly one draw per active tick). Keep each factor's contribution separately in `Sfactor` and the idio part in `Sidio`.
   - `J`: one `kouJump` call per active tick from `mkt.jump:<assetId>` with occurrence probability `λ_eff/A_year`, `λ_eff = jumpsPerYear × regime jump mult × hook jumpMult`, `pUp_eff = clamp(jumpUpProb − regime skew, 0, 1)` (skew is the down-probability shift). Draw count is fixed whether or not a jump occurs (G8).
   - `X`: Σ delivered value shocks targeting this asset with `uncertainty == 0`, plus factor jumps mapped by `factorJumpToAsset` (05 §3.3.3 "Factor jumps"; `σ_ref,k` is the realized annual vol of the factor's reference index kept in `FactorState.refSigma`, initialised from content and updated by T05-19's index EWMA). Shocks with `uncertainty > 0` are returned in `beliefShocks` and never touch `lnV` (05 §3.3.4).
   - On non-active ticks (weekends for session classes) still apply `X` (05 §3.3.4, edge 5) but no A, D, S, J.
   - ETFs: no own process; `lnV = etfValueLn(...)` each tick from constituents' `lnV` (ports.instruments.etfINavLn). Options and other derivatives: no value process (skip; 06 marks them).
   - Store `lnV`, `lnF`; add X to `aux.shocksToday`, track `aux.maxShockToday = max |X|`.
2. Shock collection: `collectValueShocks` merges 04 `macroValueShocks`, `ports.instruments.valueShocks`, `ports.companies.valueShocks`, `ports.ai.valueShocks`, `ports.conflict.valueShocks`, `ports.world.valueShocks` whose `publishTick == tick`; a shock whose target is a factor id becomes a `FactorJump`. 06 moves `lnF` by the same amount on a discrete fundamental change (05 §3.3.1 last bullet), so do not add A for that move: the anchor pull uses the post-shock `lnF` and the post-shock `lnV`. Record each applied shock in `mkt.shock` (`ValueShockRecord`, band 'EARLY', attributed 0) for T05-16's priced-in bands.
3. Crisis correlation (05 §3.3.3): `c = PARAM.mkt_crisis_corr_storm` or `PARAM.mkt_crisis_corr_major` when an active 04 `WorldEvent` of tier STORM or MAJOR is in phase TRIGGER or CONTAGION and affects the asset (its bloc in `blocs`, or its sector in `sectors`, or the asset in `assetsHint`; a WORLD event with empty blocs affects all), plus the regime's `c_reg`. `L'_GX = √(L_GX² + (c + c_reg)(1 − Σ L²))`; other loadings unchanged; if Σ L'² > 1 cap at 1 by rescaling `L'_GX` so Σ = 1 and idio share 0 (05 §8 edge 19).
4. GARCH (05 §3.3.2), at t = 719 of a trading day in P8: `r_d = (lnV_close − aux.vPrevCloseLn) − aux.shocksToday`; `h_new = ω + α r_d²/σ_d,base² + β h`, `ω = 1 − α − β`, `σ_d,base = sigmaV × 1.15 × m_reg / √Dy` (1.15 = `PARAM.mkt_lnv_vol_scale`); if `aux.maxShockToday > 3 σ_d` add `0.5 (|X|/σ_d,base)² α` using the largest shock; clamp to [`mkt_garch_h_min`, `mkt_garch_h_max`]. Stablecoins α 0.02, β 0.95. Then `vPrevCloseLn = lnV`, reset `shocksToday`, `maxShockToday`. Crypto runs it at t=719 every day.
5. Regimes (05 §3.3.5): `assetRegime` = home bloc regime (bloc = asset `ccy`), global regime for crypto, gold, commodity classes. When the regime differs from `aux.regimeBlend.to`, set `from = current blended state's regime`, `to = new`, `startTick = tick`; multipliers move linearly over 5 trading days (5 × 720 trading-day ticks; weekend ticks do not advance the blend). The Fear Index never multiplies value volatility (D075).
6. Hooks (05 §6.4, 04 §3.16.6): `ingestHookCalls` in P2 turns each 04 hook call into an `ActiveHook` row (`hookId = ctx.newId('hk')`, `startTick = tick + 1` because hooks apply from the next tick, `untilTick` from ticks or days × 720). `eventMultipliers` multiplies all active matching hooks: MAKER_WITHDRAWAL → `depthEvent` (used by T05-04), NPC_SELL_PROGRAM → `sellProgramAdvPerTick` (used by T05-14), VOL_SHOCK → `mEvent`, JUMP_INTENSITY_SHOCK → `jumpMult`. Expired rows are deleted in P2. `eventIds` carry the WorldEvent ids for EVENT cause tags.
7. Edge case 15/19 and weekend shocks handled as above. All math through `dmath`; no `Math.exp/log/pow`.

# SPEC EXCERPTS (verbatim; binding game rules)

**[05 §1 Purpose]** (context)

## §1 Purpose

The market engine turns everybody's orders (players, player AIs, delegated operators, NPC pools, central banks, treasuries and liquidation engines) into prices, once every tick, for every listed instrument, fairly and explainably.

Design commitments (old 01 §0, §7; V3 Part 4; MASTER-BIBLE Part VII T02–T10):
1. **Fairness by batching.** Every tick each asset clears in one uniform-price call auction. There is no latency race, no front-running inside a tick, and the same result on a phone and a desktop.
2. **Players are price-makers.** Small players are invisible; whales leave footprints; coordinated players can squeeze. Impact follows the square-root law from $1k to $10B, in **one** place (the NPC market maker's ladder), so no effect is charged twice (T08).
3. **Prices come from who trades and why.** A value layer (fundamentals, macro factors, news) says what an asset is worth; a flow layer (trader pools and players clearing against the market maker) says what it trades at. Inefficiencies (post-news drift, overreaction, quarter-end, crowding) emerge from the pools and die as capacity is used (specs/quant-market-ecology).
4. **Explainable afterward.** Each closed day and hour has a cause vector that sums exactly to the move, so the trade journal, the "Why it moved" ladder and the Research Desk can never contradict the tape.
5. **Nothing leaks.** Public data is aggregate: depth by price level, prints, volume. No account identity, no hidden reserve, no stops, no algo parents ever leave the engine (L11).
6. **Deterministic.** The engine is a pure function of (seed, state, sealed intents, entropy commits) (02).

#### §3.3.1 Per-tick step
For each active tick:

```
lnV_N = lnV_{N−1} + A_N + D_N + S_N + J_N + X_N

A_N (anchor pull)  = −k · (lnV_{N−1} − lnF_N),           k = 1 − 2^(−1 / (anchorHalfLifeDays × 720))
D_N (convexity)    = −½ · σ_ann,eff² / A                    (keeps E[V] a martingale between anchor moves)
S_N (diffusion)    = σ_ann,eff · √(1/A) · ( Σ_k L'_k · z_{k,N} + √(1 − Σ_k L'_k²) · ε_N )
J_N (Kou jump)     = with probability λ_eff / A: +Exp(jumpUpMean) w.p. pUp_eff, else −Exp(jumpDownMean)
X_N (external)     = Σ value shocks delivered this tick (§3.3.4)
```

- `σ_ann,eff = sigmaV × PARAM.mkt_lnv_vol_scale (1.15) × √h × m_reg × m_event × m_hype`. The 1.15 scale compensates for the flow layer printing value moves only partially (specs/quant-market-ecology `lnVVolScale`); 20 calibrates it so that realized price volatility over 63 days is within [0.9, 1.1] × `sigmaV` in calm regimes.
- `h` is the GARCH multiplier (§3.3.2); `m_reg` the regime multiplier (§3.3.5); `m_event` the product of active 04 crisis multipliers for this asset (§6.4); `m_hype = 1 + 2H` for crypto and meme (06 §3.x hype `H`), else 1.
- `z_{k,N} ~ N(0,1)` is one draw per factor per tick, shared by every asset (stream `mkt/factor/<k>`). `ε_N` is a standardized Student-t with `ν` degrees of freedom from 06 §3.21, scaled to unit variance (`ε = t_ν × √((ν−2)/ν)`), stream `mkt/idio/<assetId>`.
- `lnF` is 06's anchor for this tick (interface §3.3.6). A changed anchor is not printed as a jump: it pulls with the half-life. A **discrete** fundamental change (earnings surprise, rating action, M&A terms, default) arrives as a value shock in `X` (§3.3.4) and 06 moves `lnF` by the same amount in the same tick, so the pull does not double count.

#### §3.3.2 GARCH volatility clustering
Once per trading day at `t = 719` (P8):

```
r_d   = ln(V_close / V_prev_close) − (sum of X shocks today)     // diffusive part only; news shocks do not feed GARCH twice
h_new = ω + α · (r_d² / σ_d,base²) + β · h_old,     ω = 1 − α − β   (unconditional mean of h is 1)
h     = clamp(h_new, PARAM.mkt_garch_h_min (0.25), PARAM.mkt_garch_h_max (9))
```

`α = PARAM.mkt_garch_alpha (0.08)`, `β = PARAM.mkt_garch_beta (0.90)`; stablecoins `α = 0.02`, `β = 0.95` (06 §3.21). `σ_d,base = sigmaV × 1.15 × m_reg / √Dy`. A news shock larger than `3σ_d` adds `0.5 × (|X|/σ_d,base)² × α` to `h_new` (big news does raise future volatility, but at half weight).

#### §3.3.3 Factor model
Factors (all orthogonal by construction; correlation between assets comes only from shared loadings, which keeps the covariance matrix positive definite by construction):

| Factor id | Meaning | Who loads |
|---|---|---|
| `GX` | world equity market | every equity, ETF, crypto (0.2–0.4), HY credit |
| `EQ_<bloc>` (5) | bloc equity market beyond GX | that bloc's equities |
| `SECTOR_<sector>` (one per sector in 22, 12 at launch) | sector | equities of the sector, sector ETFs |
| `RATES_<bloc>` (5) | bloc rates level (price factor: + = rates down) | government and corporate bonds, rate-sensitive equities (utilities, REITs, banks with negative sign) |
| `CREDIT` | world credit spread (+ = spreads tighter) | corporate bonds, banks, HY-sensitive equities |
| `FX_<ccy>` (EUN, PYN, NKR, SRL) | currency value vs FDL | FX legs (loading 1), exporters (signed) |
| `CMD_ENERGY`, `CMD_METALS`, `CMD_AGRI`, `GOLD` | commodity groups | commodities, energy and mining equities |
| `CRYPTO` | crypto market | crypto majors (0.7–0.9), alts, meme, crypto equities |
| `AI_RACE` | AI race sentiment (11's index changes) | AI, chip and compute assets |

Default loadings are authored per asset in 22 within these class rules: equities `L_GX² + L_EQ² + L_SECTOR² ∈ [0.35, 0.65]` (large caps at the top), bonds `L_RATES² ∈ [0.7, 0.95]`, FX legs `L_FX = 1` (their diffusion is the factor itself, so FX crosses are consistent), crypto `L_CRYPTO² ∈ [0.5, 0.8]`. The identity `Σ L'² ≤ 1` is validated at load (22 authoring check).

**Crisis correlation.** While a STORM or MAJOR affecting the asset is in its TRIGGER or CONTAGION phase (04 §3.16), the market loading is raised and idiosyncratic share reduced: `L'_GX = √(L_GX² + c × (1 − Σ L²))`, with `c = PARAM.mkt_crisis_corr_storm (0.3)` or `PARAM.mkt_crisis_corr_major (0.5)`, plus the regime's additive `c_reg` (§3.3.5). Other loadings unchanged. This reproduces "correlations go to one in a crash" without a separate model.

**Factor jumps.** 04's release reactions (04 §3.15, "handed to 05 as a news jump on factors") and 04's crisis hooks deliver factor jumps `J_k`. Each asset applies `X += L_k × (σ_ann,asset / σ_ref,k) × J_k`, where `σ_ref,k` is the volatility of the factor's reference index (GX index, bloc index, sector index, a 10y bond line, the FX pair itself). So "GX −3%" moves a 1.5-beta stock about −4.5% and a defensive stock less.

#### §3.3.4 Value shocks (`X`)
A value shock is `ValueShock { shockId, target: assetId | factorId, logMove, sourceKind: 'NEWS' | 'MACRO' | 'FUNDAMENTAL' | 'EVENT', sourceRef, uncertainty }`, delivered by its owner module:
- 09: company events (earnings surprise, guidance, product, executive change, scandal, M&A, bankruptcy), sized by 09's own fundamentals model; 06 moves the anchor accordingly.
- 04: macro releases, CB decisions (through the curve for bonds; equity factor jumps per 04 §3.15), sovereign events, FX regime events, crisis trigger shocks.
- 06: rating actions on corporates (via 08), stablecoin depegs, venue incidents, commodity supply shocks.
- 11 (AI race milestones), 12 (successful hostile ops against a listed company, sized by 12), 16 (politics, weather, geopolitics; 16 never sizes asset moves itself, it supplies event facts and the owner module sizes them, 16 §3.6.5).
A shock with `uncertainty > 0` (an unconfirmed fact, a rumor, a claim) does **not** enter `lnV`; it enters the belief overlay instead (§6.3) until it resolves.

Shocks published on a weekend or overnight apply to `lnV` at their tick; the price catches up at the next open (§3.10.1).

## §8 Edge cases

1. **No crossing interest and the maker at band edge**: no trade; last price unchanged; indicative published.
2. **Band clamps for three ticks then reverses**: the streak resets on the first unclamped tick; no interruption.
3. **Halt and market-wide halt overlap**: the longer end tick wins; one REOPEN auction.
4. **L3 market-wide halt before the close**: no closing auction; official close = last price; MOC orders expire unfilled; 08 strikes NAV on that close.
5. **Weekend news**: `lnV` moves on the weekend tick; crypto trades it immediately; equities gap at Monday's open via openPrint and pools' opening orders.
6. **Stop triggered by a band-clamped print**: triggers on that LAST; the stop joins the next tick as a market order with protection.
7. **Iceberg reserve plus STP**: the decrement applies to displayed then hidden quantity of both orders.
8. **FOK larger than all available interest**: removed in pass 2; no partial.
9. **Order modify in the same tick as a fill**: P1 modifications precede the auction, so the modified order is what matches.
10. **Corporate action on a tick with resting GTC orders**: adjusted in P2 (§3.21); orders below one lot are cancelled with `CORPORATE_ACTION`.
11. **Asset suspended with algos working**: algos cancel; holds release.
12. **Capital controls imposed while an autoFx order works**: the next FX leg fails; the asset leg cancels with `FX_LEG_FAILED`.
13. **Held imposed mid-day** (13): all non-reducing orders cancel with `HELD_FORCED`; existing algos stop.
