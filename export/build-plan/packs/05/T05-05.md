## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

# TASK T05-05: Uniform-price batch auction, part 1 - participants and clearing-price selection

Unit 05 · stage S2 · depends on: T05-01, T05-04

Files to create:
- `packages/engine/markets/rules/auction/book.ts`

## Goal
Given one asset's participants for this tick (resting and new orders, triggered and generated orders, pool IOC limits and the analytic maker ladder) and the band `[lo, hi]`, compute the one uniform clearing price `p*` by maximum executed volume with the spec's tie-breaks, or "no trade" with the indicative price and imbalance. This function is the heart of the fairness commitment: it must be independent of submission order inside the tick.

- T05-01: `Order`, `Side`, `MarketSpec`, `PoolKind`, `gridTickAt`.
- T05-04: `MakerQuote`, `makerAskQtyAtPrice`, `makerBidQtyAtPrice`, `makerBreakpoints`.

## Implementation steps
1. Participants (05 §3.5.1): (1) resting orders with remaining displayed and hidden quantity; (2) new orders accepted in P1 and orders triggered/generated in 6.0; (3) the maker ladder as aggregate curves (`book.maker`); (4) pool orders from P4 as IOC limits. Orders with `auctionOnly` participate only when the tick's auction kind is not 'TICK' (filtered by the caller, T05-22). Hidden reserve counts toward Dem/Sup (it can fill; only allocation order differs).
2. Sort participants canonically with `sortParticipantsCanonical` (by `key`) before any computation; never depend on array input order (INV-MKT-006: ordering inside a tick depends only on `orderKey`, 19 §3.4.4; order ids are assigned in P1 in `orderKey` order by T05-11, so key order is orderKey-derived).
3. Candidate set `C`: every limit price of a participant inside `[lo, hi]`, plus `makerBreakpoints(maker, lo, hi)`, plus `lo` and `hi`. Market buys count as limit `hi`, market sells as `lo`.
4. For each `p ∈ C` (ascending): `Dem(p) = Σ buy qty with limit ≥ p + makerBidQtyAtPrice(p)`, `Sup(p) = Σ sell qty with limit ≤ p + makerAskQtyAtPrice(p)`, `Exec = min`. Implement with two prefix sums over the sorted candidate array (O(n log n)), not a nested loop, to meet the 05 §3.23 budget (≤ 0.5 ms per asset with 200 resting orders).
5. Selection (05 §3.5.2): (1) max Exec; (2) min |Dem − Sup|; (3) min |ln p − lnRef| (use `maker.lnRef`; add `refLn: number` to `AuctionBook` and use it when `maker` is null; T05-22 always passes a maker for listed assets); (4) the lower price. If max Exec = 0: `p = null`, no trade, but compute the indicative price as the candidate minimizing |Dem − Sup| then distance to lnRef then lower price, and the imbalance there (edge 1: no crossing interest and the maker at the band edge: no trade, last price unchanged, indicative published).
6. Signed imbalance at `p*` = Dem − Sup among marketable orders (+ = unfilled buy interest).
7. All arithmetic in bigint for quantities; prices compared as bigint; `ln` through `dmath`.

## Test plan
- `clear.test.ts`:
  - **05#2 for random books (10,000 cases) the chosen price maximizes executed volume, respects all limits and is invariant under permutation of order submission within the tick**: fast-check generator of 1–40 orders (random side, limit on a grid, qty, iceberg split), optional maker quote; assert (a) Exec(p*) = max over all grid prices in band by brute force, (b) every buy with limit < p* contributes 0 and every sell with limit > p* contributes 0 to Exec, (c) `choosePrice` on any permutation of `participants` returns an identical result (INV-MKT-006 property; also register this property test name `INV-MKT-006 permutation invariance`).
  - **05#3 tie-breaks follow volume, then imbalance, then distance to ref, then the lower price**: four hand books: (i) two prices with Exec 100 and 80 → the 100 one; (ii) equal Exec 100, |imbalance| 20 vs 0 → the 0 one; (iii) equal Exec and imbalance, distances to lnRef 0.002 and 0.001 → the closer; (iv) everything equal → lower price.
  - Worked: buys 100 @ 10.02, 50 @ 10.00; sells 80 @ 9.99, 60 @ 10.01, no maker, reference ln(10.00): Exec at 9.99, 10.00, 10.01, 10.02 = 80, 80, 100, 100; 10.01 and 10.02 tie on Exec and imbalance (−40), 10.01 is closer to the reference → p* 10.01, exec 100, imbalance −40.
  - Market orders: one market buy 10 lots, maker ask ladder only → p* is the lowest grid price where makerAsk ≥ 10.
  - No trade: buys @ 9.90, sells @ 10.10, maker absent → p null, indicative chosen by rule, edge 1.
  - Performance smoke: 200 resting orders + maker, 1,000 runs, median < 0.5 ms on CI (soft assertion logged; the hard budget test is 05#52 in T05-22).

# SPEC EXCERPTS (verbatim; binding game rules)

**[05 §1 Purpose]** (context)

## §1 Purpose

The market engine turns everybody's orders (players, player AIs, delegated operators, NPC pools, central banks, treasuries and liquidation engines) into prices, once every tick, for every listed instrument, fairly and explainably.

Design commitments (old 01 §0, §7; V3 Part 4; MASTER-BIBLE Part VII T02–T10):
1. **Fairness by batching.** Every tick each asset clears in one uniform-price call auction. There is no latency race, no front-running inside a tick, and the same result on a phone and a desktop.
2. **Players are price-makers.** Small players are invisible; whales leave footprints; coordinated players can squeeze. Impact follows the square-root law from $1k to $10B, in **one** place (the NPC market maker's ladder), so no effect is charged twice (T08).
3. **Prices come from who trades and why.** A value layer (fundamentals, macro factors, news) says what an asset is worth; a flow layer (trader pools and players clearing against the market maker) says what it trades at. Inefficiencies (post-news drift, overreaction, quarter-end, crowding) emerge from the pools and die as capacity is used (specs/quant-market-ecology).
4. **Explainable afterward.** Each closed day and hour has a cause vector that sums exactly to the move, so the trade journal, the "Why it moved" ladder and the Research Desk can never contradict the tape.
5. **Nothing leaks.** Public data is aggregate: depth by price level, prints, volume. No account identity, no hidden reserve, no stops, no algo parents ever leave the engine (L11).
6. **Deterministic.** The engine is a pure function of (seed, state, sealed intents, entropy commits) (02).

#### §3.5.2 Choosing the clearing price
Let the candidate set `C` be every limit price of a participant inside the band `[lo, hi]` (§3.9.1) plus every price-grid point where the maker's ladder quantity changes, inside the band. Market orders count as limit `hi` (buy) or `lo` (sell). For each `p ∈ C`:

```
Dem(p) = Σ buy qty with limit ≥ p   + makerBid(p)       // makerBid(p) = Q_bid(lnRef − ln p) for p below the bid edge
Sup(p) = Σ sell qty with limit ≤ p  + makerAsk(p)
Exec(p) = min(Dem(p), Sup(p))
```

The clearing price `p*` is chosen by, in order: (1) maximum `Exec`; (2) minimum `|Dem − Sup|`; (3) minimum `|ln p − lnRef|`; (4) the lower price. If `max Exec = 0` the asset does not trade this tick; the indicative price and imbalance are still published. Because the maker is always in `C` with positive depth, any marketable flow trades unless the band clamps it (§3.9.1).

## §8 Edge cases

1. **No crossing interest and the maker at band edge**: no trade; last price unchanged; indicative published.
2. **Band clamps for three ticks then reverses**: the streak resets on the first unclamped tick; no interruption.
3. **Halt and market-wide halt overlap**: the longer end tick wins; one REOPEN auction.
4. **L3 market-wide halt before the close**: no closing auction; official close = last price; MOC orders expire unfilled; 08 strikes NAV on that close.
5. **Weekend news**: `lnV` moves on the weekend tick; crypto trades it immediately; equities gap at Monday's open via openPrint and pools' opening orders.
6. **Stop triggered by a band-clamped print**: triggers on that LAST; the stop joins the next tick as a market order with protection.
7. **Iceberg reserve plus STP**: the decrement applies to displayed then hidden quantity of both orders.
8. **FOK larger than all available interest**: removed in pass 2; no partial.
9. **Order modify in the same tick as a fill**: P1 modifications precede the auction, so the modified order is what matches.
10. **Corporate action on a tick with resting GTC orders**: adjusted in P2 (§3.21); orders below one lot are cancelled with `CORPORATE_ACTION`.
11. **Asset suspended with algos working**: algos cancel; holds release.
12. **Capital controls imposed while an autoFx order works**: the next FX leg fails; the asset leg cancels with `FX_LEG_FAILED`.
13. **Held imposed mid-day** (13): all non-reducing orders cancel with `HELD_FORCED`; existing algos stop.
14. **Liquidation into a halted book**: 07 queues; the liquidation joins the reopen auction as `auctionOnly` market orders.
15. **Maker inventory beyond cap in a one-way crash**: depth on the buying side drops to 0.2; the price falls faster; bands and halts bound the speed; the layoff at close resets 12%.
16. **Two whales on opposite sides in the same tick**: they match each other first (players before the maker at equal price); the tally sees only the net residual taken from the maker, so neither pays impact on the matched part.
17. **Price grid collapse at very low prices**: `minPrice` floor; below it sells rest unfilled; the asset is flagged for 09 (penny-stock or delisting rules).
18. **Zero ADV at listing**: ADV uses 22's genesis turnover until 5 trading days of model inputs exist.
19. **Factor loadings that sum to more than 1 after a crisis correlation add**: capped at 1; idio share 0.
20. **Daily close tick coincides with a vol interruption**: the interruption ends early and the closing auction runs (the close always happens unless L3 stopped trading).
21. **Block cross price when no closing auction prints**: uses the official close rule (§3.10.2).
22. **A claim about an asset that is halted**: belief accumulates; it is visible at the reopen auction.
23. **Registered maker quotes inside the NPC spread with tiny size**: allowed; obligations measure size ≥ 0.02 ADV, so tiny quotes do not count for presence.
24. **Cross-currency order when one FX book is in VOL_INTERRUPTION**: the cross order waits in 6a; if not filled within its TIF it expires.
25. **Year end and chapter end** (02): no special market behaviour; GTC orders persist across chapter boundaries unless 21's reset rules cancel them.
26. **Determinism under replay with partitions** (19): a replay of the MARKET partition from a snapshot reproduces every `p*`, fill and cause vector bit for bit.
