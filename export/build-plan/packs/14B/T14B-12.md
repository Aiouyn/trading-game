## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

# SPEC EXCERPTS (verbatim; binding game rules)

**[14 §1 Purpose]** (context)

## §1 Purpose

1. **Make money feel like something.** Rank, home, shell, possessions and titles turn net worth into a place and an identity. A player should feel the jump from $50k to $5M without reading a number (old 04 §0.1).
2. **Drain money in a way players want.** Lifestyle is the economy's most voluntary sink. Mass luxury loses value on purchase and fades in Prestige, so it must be refreshed; collectibles hold value but carry upkeep (old 04 §5.1).
3. **Give small, real, capped advantages** for spending (access, convenience, talent, collateral, reach, physical security) so spending is a decision, never a cash faucet (old 04 §0.4).
4. **Keep three separate social axes**: Prestige (status from what you own and display), Reputation (trust from clean conduct), Notoriety (fame from crime). A player can be high on all three (old 04 §7.1, bible decision 5).
5. **Remember.** The world never resets (L1), so Legacy, Houses and succession give a permanent public history: founding plaques, generations, heirlooms, chapter portraits (V3 Part 9).
6. **Respect the player.** No demotion, no punishing streaks, no real-money path to any of this (L7), quiet money stays a valid strategy (old 04 §7.8).

### §3.1 Account and character lifecycle

**§3.1.1 Creation (guest).** A first launch creates `Account{state:'GUEST'}` bound to a device id, a `Character` and a `Profile` with a generated handle `guest_<6 base32>`. Starting state is 00 §5.9: cash $5,000, LIC0, R0, home city among the three FDL-bloc cities (default Port Avalon), protection until `joinTick + 72·720`. Guests can play every solo-visible system but cannot: send or receive P2P transfers or contracts, chat outside their league group read-only view, join alliances, or appear on boards (15 §3.12). The game requires an account after `PARAM.guest_max_real_minutes = 30` minutes of play or before any P2P action.

**§3.1.2 Upgrade to registered.** Adding any auth method (19) moves the account to `REGISTERED`. The age gate asks for a birth year; `U16` is refused with a message and the guest data is deleted after 24 real hours (L5). The country is captured per 15 §3.2.

**§3.1.3 Handle rules.** 3–20 characters, `[A-Za-z0-9_.-]`, must start with a letter, not all digits, case-insensitive unique among live handles and among handles released in the last `PARAM.handle_release_hold_chapters = 1` chapter. Passes the moderation filter (21) and a reserved list (staff, institutions, NPC actor names in 22, brand names). A handle can change once per chapter for `PARAM.handle_change_fee_real = $1,000` (sink `ACCT_HANDLE_FEE`). The previous handle shows as "formerly X" on the profile for one chapter. Handle changes are blocked while the character is under investigation, in a case, Held, or within 7 real days after a conviction (anti-evasion).

**§3.1.4 Background.** Chosen once at creation; flavor plus one tilt, never cash (old 04 §4.2):

| Background | Tilt (applied by the named module) |
|---|---|
| `DROPOUT_CODER` | 10% off the first Freelance dev studio or IT support shop (09) |
| `EX_BANK_INTERN` | 7 game days of free Terminal news tier on the first license (16 information tiers) |
| `STREET_FLIPPER` | 10% off the first Sneaker resale or Food truck (09) |
| `BARISTA_WITH_A_PLAN` | 10% off the first Coffee cart (09) |

The discount is a reduced purchase price, recorded as `ACCT_BACKGROUND_DISCOUNT` (FAUCET, ≤ $600 per character, once).

**§3.1.5 Home city.** Chosen at creation among FDL-bloc cities. Changeable once per chapter for `PARAM.home_city_change_fee_real = $25,000` (sink `ACCT_HOME_CITY_FEE`), effective at the next day close. The home city decides city-board membership and Hall of Patrons eligibility (10, §3.16.4). It is not the residence: a player may live anywhere they own a home. A change resets the current-chapter city-board score in both cities to 0 (anti-hopping, mirrors 15 §3.2 country rule).

**§3.1.6 Two-factor requirement.** When a character enters the top 1% of NWI (checked at day close), enters the top 100 of any global board, or becomes an alliance Chair, the account is asked to enable 2FA (the same MFA as 19 Rule 3.9.3, which also requires it for API keys and staff; ruling in 24); without it, P2P transfers and contract signatures above $1M real are blocked until enabled (protects against real account theft, old 02 §5.1). The UI states plainly that this is real-account security, not the in-game hacking system.

**§3.1.7 Deletion and anonymization.** On a verified deletion request (21 privacy): (1) open contracts are terminated with each contract's termination clause (15 §3.6.9), escrow returned per clause; (2) the estate is liquidated: debts to other entities paid first in 07's liquidation order, UNIQUE items and concessions go to the estate auction (15 §3.13), everything else is sold at fair value −15%; (3) remaining cash is destroyed (`ACCT_DELETION_ESCHEAT`, SINK); (4) the character becomes `ANONYMIZED` with handle `former_<n>`, all public history lines keep their facts but show "Former player #n"; (5) Legacy plaques are hidden; (6) the House record is anonymized. Deletion is blocked while Held or with an unpaid judgment; the judgment is paid from the estate first.

### §3.6 Support, compensation and clawback

**Rule 3.6.1 (channels and targets).** Players reach support through Help › Report a problem (17 app 28) in game, the web account page, and an email address shown in the store listing. Ticket priorities and first-response targets (real time): P1 account security, payment double-charge, an ongoing exploit, a safety threat: 4 h; P2 lost items or money due to a defect, appeals: 24 h; P3 bugs, ad rewards not received: 72 h; P4 questions: 5 days. Resolution targets are 3× the first-response target. Targets are published.

**Rule 3.6.2 (triage).** Bug and exploit tickets with a reproducible run file or tick range are linked to a 20 RegressionCase (20 Rule 3.10.5) or Finding. An EXPLOIT ticket starts the 20 disclosure clock (20 Rule 3.16.2). A player question about why something happened is answered from the explainability tools (18 ladder, 05 cause vector), never from staff opinion about strategy (no financial advice, §3.16).

**Rule 3.6.3 (compensation tiers).** Compensation is paid only for harm caused by a platform defect (engine bug, server incident, wrong rule implementation), never for losses from play, other players' legal or illegal game actions, or market moves.

| Tier | Size (real dollars, per character) | Approvals | Method |
|---|---|---|---|
| C1 | ≤ max($25,000, 1% of rank-basis NW) | SUPPORT_AGENT proposes, SUPPORT_LEAD approves | fixed schedule or item restore |
| C2 | ≤ max($1,000,000, 10% of rank-basis NW) | SUPPORT_LEAD proposes, a second SUPPORT_LEAD or TM_LEAD approves | replay counterfactual required |
| C3 | above C2, or > 100 characters | CRITICAL: proposer + TM_LEAD + 30-minute delay | replay counterfactual required; incident postmortem attached |

**Rule 3.6.4 (replay counterfactual).** For C2/C3 the amount is computed, never guessed:
1. TM_ENGINEER forks a MIRROR world (20 Rule 3.5.7) at the last snapshot before the defect's first tick `T0`.
2. The mirror re-runs ticks `T0 … T1` (the defect window) with the fixed engine and the same sealed intents and entropy.
3. For each affected character `c`, `Δ_c = NWreal_fixed(c, T1) − NWreal_actual(c, T1)`, using 03's rank-basis valuation at `T1` marks.
4. If `Δ_c > PARAM.comp_min_real = $10` the character is owed `Δ_c` (compensation); if `Δ_c < −$10` the character gained from the defect and the gain is subject to clawback (Rule 3.6.6).
5. Intents a character would plausibly have changed after seeing the correct state are not modelled (the counterfactual replays the same intents); the plan states this limitation in its notes.
6. Assets wrongly lost (an item, a business, a property) are restored in kind when they still exist in the world (`ITEM_RESTORE`) and the cash `Δ_c` is reduced by their value.

**Rule 3.6.5 (posting).** Compensation posts `ADM_COMPENSATION` (FAUCET, 03) through `adm.compensate` (19 §4.3) as **unrestricted** cash (it replaces value the player had), with a PRIVATE event to the player and an in-game message "The Exchange corrected an error affecting your account: +$X. Reference INC-…". Compensation never scales with spending and is never paid in cosmetics instead of money when money was lost (a cosmetic apology item may be added on top for incidents, `source: 'COMPENSATION'`).

**Rule 3.6.6 (clawback).** A defect-gain `G_c = −Δ_c` is clawed back through `adm.clawback` as `ADM_CLAWBACK` (SINK, 03) or, when the gain went to another player, as `ADM_TRANSFER_REVERSAL` (TRANSFER) back to that player. Order: cash first; if cash < `G_c`, the remaining amount becomes a platform claim repaid from `PARAM.clawback_income_share = 0.30` of daily income (the same mechanism as 13's garnishment plan), never forcing a liquidation and never going below 14's Fresh Start line or 13's conflict floor. Good-faith beneficiaries (they did nothing unusual; the defect simply paid them) get clawback only, with no enforcement action and a plain message. Repeated deliberate abuse is handled by §3.7 as V03.

**Rule 3.6.7 (no world rollbacks).** The world is never rolled back to an earlier tick to undo an incident (L1). The only rollback is the Truth Machine's uncommitted-tick rollback (20 Rule 3.2.2), which affects a tick no player has seen committed.
