## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. `dealingTickFor` (§3.1.5 step 2, forward pricing, §9 row 4): `tickOfDay ≤ PARAM.fund_dealing_cutoff_tod` (539) → this game day's tick 719; otherwise the next game day's tick 719. Strikes happen every game day including weekends (edge 9).
2. P1 checks of `fund.subscribe` (those possible now, 08 §4.1), in this order: actor Held (`FUND_HELD`; edge 5: Held blocks new intents only); fund exists and is ACTIVE (FUNDRAISING only for `fund.seed`) and `structure` is OPEN_ENDED or ETF-as-fund units are not subscribed here (ETF units are created only by APs, `FUND_NOT_OPEN_ENDED`; closed-end uses `fund.commit`); SWF: investor must be in the sponsor's ownership chain (`FUND_SWF_ONLY`); dealing not SUSPENDED (`FUND_DEALING_SUSPENDED`); `amount ≥ PARAM.fund_min_ticket` (`FUND_MIN_TICKET`); investor account age ≥ `PARAM.fund_investor_min_age_days` (`FUND_INVESTOR_AGE`); not linked to the manager: `linkScore(investorRoot, managerRoot) ≥ PARAM.fund_link_score_block` or `sameAllianceSignatory` (`FUND_LINKED`; the manager's own stake via `fund.seed` is exempt); restricted cash (`restrictedCashCheck(..., 'P2P')` → `FUND_RESTRICTED_CASH`, edge 30); then `ctx.holds.placeCash(investor, baseCcy, amount, dealingTick + 2, intentId)` (`FUND_INSUFFICIENT_CASH` on `LED_INSUFFICIENT_FUNDS`). The hold is the escrow of §3.1.5 step 1: the cash is locked from P13 of this tick, not invested, not in NAV.
3. `queueSubscription` writes `FundRequest { reqId: ctx.newId('freq'), kind: 'SUBSCRIBE', amount, submittedTick, dealingTick, status 'PENDING', filledUnits 0, filledCash 0, carriedForward 0 }` plus the hold id (keep in a `holdId` field on the row: add `holdId?: Id` and `isManagerStake?: boolean` when writing; these two optional fields are the only additions to §2's `FundRequest`).
4. `fund.seed`: same path with the T08-04 seed rules (actor manager or sponsor root, `amount ≥ minSeed(targetAum)`); FUNDRAISING or ACTIVE fund; no age/link checks for the manager's own stake.
5. `fund.cancelRequest`: request exists, actor is its investor, status PENDING, and `ctx.tick` is before the dealing cutoff of its dealing day (`tick < dealingTick − 719 + cutoff + 1`), else `FUND_PAST_CUTOFF`; release the hold (subscriptions) or delete the pending units reservation (redemptions, T08-06 places a qty hold), status CANCELLED, emit nothing public.
6. `fund.allocateNpcRival` (N5): target fund's sponsor is an `npc` (`FUND_BAD_MANAGER` otherwise reused as `FUND_NOT_ACTIVE`); same checks and path as `fund.subscribe`.
7. `strikeRejectReason` (§3.1.5 step 4) in this order, returning the first: fund not ACTIVE (`FUND_NOT_ACTIVE`); Level-3 subscription pause (`FUND_LEVEL3_PAUSE`, set by T08-09); NW cap: `(existingUnits × G + amount × (1 − subFee)) > PARAM.fund_investor_max_nw_pct × netWorth(investor at strike)` (`FUND_NW_CAP`; NW already includes the locked cash; edge 3: checked only here, never forces a redemption); age (`FUND_INVESTOR_AGE`); link (`FUND_LINKED`); manager stake absolute floor `stakeValue < PARAM.fund_manager_stake_min_abs` (`FUND_STAKE_FLOOR`, subscriptions pause, edge 2); `amount < PARAM.fund_min_ticket` (`FUND_MIN_TICKET`). Each rejection: release the hold, status REJECTED, emit `fund.requestRejected` (PARTIES) with code and `refunded = amount` (reason code `FUND_SUB_REFUND` is the hold release: no posting).
8. `capRoom` (§3.1.10, partial acceptance §3.1.5 step 5): `room = min(PARAM.fund_aum_stake_multiple × stakeValue − aum, fundAgeDays < PARAM.fund_new_period_days ? fund_new_aum_cap − aum : ∞)` where `aum` = `aumAfterRedemptions` + cash already accepted today; manager-stake subscriptions are exempt from the multiple cap (they raise it); NPC/elastic subscriptions also bounded by `PARAM.fund_npc_max_share × (aum + x) ≥ npcValue + x` → `x ≤ (share × aum − npcValue)/(1 − share)`. `room ≤ 0` → reject `FUND_AUM_CAP` with full refund; `0 < room < amount` → fill `room`, refund the rest (`hold reduce` then settle), status PARTIAL; the refund part posts nothing.
9. `dealSubscriptions(ctx, fundId, Gdeal, aumAfterRedemptions)`: requests with `kind 'SUBSCRIBE'`, `status PENDING`, `dealingTick === ctx.tick`, sorted by `(submittedTick, reqId)` (first come first served for cap room; documented decision). For FUNDRAISING funds `Gdeal = PARAM.fund_initial_nav` and only seed requests deal; after the seed fills call `onSeedSettled`.
10. `issueUnits`: `fee = amount × subscriptionFeeRate`; `units = toQty((amount − fee) / Gdeal, UNIT_SCALE)`; ledger: core holder `ctx.ledger.swapAsset(investor, fundId, fundId, units, toMoney(amount − fee), ccy, FLOW.SUB_SWAP, { holdId, refs: [reqId] })` and, if `fee > 0`, `ctx.ledger.pay(investor, fundId, toMoney(fee), ccy, FLOW.ANTI_DILUTION, { holdId })`; elastic holder (`elasticSectorFor(kind) === 'hh'`, NPC allocator capital, §3.1.17): `ctx.ledger.elasticIn(hhId, fundId, toMoney(amount), ccy, FLOW.SUB_ELASTIC, { sub: fundId, refs: [reqId] })` (08 keeps the units in `fnd.position`; the fee stays in the fund). Then: `Fund.unitsOutstanding += units`; series `seriesIdForDay(day)` created or merged (`H_s = Gdeal` on creation; units added); position row (one per investor per series) with `lockupUntilTick = tick + lockupTicks`, `subscribedTick`, `costBasis += amount`, `hwmNavPerUnit = toPrice(Gdeal)`, `isManagerStake`; manager stake: `managerStakeUnits += units`. Emit `fund.subscriptionFilled` (PARTIES: investor, manager) `{ reqId, units, cash, gatedRemainder: 0 }`.
11. Edge 4 (bankrupt investor): no special path here; 14's estate liquidation calls `fund.redeem` (T08-06). Edge 5: pending requests of a Held investor still deal (no Held check at strike).
12. Exploit 20 (wash circulation): units of OPEN_ENDED funds are never transferable: no intent moves `fnd.position` between investors (closed-end interests use `fund.transferInterest`, T08-12).

# SPEC EXCERPTS (verbatim; binding game rules)

**[08 §1 Purpose]** (context)

## §1 Purpose

This module is the buy-side and risk-transfer half of the institutional layer (V3 Part 3.5, 3.6, 3.8):

1. **Funds** let capital be pooled and managed under a mandate: players run hedge funds, long-only funds, funds of funds, credit funds, venture and private-equity funds, money-market funds, ETFs and (at Dynasty rank) sovereign wealth funds. Investors (players and NPC allocators) buy units at NAV. Track record, trust and betrayal are public (MASTER-BIBLE VI #2). Theft is impossible by construction; market abuse through a fund is possible and prosecutable (roadmap Q6, resolved §3.1.12).
2. **ETFs** are funds with listed units and a primary market. Authorized participants (APs) create and redeem baskets to keep price near NAV. ETF flows move the underlying; in a crisis, basket illiquidity opens real discounts.
3. **Securitization** turns pools of loans, mortgages, receivables and leases into tranches (senior, mezzanine, equity) sold to investors. Default correlation, underwriting standards and rating methodology together can produce a 2008-style event from rules, never from a script.
4. **Rating agencies** grade sovereigns, corporates, banks, insurers, funds and tranches. Grades move spreads and trip collateral, mandate and capital rules, so cliff effects create gameplay.
5. **Insurance and reinsurance** price and absorb operational, property, cyber, liability and catastrophe risk. Losses from storms, cyber pandemics and unrest propagate from policyholders to insurers, reinsurers and cat-bond holders.

Design rules: every flow is a ledger posting with a reason code (03); every price comes from a model a player can learn or from an auction; no actor gets private information (L11); every institution can fail by rule and leaves a public record.

#### §3.1.5 Subscriptions

1. `fund.subscribe { fundId, amount }` moves `amount` from the investor's cash into the fund's subscription escrow at the CCP immediately (P13 of the intent's tick), status PENDING. Escrowed cash is not invested and not counted in NAV.
2. Dealing day: requests received before `PARAM.fund_dealing_cutoff_tod = 539` (closing auction) deal at today's strike; later requests deal at the next game day's strike (forward pricing; no stale-NAV trading).
3. At the strike: `units = amount × (1 − subscriptionFeeRate) / G_deal`; the subscription fee stays in the fund. A new series is opened with `H_s = G_deal` (series of the same dealing day are merged). `lockupUntilTick = strikeTick + lockupTicks`.
4. Rejections at strike (cash returned, reason code `FUND_SUB_REFUND`): fund not ACTIVE; investor would exceed `PARAM.fund_investor_max_nw_pct = 0.25` of the investor's NW (NW at strike, including the new units); investor account younger than `PARAM.fund_investor_min_age_days = 168` game days (7 real days); investor linked to the manager (19 link score ≥ `PARAM.fund_link_score_block = 0.6`, or same alliance treasury signatory); AUM cap breached (§3.1.10); manager stake would fall below 10%; ticket < `PARAM.fund_min_ticket = $1,000`.
5. Partial acceptance: if only part fits the cap, the accepted part is filled and the rest refunded.

**[08 §3.1.10]** (from spec file 08-FUNDS-STRUCTURED-INSURANCE.md)

#### §3.1.10 Skin in the game and AUM caps

- Manager stake value ≥ `PARAM.fund_manager_stake_min_pct = 0.10` × AUM at all times, and ≥ $250,000. If AUM growth or manager losses push it below, new subscriptions pause (rejected at strike) until restored. The manager cannot redeem stake units that would breach this (except in wind-down).
- AUM ≤ `PARAM.fund_aum_stake_multiple = 10` × manager stake value.
- AUM ≤ `PARAM.fund_new_aum_cap = $10,000,000` until the fund is `PARAM.fund_new_period_days = 336` game days old (14 real days).
- The stake is first-loss for restitution only: if a court orders fund-related restitution (13), the stake units are cancelled first and their value distributed to the other investors pro rata; only after the stake is exhausted does 13 collect from the manager's other assets.

## §8 Edge cases

1. **Fund with zero units outstanding** (all redeemed except none): NAV per unit is undefined; the fund moves to WINDING_DOWN automatically and closes when positions are flat.
2. **Manager stake falls below 10% because the manager redeemed elsewhere?** Impossible: stake units cannot be redeemed below the floor. If losses push the absolute stake below $250,000, subscriptions pause; existing investors are unaffected.
3. **Investor's NW falls so the fund exceeds 25% of NW**: the cap applies only at subscription; no forced redemption.
4. **Investor goes bankrupt (14 fresh start)**: fund units are assets; 14's bankruptcy liquidates them through `fund.redeem` at the next strike (gate applies; the estate waits like anyone).
5. **Investor Held (13)**: Held blocks new intents; pending requests still execute at strike.
6. **Manager convicted mid-quarter**: performance fees accrued but not crystallized are forfeited to the fund; the fund winds down (ban).
7. **Fund holds an asset that is delisted or bankrupt (09)**: becomes Level 3 at the recovery estimate until the 09 restructuring distributes; may force a side pocket.
8. **Cross-currency funds**: positions in other currencies are marked and converted at the 05 FX close mark; FX hedges are normal positions.
9. **Weekend NAVs**: struck every game day; equity marks unchanged on weekends, crypto marks move.
10. **ETF with zero APs** (all suspended): no creations or redemptions; it trades freely at any premium; a PUBLIC notice warns; the sponsor may add NPC APs.
11. **Basket constituent halted**: in-kind creations exclude the halted line and substitute cash at its last mark plus 1% (`PARAM.etf_halt_cash_premium`).
12. **Index constituent count below minimum** after deletions: the next eligible instruments by the method's ranking are added at the next rebalance; until then the index runs short.
13. **Leveraged ETF NAV approaching zero** (underlying moves > 1/L in a day): if NAV per unit falls below 5% of its 28-day average, the ETF terminates and distributes at the next close.
14. **SPV pool asset prepays fully**: principal collection; the pool shrinks; tranches amortize.
15. **Pool asset's borrower is a player who goes bankrupt**: 07's bankruptcy rules decide recovery; the SPV is a creditor like any other.
16. **Sponsor bank fails (07)**: the SPV is bankruptcy-remote: it continues; servicing moves to an NPC servicer at 40 bps; the sponsor's retained tranches go to its estate.
17. **All bids below a tranche's size**: unsold notional stays with the sponsor; the deal still closes if the senior-most tranche is ≥ 90% placed, otherwise the sponsor chooses close (keeping the unsold) or withdraw.
18. **Rating agency capacity saturated**: requests wait; deals cannot launch rated until ratings arrive; a deal may launch unrated (NPC buyers with rating floors will not bid).
19. **Composite rating with an even number of ratings ≥ 4**: impossible (3 agencies).
20. **Rated subject disappears (merger)**: ratings transfer to the surviving entity and are put on WATCH.
21. **Policy insuring an asset that is sold**: cover ends at transfer; pro-rata refund; the buyer must bind its own cover.
22. **Claim exceeding the insurer's cash**: the insurer has 1 game day to raise cash (sell assets, draw reinsurance, capital injection); otherwise INSOLVENT (§3.5.7).
23. **Two cat events in the same week**: CAT_XOL treats each as an event; reinstatements are consumed in order; the 7-game-day aggregation applies only to the same peril and city.
24. **Cat event during a moratorium on a policy bound before the warning**: covered (cover bound before the warning is valid).
25. **Cat bond trigger hit after maturity date but for an event during the term**: covered if the event started during the term; determination continues after maturity, with collateral held until determined.
26. **Insurer is also the holder's alliance member**: allowed; the fraud score weights shared clusters; claims are still engine-determined.
27. **Money-market fund holds a bill of a sovereign that defaults (04)**: shadow NAV drops by the loss; likely break the buck.
28. **Fund-of-funds redeems from a gated underlying**: its own redemption payable waits; it may gate itself.
29. **Fund in custody at a CCP that is under default-waterfall stress (07)**: custody assets are segregated and never used for the CCP's waterfall.
30. **Investor tries to subscribe with ad cash (L12) inside the restricted window**: rejected (00 §5.9 and roadmap C5: ad cash cannot fund ops, margin or P2P for 72 game days; fund subscriptions count as P2P).
