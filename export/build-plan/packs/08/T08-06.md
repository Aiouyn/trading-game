## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Goal
Pay what 08 §3.1.7 says, when it says: management fees and custody accrued daily by the strike (T08-03) are paid at each game-month end; performance fees crystallize at each game-quarter end (or year end for ANNUAL) and on redemption, are paid in cash to the manager by cancelling the investor's units so that `G` is unchanged, and paying series are re-based and merged. There are no per-trade manager fees (08 §9 row 6).

## Implementation steps
1. `feeRecipient`: the manager entity when it is a `chr` or `cmp` whose root is the sponsor's root (the manager is the sponsor or one of its companies); for a hired NPC manager or an AI model operator, the sponsor (who pays the NPC salary under 09 and owns the model). NPC funds pay their NPC sponsor.
2. `payMonthlyFees` (P8 at t = 719 when `cal.boundaries` has `MONTH_CLOSE`, after the strike and dealing of the day): `m = fundState.accruedMgmt`; `npc = npcShare(fundId)`; `mNpc = allocate(m, [{id:'NPC', w: round(npc×1e9)}, {id:'PLAYER', w: 1e9 − that}])` (largest remainder, parts sum exactly); post `ctx.ledger.pay(fundId, recipient, mPlayer, ccy, FLOW.MGMT_FEE, { sub: 'PLAYER_SHARE' })` and `…(mNpc, … { sub: 'NPC_SHARE' })` (zero parts skipped). Custody: `ctx.ledger.burn(fundId, accruedCustody, ccy, FLOW.CUSTODY_FEE)` (SINK, to the CCP custodian per 07 §3.20). If the fund's available cash is short, pay what is available and keep the rest accrued (it remains a NAV liability); never overdraw. Reset the paid accruals.
3. Class note (binding, see T08-02 step 3): the "NPC share" fee is the same 03 TRANSFER code with `sub: 'NPC_SHARE'`; the FAUCET side of NPC capital is the elastic subscription. 08#15 asserts this split (T08-07).
4. `crystallizeSeries`: for each series of the fund (id order) with `a_s = perfAccrualPerUnit(G, H_s, hurdle_s, perfFeeRate, hurdleType) > 0`, for each position in it (id order): `fee = a_s × units/1e6`; `cancel = toQty(fee / G, UNIT_SCALE)`; core holder: `ctx.ledger.moveQty(investor, fundId, fundId, cancel, toMoney(fee), ccy, FLOW.UNITS_CANCEL)`; elastic holder: no ledger qty (08 holds the unit record). Then `ctx.ledger.pay(fundId, recipient, toMoney(fee), ccy, FLOW.PERF_FEE, { sub: holderIsElastic ? 'NPC_SHARE' : 'PLAYER_SHARE', refs: [positionId] })`; `position.units −= cancel`, `series.units −= cancel`, `Fund.unitsOutstanding −= cancel` (manager-stake positions pay no performance fee to themselves: skip positions with `isManagerStake`). After all positions: `H_s = G`, `crystallizedTick = tick`. Return total fee.
5. Why `G` is unchanged: the fund pays `fee` cash and cancels `fee/G` units, so `(nav − fee)/(units − fee/G) = G`. Rounding: `toQty` half-even on units; the residual (< 1e-6 unit × G) is accepted and covered by INV-FND-001's one-micro tolerance per unit.
6. `crystallizeOnRedemption(pos, unitsRedeemed, Gdeal)` (08 §3.1.6 step 3, §3.1.7): `a = perfAccrualPerUnit(Gdeal, H_s, …)`; `fee = a × unitsRedeemed/1e6`, paid in cash `fund → recipient` with `FLOW.PERF_FEE`; the investor receives `Gdeal − a` per unit (T08-07 posts that), so no unit cancellation is needed for redeemed units; returns `{ fee, unitsCancelled: 0n }`.
7. `mergeSeries`: after crystallization, the lead series is `leadSeriesOf(series, G)`; every other series with `H_s ≥ lead.H_s` (within 1e-9) is merged: its positions move to the lead series id (position rows of the same investor are summed: `units`, `costBasis`; `lockupUntilTick` = max; `subscribedTick` = min), the series row is deleted, the lead series units increase.
8. `quarterlyCrystallization`: if `fees.crystallization === 'QUARTERLY'` and `QUARTER_CLOSE ∈ cal.boundaries`, or `'ANNUAL'` and `YEAR_CLOSE`, run `crystallizeSeries` with today's strike `G`, then `mergeSeries`. Side-pocket units never crystallize here (fees on side pockets only on realization, T08-09). Convicted manager (edge 6): when `law.convictedManagers` lists the manager, accrued uncrystallized performance fees are forfeited: skip crystallization from that tick on (the fund winds down per T08-09).
9. No fee is ever taken per trade; `fund.trade` has no fee hook (exploit 6).

# SPEC EXCERPTS (verbatim; binding game rules)

**[08 §1 Purpose]** (context)

## §1 Purpose

This module is the buy-side and risk-transfer half of the institutional layer (V3 Part 3.5, 3.6, 3.8):

1. **Funds** let capital be pooled and managed under a mandate: players run hedge funds, long-only funds, funds of funds, credit funds, venture and private-equity funds, money-market funds, ETFs and (at Dynasty rank) sovereign wealth funds. Investors (players and NPC allocators) buy units at NAV. Track record, trust and betrayal are public (MASTER-BIBLE VI #2). Theft is impossible by construction; market abuse through a fund is possible and prosecutable (roadmap Q6, resolved §3.1.12).
2. **ETFs** are funds with listed units and a primary market. Authorized participants (APs) create and redeem baskets to keep price near NAV. ETF flows move the underlying; in a crisis, basket illiquidity opens real discounts.
3. **Securitization** turns pools of loans, mortgages, receivables and leases into tranches (senior, mezzanine, equity) sold to investors. Default correlation, underwriting standards and rating methodology together can produce a 2008-style event from rules, never from a script.
4. **Rating agencies** grade sovereigns, corporates, banks, insurers, funds and tranches. Grades move spreads and trip collateral, mandate and capital rules, so cliff effects create gameplay.
5. **Insurance and reinsurance** price and absorb operational, property, cyber, liability and catastrophe risk. Losses from storms, cyber pandemics and unrest propagate from policyholders to insurers, reinsurers and cat-bond holders.

Design rules: every flow is a ledger posting with a reason code (03); every price comes from a model a player can learn or from an auction; no actor gets private information (L11); every institution can fail by rule and leaves a public record.

#### §3.1.7 Fees (all transfers except custody)

| Fee | When | Paid by → to | Reason code (class) |
|---|---|---|---|
| Management | accrued daily (§3.1.4), paid at each game-month end | fund → manager entity | `FUND_MGMT_FEE` (TRANSFER); on the NPC-investor share: `FUND_MGMT_FEE_NPC` (FAUCET) |
| Performance | crystallized at each game-quarter end (or ANNUAL), and on redemption | fund → manager entity, paid in cash; the investor's units are reduced by `a_s × units / G` and those units cancelled, so `G` is unchanged | `FUND_PERF_FEE` (TRANSFER); NPC share `FUND_PERF_FEE_NPC` (FAUCET) |
| Custody | accrued daily, paid monthly | fund → CCP (07) | `FUND_CUSTODY_FEE` (SINK) |
| Subscription / early exit / swing | at dealing | investor → fund | `FUND_ANTI_DILUTION` (TRANSFER) |
| Creation / redemption (ETF) | at settlement | AP → fund | `ETF_CU_FEE` (TRANSFER) |

After crystallization `H_s = G` for every series that paid a fee; series at or above the lead series HWM are merged into it. There are no per-trade fees to the manager (no churning incentive). Fund trading costs (05 fees, spreads) are paid by the fund.

FAUCET classification rule (03 owns the class registry): a fee paid out of value attributable to NPC investors is a FAUCET because it moves NPC money into the player economy; the NPC investors' capital itself is not player wealth and is excluded from player NW and from the Stabilizer's `M` (03 consolidates NPC-owned units outside the player economy).
