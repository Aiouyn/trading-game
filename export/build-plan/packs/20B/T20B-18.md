## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

# SPEC EXCERPTS (verbatim; binding game rules)

**[20 §1 Purpose]** (context)

## §1 Purpose

1. **Prove the world is honest.** Every tick, the engine checks that money and assets are conserved, that every movement has a reason, that nobody's collateral is pledged twice and that ownership adds up (B02). A violation never commits: the tick is rolled back, replayed in safe mode, and if still failing the world halts and a reproducible case is filed (V3 Part 8).
2. **Prove the world is one world.** The same seed and the same intents produce the same logical state hash whether the world is run as 1, 4 or 16 partitions, on any supported host, after any replay (L1, 19 §1.2). `DEFAULT (Mathis may override)`: the equivalence set is {1, 4, 16} partitions on every nightly run.
3. **Hunt exploits before players do.** Game-balance test agents with player-level permissions only (B03) run continuously against staging worlds and production mirrors, trying every exploit class in §3.6 across every institution of 07, 08 and 09. Every exploit found becomes a permanent regression case (B06).
4. **Keep the game in balance.** Every tunable outcome that matters (crime EV, wealth curves, market statistics, crisis frequency, bank failure rates, ad and bankruptcy faucets, learnability of edges) has a numbered band with a seed count. A release ships only when its bands pass (03 §16, Tape specs).
5. **Keep evidence honest.** Unit tests, authored model calculations, engine simulations, human playtests and live telemetry answer different questions and are reported separately, never merged into one "it works" claim (B07).
6. **Gate every change.** Pull requests, build units, nightly integration, adversarial and balance runs, releases (every production deploy) and chapter-boundary parameter changes each pass a named gate, G0 to G5 (§3.9). 19 uses G1–G4 as the stage gates of its build order (19 §12.4) and requires G2 for toolchain upgrades; both uses follow §3.9. 19 cites "the G2 gate (20 §3.9)" for toolchain upgrades; that gate is defined there.
7. **Make trust visible.** A public, diegetic **Integrity Report** (§3.12) publishes money supply, invariant results, exploit-fix history and compensation totals, so players can see the game is fair (V3 Part 8).
8. **Separate edges from defects.** Strong legal performance, sometimes-successful crime and temporary scarcity are not defects (F06, R06). Every band carries a class (§3.7.1) that says whether a breach means an accounting defect, unwanted dominance, an intended-risk mis-tuning, a calibration miss or an experience problem, and each class has its own response.

### §3.12 Entropy, commit-reveal and verifiable rolls

**Rule 3.12.1 (epochs).** Entropy is managed in epochs of `PARAM.entropy_epoch_ticks = 720` (one game day). Before epoch `e` starts, COORD obtains a fresh 256-bit secret `S_e` from the KMS-backed generator and publishes `C_e = SHA-256("tycoon-entropy" ‖ e ‖ S_e)` in the batch of the last tick of epoch `e−2` (so the commitment is public at least one full epoch in advance) and in a `sys.entropy_committed` PUBLIC event.

**Rule 3.12.2 (tick entropy).** `entropy(N) = HMAC-SHA-256(S_e, "tick" ‖ N)` for tick `N` in epoch `e`; this is 02's per-tick secret `e(N)`, and the value fed to RNG streams is 02 §3.11.2's `TickEntropy(N)`, which also mixes `intentsRoot(N)` and `worldHash(N−1)` (02 owns the entropy guarantees; ruling in 24). 02's RNG streams are seeded as `seed(stream, entity, N) = SHA-256(worldSeed ‖ entropy(N) ‖ streamId ‖ entityId)` for world-internal draws, and **player-party rolls** (breach, detection, any roll a player can dispute) use `rollU = u53(SHA-256(entropy(N) ‖ rollDomain ‖ sortedSubjectIds ‖ rollIndex)) / 2^53`, which does not involve the secret world seed, so players can verify it.

**Rule 3.12.3 (reveal).** `S_e` is revealed `PARAM.entropy_reveal_lag_ticks = 1000` ticks after epoch `e` ends (vision/02-multiplayer §3.3: "revealed at N+1000"), by `sys.entropy_revealed { epoch, secret }` (PUBLIC). Anyone can check `C_e`. Until reveal, nobody outside the world hosts can compute any tick's entropy, so no one can predict auction order keys or rolls.

**Rule 3.12.4 (verify a roll).** Each player-party roll event carries `{tick, rollDomain, subjectIds, rollIndex, threshold, outcome}` in the party's private event (thresholds as the owning module exposes them; where a module shows only bands, the band). After reveal, `GET /api/v1/verify/roll?eventId=…` recomputes `rollU` from the revealed secret and returns `rollU`, the threshold and whether `rollU < threshold` matches the recorded outcome. The same function is in `packages/sdk`, so players can check independently.

**Rule 3.12.5 (public integrity report).** Every game day the jobs service publishes a signed report (V3 Part 8): money minted and destroyed by reason class, M0/M2 per bloc, systemic indicators, invariant check counts and failures, entropy commitments and reveals of the day, audit-log chain head, exploit-fix history entries released by 21. Shown in the Exchange diegetic "Stabilizer and Exchange report" screen (17).
