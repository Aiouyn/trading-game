## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. Personality (§3.6.2): at genesis `appointGovernor(…, 'GENESIS')` draws, on `S.cbPersonality(b)` in this order: `hawk = U(hawkMin, hawkMax)`; 9 member offsets `o_j = 0.15·normal()`; `rStarBias = U(−0.005, +0.005)` (§3.4.4). At later appointments (`TERM_END` every `macro_governor_term_days` = 2,912 game days; `POLITICAL` only when 16 requests it and unemployment > NAIRU + 0.03 for 182 days, or `PEG_BREAK` after a peg break): if `ports.world.governorAppointment(b, tick)` returns `{hawk0}` use it (D325, 16 §3.5.10) and still draw offsets and bias; else draw hawk from the range. The market belief resets halfway: `ĥ ← ĥ + 0.5·(0.5 − ĥ)` (T04-07 state). Credibility moves 0.05 toward `credibility0`. Emit `macro.governor.appointed` (bloc, governor npc id from 16 or null, term end).
   Daily drift between appointments: `hawk += 0.05·√Δ·normal()` on `S.cbPersonality(b)`, clamped to `[hawkMin, hawkMax]`; when 16 supplies `governorHawk(b)` (16 moves `h` at most 0.05 per strategic epoch), use 16's value instead of the random walk (no draw is consumed then? No: always consume the draw for a fixed count, ignore it).
   Coefficients: `φ_π = 0.5 + 0.6(hawk − 0.5)`; `φ_x = 0.5 − 0.5(hawk − 0.5)`, × 0.7 for PRICE_STABILITY mandates (EUN, NKR, SRL); `bias = 0.005(hawk − 0.5)`; `φ_fs = macro_cb_phi_fs` 1.5; `φ_fx` from `BLOC_DEFAULTS` (SRL 0.30, PYN 0.20); `ρ = macro_cb_smoothing` 0.5.
2. Rule (§3.6.3) on published data only: `π_cb` = latest published CPI core yoy; `x_gdp_pub` = the true gap at the tick of the latest GDP print plus that print's measurement error expressed as a gap (T04-16 stores `gapAtPrint` and `errGap = measurementError/4/... `: DEFAULT conversion: error in q/q annualized growth pp × 0.25 → gap units), `u_pub` latest JOBS; `FSI_ex = max(0, FSI − 0.3)`; `i* = r*_cb + π_cb + φ_π(π_cb − π*) + φ_x·x_cb − φ_fs·FSI_ex + φ_fx·fxTerm + bias`, `r*_cb = r* + rStarBias`. Store all seven `ruleTerms`.
3. Scheduled decision (§3.6.4) at each `meetingPlan` tick (P2, t = 420): `Δraw = ρ(i* − i)`; hold if `|Δraw| < 0.00125`; else `Δ = 0.0025·roundHalfEven(Δraw/0.0025)` clamped ±`macro_cb_max_step` (0.005), or ±`macro_cb_max_step_wide` (0.0075) when `|i* − i| ≥ 0.02`; `i_new = max(elb, i + Δ)` (edge 1: at the ELB the rate stays; QE takes over in T04-09; guidance score is clamped to ≥ −1). Corridor rates updated by T04-08's `corridor`. QE/QT/YCC decisions run in the same tick (T04-09 hook `onMeeting`). Votes: each member's preference = `scheduledStep(i, i*_j, elb, ρ)` where `i*_j` uses `hawk + o_j`; `tally`. `statementKey` by direction, size, guidance match (decision direction equals guidance band direction), dominant `ruleTerms` component by |value| excluding `neutral`. Emit `macro.cb.decision` (PUBLIC; ruleTerms rounded per T04-01).
4. Guidance and dots (§3.6.5) at the guidance tick: `i*_proj` = rule rate now; `impliedMove = clamp(roundHalfEven(ρ(i*_proj − i)/0.0025), −2, 2)`; `score = clamp(impliedMove/2 + (1 − clarity)·0.3·normal(), −1, 1)` on `S.cbDecision(b)`; text band: < −0.6 VERY_DOVISH, < −0.2 DOVISH, > 0.6 VERY_HAWKISH, > 0.2 HAWKISH, else NEUTRAL. Dots: iterate quarterly (4 steps of 0.25 years per year up to 8 quarters) with `π_cb → π*` (half-life 0.75 y), `x_cb → 0` (0.5 y), `FSI → 0.2` (0.25 y) and `scheduledStep` each quarter; publish horizons 1, 2, 4, 8.
5. Credibility (§3.6.7), daily: +0.10(1 − cred)Δ when `|π_e5 − π*| < 0.005` and `|π_core − π*| < 0.01`; −0.30·cred·Δ when `offTargetDays > 182` (counter of consecutive days with `|π_core − π*| > 0.02`); −0.10·cred·Δ when QE active and `π_core > π* + 0.02`. One-offs: decision against guidance (score ≥ +0.25 then a cut, or ≤ −0.25 then a hike) `−macro_cred_guidance_break` (0.05); a move differing from `impliedMove` by ≥ 2 steps with no release since guidance having |surprise| ≥ 2: −0.03; decisive emergency FX-defence hike +0.05; peg break or YCC abandonment −0.10 (called by T04-14, T04-09); new governor ±0.05 toward credibility0. Clamp [0.05, 0.98].
6. Emergency meetings (§3.6.6), checked at day close and at the hourly FSI update (T04-15 calls `emergencyTriggers`): any trigger fires and `emergencyCountQuarter < 2` ⇒ schedule the meeting at `t = 45` of the bloc's next trading day (record `pendingEmergency` in the CB row; at most one pending). Size: cuts `Δ = clamp(0.0025·roundHalfEven((i* − i)/0.0025), −macro_cb_emergency_step (0.01), 0)` with ρ = 1; FX-defence hike (SRL or PYN with the CURRENCY trigger): `Δ = clamp(0.0025·roundHalfEven((i* − i)/0.0025), +0.01, +0.05)` (unit decision: an emergency defence moves at least 100 bp, the spec's "up to +0.0500" is the cap), credibility +0.05. `emergency = true` on the decision; the tools (LTRO, swap lines, QE at ELB, CCyB release) are triggered by T04-08/T04-09 reading `lastDecisions[0].emergency`. The count resets each quarter (edge 7: a scheduled meeting still occurs).
7. Minutes (§3.6.1) at minutesTick: `macro.cb.minutes` with `dissentHigher`/`dissentLower` counts and risk keys. Speeches (16) never contain information beyond guidance (§6.1, B09).
8. Events: `macro.cb.guidance`, `macro.cb.decision`, `macro.cb.minutes`, `macro.governor.appointed`, all PUBLIC; the hidden `hawkishness` never appears in a payload.

**[04 §1 Purpose]** (context)

## §1 Purpose

The macro layer is the one shared state every price, business, loan and property in the world reads (V3 Part 2.4). It exists so that:

1. **Prices have reasons.** A rate hike, a CPI surprise, a downgrade or a currency defence hits bonds, mortgages, growth stocks, bank margins, cap rates, carry trades and leveraged funds on the same tick, through named transmission channels that the "Why it moved" ladder (05 §3.12) can cite.
2. **Recessions are caused, not random** (old 01 §5.3). Imbalances (credit growth, valuation stretch, an inverted curve, tight real rates, oil shocks) raise the hazard of a downturn, so a careful player can see one building.
3. **Central banks, treasuries and sovereign bond markets are real machinery** (V3 Part 3.2): policy rates with a corridor, reserves, standing facilities, asset purchases, forward guidance, deficits that are financed by auctions, debt that can be downgraded and restructured, currencies that can be defended and can break.
4. **Crises emerge from rules** (V3 T2) and also arrive on a calibrated schedule so the world has rhythm (one major crisis in about 35% of chapters, storms every game quarter, ripples every game week).
5. **The money stays honest.** The Stabilizer controller keeps the player economy on its designed path, and the Money Supply Index deflates rankings so inflation cannot pump rank (old 01 §8.2–8.3).

### §3.6 Central bank policy

#### §3.6.1 Meeting calendar
- Scheduled meetings: `PARAM.macro_cb_meetings_per_year = 4` per bloc, one per game quarter. Each quarter has 65 trading days; the meeting is on trading day `q_b` of the quarter: NA 15, SC 27, FU 39, EC 51, PL 63, at `t = PARAM.macro_cb_decision_tick = 420`. So some central bank decides about every 12 trading days (about 0.7 real day).
- **Resolves an old inconsistency:** old 01 §1 put central bank meetings in the quarterly rhythm, old 01 §5.4 said "every ~6 real days". This spec keeps quarterly meetings per bloc (about every 3.8 real days per bloc, staggered across the five blocs).
- Forward guidance: published `guidanceLeadTicks = 24 × 720` (24 game days, one real day) before the meeting, at `t = 420`, moved to the previous trading day if it lands on a weekend.
- Minutes: published 14 game days after the meeting at `t = 420` (next trading day if a weekend).
- Emergency meetings: §3.6.6.

#### §3.6.2 Personality (hidden)
At genesis and at each governor appointment (§6.1) draw `hawk ~ U(hawkMin_b, hawkMax_b)` on `macro:<bloc>:cb`. Between appointments `hawk` drifts as a random walk with `σ = 0.05/√yr`, clamped to the bloc range. Derived coefficients:
- `φ_π = 0.5 + 0.6 × (hawk − 0.5)` (0.2 … 0.8)
- `φ_x = 0.5 − 0.5 × (hawk − 0.5)` (0.25 … 0.75); for `mandate = PRICE_STABILITY`, `φ_x × 0.7`
- `bias = 0.005 × (hawk − 0.5)`
- `φ_fs = PARAM.macro_cb_phi_fs = 1.5`
- `φ_fx`: SC 0.30 (on depreciation beyond 15% yoy), PL 0.20 (on any yoy move; leans against appreciation too), others 0.
- `ρ = PARAM.macro_cb_smoothing = 0.5`.

#### §3.6.3 The rule (old 01 §5.4 Taylor rule, extended)
The CB uses published data only:
- `π_cb` = latest published core CPI yoy.
- `x_cb = 0.5 × x_gdp_pub + 0.5 × (−2 × (u_pub − u*))`, where `x_gdp_pub` is the true gap at the tick of the latest GDP print plus that print's measurement error (§3.15.2), and `u_pub` the latest published unemployment.
- `FSI_ex = max(0, FSI − 0.3)`.
- `fxTerm`: SC `max(0, dep_yoy − 0.15)`; PL `dep_yoy`; others 0.

`i* = r*_cb + π_cb + φ_π × (π_cb − π_target) + φ_x × x_cb − φ_fs × FSI_ex + φ_fx × fxTerm + bias`

The decomposition `ruleTerms` is stored on every decision so the explain ladder and the CB statement can cite causes.

#### §3.6.4 Decision at a scheduled meeting
1. Recompute `i*` at the meeting tick.
2. `Δraw = ρ × (i* − i)`.
3. If `|Δraw| < 0.00125` (12.5 bp): hold.
4. Else `Δ = 0.0025 × roundHalfEven(Δraw / 0.0025)`, clamped to ±0.0050, or ±0.0075 when `|i* − i| ≥ 0.02` (`PARAM.macro_cb_max_step = 0.005`, `PARAM.macro_cb_max_step_wide = 0.0075`).
5. `i_new = max(elb_b, i + Δ)`.
6. QE/QT and YCC decisions (§3.8.5, §3.8.6) are taken at the same meeting.
7. Votes: 9 members, each with a fixed offset `o_j ~ N(0, 0.15)` drawn at appointment. Member preference = the rule rate computed with `hawk + o_j`, smoothed the same way. A member votes FOR if `|pref_j − i_new| ≤ 0.0025`, else AGAINST. The tally is in the decision; the direction of dissent ("two members preferred a larger hike") appears in the minutes. This is the main public clue to hidden hawkishness.
8. Emit `macro.cb.decision` (PUBLIC) with the new corridor rates, statement key (chosen from 16's template library by: direction, size, guidance match, dominant `ruleTerms` component) and reasons.

#### §3.6.5 Forward guidance and dots
- At the guidance tick: `i*_proj` = the rule rate on data published so far; `impliedMove = clamp(roundHalfEven(ρ × (i*_proj − i)/0.0025), −2, +2)`; `score = clamp(impliedMove/2 + (1 − communicationClarity) × N(0, 0.3), −1, 1)` on `macro:<bloc>:cb`. Text key from the score band (very dovish < −0.6, dovish < −0.2, neutral, hawkish > 0.2, very hawkish > 0.6).
- Dots: projections at +1, +2, +4, +8 quarters, computed by iterating the rule quarterly from today's published data with the CB's own forecast paths: `π_cb` converges to `π_target` with half-life 0.75 game years, `x_cb` to 0 with half-life 0.5, FSI to 0.2 with half-life 0.25; apply smoothing and step limits each quarter.
- **Credibility effects:** a decision against the guidance direction (score ≥ +0.25 then a cut, or ≤ −0.25 then a hike) costs `−PARAM.macro_cred_guidance_break = 0.05`. A move that differs from `impliedMove` by ≥ 2 steps when no release since guidance had `|surprise| ≥ 2` costs `−0.03`.

#### §3.6.6 Emergency meetings
Triggered at a day close (or at the hourly FSI check) if any holds: `FSI ≥ 0.7`; the bloc equity index fell ≥ 15% over 5 trading days; the interbank spread over policy (07) ≥ 1.5%; for SC or PL, the currency fell ≥ 10% over 3 trading days; a major crisis in this bloc entered POLICY phase. Limit `PARAM.macro_cb_max_emergency_per_quarter = 2`.
- Timing: at `t = 45` of the next trading day (pre-market, so the opening auction absorbs it).
- Size: cuts up to `−0.0100` (`PARAM.macro_cb_emergency_step`), computed as the scheduled rule with ρ = 1 and the wider clamp; FX-defence hikes (SC, PL only, when the currency trigger fired) up to `+0.0500`.
- Usually accompanied by tools: facility term extension to 91 days (LTRO), swap line activation, QE start if at ELB, CCyB release.

#### §3.6.7 Credibility (0..1, published ×100 as the Credibility gauge)
Each day close:
- If `|π_e5 − π_target| < 0.005` and `|π_core − π_target| < 0.01`: `cred += 0.10 × (1 − cred) × Δ`.
- If `|π_core − π_target| > 0.02` for more than 182 consecutive game days: `cred −= 0.30 × cred × Δ`.
- If QE is active while `π_core > π_target + 0.02` (monetary-financing perception): `cred −= 0.10 × cred × Δ`.
- One-off: guidance breaks (§3.6.5); a decisive emergency hike in a currency defence `+0.05`; a peg break or YCC abandonment `−0.10`; a new governor `±0.05` toward the bloc's `credibility0`.
- Clamp [0.05, 0.98].

### §3.5 Politics and lobbying (layer 4)

**§3.5.1 Structure.** Each of the 5 blocs has one `Legislature` of `PARAM.legislature_seats = 300` seats, 4 parties (22 names them; launch positions are drawn so that one party sits in each ideological quadrant of `(econ, reg)`, with `trade` and `tech` jittered U(−0.6, 0.6)), and 12 caucuses (3 per party, each tied to a constituency: a set of cities and sector weights). Each caucus has a POLITICIAN actor as leader (the 12 per bloc of §3.3.1); party leaders are the leader of that party's largest caucus. Ideology convention for all of 16: `econ +1` = low tax, small state; `reg +1` = light regulation; `trade +1` = open trade; `tech +1` = permissive on new technology. A party's `position` is the seat-weighted mean of its caucuses' `party.position + ideologyOffset` (offsets U(−0.2, 0.2) per axis).

**§3.5.2 Government formation.** After each election (and when a coalition collapses), the government is the smallest set of parties with ≥ 151 seats that minimizes ideological spread `Σ pairs ‖pos_i − pos_j‖₂`; ties broken by the largest party first, then by `partyId`. If no 3-party set reaches 151, the largest party governs as a minority government (`minority = true`: its bills need +1 logit on the floor from opposition caucuses, see §3.5.6). The government sets the agenda (§3.5.4) and names the finance minister (FINANCE_MINISTER actor of the bloc, ideology re-drawn as the government's seat-weighted position + N(0, 0.1) per axis, clamped).

**§3.5.3 Public mood.** Updated at each day close per bloc:
```
approvalTarget = 0.5 + 0.8·(g − g*) − 1.2·(π − π*) − 1.5·(u − u*) − 0.1·scandalLoad + 0.05·(S − 50)/50
                 // g* = trend growth, π* = 04 inflation target, u* = 04 natural rate
govApproval   ← govApproval + 0.02·(clamp(approvalTarget, 0.1, 0.9) − govApproval)
scandalLoad   ← 0.98·scandalLoad + Σ (severity of SCANDAL news about government members today)   // severity 0.1..1
salience.x    = normalized share of last 28 game days' published newsworthiness by axis (econ: MACRO_DATA, CENTRAL_BANK, EARNINGS, BANKRUPTCY; reg: REGULATION, SCANDAL, VERDICT, CRYPTO_INCIDENT; trade: GEOPOLITICS, SUPPLY; tech: TECH, PRODUCT, ERA)
voterMedian   drifts toward  (0.97·voterMedian + 0.03·issueShift)  each game quarter, where issueShift is the cumulative effect of issue campaigns (§3.5.8) and eras (§3.10.4)
```
If `govApproval < PARAM.coalition_collapse_approval = 0.20` (E-34, PROVISIONAL [Quant]) for 28 consecutive game days and the government is a coalition, the most distant junior partner leaves with probability 0.5 per game quarter; the government re-forms per §3.5.2 without an election, or a snap election is called if no government reaches 151 seats. At most `PARAM.coalition_collapse_max_per_chapter = 1` collapse per bloc per chapter (E-34, PROVISIONAL [Quant]).

**§3.5.4 Agenda.** Each game quarter the government introduces `1 + Poisson(1)` bills, clamped to [1, 3], drawn from levers where `|preferred − current| > 0.25·maxChangePerBill`; `preferred` for lever `k` is `default_k + Σ_axis (govPosition.axis × direction_k.up.axis) × (max_k − min_k)/2`, clamped to bounds; the proposed value moves at most `maxChangePerBill` toward it. Opposition caucus leaders each introduce a PRIVATE_MEMBER bill with probability 0.1 per game quarter (rarely passes). A **petition** bill (`soc.pol.petition`, §4) is introduced when registered backers commit lobbying spend totalling at least `PARAM.petition_threshold_real = $50M` within `PARAM.petition_window_game_days = 28` game days (E-35, PROVISIONAL [Quant]) (a real sink, nonrefundable); a bloc has at most 2 petition bills per game quarter (first come, first served).

**§3.5.5 Pipeline.** INTRODUCED → COMMITTEE for `PARAM.committee_game_days = 14` → FLOOR vote at the next day close → PASSED or FAILED → ENACTED after the lever's `implementationLagGameDays` (in the registry table, typically 28) → IN_FORCE. 04 and the other owners read `PolicyValue` only once IN_FORCE. Every stage change is a PUBLIC event and a BILL news item (always published). A bill's lever and proposed value are public from INTRODUCED, so players and NPC actors can position before enactment (a central learning loop, P05). A failed bill on the same lever and scope cannot be reintroduced for 91 game days. The REPEALED stage occurs only when a later enacted bill moves the same lever.

**§3.5.6 Floor vote.** Each caucus votes as a block:
```
p_yes(k) = σ( 2·whip_k + 2·ideoFit_k + 1·constFit_k + 1·L_k + 1·mood_k + ε ),   ε ~ N(0, PARAM.vote_noise_sd = 0.5)
whip_k     = +1 if caucus in government and bill origin GOVERNMENT; −0.5 if in opposition and GOVERNMENT bill; 0 otherwise
ideoFit_k  = sign(proposed − current) × Σ_axis (caucusPos.axis × direction.up.axis) / max(1, #axes in direction.up)   // in [−1, 1]; +1 = the move fits the caucus
constFit_k = Σ_sector constituency.sectorWeights[s] × sectorImpact_s(bill)   // 22 table per lever: +1 benefits, −1 harms; in [−1, 1]
L_k        = lobbying index (§3.5.7)
mood_k     = (govApproval − 0.5) × 2 × (+1 if in government else −1) × 0.5
corrupt_k  = +1 added inside σ when a bribery operation (12) succeeded on this caucus leader for this bill (13 consequences apply)
minority   = −1 added for government caucuses' bills when the government is a minority (passes only with opposition help)
```
The caucus votes YES if `rng('world.politics', blocId, tick) < p_yes(k)`. The bill passes if YES seats ≥ 151. Votes by caucus are published.

**§3.5.7 Lobbying.** A lobbyist (any player character holding an active `LobbyRegistration`, or an NPC actor) registers once per (client, lever, scope, direction) via `soc.pol.lobby.register` (fee `PARAM.lobby_registration_fee_real = $10,000`, sink `LOBBY_SPEND`). Spend (`soc.pol.lobby.spend`) is a real SINK (paid to NPC consultancies, booked to `row`), in real dollars (nominal ÷ MSI at the tick paid). All registrations and spend totals per lever are **public** in the lobbying register (Civic screen), refreshed at each day close; the client is named (13 §lobbying rules: unregistered spend is impossible as an intent). For each caucus `k` and bill on lever `l`:
```
F_for,k     = Σ spends with direction toward the bill's proposed value, last PARAM.lobby_window_game_days = 91, targeted at k
              + (untargeted spend) × seats_k / 300
F_against,k = same for the opposite direction
L_k = clamp( PARAM.lobby_coeff = 0.25 · ( sqrt(F_for,k / $1M) − sqrt(F_against,k / $1M) ), −0.75, +0.75 )
```
The square root gives diminishing returns, and opposing coalitions cancel. Spend older than 91 game days stops counting. A single entity's spend counts in full; linked accounts (15 §3.12) are pooled and their pooled spend is capped as if one entity. Effect bound: even `L_k = +0.75` cannot flip a caucus that opposes on ideology and constituency (`2·ideoFit + constFit ≤ −2` keeps `p_yes < 0.25`).

**§3.5.8 Issue campaigns.** `soc.pol.campaign` buys public advocacy on one axis in one bloc (min $1M real, SINK `ISSUE_CAMPAIGN`):
```
Δsupport = PARAM.campaign_coeff = 0.05 × ln(1 + spend / $10M)     toward the chosen axis direction
cap: Σ |Δsupport| per (bloc, axis) ≤ PARAM.campaign_cap_per_quarter = 0.15 per game quarter (all campaigners combined)
```
Δsupport is added to `issueShift` (moves `voterMedian` per §3.5.3) and, for the next election, to the vote utility (`β_iss` term). Opposing campaigns net out before the cap.

**§3.5.9 Elections and contributions.** Each bloc holds an election every `PARAM.election_interval_game_years = 4` game years (1,456 game days, about 60.7 real days), staggered so blocs are offset by 291 game days. 28 game days before an election a CAMPAIGN period starts (ELECTION news). Vote shares by softmax over parties `p`:
```
V_p = β_inc · incumbent_p · (govApproval − 0.5)·2       β_inc  = 1.0
    − β_iss · ‖voterMedian − position_p‖₂                β_iss  = 2.0
    + β_camp · ln(1 + campaignFunds_p / $10M)             β_camp = 0.3
    + ε_p,  ε_p ~ N(0, 0.15)
share_p = exp(V_p) / Σ exp(V_q)
```
`campaignFunds_p` = party treasury + contributions this cycle. Seats by Sainte-Laguë over parties with share ≥ 5%; caucus seats within a party by constituency strength (22 table, re-drawn ± 10%). Turnout `= 0.55 + 0.1·(salienceMax − 0.25)`, display only. Contributions (`soc.pol.contribute`): at most `PARAM.contribution_cap_real = $5M` real per donor per party per election cycle (linked accounts pooled), SINK `POL_CONTRIBUTION` (the party is an NPC entity; its treasury is spent on campaigns, which are NPC-internal), public by donor name at the day close (Civic screen). Corporate contributions are allowed from the company's treasury and named as the company. Contributions are never anonymous and never refundable.
