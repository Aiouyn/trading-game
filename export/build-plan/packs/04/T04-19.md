## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. **Public view refresh (§2.4).** `refreshPublicView(ctx, b)` reads `mac.bloc[b]`, `mac.cb[b]`, `mac.global`, `mac.schedule` and writes the non-print, non-curve, non-label fields: `asOfTick = ctx.tick`; `policyRate`, `depositRate`, `lendingRate`, `reserveRequirement`, `nextMeeting { tick, guidanceTick }` (next `mac.schedule` CB rows with tick > now), `guidance`, `dots`, `marketImpliedPath`, `sovereignSpread10y`, `sovereignPd1y` (market PD, never `hazard`), `fiscalPrints` (last published quarterly fiscal values, not the daily true state), `fx { spotVsFdl, regime, band?, reservesFdl, reserveCoverMonths, capitalControls }`, `qeHoldingsGdp`, `ccyb`, `ltvCapResidential`, `ltvCapCommercial`, `credibilityPublic`. Every value is copied from an already-public source; no field in `HIDDEN_FIELD_NAMES` is read into the row. Called by T04-20 after each event that changes one of those fields (decision, guidance, FX regime event, capital-control change, auction result, day close step 13).
2. **Screen views (§7).** One `ViewHandler` per row of the §7 table that 04 owns. Wire and Research Desk are not 04 views (16 and 05 build them from 04 events and the T04-20 api). Rules shared by all handlers:
   - Read only `mac.public_view`, published events' rows (`mac.release` with `publishedTick ≤ now`, `mac.auction` results, `mac.schedule`) and public world event views (`publicEventView`). A release row is visible only when `publishedTick ≤ store tick`; consensus is visible from its `consensusTick`.
   - `macro.calendar`: rows sorted by (tick, bloc in `BLOC_ORDER`, kind, ref). Crisis-week rows appear only after the announcement hook fired (T04-17); capital-control expiries only for active controls.
   - `macro.rates`: `spread2s10s = y10 − y2` from the public curve; `inverted = spread2s10s < 0` (label "Inverted"). `prior` = the curve of the previous recompute kept on `mac.curve`.
   - `macro.auctionTicket` and `macro.bankConsole` are OWNER views: own bids and own facilities only; another viewer gets the public auction terms and empty own sections.
   - `macro.dealerLeague` returns `leagueTable(store, bloc, quarter)` unchanged (names already masked by T04-12).
   - Every handler's output passes `assertNoHiddenFields` (04#15).
3. **Stabilizer mirror (§3.17 duty 1).** At t = 0 of each game day, `mirrorStabilizer` reads `led.stab` and `led.msi` and writes `mac.stab`: `levers` = `leverValue(read, L)` for each `LEVER_SPEC` lever, `integral`, `msi = msiValue(read)`, and `errorLog` = the last 7 entries of `led.stab.history` (`{ dayIndex, e }`). No 04 rule uses these values. There is no controller code in 04: no PI step, no lever bounds, no deadband (04#38 static check).
4. **Daily MSI (§3.17 duty 2, last sentence).** `publishMsi` at macro day step (13): emit `macro.stab.msi` `{ dayIndex: cal.gameDay, msi }` PUBLIC with `msi = msiValue(read)` unchanged (4 decimals as 03 publishes it).
5. **Weekly report (§3.17 duty 2).** Runs when `cal.weekday = 0` (Monday) and `cal.tickOfDay = 45`, i.e. tick `720·d + 45` with `d ≡ 0 (mod 7)`. On day 0 there is no completed 03 day, so it returns null and emits nothing. Otherwise, with `D = d − 1` (the most recent 03 day close):
   - `msi`, `levers`, `e`: from the `led.stab.history` entry with `dayIndex = D` (exactly 03's values, 04#38); `direction = leverDirection(levers_D, levers_{D−7})` (sign of the difference, 0 when equal or when D − 7 < 0).
   - `eLabel = formatMoneyVsPath(e)`: `"Money vs designed path: " + sign + round(100·e) + "%"`, sign `+` for ≥ 0 (0 → `+0%`), `−` rendered as ASCII `-`.
   - `faucetsWeek`, `sinksWeek`: for FDL, Σ over `FlowDay` rows `FDL:k`, k = D−6..D (rows that exist), of `byClass` amounts per reason-code class, as decimal strings (bigint sums, no float). Faucets are the `FAUCET` class entries, sinks the `SINK` class entries, each keyed by class name.
   - `netMintWeek = Σ faucets − Σ sinks` (bigint, decimal string; negative allowed).
   - `m0Index`, `m2Index`: `100 × M(D) / M(base)` from `FlowDay.M0` and `FlowDay.M2` of FDL, where `base` is the oldest FDL `FlowDay` row still kept (03 keeps 364 days). Ratio computed as `Number(M_D × 10^8 / M_base) / 10^6` (bigint first, then float), `safeDiv` fallback 100 when the base is 0. See Open points.
   - `npcToPlayerWealthRatio = npcToPlayerWealthRatio(worldNominalGdpFdl, BigInt(report.pew))` with `report = src.latestDailyReport(read)`; when null, keep the previous value in `mac.stab.diagnostics`.
   - `crisisCountChapter = mac.global.scheduler.majorsThisChapter`.
   - Write `mac.stab.diagnostics { faucetsWeek, sinksWeek, netMintWeek, npcToPlayerWealthRatio, m0Index, m2Index }` and `lastPublishedReportTick = ctx.tick`; emit `macro.stab.report` PUBLIC with `StabWeeklyReport`. No individual data: no entity id, character id or name appears (schema test).
6. Determinism: no RNG; all sums in bigint; iteration over classes in sorted key order; blocs in `BLOC_ORDER`.

## §1 Purpose

The macro layer is the one shared state every price, business, loan and property in the world reads (V3 Part 2.4). It exists so that:

1. **Prices have reasons.** A rate hike, a CPI surprise, a downgrade or a currency defence hits bonds, mortgages, growth stocks, bank margins, cap rates, carry trades and leveraged funds on the same tick, through named transmission channels that the "Why it moved" ladder (05 §3.12) can cite.
2. **Recessions are caused, not random** (old 01 §5.3). Imbalances (credit growth, valuation stretch, an inverted curve, tight real rates, oil shocks) raise the hazard of a downturn, so a careful player can see one building.
3. **Central banks, treasuries and sovereign bond markets are real machinery** (V3 Part 3.2): policy rates with a corridor, reserves, standing facilities, asset purchases, forward guidance, deficits that are financed by auctions, debt that can be downgraded and restructured, currencies that can be defended and can break.
4. **Crises emerge from rules** (V3 T2) and also arrive on a calibrated schedule so the world has rhythm (one major crisis in about 35% of chapters, storms every game quarter, ripples every game week).
5. **The money stays honest.** The Stabilizer controller keeps the player economy on its designed path, and the Money Supply Index deflates rankings so inflation cannot pump rank (old 01 §8.2–8.3).

### §3.8 Money Supply Index (MSI) and Net Worth Index (NWI)

The NWI is the ranking metric (00 §4): net worth in **real** terms, so that "a dollar in year 3 is worth the same as on launch day" (01 §0.6).

```
design_money(t) = κ · Σ_i w_i · W_target(age_i)          over all characters (not only engaged), κ = PARAM.msi_money_share = 0.20
raw(t)          = PEM_FDL(t) / design_money(t)            (actual player money relative to designed money for this population)
ema(t)          = ema(t-1) + α · (raw(t) − ema(t-1)),     α = 1 − 2^(−1/28)  (half-life 28 game days), daily at day close
MSI(t)          = clamp( ema(t) / ema_base, MSI(t-1)·(1 − 0.005), MSI(t-1)·(1 + 0.005) )
ema_base        = mean of ema over the world's first 168 game days; MSI = 1.000 during that period
NWI_i(t)        = NWrank_i(t) / MSI(t)
```

- Reading: MSI = 1.10 means players hold 10% more money than the design path for a population of this age profile; every nominal dollar of net worth then counts as 0.909 "real" dollars on the boards.
- MSI is published daily with 4 decimals. Boards show NWI in "real $" with the label `real`; personal screens show nominal NW first and NWI second (17).
- Seasonal ladders (15) use NWI deltas exactly as 01 §14.4 defines.
