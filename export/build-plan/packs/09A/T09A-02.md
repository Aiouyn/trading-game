## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Implementation steps
1. `TIER_TABLE` exactly per 09 §3.1.2 (setup: B1 1 game hour = 30 ticks, B2 1 game day = 720, B3 3 days, B4 7, B5 14; B6 per type from 22 `buildDays`, 28 to 182 game days). Rank gates are 14's thresholds; this table only names the rank.
2. Indexing (09 §3.1.3): `c0`, `refPrice`, fixed costs are multiplied by `priceLevel(bloc)` and wages by `wageLevel(bloc)` every day; callers pass the level, this module never compounds inflation itself (04 rule). Each business uses its own bloc (edge 10).
3. Calibration exactly per 09 §3.2.4, in the reference city, at launch prices, for the type's default segment (apply `SEGMENT_PRICE_MULT` and `segmentCostAdj` to refPrice, κ and φ first):
   - `piStar = c0 / paybackDays`, `rStar = piStar / (1 − κ − φ)`, `unitsStar = rStar / refPrice`, `sRef = (1 − 0.5) / PARAM.biz_calib_density`, `dRef = unitsStar / sRef`.
   - HOUSEHOLD: `perCapita = dRef × nDistricts / (refPop × segShare)` for DISTRICT-scope types (the reference district has the mean footfall share 1/nDistricts) and `dRef / (refPop × segShare)` otherwise. BUSINESS_DERIVED: `ioCoef[driver] = dRef / (segShare × driverActivityRef)` with `driverActivityRef` = the driver category's own `dRef` (its reference market demand, computed first: process types in dependency order of `ioDrivers`) or the 10/11 reference quantity named by `driverQty`. TOURISM: `roomNightsPerIndex = dRef / (segShare × tourismIndex(ref))`. PLAYER_SERVICES: NPC share uses `perCapita` like HOUSEHOLD.
   - Capacity (resolution of the ambiguous "Σ_h hourProfile-weighted open hours", written down here so it is not left to the implementer): the stated purpose is "capacity binds only above 125% of reference volume", so capacity must cover the busiest hour at 125%: `capacityPerHour0 = 1.25 × unitsStar × max_h hourProfile[h]`.
   - `f0 = φ × rStar`, split by 22's `fixedSplit` (wages, rent, upkeep, energy, insurance).
   - No-demand-pool archetypes (COMMODITY_PRODUCER, FLOW_TAKE platforms, COMPUTE_PROVIDER, TRIAL_BINARY, FINANCIAL_INSTITUTION, TROPHY, FLIP_TRADING): store `outputRate0` (units per hour) or `takeRate` such that expected daily profit at launch macro equals `piStar`: `outputRate0 = rStar / (refPrice × openHours)` with refPrice = the 06 launch spot of the output; platforms keep 22's `takeRate` and solve the `platformShare` reference = 1/12 the same way as shares. FINANCIAL_INSTITUTION and TROPHY are not on the payback curve (09 §3.8.1) and store only `f0` from their upkeep rules.
   - Categories shared by several types: `perCapita` of the category comes from the lowest-tier type selling in it (ties: catalog order), every type still gets its own capacity and costs. Calibration runs once in genesis and is never re-run (later crowding and macro move profits).
4. `referenceWeight0(seg, density)`: reference player u = `a_s × ln(0.96)` (quality index 1, condition 100, fully staffed, skillAvg 3 so staffFactor = 0.96, marketing 0, price = ref, location 0, brand 0, reliability 0.9 → 0, promise PRICE gives no bonus at ref price); NPC field u = `b_s × ln(2) + r_s × 0.02` (quality 1, marketing M_ref, reliability 0.92). `weight0 = density × exp(u_p − u_npc)`, so at genesis the field share against `density` reference businesses is exactly 0.5.
5. `genesisCatalog`: for each type in content order: `calibrateType`, put `biz.calib`. For every city and every type's allowed segments create the market rows of its scope (district markets for DISTRICT-scope types per district of each city; city, bloc and WORLD markets once): `npcField = { weight: weight0, weight0, price: refPrice (indexed at read time), quality: 1 }`, `participants: []`, `shares: { NPC: 1 }`, `hourOffset = marketHourOffset(id)`, `demandDay = 0` (filled at the first t = 0), `hhi = 1`. Market creation for cities that open later (10) happens lazily: `ensureMarket(ctx, id)` (exported from genesis.ts as a helper) builds the same row on first access.
6. Content counts: `catalog_size_target` (150) is a 22 completeness target; R39 makes 22 authoritative for counts and names: genesis asserts `types.length === content count` (no hard-coded 150) and emits nothing else.

# SPEC EXCERPTS (verbatim; binding game rules)

**[09 §1 Purpose]** (context)

## §1 Purpose

Businesses are the steady engine of wealth (the tycoon half; markets are the volatile half, 01 §4). Companies are how a player turns businesses into an institution: found a company, build products, hire, borrow, compete for customers, publish earnings, list on the exchange, acquire rivals, survive distress.

What the module guarantees:
1. **Real shared competition.** Every business sells into a demand pool shared with every other player and NPC competitor in its market (city or district × product category × segment). A logit share model decides who wins customers (01 §4.1). Similar firms coexist; nothing consumes a unique worldwide slot except named unique infrastructure (C03).
2. **Distinct economics.** Each business belongs to one of 16 economic archetypes with its own formula (footfall retail, local service, B2B contract, commodity producer, processor, platform, subscription, hit-driven, tourism, transport capacity, regulated utility, compute provider, trial binary, financial institution, trophy, flip trading). A niche is a combination of archetype, category, segment, location, operating model and promise (C02), not just a new name (C04, R01).
3. **Customers with requirements.** NPC customers post tenders with price caps, reliability, certification, response time and confidentiality requirements; switching takes effort; concentration has risks (C05–C08).
4. **Company building in depth** (Mathis directive 2026-10-09, STONKS-9800 spirit): R&D, product lines, marketing, hiring, production and capacity, pricing, expansion, financing; real operating economics; filings and earnings that feed the market; IPO onto the same exchange.
5. **Corporate finance and control**: capital structure, covenants, dividends, buybacks, issuance, IPOs, takeovers and defences, activism, LBOs, restructuring with absolute priority. A bankrupt company is a market, not just a delisting (V3 3.7).
6. **Honest money.** Revenue from NPC customers is a faucet, costs paid to NPCs are sinks, everything between players is a transfer; diminishing returns (logit share, exponential upgrade costs, finite demand) and the offline cap keep business income from running away (01 §8.3).

**[09 §3.2.4]** (from spec file 09-BUSINESSES-AND-COMPANIES.md)

#### §3.2.4 Calibration rule (how `perCapita` and coefficients are set at world genesis)

For each type, at launch prices, in the reference city (the median-population launch city):

```
π*        = c0 / paybackDays(tier)                         target daily operating profit
R*        = π* / (1 − κ − φ)                               target daily revenue (κ = cogsRatio, φ = fixedRatio)
units*    = R* / refPrice                                  target units per day
s_ref     = (1 − npcShare0) / PARAM.biz_calib_density      reference share: npcShare0 = 0.50 (DEFAULT, 01: NPCs take 30–60% in a fresh city),
                                                            biz_calib_density = 12 player businesses per market
D_ref     = units* / s_ref                                 reference market demand per day
perCapita = D_ref / pop(refCity)                           (HOUSEHOLD); ioCoef solved the same way against reference driver activity
capacityPerHour0 = 1.25 × units* / Σ_h hourProfile-weighted open hours   (capacity binds only above 125% of reference volume)
fixed cost per day F0 = φ × R*; split by 22's per-type split: wages, rent, upkeep, energy, insurance baseline
```

Types whose archetype has no demand pool (COMMODITY_PRODUCER, FLOW_TAKE platforms, COMPUTE_PROVIDER, TRIAL_BINARY, FINANCIAL_INSTITUTION, TROPHY, FLIP_TRADING) are calibrated by choosing their output rate or take rate so expected profit at launch macro equals π* (§3.4.2). Calibration runs once at genesis and is stored in 22's data; it is not re-run (later crowding and macro move profits; that is the game).
