## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Goal
This task keeps the data that group accounting needs and builds consolidated books from it:
- **Period running totals per account** (03 §3.13.1), with the part of each total that came from intra-group counterparties.
- **Intercompany claim balances by counterparty.**
- **Deferred intra-group profit** on assets that are still inside the group.

From these it builds the consolidated books of any group parent or character (03 §3.11.5): line-by-line aggregation with translation, the six eliminations (a)–(f), NCI, and associates at equity method.

It also covers:
- **Related parties** (03 §3.11.6, Bible I07): band check, flag event, minority damages, the arm's-length price for tax. Marks are never taken from these prices.
- **Concessions** (03 §3.11.7): helpers for 10's daily `CON_CONCESSION_PROFIT`.
- **INV-BS-008:** intercompany balances eliminate exactly, and consolidated NW never exceeds Σ standalone NW minus intercompany equity.

Consolidated books are derived records. `LED_FX_TRANSLATION` (3500) and `LED_INTERCO_PROFIT_RESERVE` label consolidation lines and are never committed to a member's solo books. The chart marks 3500 and 3600 "consolidated statements only".

## Implementation steps
0. **New fact kinds.** Add to T03-01's `LedgerFactKind`:
   - `'INTRAGROUP_GUARANTEE'`: subject `${guarantorId}>${beneficiaryId}`, value Money string, written by 07/09;
   - `'CONCESSION_RESERVE'`: subject operatedId, value the Money string of the day's mandated reserve, written by 10.
1. **Period totals** (`updatePeriodTotals`, P13 after `commitTick`). For each committed valid entry and each posting, for both accounts and for each `PeriodKind`, take the current index from `ctx.cal`. Then:
   - add `amount` to `debits` (debit side) or `credits` (credit side);
   - if `counterpartyOfPosting` shares `rootOwnerOf` with the account's entity, add the signed amount to `intraGroup`;
   - for money accounts (1001, 1002, 1003, 1010, and 1050 as "cash pledged"), add the signed amount to `byCode[reason]`.
   Rows are created lazily. Indexes older than `PERIOD_RETENTION` are pruned at the matching close boundary. The FLASH statement is the running row of the current index.
2. **Intercompany** (`updateIntercompany`):
   - `counterpartyOfPosting`:
     - if the posting's two accounts belong to different entities, each account's counterparty is the other entity;
     - otherwise, if the entry has exactly two parties (headline payer/payee, or ACCRUE_PAIR a/b), the counterparty is the other party;
     - else undefined.
   - **xbal.** For every posting on an account whose code is in `CLAIM_ACCOUNTS`, or on a holding of an instrument whose issuer is a core non-public entity (1520 against 2300, 1500/1570 against 3100), when the counterparty's kind is one of chr, ali, cmp, bnk, ins, fnd, spv, biz, prop, npc: add the signed amount to `xbal[account<counterparty]`. Rows at 0 are deleted.
   - Claim balances between any two such entities are therefore known at any time, even if they join a group later.
   - **icprofit.** For a SWAP_ASSET/MOVE_QTY/PAY entry transferring an asset (inventory 1200, 1580 biz/prop, 1700 model, 1800 via its prop entity, 1830–1880) between two entities with the same root at commit, where the seller's gain posting (4060/4090) is `g > 0`:
     - add `g` to `icprofit[buyer asset key]` (with qty);
     - when the buyer later moves qty of that account to an entity outside the root, release `deferred × movedQty / qty` (proportional, half-even) and decrease the row;
     - depreciation or amortization of the buyer's asset releases the deferred profit in proportion to the net-book reduction.
3. **Consolidation** (`consolidate(read, P, period, tick)`):
   - **Members.** `M` = P plus every entity P controls, directly or through controlled subsidiaries (T03-16 `controls`), minus `CHALLENGE_BOOK` entities. Funds are never members of their manager's group (custody rule).
   - **Aggregation (step 1).** For every member and every account, aggregate the balances by code, translated with `closingRateE6` at the period's last day. Aggregate the P&L period nets (`periodNet`) translated with `averageRateE6` over the period. The difference between translating equity at closing and average rates goes to the 3500 line, labelled `LED_FX_TRANSLATION`.
   - **Elimination (a).** P's investment in each member X (1580/1570/1500 of X at book), against X's equity (3100, 3110, 3200, 3300, 3400). The excess paid at acquisition is goodwill 1730, read from `led.goodwill` (`navAtAcquisition`) when present, otherwise from the parent's own 1730 balance. The remaining difference stays in group equity.
   - **Elimination (b).** For each member account in `CLAIM_ACCOUNTS`, subtract `Σ xbal[account<j]` over the other members j. Instrument holdings issued by members (bonds 1520 vs 2300) are eliminated the same way.
   - **Elimination (c).** Subtract each P&L account's `intraGroup` period amount: intercompany sales, purchases, interest, fees and dividends.
   - **Elimination (d).** Subtract the `icprofit` rows of the root from the asset lines and from the period result, labelled `LED_INTERCO_PROFIT_RESERVE`. They are released when the asset leaves the group.
   - **Elimination (e).** Members' holdings of P's own shares are shown as treasury shares (3150 contra), not as assets.
   - **Elimination (f).** Intragroup guarantees, from `INTRAGROUP_GUARANTEE` facts between members, are listed in `guaranteesMemo` only.
   - **NCI.** For each subsidiary X: `nci = 1 − effectiveOwnership(P, X)`. Then `nciEquity += nci × X's net assets after eliminations` and `nciResult += nci × X's period result`. Both appear in the 3600 line and the "attributable to NCI" line, rounded half-even per member.
   - **Associates** (`isAssociate`: votes between 0.20 and 0.50, and the holder's group does not control the issuer). `equityMethodValue(read, holder, issuer, tick) = economicShare × lookThroughNav(issuer)`. T03-13 uses it for 1570 stakes in the parent's solo books. Listed associate stakes (1500) keep their market mark: the §3.9.2 row for listed equities is explicit, and the reading is that equity method applies to unlisted associates. The same value is used in consolidated books.
   - **Characters.** A character's consolidated view is `consolidate(chr, …)` over everything it controls (03 §3.13.1).
   - `consolidatedNw` = Σ consolidated assets − liabilities − NCI equity. It equals T03-16's look-through NAV for P up to the valuation basis: both use `valueAccount`.
4. **Related parties** (`checkRelatedParties`, P13 after commit, over committed valid TRANSFER entries with two parties A and B where `isRelated(A, B)`):
   - **Fair value.** `fv = fairValueOf(...)`:
     - with an asset leg: qty × effective mark (`valueAccount` of the qty), or `lookThroughNav × share` for 1580 transfers;
     - otherwise: the value noted with `noteFairValue` by the owning module (services, internal capacity booked at list price as `BIZ_SALES_B2B` / `LAB_COMPUTE_RENT_B2B` by 09/11, Bible I02);
     - otherwise: skip.
   - **Flag.** `dev = (price − fv) / fv`, with `band = params.num('related_party_band')`. If `|dev| > band`:
     - write `RelatedPartyFlag` with `bandEdgePrice = toMoney(fv × (1 + sign(dev) × band))`;
     - `minorityDamages = minorityShare × |price − fv|`, where `minorityShare` = `1 − effectiveOwnership(root, X)` for the side X that has outside holders (NCI > 0 or listed) and lost value, and 0 when neither side has outside holders;
     - emit `ledger.related_party.flag` with payload `{ entryId, deviationPct }`, visibility PRIVATE to the parties plus the regulator (03 §5). 15 discloses it in the next filing (it sets `disclosed`); 13 creates the derivative claim from `minorityDamages`.
   - The flag fires for every related-party trade outside the band, including 100%-owned companies. 03#16 expects it, even though §3.11.6's first sentence scopes the minority consequences to sides with outside holders. The minority claim keeps that scope.
   - The transaction always executes: the engine never blocks a lawful choice. It never sets a mark, because T03-13 takes marks only from engine sources.
   - `taxPriceFor(entryId)` returns `bandEdgePrice`. Tax (T03-21 assessments, T03-22 transfer pricing) uses it as the arm's-length price.
5. **Concessions** (`concessionNetFeeIncome(operated, day)`): `−(periodNet of 4040 for DAY) − Σ periodNet of the operated entity's 5xxx for DAY − CONCESSION_RESERVE`, with a floor of 0. 10 posts `CON_CONCESSION_PROFIT` with it each day at close.
   - The operated entity stays NPC-core, owned by the treasury. A concession is a contract and never control: T03-16's control rules count votes only.
   - The right (1740) is amortized over one chapter by a T03-14 schedule that 10 registers. It is derecognized by `PROP_CONCESSION_BUYOUT` (10) when the holder is outbid.
6. **INV-BS-008** (TICK FATAL, 20 §3.1; Bible I06). For each group root touched by this tick's committed entries (all roots at DAY_CLOSE):
   - (1) Σ over members i and other members j of `xbal[i.account<j]`, per ccy and per claim pair (receivable with payable, deposit with customer deposit, loan with loan payable), is 0: intercompany balances eliminate exactly;
   - (2) `consolidatedNw(root) ≤ Σ_members nwSolo(member) − intercompanyEquity`, where `intercompanyEquity` = Σ of members' holdings of other members' shares (1500/1570/1580) at `valueAccount`. Computed in Money, in the root's reporting ccy, with an exact comparison.
   A failure is `ctx.fail('INV-BS-008', { entityId: root, sub: '1' | '2' })`.

# SPEC EXCERPTS (verbatim; binding game rules)

**[03 §1 Purpose]** (context)

## §1 Purpose

The ledger is the game's first law: **every unit of money and every unit of every asset exists on exactly one balance sheet, and moves only by a posting with a reason code**. This module defines:

1. the entity kinds and the balance sheet each one carries;
2. the full chart of accounts;
3. the double-entry posting model, its standard templates (pay, mint, burn, lend, revalue, FX) and the payment rail across settlement cash, bank deposits and partitions;
4. the complete reason-code catalog of the game, each code in exactly one class (FAUCET, SINK, TRANSFER, CREDIT_CREATE, CREDIT_DESTROY, REVALUE);
5. money aggregates (M0, M2, player-economy money and wealth), the faucet and sink inventory with target ratios, the **Stabilizer** PI controller, the **Money Supply Index (MSI)** and the **Net Worth Index (NWI)**;
6. valuation (marking) rules for every asset type, including illiquid ones;
7. consolidation of ownership chains, minority interests and intercompany elimination;
8. taxes in the five blocs and the Isla Serena free zone;
9. financial statements generated for every entity;
10. insolvency and bankruptcy accounting;
11. the invariants asserted every tick.

Design stance: real accounting where it creates gameplay (balance sheets, consolidation, taxes, credit creation, insolvency), simplification only where it would be invisible (no accrual-vs-cash tax timing nuances beyond those listed, no lease accounting standards). The ledger is also the evidence base for courts (13), the explanation base for "Why it moved" (18) and the data base for the Truth Machine (20).

#### §3.11.5 Consolidated financial statements

For a group parent P with controlled members:
1. Aggregate line by line all members' statements, translated into P's reporting currency (balance sheet at closing rate, income statement at the period's average daily rate; differences to 3500 FX translation reserve, `LED_FX_TRANSLATION`).
2. **Eliminate**: (a) the parent's investment in each subsidiary against the subsidiary's equity, creating goodwill (1730) for the excess paid at acquisition; (b) intercompany receivables and payables; (c) intercompany sales, purchases, interest, fees, dividends; (d) unrealized intercompany profit on assets still held in the group (inventory, property, businesses, models sold within the group) via `LED_INTERCO_PROFIT_RESERVE`, released when the asset leaves the group; (e) cross-held shares as treasury shares; (f) intragroup guarantees (memo only).
3. **Non-controlling interests**: NCI share of each subsidiary's net assets and result = `1 − eff(P, X)`; shown in 3600 and as "attributable to NCI" in the income statement.
4. Associates (20–50% without control) are carried at equity-method value (share of NAV) in the parent's solo and consolidated books.

**[03 §3.11.6]** (from spec file 03-LEDGER-AND-ACCOUNTING.md)

#### §3.11.6 Related parties and minority protection (Bible I07)

Two entities are related if they share a root owner, or one controls the other, or they are linked accounts (15 anti-cheat). For transactions between related parties where at least one side has outside minority holders (NCI > 0 or listed):
- The price must lie within ±`PARAM.related_party_band` (DEFAULT 10%) of the engine fair value of the asset or service (the band 01 §9 uses for anti-funneling).
- Outside the band the transaction still executes (the engine never blocks a lawful choice), but: it is flagged in the next filing (15); minority holders gain a derivative claim (13) with damages = minority share of the value transferred; tax uses the arm's-length price (§3.12.9); the transaction never sets a mark.
- Internal capacity used for a related entity (Bible I02: a data-center business serving its owner's lab) is booked at the business's list price as `BIZ_SALES_B2B`/`LAB_COMPUTE_RENT_B2B` so the opportunity cost is visible in both statements.

**[03 §3.11.7]** (from spec file 03-LEDGER-AND-ACCOUNTING.md)

#### §3.11.7 Concessions

A concession (stock exchange, port terminal, utility, chip fab, nuclear plant, 01 §14.2; 10 runs the auctions) is a right (1740) held by the winning entity for one chapter. The operated entity (e.g. the bloc's `exc`) stays an NPC-core entity owned by the treasury; each day at close it pays its net fee income (fees − operating costs − mandated reserves) to the holder with `CON_CONCESSION_PROFIT`. When the holder is outbid, the treasury pays it the built asset's book value (`PROP_CONCESSION_BUYOUT`) and the right is derecognized.

#### §3.13.1 Generation

- Every entity's books are always complete, so statements are a projection of account balances and postings; nothing is entered by hand.

| Exploit | Counter |

| Pumping own listed company to climb the board | concentration haircut and control cap (§3.10.3); thin-print guard; surveillance (05/13) |
| Ramping a thin market at the hourly board snapshot | thin-print guard (§3.9.1) weights marks by volume; board NW uses the hour's mark history, not one print |
| Alt-account funnelling via off-market P2P sales | P2P tax 2%, related-party flags, 15's caps and linked-account detection, marks unaffected |
| Transfer-pricing profits into Serena | engine applies arm's-length prices for tax (§3.12.12); CFC rules; substance test; audit odds rise with Serena share |
| Becoming a Serena tax exile | characters cannot be Serena residents (§3.12.2) |
| Harvesting losses and rebuying immediately | wash-sale rule including related parties (§3.12.6) |
| Exit before tax bill (change residency) | exit tax with step-up (§3.12.13) |
| Spending down before a fine | fines are % of NW at the higher of offense and verdict ticks (03-conflict §1); protected floor only for crime/court debts |
| Going bankrupt to escape the Clearing House or victims | persistent claims survive discharge and are garnished (§3.14.5) |
| Repeated fresh starts | once per 56 real days, restricted cash, reputation hit, 1× leverage and credit blocks (14 §3.13.5) |
| Using ad or fresh-start cash to fund ops | restricted cash (§3.5.6, I21) |
| Printing money via a player bank | bank lending creates deposits and an equal loan asset (no NW created); capital and liquidity rules (07); loans to alts are related-party and 15-flagged; defaults hit the bank's own equity |
