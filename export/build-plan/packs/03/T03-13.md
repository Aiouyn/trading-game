## G4. Time (00 §5.1)

5 real seconds per tick; 720 ticks per game day (= 1 real hour); 30 ticks per game hour; one tick = 2 game minutes. Week = 7 game days (Mon–Fri trading, Sat–Sun weekend). Quarter = 13 weeks = 91 game days, months 28/28/35 days. Year = 364 game days = 262,080 ticks. Chapter = 8 real weeks = 1,344 game days. Real day = 24 game days.
Trading day tick-of-day `t`: pre-market 0–59; opening auction t=60; continuous 61–539; closing auction t=540; after-hours 541–719. Accruals (interest, rent, wages, fees) post at day close t=719. Business operations run once per game hour, staggered: an entity runs when `tickOfDay mod 30 == fnv1a32(id) mod 30`.

## G5. Tick pipeline (00 §5.2)

```
P0 ingest  P1 validate  P2 calendar  P3 world(16)  P4 npc(05,16)  P5 ai(11)  P6 match(05,06)
P7 clear(07)  P8 finance(07,08)  P9 real(09,10)  P10 conflict(12)  P11 law(13)  P12 social(14,15)
P13 ledger(03: commit postings atomically, settle/release holds, assert invariants)  P14 emit
```
A phase may read any committed state and the outputs of earlier phases of this tick; it writes only its own module's tables and queues postings for P13. Postings never commit before P13. A failed invariant rolls the tick back and replays it in safe mode. Consequences of tick N that other modules react to land in tick N+1 (via `ctx.send(..., 'NEXT')` or events).

### G6.1 Ports for later modules (dependency inversion)

A module may never import a module built after it. When its rules need data from a later module (for example 05 needs fundamental values from 09 or index weights from 08), it declares a **port**: a TypeScript interface in its own `ports.ts` (e.g. `MarketPorts`), and its factory takes the implementations: `createMarketsModule(ports: Partial<MarketPorts>)`. The later module exports an implementation of that port, and `packages/engine/index.ts` wires them when building the world. A missing port uses the default the spec gives for "module not present" (stated in the card), never an invented rule.

## G8. Determinism rules (02 §3.7, 19 Rule 3.6.2) — lint-enforced in packages/engine

Forbidden in engine code: `Date`, `performance`, `Math.random`, `crypto` randomness, timers, `process`, `globalThis`, `Intl`, `toLocaleString`, `localeCompare`, `async/await`/Promises, `for…in`, iterating `Object.keys/values/entries` of map-like objects, `Map`/`Set` iteration where order matters (use `SortedMap`/`SortedSet`), `Array.sort` without a total comparator (use `sortBy`), `JSON.stringify` for hashing/persistence (use `canonEncode`), `WeakMap/WeakRef`, `Math.exp/log/pow/sin/cos/tan/atan2/cbrt/hypot/...` (use `dmath`), `Math.round` (use `roundHalfEven`), `Number` for money or quantities. Allowed raw math: `+ - * /`, `Math.sqrt/abs/floor/ceil/trunc/min/max/sign/fround/imul/clz32`.
NaN/Infinity are illegal in state. Ties are broken by entity id then intent id. Iterate collections only in sorted order. Rejection sampling is forbidden; each variate uses a fixed number of draws. A module may draw only from its own streams. Split money into parts only with `allocate`. No exceptions for control flow: report impossible states with `ctx.fail`.

## Goal
Marks are the prices at which the ledger values positions for net worth, statements, boards and day-close revaluation. This task builds the mark registry that market and model modules publish into (05 clearing and official close, 08 NAV, 04/06 curves and option models, 09/10/06 appraisals, 11 compute spot), the anti-ramping thin-print guard, stale and halted handling, the fallback chain of every row of the 03 §3.9.2 table, the function that values any account at a tick, expected credit loss (03 §3.9.3) and the revaluation-surplus routing rule (03 §3.9.4). Marks never come from a price a player declares, a P2P or related-party price, or a contract term.

## Implementation steps
1. Governance (03 §3.9.1 rule 1): `publishClearing`/`publishClose` accept calls only when `ctx.module` is '05' or '06' (else `ctx.fail('INV-LED-007', [], 'mark from module <m>', '05|06')`); `publishModelMark` rejects source CLEAR/CLOSE; 03 itself never derives a mark from a posting's price (P2P, related-party and contract prices never reach this API).
2. Thin-print guard (rule 2): `mark = (V·P + V_min·mark_prev) / (V + V_min)` with `V_min = PARAM.mark_min_volume_frac × ADV20` (ADV20 from fact `MARKET_STATS` of the asset, quantities as float via `Number(qty)/lotScale`); first print (no prev) → P. Result through `toPrice`. Store in `hourMarks` (reset when `tick % 30 === 0`), set `lastTradeTick`, `validUntilTick = tick + EXCHANGE_STALE_TICKS`, confidence LIQUID, source CLEAR.
3. Stale (rule 3): `effectiveMark` flags `STALE` when `tick > validUntilTick`; NW still uses it; boards apply the extra 10% haircut (T03-17). Equities/ETFs with no trade for 5 game days fall back to `fundamental` (source MODEL_FUND, confidence STALE so the board haircut applies, 03 §8 edge 14). Halted (rule 4): last mark flagged STALE until a new `publishClearing` after `setHalted(false)`.
4. `valueAccount` by code (03 §3.9.2; all in the account's ccy; translation is T03-17's):
   - 1001, 1002, 1003: face (balance). 1010: face; if the bank's status is IN_INSOLVENCY: insured part at face (fact `DEPOSIT_INSURED_LIMIT` of the bank's bloc, 07) and the uninsured part × fact `RESOLUTION_RECOVERY` of the bank (07), recovery 1.0 if absent.
   - 1050, 1060, 1070, 11xx, 1200, 13xx (net of 1309), 1830–1880 (net of 1839), 1700–1740, 1810, 1900, 2xxx: book balance (their values are maintained by postings: called losses, ECL, NRV writedowns, amortized cost, depreciation, amortization, impairment; T03-14 posts the periodic ones). Liabilities are never fair-valued (own credit), except 2600 derivative liabilities.
   - 1210: `qty × mark(commodity)` (06 publishes spot less location basis), fallback front future mark (id `${commodityId}:FRONT`).
   - 1220 OWNED/RESERVED: `qty/1000 × 10 × mark('compute_spot')` ($/GPUh, 11 publishes; RESOLVED C1). 1221: 0 (03 §3.10.2).
   - 1500, 1510: `qty × effectiveMark`. 1520: `qty × clean mark` (fallback `MODEL_CURVE` mark id `${assetId}:MODEL`; defaulted sovereign issuers at RECOVERY marks) plus the accrued interest receivable book (1110 sub assetId).
   - 1530: last NAV mark (08 publishes NAV at day close, intraday estimates as MODEL_FUND); gated funds: 08 publishes the gate-adjusted NAV.
   - 1540: clearing mark (depegged stablecoins at market, never at peg). 1541, 1542: LP or deposit token marks published by 06 (pool reserves × underlying marks).
   - 1560: clearing mark if traded within its validity, else last model mark.
   - 1570: if the installed `EquityMethodFn` returns a value for (holder, issuer of the stake), that value: associates are carried at equity-method value in the parent's solo books (03 §3.11.5 item 4); otherwise `peMark`: last arm's-length round price per share × (1 − `PARAM.pe_mark_decay_per_quarter`)^(whole game quarters since the round), then `min` with `modelValue` (09 valuation per share, preference-adjusted by 09's waterfall); no round → `modelValue × 0.75` (25% illiquidity). Rounds with `armsLength false` are ignored (arm's length = no related parties and ≥ 2 unrelated investors, decided by 09).
   - 1580: `LookThroughFn(holder, sub)` (installed by T03-16; default book balance).
   - 1600/2600: cleared positions book (VM already moved cash); uncleared `qty × MODEL_OPTION / swap / CDS mark` (06 publishes per position id).
   - 1800: latest APPRAISAL mark of the property (10; cadence `PARAM.prop_appraisal_cadence_game_days`, cap ±15% per cadence unless an event; T03-14 posts). 1860: book (14's resale curve applied by `LED_LIFESTYLE_DEPRECIATION`). 1870: INDEX mark × item multiple (06 publishes the item mark).
5. `closeMarkValue`: `notional(qty, closePrice, lotScale)` for the marketable codes of `MARKETABLE_CODES`; undefined if no close today.
6. ECL (03 §3.9.3): `eclAllowance` computes Σ in float then `toMoney` per loan (rounding per loan, then sum). PD and LGD are supplied by 07 (borrower rating or scorecard, collateral LGD); T03-14 posts the daily `LED_ECL_PROVISION` delta and `BNK_LOAN_CHARGEOFF` is 07's on default resolution.
7. `revaluationTarget` (03 §3.9.4): companies (`cmp`, `bnk`, `ins`, `exc`, `rat`) holding property for own use (`heldForUse`) or intangibles above cost → `OCI_3400` (recycled to P&L on disposal); characters and alliances always `PNL`; everything else `PNL` (D042: all characters' property through P&L).

**[03 §1 Purpose]** (context)

## §1 Purpose

The ledger is the game's first law: **every unit of money and every unit of every asset exists on exactly one balance sheet, and moves only by a posting with a reason code**. This module defines:

1. the entity kinds and the balance sheet each one carries;
2. the full chart of accounts;
3. the double-entry posting model, its standard templates (pay, mint, burn, lend, revalue, FX) and the payment rail across settlement cash, bank deposits and partitions;
4. the complete reason-code catalog of the game, each code in exactly one class (FAUCET, SINK, TRANSFER, CREDIT_CREATE, CREDIT_DESTROY, REVALUE);
5. money aggregates (M0, M2, player-economy money and wealth), the faucet and sink inventory with target ratios, the **Stabilizer** PI controller, the **Money Supply Index (MSI)** and the **Net Worth Index (NWI)**;
6. valuation (marking) rules for every asset type, including illiquid ones;
7. consolidation of ownership chains, minority interests and intercompany elimination;
8. taxes in the five blocs and the Isla Serena free zone;
9. financial statements generated for every entity;
10. insolvency and bankruptcy accounting;
11. the invariants asserted every tick.

Design stance: real accounting where it creates gameplay (balance sheets, consolidation, taxes, credit creation, insolvency), simplification only where it would be invisible (no accrual-vs-cash tax timing nuances beyond those listed, no lease accounting standards). The ledger is also the evidence base for courts (13), the explanation base for "Why it moved" (18) and the data base for the Truth Machine (20).

**[03 §3.9.1]** (from spec file 03-LEDGER-AND-ACCOUNTING.md)

#### §3.9.1 General rules (mark governance)

1. Marks come only from engine sources: market clearing, engine models, engine appraisals, NAV strikes. **Never** from a price a player declares, from a P2P or related-party transaction price, or from a contract term.
2. **Thin-print guard** for exchange-traded assets: the intraday mark after a tick with clearing volume `V` at price `P` is `mark = (V·P + V_min·mark_prev) / (V + V_min)` where `V_min = PARAM.mark_min_volume_frac (DEFAULT 0.002) × ADV20` (05 provides ADV). A single tiny print cannot move the mark much (anti-ramping for NW).
3. **Stale marks**: a mark older than its `validUntilTick` is flagged `STALE`; NW still uses it, but boards apply the illiquidity haircut of §3.10.3; collateral systems (07) apply their own haircuts.
4. **Halted instruments** keep the last mark flagged `STALE` until the reopening auction.
5. All marks are in the asset's currency; translation per §3.3.6.

#### §3.9.3 Expected credit loss (loans, receivables)

`allowance = Σ_loans EAD × PD_12m × LGD` for performing loans and `EAD × LGD` for defaulted ones; PD from the borrower's rating or 07's scorecard, LGD from collateral (07). Updated daily with `LED_ECL_PROVISION`. Charge-off on default resolution with `BNK_LOAN_CHARGEOFF`.

**[03 §3.9.4]** (from spec file 03-LEDGER-AND-ACCOUNTING.md)

#### §3.9.4 Revaluation surplus vs P&L

Companies holding property for their own use and intangibles carried above cost book the excess in 3400 (OCI) and recycle it to P&L on disposal. Everything else revalues through P&L. Characters have no OCI: every revaluation is P&L. Net worth includes both.
