Written **2026-11-11T18:41:03.251281+01:00 Europe/Paris**, before implementation or tests. Branch `sys/fx`; base `110583b0aa73ece1dc3b856665f3be0405f1acc3` fetched and verified.

## Player outcome
A funded account can convert money through four real finite FX legs, make an all-or-none cross conversion, or pay a bank for retail conversion. Currency cannot appear by exchanging it: every debit has a funded counter-credit in the same currency. Auto-FX executes before a finite asset delivery, cancels that delivery on FX failure, and keeps unused converted money. This is an isolated engine integration seam, NOT already-visible app functionality. No auth/claims/Wire/UI writers are changed.

## Grounding: how the base works
Overview: base web catalog has equities/index and graduated crypto, no FX balances/books. AuthService owns one FDL cashCents per account and locked Broker/Launchpad commits. Broker finite-book execution (`src/server/broker/book.ts:1-3,44-92`) transfers cash/tokens and fees, but its token-quantity conventions, meme depth and one-currency auth schema are not FX.
Key concepts: the macro package owns PPP/UIP fair values, reserve-limited interventions, regime events (`packages/engine/macro/rules/fxFair.ts:19-29`, `fxRegimes.ts:41-43`); it is not mounted in web and cannot be imported with its private package aliases. No live FX producer exists at this base.
How it works now: auth locked snapshot → Broker decision → atomic account/book save → market prints only after commit (`src/server/broker/service.ts:69-86,116-167`). A second wallet writer here would violate that boundary.
Where the new module lives: src/server/market/fx/ owns five-currency allocations, finite offers, quotes, staged conversions and delivery, plus one durable journal facade. Future mounting must transfer ownership into one atomic store, not copy live balances into a parallel engine. Public aggregate view strips account/order identities.
Gotchas: immutable base is not the latest calibration worktree; previous sys units are not merged dependencies. No bank/FX source is invented. Full ledger posting integration, authorization boundary, live clock epoch mapping, hooks and UI remain coordinated later work.

## Usage sketch and synthesis
Caller supplies explicit allocations, opens one FxEngine per path, and observes consecutive authoritative frames containing marks/controls and sealed commands. preview operates on a copy; observe saves before publishing; snapshot is private, publicView aggregates only. Native offers are finite payout quantities at a limit quote/base rate. Fee-unfunded offers are not executable depth.
Candidate A: extend AuthService wallet schema, Broker and shared clock now. Hides lookup but changes shared writers and requires whole-app migrations; rejected for split ownership and Builder overlap.
Candidate B (selected): one isolated pure state owner with durable replay journal and typed commands. Small observe/preview/view surface hides two-leg rollback, holds, fees, phases, replay and per-currency conservation. Offers and auto-asset contracts are part of this single state, never callbacks mutating another store. Stable id is the final tie-breaker. Richer than a currency-conversion math wrapper, no forwarding-only adapter.
Screened both against design-red-flags: no duplicated mutable live owner, no hand-synced currency lists, no caller-coordinated partial commit. Accept journal replay growth instead of a second checkpoint-state validator; retention/compaction/multiprocess ownership/fsync/auth remain future integration duties. Task/arena/cloud workers are unavailable or forbidden here; two distinct designs compared locally, no cross-model judge claimed.
